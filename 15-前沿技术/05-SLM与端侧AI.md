## §1 定位：三个场景账，为什么端侧需要"小模型"

先放弃一个直觉——"小模型 = 大模型的缩水版，因为它装不下更差的"。按这个直觉，"小模型"永远在羞愧地仰望大模型。端侧的判断标准不是参数军备竞赛，而是**三个场景,大模型物理上就不成立**：

| 场景 | 为什么大模型（云）回答不了它 | 端侧 SLM 怎么回答 | 代价 |
|---|---|:---|:---|
| **成本** | 每 token 都要网络 + API + 云端算力；高频任务（语音转写、摘要、分类）打 API 贵得离谱 | 权重一次买断、离线跑、token 零边际成本 | 质量天花板低于云端最强 |
| **隐私** | 数据出设备 = 不可控（医疗、办公文档、实时录音） | 数据不出设备，权重在本地 | 本地差，就要用更小模型忍质量 |
| **离线** | 飞机、隧道、弱网、断电断网场景无 API 可打 | 完全离线可跑 | 断网时无法更新能力 |

把表竖着读，得到 `15-05` 的定位句（plan3 原话）：**小模型 = 成本 + 隐私 + 离线场景的答案**。而"不是牛更小的牛"的证据正是代表清单——每一个都是为端侧约束**重新设计**，不是剪枝大模型。

## §2 代表清单：六家，"小"的不同切法

同一件事——"把模型做小到能装进端侧"——不是每家同一条路。按"小"从哪里来分四族：

| 代表 | 参数档（公开） | "小"的来源 | 一句话理解 |
|---|---|:---:|---|
| **Phi 系列**（微软） | 1.5B / 3B / 4B | **教科书级高质量数据**（"教小学生用最精的课本"） | 用极少 token 训出同尺寸标杆：证明"数据质量>墙高数据量" |
| **SmolLM**（HuggingFace） | 135M / 360M / 1.7B | **为小参数量身设计的合成+筛选数据** | 端侧教学/实验的入口：小到手机 demo 也能学 |
| **Gemma 3n**（Google） | ~1B（n=端侧变体） | 蒸馏 + NPU 专门的权重量化 | 端侧开放权重线，直接配 Google NPU 生态 |
| **Qwen3 小 / Qwen3-0.6B-4B**（阿里） | 0.6B / 1.7B / 4B | **截断版本 + 蒸馏**（Qwen3-4B 被当作"小而全"部署宠儿） | 中文端侧部署的事实主力之一 |
| **MiniCPM**（面壁） | 1.2B / 2.4B / 4B | **蒸馏 + 长上下文 + 端侧量化**一体化 | "以小博大"的中文阵营代表，多模态也做 |
| **Llama 3.2 1B / 3B**（Meta） | 1B / 3B | **大模型继续训练（distillation-like）**；3B 为端侧优化的剪枝 | 欧美端侧生态默认入口（Ollama/llama.cpp 预置） |

读表要点：**"小"的四条来源 = 高质量数据（Phi）/ 专门合成数据（SmolLM）/ 蒸馏+剪枝（Qwen3小、Llama3.2）/ 端侧原生定制（Gemma 3n、MiniCPM）**——它们不是"把 70B 缩小到 7B 的同一件事"。

## §3 端侧推理栈：MLX · llama.cpp · NPU 三栈不互斥

"端侧"不是一种硬件，三个栈回答三个不同的"谁在跑"：

| 栈 | 目标设备 | 谁为它设计 | 特点 | 适用 |
|---|---|:---:|---|---|
| **llama.cpp** | CPU / Apple N/A、纯 C++ | 人人可装 | 消费级 CPU 就能跑 1B-8B；GGUF 量化格式是文件事实标准 | 桌面/Linux/任何机器快速试模型 |
| **MLX**（Apple） | Apple Silicon（M1-M4） | Apple 自家 | 原生 MPS 后端，内存统一架构（GPU 可用整个内存） | Mac 上跑 SLM 的主流路径 |
| **NPU 集成** | 手机 SoC（高通/联发科/华为/Apple）内的专用芯片 | 硬件厂商 | 极低功耗跑小模型；绑定厂商 SDK/格式 | 常驻端侧（通话助理、端侧 OCR） |

**三条不互斥**：llama.cpp 出 GGUF 文件 → MLX 读到 Mac 上、NPU 读到手机里；同一个模型可以三栈都跑，只是"哪个栈是主力"看设备。No"端侧堆栈"的标准答案——**它是一套"文件格式 + 三种后端"的可移植体系**。

## §4 技术点：蒸馏+高质小数据是"小得好看"的关键

小模型质量塌不塌，提前决定在数据与来源，不主要在参数量。三件事：

### 4.1 蒸馏：小模型的"老师"都在这儿

SLM 的绝大多数不是从头训的——**蒸馏**（知识从大模型"教"给小的）是省训练预算 + 继承大模型知识面的主通道。路径（挂 `02-核心原理/22-蒸馏与CPT.md`）：

```
大模型（老师）
   │ 训练时蒸馏（logits/自蒸馏、数据来自老师生成）
   │ 或 推理时蒸馏（老师打标签 → 学生微调）   ← 最常见的"合成数据→小模型"
   ▼
小模型（学生）← 高质量小数据清洗后的"精华"喂进去
```

### 4.2 高质量小数据：Phi 的"课本"记账

Phi 系列的关键不是"小"，是**数据预算的极端倾斜**：用极少量精心挑选的"教科书级"文本，达成同尺寸的算法效率。这记在 `15-06 合成数据进阶` 的数据飞轮账上——**给小模型的数据不是"更多"，是"更对"**。

### 4.3 量化装载：int4 = 端侧入场券

端侧内存是第一约束，量化是把模型装进去的钥匙：

```
fp16 装载：≈2.0 GiB / 1B 参数
int4（GGUF/int4 权重）：≈0.5 GiB / 1B 参数
```

挂 `03-06 Gemma` 的锚点算实在账——**Gemma3-1B fp16 装 2.0 GiB，手 4 GiB 可装；Gemma2-9B fp16 9.0 GiB 进不了桌面 8 GiB，只有 int4 的 4.3 GiB 才进**。"int4 端侧入场券"四个字，具体就是这个锚点（探针账 A 用同一本账）。
