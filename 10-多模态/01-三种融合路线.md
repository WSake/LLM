## 0. 为什么第 0 课是「三种融合路线」？

10 章的教学法约定在 plan/project 里写死了两条，本篇就是要立这两条规矩：

1. **每篇必须回答“这条路线改动的是哪一层（编码器/对齐/解码器）”**——多模态积木多（ViT/CLIP/Q-Former/投影器/SigLIP/动态分辨率/原生 token），**背参数没用，知道改在哪一层才有用**：改编码器 = 眼睛换不换；改对齐 = 眼睛和嘴巴怎么接；改解码器 = 大脑本身懂不懂图。

开篇必须先立 10 章最小的地图：**三种融合路线 = 多模态的演化主线**。这条主线不是三条并列的技术方案，而是“模型处置图像输入”的三种态度——**图像要不要经模型、改哪一层才能让模型懂图**。理解这条主线，后面 02-10 篇全是它的展开与案例。

## 1. 先把三路线钉死：三类“改动层” ？

在看任何多模态模型之前，先背下这张最小的地图（知识地图 §10.1 原话整理）：

| 路线 | 想法（一句话） | 改动的是哪一层 | 代表 | 代价 |
|---|---|---|---|---|
| **A 桥接** | 冻结现成 LLM，接一个“投影器”把图翻译成 LLM 看得懂的 token | **只改对齐层（桥）**：编码器冻结、LLM 冻结 | Flamingo(2022) · BLIP-2(2023) · 早期 LLaVA(2023) | 快、省，**上限受制于桥的质量** |
| **B 开放参数** | 视觉-语言联合指令微调：开放全部或部分参数做多模态 SFT/RL | **改对齐层 + 解码器**：编码器微调或冻结，LLM 全参微调 | LLaVA-1.5(2024) · Qwen-VL · InternVL | 今天开源主流，质量上去、训练成本上升 |
| **C 原生多模态** | 从预训练开始把文本/图像/音频统一成一个 token 空间来建模 | **改解码器全网络**：没有独立“桥”这层概念 | GPT-4o · Gemini · Llama4 | 融合最彻底，**成本最高**（从零预训练） |

**读法**：三路线不是“谁取代谁”的三档，是“改哪一层”的三个答案——**A 只碰对齐层（桥），B 解冻了解码器（开放 LLM），C 干脆把输入空间重新定义过（没有桥）**。教学法约定的第一句话，在每一行里就是那一列。

> 关键区别（为什么不是 02-01 Transformer / 03 模型家族的重复）：**02-01 讲文本 token 怎么变成上下文；03 各个家族把“多模态”作为八要素之一一笔带过；本篇把“模型处置图像的三条路线 + 改哪一层”钉成一张决策地图，并给出算账（图进模型要花多少 token / 三个路线各花多少钱）。**

## 3. 账 A · 路线账：改动的是哪一层（§10.1 教学法约定第一问）

**一句话：先把三路线和“改哪层”默写下来——不知道改在哪层，后面 02-10 篇全部白看。**

运行结果：
```
A1 三路线齐备 3/3： A桥接 · B开放参数 · C原生
A2 A桥接 改动层：编码器[冻结（复用现成视觉编码器）] · 对齐[训练（投影器/Q-Former/交叉注意力）] · 解码器[冻结（LLM 权重不动）]
A2 B开放参数 改动层：编码器[微调或冻结（Qwen-VL 大ViT微调 · LLaVA-1.5 ViT冻结）] · 对齐[训练（投影器参数全参与）] · 解码器[全参微调/RL（开放 LLM）]
A2 C原生 改动层：编码器[原生并入（统一 token 空间）] · 对齐[无独立桥（不需要投影器）] · 解码器[从预训练开始统一建模（改动解码器全网络）]
A3 A桥接 主改动层 → 对齐层（桥） · A3 B开放参数 主改动层 → 对齐层 + 解码器（开放参数） · A3 C原生 主改动层 → 解码器全网络（无独立对齐层）
A4 演化谱系 8 节点排序正确（桥→开放参数→原生）： Flamingo(2022) → BLIP-2(2023) → LLaVA(2023) → LLaVA-1.5(2024) → Qwen-VL(2023-2025) → InternVL(2024-2025) → Gemini(2023-) → GPT-4o(2024)
A5 冻结矩阵：编码器+解码器双冻结的只有 A 桥接（B 的 LLM 被解冻、C 没有“冻结”概念）
```

**A1 三路线齐备 3/3** + **A2 改动层矩阵 3×3**——每条路线在"编码器 / 对齐 / 解码器"三个位置各填一格，教学法约定的第一问落到表格：

| 路线 | 编码器（眼睛） | 对齐（眼睛→嘴巴的桥） | 解码器（大脑） |
|---|---|---|---|
| A 桥接 | 冻结 | **训练（投影器/Q-Former/交叉注意力）** | 冻结 |
| B 开放参数 | 微调或冻结（Qwen-VL 大 ViT 微调 · LLaVA-1.5 ViT 冻结） | 训练 | **全参微调/RL** |
| C 原生 | 原生并入 | **无独立桥** | 统一 token 预训练 |

**A3 主改动层 3/3**——每路线只抓一个主干：**A = 对齐层（桥）/ B = 对齐+解码器（开放参数）/ C = 解码器全网络（无桥）**。这就是"看得懂架构差异落在哪层"的起点。

**A4 演化谱系 8 节点**——按发布时间把这条主线走一遍：**Flamingo(2022)** 交叉注意力把视觉条件拿进冻结 LLM（A）→ **BLIP-2(2023)** Q-Former 桥、编码器+LLM 双冻结（A）→ **LLaVA(2023)** 线性投影桥、两阶段（A 的桥）→ **LLaVA-1.5(2024)** 解冻 LLM 全参微调（跨进 B）→ **Qwen-VL** 大 ViT + M-RoPE + 动态分辨率（B）→ **InternVL** 像素对齐/准原生 token（B 走向 C 的门口）→ **Gemini / GPT-4o** 原生统一 token 空间（C）。**同一只 LLaVA 两代**：初版是 A（冻结 LLM 只训桥），1.5 升级成 B（解冻 LLM 全参微调）——交界点就一个，**"LLM 的权重动不动"**。

**A5 冻结矩阵**——双冻结（编码器+解码器都不动）的**只有 A**；B 解冻了 LLM、C 压根没有"冻结"这个概念。这条是剥掉参数细节后最干净的分界线。

## 4. 账 B · token 流水账：图像怎么变成 LLM 的输入

**一句话：图进模型的第一步是变 token——一张图的 token 数接近一段不短的文本，这是所有多模态成本账的起点。**

运行结果：
```
B1 一次性 patch 化：224px→256 tok · 336px→576 tok · 448px→1024 tok（patch=14）
B2 长宽比归一到 336×336 → 固定 576 tok（长边缩放+中心裁剪，造型输入一个尺寸）
B3 视觉 prefill 占比：576 tok 图 + 200 tok 提示 → 序列 0.74 都是视觉
B4 BLIP-2 Q-Former 压缩 256→32 个 query token：KV 条目省 87.5% · 注意力二次项省 98.4%
B5 图为成本大头：token 减半 → 注意力二次项变 1/4（576²=331776 → 288²=82944 · 144²=20736 → 0.0625×）
B6 一张图≈一段文本：576 visual tok ÷ 2 tok/字（中文量级）≈ 288 个汉字——图不是“短输入”
B7 patch 粒度是价格旋钮：224px 用 patch=14 → 256 tok · patch=32 → 49 tok（格子粗=省token=丢细节）
B8 LLaVA 不压缩直接进 vs BLIP-2 Q-Former 压到 32：注意力二次项省 99.7%（576²=331776 → 32²=1024）
```

**B1 patch 化成 token**——ViT 把图切成 14×14 的小格子（patch），每格线性投影成 1 个 token：224px → (224/14)²=256 个 token；336px → 576；448px → 1024。**图被 token 化的那一刻就进了上下文，和文本 token 同价**（02-01 Transformer 只引）。

**B2 长宽比归一**——真实输入图片千姿百态，LLaVA-1.5 的静态处理器把任意外观缩放到最长边 336 再中心裁剪成 336×336 → **固定 576 token**（"一张图上到队列里占 576 个位置"）。造型输入只有一个尺寸，是静态路线的省心点；代价是矮胖图被裁掉内容——动态分辨率（Qwen-VL）就是来修这个的，02 站展开。

**B3 视觉 prefill 占比**——同样一段请求里，一张 576-token 的图 + 一条 200-token 的提示 → 序列的 **0.74 是视觉**。**多模态成本的第一推动力就是图像 token**（prefill 看 token 数、注意力看 token 数，KV 也看 token 数）。

**B4/B8 压缩是路线 A 的护城河**——BLIP-2 的 Q-Former 用 32 个可训练 query token "问"出图里的关键信息，把 ViT 的 256（或 576）个 patch token 压到 32 个再送进 LLM：**KV 条目省 87.5%（32/256）· 注意力二次项省 98.4%**。不压缩直接进（LLaVA 的线性投影）在 576 token 上也只要一个线性层，省的是"桥的参数"；但**注意力对 token 是二次增长**（B5：token 减半 → 注意力变 1/4），所以"少 token"从来都是多模态的天字第一号工程——Q-Former 压 token、动态分辨率限 token，全都在答"尽量少带图进上下文"这道题。

**B6 换算成文**——576 token ÷ 2 token/字（中文量级）≈ **288 个汉字**：一张图在 LLM 眼里就是一小段文本，不是"零成本附加"。**B7 patch 粗细**——patch=14 与 patch=32 是同一张图的两种 token 价签（256 vs 49）；格子粗省 token 但丢细节，这就是为什么高分辨率任务要更细的 patch 或动态分块。

## 5. 账 C · 决策账：什么场景走哪条路线

**一句话：会挑路线才算会——三档成本、三档数据、五个场景决定走哪条。**

运行结果：
```
C1 三档成本级：A 桥×1（只训对齐层） < B 开放参数×10（多模态 SFT/RL） < C 原生×100（从零预训练）
C2 可训参数档：A 投影器 ≈0.03B（7B LLM 冻结不训）· B 全参微调 ≈7.0B · C 原生从零（规模量级 ≥100B）
C3 数据档：A 对齐样本 ≈0.56M · B 视觉指令 ≈0.67M · C 图文对+交错语料（百亿级，右列为教学量级）
C4.1 场景选路线 1/5：已有 7B 文本 LLM，预... → A桥接
C4.2 场景选路线 2/5：要做领域图表问答产品，视觉质... → B开放参数
C4.3 场景选路线 3/5：旗舰全模态助手：实时语音+视... → C原生
C4.4 场景选路线 4/5：发票/账单 OCR 结构化，... → 工程(不动模型层)
C4.5 场景选路线 5/5：公司知识库里的图表/截图都要... → B开放参数
C5.1 经典选型 1/3：已有文本 LLM 且预算极小... → BLIP-2 / 早期LLaVA（A桥接）
C5.2 经典选型 2/3：领域图表问答 质量要求高... → Qwen2.5-VL / InternVL（B开放参数）
C5.3 经典选型 3/3：旗舰实时语音全模态助手 → Gemini / GPT-4o（C原生）
C6 决策方向：A 已有强 LLM + 预算小 + 质量容忍 → 只训对齐层 → B 有算力/数据 + 质量优先 → 开放 LLM SFT/RL → C 成本不敏感旗舰 → 从零统一定义输入
```

**C1 三档成本**（教学层数量级）：A 桥 ×1（只训对齐层）→ B 开放参数 ×10（多模态 SFT/RL）→ C 原生 ×100（从零预训练）。**记一张梯子：能桥不训、能微调不开练**——跟 14 章的"能工程先工程、能 SFT 不 CPT"同构。**C2/C3 参数与数据档**：A 只训 ≈0.03B 的投影器、样本 ≈0.56M（LLaVA-558K 量级）；B 全参微调 7B、视觉指令 ≈0.67M（665K 量级）；C 从零是百亿级图文语料——**路线 C 贵的不只是算力，是"生日数据"（从预训练第一天就得多模态语料），这是小团队的天花板，也是 2025 开源才追上来的原因。**

**C4 五场景选路线 5/5**——同一道"多模态选型"题的五种答案：

| 需求 | 路线 | 为什么 |
|---|---|---|
| 已有 7B 文本 LLM、预算极小、快速补看图 | **A 桥接** | 只训投影器，LLM 不动——一周内能上线，上限够用就行 |
| 领域图表问答、视觉质量要求高、有算力/数据 | **B 开放参数** | 质量优先就解冻，领域图/版式强相关时 ViT 也值得微调 |
| 旗舰全模态助手（实时语音+视频+文本） | **C 原生** | 实时跨模态需要统一 token 空间的低延迟融合，桥的缝隙藏不住 |
| 发票/账单 OCR 结构化、OCR 引擎已够、接 LLM 总结 | **工程（不动模型层）** | 图片里信息已由 OCR 提出来了，模型吃文本就行——**不改任何层** |
| 知识库里的图表/截图问答、文本 RAG 升级文档理解 | **B 开放参数** | 图表/截图直接进模型（10-09 多模态 RAG 的口子），开源 VLM 够用 |

**教学点**：**最贵的不总是最对**——发票那条是"工程路线"（Image 根本不需要进模型，OCR 引擎先把字抽出来再喂 LLM），这才是最多商业场景的真实答案；动不动模型层，取决于"图里的信息能不能在模型之外提出来"。

**C5 三组经典选型**——低资源补视觉 → BLIP-2/早期 LLaVA（A）；高质量开源多模态/UI 操作 → Qwen2.5-VL/InternVL（B，今天的主流购物车）；旗舰原生 → Gemini/GPT-4o（C）。**C6 决策方向**——一句话版：**A 是"我已有 LLM 只想加眼睛"，B 是"我要开源的强"，C 是"我从第一天就要融合"。**

## 6. 账 D · 掌握度检验账：架构→路线 + 发票 OCR→结构化

**一句话：plan 的掌握度检验有两问——"架构差异对应哪种路线"与"发票丢进 OCR→结构化管线"——探针把两问都做成可跑。**

运行结果：
```
D1 架构→路线 9/9： BLIP-2→A · Flamingo→A · 早期LLaVA→A · LLaVA-1.5→B · Qwen-VL→B · InternVL→B · GPT-4o→C · Gemini→C · Llama4→C
D1.x 架构描述→路线 5/5： ViT冻结+线性投影+LLM全参SFT → B · Q-Former+双冻结 → A · 统一token空间全预训练 → C · 大ViT微调+M-RoPE+LLM全参(Qwen-VL式) → B · 交叉注意力注入(Flamingo式) → A
D2 发票 OCR→结构化 5/5 字段：发票号码=33102233445566778899 · 开票日期=2026-09-22 · 购买方名称=上海某某科技有限公司 · 销售方名称=北京某某信息服务有限公司 · 合计金额=1,258.00
D3 挂靠：A→10-08 OCR 与文档理解管线 · B→10-02/10-03/10-04 · C→10-06/10-07
```

**D1 9 模型定路线 9/9**——掌握度检验第一问的探针化。三个"陷阱点"要会说：
- **早期 LLaVA 是 A，LLaVA-1.5 是 B**（同一家族跨路线——看 LLM 动不动）；
- **InternVL 归 B**：它用像素对齐/接近统一的 token 输入（比 LLaVA 更像 C），但仍是"开放参数 + SFT 家族"，训练起点不是从零——**"准原生"四字就是它**；
- **Flamingo 归 A**：交叉注意力是"桥的一种"，LLM 冻结。

**D1.x 架构描述反向 5/5**——只给架构描述不报模型名，照样定位路线：**Q-Former+双冻结 → A · ViT 冻结/微调+全参 SFT → B · 统一 token 预训练 → C**。这就是"看得懂架构差异落哪层"。

**D2 发票 OCR→结构化 5/5**——掌握度检验第二问的确定性样板：一张"发票"过 OCR 引擎（模拟输出）→ 正则提取 5 个字段（发票号码/开票日期/购买方/销售方/合计金额）。**这条管线一次权重都不用动**——正是账 C 里说的"工程路线"：图里的字先被 OCR 提出来，LLM 只吃结构化文本。

**D3 场景挂靠**——三条路线的"什么场景用得上"接到 10 章后续站：A → **10-08 OCR 与文档理解管线**（商业最密）；B → **10-02 视觉组件 / 10-03 图文对齐 / 10-04 VLM 路线对比(🔴)**；C → **10-06 视频与文本 / 10-07 音频与语音**。

## 7. 这篇怎么用（一页带走 + 掌握度检验）

**一页带走：多模态起步 = 钉三路线（A）→ 算 token 账（B）→ 挑路线（C）→ 过检验（D）。**

```
钉路线：A 桥接（冻 LLM+投影器 · 改对齐层 · 快省天花板是桥）
        B 开放参数（解冻 LLM SFT/RL · 改对齐+解码器 · 今天开源主流）
        C 原生（统一 token 空间 · 改整个解码器 · 融合最彻底成本最高）
算 token：224px→256 · 336px→576 · 448px→1024；一张图≈288 汉字；视觉 prefill ≈0.74
挑路线：能桥不训(×1)· 能微调不开练(×10)· 旗舰才从零(×100)；图外能提取就走工程(不动模型层)
过检验：看到架构说得清对应路线；丢张发票跑得通 OCR→结构化管线
```

**掌握度检验（不看代码，答得出才是真会）：**

1. 三路线各"改动的是哪一层"？（答：A 对齐层/桥 · B 对齐+解码器/开放参数 · C 解码器全网络/无桥）
2. 为什么早期 LLaVA 是 A、LLaVA-1.5 是 B？（答：交界点=LLM 权重动不动：初版冻结 LLM 只训桥，1.5 解冻全参微调）
3. InternVL 为什么归 B 而不是 C？（答：像素对齐像 C，但仍是"开放参数+ SFT 家族"、训练起点不是从零——"准原生"）
4. 一张 336px 图进模型占多少 token？约等于多少汉字？（答：576 token ≈ 288 汉字（2 tok/字））
5. 为什么 Q-Former 要把视觉 token 压到 32 个？（答：注意力对 token 二次增长——256→32 省 KV 87.5%、注意力二次项 98.4%）
6. "已有强 LLM 预算极小"走哪条？"旗舰实时全模态"走哪条？（答：A · C）
7. 发票场景为什么是"工程路线"？（答：OCR 引擎先把字抽出来，图不进模型、模型层一字不动）
8. 推倒重来：什么时候你无论如何都不该做 C？（答：预算/数据不够从零、或只需要"文本 LLM + OCR 提取"——动的只有工程，不动的只有权重）

## 8. 常见坑（理解多模态路线的 7 个）

1. **把"多模态"当"加个视觉编码器"**——三种路线区分的是改哪一层；只挂编码器不训桥=图进不去（A 也要训对齐）。
2. **以为 C 是"更强的 B"**——B 是在既有文本 LLM 上开放参数，C 是从预训练第一天就把图像混进去；成本不是同一件事（×10 vs ×100）。
3. **背参数不背层**——"Q-Former 是什么"不如"它是桥的一种、作用是把几百 token 压成几十个送进冻结 LLM"。
4. **把 InternVL 当 C**——准原生 ≠ 原生；训练起点决定路线（开放参数 vs 从零）。
5. **无视图像 token 的成本**——一张图 ≈ 288 汉字 ≈ 0.74 prefill——多模态贵在 token，不是贵在"魔法"。
6. **能 OCR 却偏要上 VLM**——发票/账单这类"信息已在图上、提取是成熟工程"的场景，图不进模型更省更稳（工程路线）。
7. **只留着"请用 Gemini 旗舰"一句**——C 的成本门槛是真实的，没需求压着就该 B 甚至 A；路线是需求挑出来的，不是身份。
