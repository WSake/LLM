## 0. 为什么第 2 课讲「眼睛」？

01 篇把三条路线钉死了。回看那张 3×3 改动层矩阵（01 账 A2），编码器那一列只有一句话：

| 路线 | 编码器（眼睛） |
|---|---|
| A 桥接 | 冻结（借现成的 CLIP/ViT） |
| B 开放参数 | **微调或冻结**（Qwen-VL 大 ViT 微调 · LLaVA-1.5 ViT 冻结） |
| C 原生 | 原生并入 |

这一格藏着今天开源 VLM 全部的技术下半身：**拿到一张图，先要过编码器**——编码器把图切成 patch token，token 才进得去 LLM。01 篇用账 B 证明了「一张图 ≈ 288 汉字 ≈ 0.74 prefill」，全是编译码器的吐量。所以第二个教学问题顺理成章：

> **这一格到底怎么填？——眼睛怎么选（选哪只）、怎么对（怎么对焦）、怎么认（怎么认位置）。**

本篇把「编码器格」展开成三件事，一一对应一个会过账的确定性探针账：

1. **选哪只** → 编码器族谱（ViT/CLIP/SigLIP/DINOv2/InternViT）——图文要对齐才进 VLM，要稠密才适合像素级任务；
2. **怎么对** → 动态分辨率——不为一张图压扁一张图，分块保信息、预算帽限 token；
3. **怎么认** → M-RoPE——把「图的 2D 位置」和「文本的 1D 位置」放进同一个 3D 坐标空间。

> 关键区别（为什么不是 02 章 Transformer 的重写）：02-01 讲的是「文本/任意 patch 都是 token」的机制；本篇讲的是**编码器层的工程配方**——选型（族谱）、对焦（动态分辨率）、定位（M-RoPE），并且三样都落到「多少 token、多少比例」的确定性数字上。

## 1. 眼睛 = 三件事（先把地图钉上）

三件事用三个问句表达，教学法约定在本篇的第一句是"改动的是哪一层 → 编码器"，第二句"什么场景用得上"就藏在这三个问句里：

| 眼睛的三件事 | 问句 | 答案（本篇要练成一句话） |
|---|---|---|
| 选哪只（族谱） | 我的任务要「语义对齐」还是要「像素稠密」？ | 对齐文本 → CLIP/SigLIP；像素级任务 → DINOv2 |
| 怎么对（动态分辨率） | 大图/小字怎么办？ | 分块保可读（每片 224~1024px）+ 预算帽（≤6 片 + 缩略） |
| 怎么认（M-RoPE） | 位置要不要空间感？ | 图走 h/w 通道（2D）、文走 t 通道（1D）、视频走 t 时序 |

一句话版：**眼睛的大小不重要（ViT-L 只是 7B 的 4.3%），眼睛的三件套——族谱、对焦、定位——才是决定图像 token 贵不贵、糊不糊、塌不塌的关键。**

## 2. 把三件事降维成本机测量（探针设计：四本账）

理解三件事不能靠背参数。探针 `vision_encoder_demo.py` 用纯 stdlib 把四件事测出来：

|---|---|---|

| B | 怎么对焦（动态分辨率）？ | 固定压扁 vs 动态分块：6 种尺寸的网格决策 + token 账（分块×576+缩略 256）+ 预算帽 + prefill 占比 0.74→0.949 |
| C | 怎么认位置（M-RoPE）？ | 3D 坐标 (t,h,w) 频带三等分 + RoPE 频率 + 1D 拉平失真 vs 2D 拓扑保真 + 场景 5/5 + 位置量化 |

## 3. 账 A · 眼睛族谱：选哪只（编码器选型）

**一句话：先分清两大家族——会「对齐文本」的（CLIP/SigLIP/InternViT）与不会的（ViT/DINOv2）；VLM 的眼睛只能是前者，像素级任务的工兵是后者。**

运行结果：
```
A1 编码器家族 5 家齐备 · 年份 5/5（2020/2021/2023/2023/2024）
A1 图文对齐标记 5/5（CLIP/SigLIP/InternViT 对齐 · ViT/DINOv2 不对齐）
A2 场景选眼睛 5/5：发票/表格文字密集 → 高分辨率动态分块 · 搜图图文检索 → CLIP/SigLIP
              道路分割目标检测 → DINOv2 · 图表看图问答 → SigLIP/CLIP-ViT · 4000px 卷宗长图 → 动态分辨率
A3 账 A 矩阵『编码器格』三态 3/3：A桥接 冻结复用 · B开放参数 微调或冻结 · C原生 原生并入
A4 编码器参数只是 LLM 的零头（ViT-L 占 7B ≈ 4.3% · Qwen 大 ViT ≈ 9.6%）
A5 patch 粒度三档（224px）：14→256 tok · 16→196 tok · 32→49 tok（回引 01 账 B7）
A6 回引 01 锚点：336×336→576 tok · 固定压扁 336×189→312 tok（静态处理器丢信息）
```

**A1 族谱五家**（知识地图 §10.2 原话整理）：

| 编码器 | 年份 | 一句话 | 图文对齐？ |
|---|---|---|---|
| ViT | 2020 | 视觉版 Transformer：patch→线性投影→Transformer | ✗ |
| CLIP | 2021 | 对比学习（softmax 图文配对），图文对齐的事实底座 | ✓ |
| SigLIP | 2023 | sigmoid 逐 token 二分类，开源 VLM 最常用 | ✓ |
| DINOv2 | 2023 | 自监督（无标签、无文本），稠密/像素级特征 | ✗ |
| InternViT | 2024 | CLIP 系，按多模态需要扩大的大 ViT | ✓ |

**分水岭就一条：有没有对齐文本。** CLIP/SigLIP/InternViT 手上有"这张图的语义约等于这段文字"的知识，VLM 把图像 token 投影进 LLM 之后才接得上话；DINOv2 是从像素自己学出的世界结构（分割、检测、稠密特征），它不懂文本，所以不接 LLM。**A2 场景选眼睛 5/5** 就是这套判据的单选题：发票/表格 → 先保清晰度（动态分块）；搜图 → CLIP/SigLIP；分割/检测 → DINOv2；图表看图问答 → 开源 VLM 通用编码器（SigLIP 系）；卷宗长图 → 动态分辨率。

**A3 回挂 01 的矩阵**——同一个「编码器格」，三条路线三种处置。**A4 "眼睛不大"**：ViT-L 只有 ≈0.3B 参数，占 7B LLM 的 **4.3%**；Qwen-VL 把编码器加到大 ViT（≈0.675B）也只有 9.6%。**眼睛不是越大越好的瓶颈——token 数与清晰度才是**：A5 显示同样 224px，patch=14 → 256 token，patch=32 → 49 token，粗格子省 token 但丢细节（01 账 B7 的回引）。

## 4. 账 B · 动态分辨率：不为一张图压扁一张图

**一句话：固定处理器把任何图压到一种尺寸（336→576 token），图里的小字跟着糊成一团；动态分辨率按原图长宽比分块（2x1/2x2/3x2/4x1…），每片保持可读——可读性是用 token 买的。**

运行结果：
```
B1 固定缩放把 1600×900 压到 336 长边（≈4.76×）→ 小字糊 · 缩略图永久保留（1 片主力 + 1 张 224 缩略 = 全局版式）
B2 1600×900 → 2×1 分块 · 1408 tok（每片 800×900 可读，不压扁）· 动态/固定 token 比 ≈2.44×：可读性用 token 买
B3 正方形 1024 → 2×2 · 2560 tok · 极宽 4000×1000 → 4×1 · 2560 tok（每片 1000×1000）
   极高 600×2400 → 1×4 · 2560 tok（每片 600×600）· 小图 400×400 → 1×1 · 832 tok（不折腾）
   发票 1080×720 → 3×2 · 3712 tok（每片 360×360 小字清楚）
B4 token 公式：分块×576 + 缩略 256
B5 视觉 prefill 占比 0.74→0.949（动态分块把多模态成本推向视觉）
B6 预算帽全守：分块总片数 ≤6 · 每片边长 ∈[224,1024]
B7 六图全守：预算帽 ≤6 · 每片边长 ∈[224,1024] · 网格比例贴原图长宽比（2×1/2×2/4×1/1×4/1×1/3×2）
```

**B1 固定处理器的问题**——一张 1600×900 的大图，静态 resizer 先等比例缩到最长边 336（≈4.76×），再裁成 336×336 → **只有 576 token**。token 没多花，但**信息被压没了**：图里 8 号小字缩到 336×189 那一小块根本认不出来——"压小图丢信息"。

**B2/B3 动态分块**——按原图长宽比切网格，每片边长保持在一个安全区间（教学规则取 [224, 1024]px，精确实现见探针 `nearest_grid`），再各自 resized 到 336×336 → **每片 576 token + 缩略图 256**：

| 原图 | 网格 | 每片尺寸 | token | 相对固定 576 |
|---|---|---|---|---|
| 1600×900（横版） | 2×1 | 800×900 | 1408 | **2.44×** |
| 1024×1024（方块） | 2×2 | 512×512 | 2560 | 4.44× |
| 4000×1000（极宽） | 4×1 | 1000×1000 | 2560 | 4.44× |
| 600×2400（极高） | 1×4 | 600×600 | 2560 | 4.44× |
| 400×400（小图） | 1×1 | 400×400 | 832 | 1.44× |
| 1080×720（发票） | 3×2 | 360×360 | 3712 | 6.44× |

**B4 token 公式**：`分块数 × 576 + 缩略图 256`。**B6 预算帽**：总片数 ≤ 6，每片边长 [224, 1024]——小于 224 会"放大失真"（把 600×600 塞进 224 片里反而虚），大于 1024 会"压小丢信息"（跟 B1 一个病）；**缩略图 256 token 永久保留**，因为局部可读靠分块、全局版式靠缩略图。

**B5 代价**——同样的请求里，视觉占比从 0.74（01 账 B3 单张整图）跳到 **0.949**：**多模态的成本被动态分块进一步推向视觉侧**。这条线要记住：可读性是用 token 换的，预算帽就是"token 预算"的名字。

## 5. 账 C · M-RoPE：把 2D 位置和 1D 文本请进同一个 3D 坐标

**一句话：文本的注意力是一维的（前后文），图的空间关系是二维的（上下左右）——M-RoPE 把旋转维度三分成 (t, h, w)，文本走 t、图走 h/w，同一套注意力既能问"相邻字"也能问"相邻像素"。**

运行结果：
```
C1 3D 坐标 (t,h,w) 三等分旋转维度（60→20/20/20）· RoPE 频率 θ_1≈0.7356（低频长距离·高频局部）· 频率随 k 严格递减
C2 1D 拉平：图被拉成一行，位置=行序×行宽+列
C3 M-RoPE 分通道：h 只答垂直差、w 只答水平差 · 互不串扰
C4 1D 里下移一格=+行宽（跨行距离与同行距离在同一把尺）· M-RoPE 保留拓扑：同列相邻 h=1 < 同行远端 w=3
C5 文本 token 用 t 通道 · 图 patch 用 h/w 通道（每片内 h=行号、w=列号，2D 邻接保留）
C6 M-RoPE 场景 5/5（多图对比/视频/UI 要 · 单张小字/纯文本不要）
C7 1600px 分 2 片：0-799→片0 · 800-1599→片1（位置按图量化，跨分辨率可比）
```

**C1 三分通道**——M-RoPE 是 RoPE 的多模态版（02-05 章有 RoPE 完整铺垫，只引不重测）：把旋转维度三等分给三个坐标轴——`t`（文本/时序）、`h`（垂直）、`w`（水平），同一个 θ_k = base^(-2k/dim) 公式（θ₁≈0.7356，低频长距离、高频局部）。

**C2/C3/C4 为什么 1D 认不了图**——把一张 4×4 的图拉成一行，位置 = 行序×行宽+列：
- 1D 里 **(0,0)→(1,0)**（同列下移一格）= 距离 **4**；**(0,0)→(0,3)**（同行跳到最右）= 3——**"垂直移一格"比"水平跳 3 格"还远**，空间拓扑被压扁了。
- M-RoPE 里 **(0,0)→(1,0)** 只要 h 差 = **1**（w 差 0），**(0,0)→(0,3)** 只要 w 差 = 3（h 差 0）——**同列相邻距离 1 < 同行远端 3，邻接关系全程保真**。

这正是 §10.2 说的"多模态位置感知的关键"：图不被拉成字，图像 patch 之间的上下左右关系在注意力里是真实存在的。

**C5/C7 统一坐标空间**——文本走 t 通道（一段 200 词的提示 = 200 个 t 坐标）；图的每个 patch 走 (h,w) 通道。动态分辨率下同一图像有多个分块，M-RoPE 先做**位置量化**（C7：1600px 分 2 片，第 800px 就归到片 1），位置跟着分辨率走、跨尺寸可比。

**C6 什么场景用得上**——需要"空间/时序邻接"就要 M-RoPE：**多图并排对比、视频抽帧（t 通道串时序）、UI / 界面截图（控件相对位置）**；**单张小字 OCR、纯文本**不需要——这也解释了 Qwen-VL 系列在文档理解/UI 操作上为什么强（03-08/03-11 只引）。

## 7. 这篇怎么用（一页带走 + 掌握度检验）

**一页带走：编码器层的三件事 = 选族谱（A）→ 对焦动态分辨率（B）→ 认位 M-RoPE（C）→ 过检验（D）。**

```
选眼睛：对齐文本 → CLIP/SigLIP 进 VLM；像素稠密 → DINOv2 做分割；眼睛只是 LLM 的零头（4.3%）
对焦：固定处理器压小图丢信息（1600×900→576 tok 糊）；动态分块按比例切、每片 224~1024px
       预算帽 ≤6 片 + 缩略 256：token = 分块×576 + 256（2×1=1408 · 发票 3×2=3712）
认位：1D 拉平把「下移一格」当 4（拓扑塌）；M-RoPE 三分 (t,h,w)——图走 h/w、文走 t、视频走 t 时序
算账：图里字在图外可提取 → OCR/工程（发票 50 tok）；图里语义才值得 3712 tok 看图（≈74×）
```

**掌握度检验（不看代码，答得出才是真会）：**

1. 一张图进 VLM，90% 的工程问题浓缩成哪句话？（答：怎么把一张图变成不糊、不塌、不贵的 token——选眼睛/对焦/认位）
2. 图文检索要选哪个编码器？分割检测选哪个？（答：CLIP/SigLIP（图文对齐）；DINOv2（自监督稠密，不对齐文本））
3. 为什么说"编码器的大小不是瓶颈"？（答：ViT-L 只有 7B 的 4.3%，Qwen 大 ViT 也只有 9.6%；决定质量的是 token 数与清晰度）
4. 一张 1600×900 的图，固定处理器和动态分块各花多少 token、差在哪？（答：固定 576（压成 336×189 小字糊）· 动态 2×1=1408（每片 800×900 可读）——2.44× 用 token 买可读性）
5. 动态分辨率的预算帽长什么样？（答：总片数 ≤6 + 1 张缩略图；token = 分块×576 + 256；每片边长 [224,1024]）
6. 为什么纯 1D 位置认不了图？（答：图拉成一行，同列下移一格=+行宽=4，比"同行跳 3 格"还远，拓扑塌；M-RoPE 同列相邻=1）
7. M-RoPE 三个通道各管什么？（答：t 管文本/时序 1D · h 管垂直差 · w 管水平差；视频抽帧用 t 串时序）
8. 什么场景不该让整张图进模型？（答：图里的信息能在图外提取（票据/合同/表单）→ OCR/工程列 50 tok，看图 3712 tok≈74× 不值）

## 8. 常见坑（理解编码器层的 7 个）

1. **以为「视觉编码器 = 一个 ViT」**——族谱是大分叉：CLIP/SigLIP 对齐文本能进 VLM，DINOv2 不对齐只做像素级任务。
2. **以为编码器参数越大越好**——ViT-L 只是 7B 的 4.3%，Qwen 大 ViT 也只有 9.6%；瓶颈在 token 数与清晰度，不在眼睛体积。
3. **固定处理器随手压图**——1600×900 压到 336×189 = 4.76×，小字全糊；信息不是丢了，是被压没了（"压小图丢信息"）。
4. **以为动态分辨率是"无代价放大"**——预算帽 6 片+缩略站稳（token 2.44×~6.44×），视觉 prefill 占比 0.74→0.949，钱都花在 token 上。
5. **给图塞 1D 位置**——拉平丢拓扑；M-RoPE 按图量化、h/w 各管一轴，"同列相邻=1"。
6. **该工程的地方整图进模型**——票据 3712 tok vs OCR 50 tok ≈74×；能工程提取的不需看图。
7. **只背「Qwen-VL = 动态分辨率 + M-RoPE」**——要会说清"改的是编码器 + 位置这一层，是 01 账 A 三态里的哪一态"，这才算掌握了架构差异落点。
