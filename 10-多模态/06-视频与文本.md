## 0. 为什么第 6 课讲「视频」？

05 篇把 C 原生的「统一 token」拆完了——图/音/文进同一个序列（816）。但你细看那张 token 表会发现一件事：**视频在那张表里是"16 帧 = 4096"带过的**——05 篇用视频 token 只做了个演示，没回答一个工程问题：

> **视频不是"一张图"，是每秒 30 张图。VLM 能看懂一张图，凭什么看得懂 10 分钟的视频？**

10 秒视频 = 300 帧。300 帧 × 256 token/帧 = **76800 token**——一个图片模型一次只能吃一两张图（几百 token），76800 直接顶爆上下文。所以视频理解的第一课不是"模型多聪明"，而是**三个工程动作**：

- **抽帧**：每秒 30 帧太多，抽每秒 1-2 帧（或按场景切换取帧）——token 预算第一刀。
- **帧间时序编码**：抽出来的帧得知道"谁先谁后"——M-RoPE (t,h,w) 的 t 轴管这件事。
- **长视频分段**：1 小时视频抽了帧还是大（0.92M token），但 1M context 现在**装得下**——"整片塞进去"（Gemini 招牌）；再长就分段。

这三件事不是神经网络的新发明，是**视频进入 LLM 的"管道工程"**——本篇把每条管道上的数字都算给你看。

## 3. 账 A · 抽帧账：视频 → 帧 → token

**一句话：视频 token = 帧数 × 每帧 token；每秒 30 帧全喂 = token 爆炸（10s 视频 76800 tok），抽帧（每秒 1-2 帧或按场景）是预算第一刀——10s 视频 2fps 只要 5120 tok（省 15×）。**

运行结果：
```
A1 10s@30fps：总帧 300 → 全量 76800 tok（放不下）· 抽 1fps = 10 帧 = 2560 tok · 抽 2fps = 20 帧 = 5120 tok · 300→10 帧省 30×
A2 每帧 token 底座：224 图 patch14 → 256 tok/帧（02 篇锚点只引）
A3 抽帧策略①「每秒 1-2 帧」→ 均匀抽帧 · ②「按场景（镜头切换处取帧）」→ 按场景抽帧
A4 60s@24fps：全量 1440 帧 = 368640 tok → 抽 1fps = 60 帧 = 15360 tok
```

**A1 换算**——视频 token 的账就一行：`帧数 × 256`。10 秒 30fps = 300 帧 = 76800 tok（这个数比绝大多数模型的 context 都大）；2fps 抽帧 = 20 帧 = 5120 tok（省 15×）；1fps = 10 帧 = 2560 tok（省 30×）。**"视频贵"的真相不是模型贵，是帧数乘出来的**——先抽帧再谈理解。

**A2 底座**——每帧 256 token 来自 02 篇的"一张 224 图 patch14→256"（只引不重测）。视频帧就是独立图片，token 算法完全一样。

**A3 抽帧策略**——§10.5 原话"每秒 1-2 帧或按场景"：均匀抽帧（每 N 秒取一帧，最稳）、按场景抽帧（镜头切换处取帧，动作戏省帧、静态画面少帧）。**两个极端都不行：30fps 全喂 = 爆炸；1 帧到底 = 只见首帧丢全程。抽帧是"频率选择"，不是"丢帧"。**

**A4 长一点**——60 秒视频（24fps）全量 = 1440 帧 = 368640 tok（半 4 十万，仍未爆 1M 但已超 90% 模型）；1fps 抽帧 = 60 帧 = 15360 tok。**规律：token 与帧数线性，抽帧频率直接决定 token 预算。**

## 4. 账 B · 帧间时序编码账：怎么知道"谁先谁后"

**一句话：抽出来的帧要告诉模型"哪帧在前"—M-RoPE (t,h,w)：t 管第几帧（20 维）、(h,w) 管帧内哪格；全帧间注意力太贵（4096 tok 全局 pair 16.7M），帧内 attention 只要 1.05M（省 16×）——时序编码是"位置"，不是"模型层数"。**

运行结果：
```
B1 M-RoPE (t,h,w)：60 维三等分 → t=20（帧序）· h=20 w=20（帧内哪格）· 视频 token 位置 = (t,h,w) 三元组
B2 16 帧 = 4096 tok（05 锚点）：全局 self-attn 对 = 4096² = 16,777,216 · 帧内 attention = 16×256² = 1,048,576 → 省 16×
B3 时序判别：M-RoPE (t,h,w) → 有帧序 ✓ · 抽帧拼 grid 大图 → 无帧序（时间压成空间）✗ · 帧 token 简单拼接无位置 → 无帧序 ✗
B4 帧 token 计数锚点：16×256 = 4096（=05 篇锚点只引）· 第 2 帧 token t=1、第 3 帧 t=2 → 位置不同可区分
```

**B1 位置三元组**——05 篇 M-RoPE 锚点（只引不重测）：M-RoPE 把 60 维旋转三等分 (t,h,w)=20/20/20。视频的用法：**t 管"第几帧"，(h,w) 管"帧内第几格"**。不同帧的 token 即使画面内容一样，位置也不同——模型用位置区分"两帧"而不是"两张相同图"。这就是"帧间时序编码"的本质。

**B2 注意力成本**——16 帧 = 4096 token（05 锚点）。如果全部 4096 帧间彼此 attention：`4096² = 16,777,216` 对；如果只在帧内 attention（每帧 256 token 内部）：`16×256² = 1,048,576` 对——**省 16×**。这就是为什么视频 VLM 常做"帧内注意力 + 少量帧间"：全帧间太贵，全帧内又丢帧间关系，工程上是折中。

**B3 时序判别**——给一段编码描述判"帧序有没有被表达"：M-RoPE (t,h,w) 有（t 明确）；抽帧后拼成 grid 大图没有（时间被压成空间——你分不清第 3 帧和第 4 帧谁先）；帧 token 简单拼接不加位置也没有（模型只看到"一列帧图像素"，不知道先后）。**口诀：有没有把"第几帧"写进位置。**

**B4 锚点交叉**——16 帧 = 4096、t=20 都是 05 篇锚点（只引不重测）；位置可区分性（t=1 vs t=2）是纯算术验证。

## 5. 账 C · 长视频分段账：塞不下怎么办

**一句话：§10.5 的"长视频分段（1M context 后可以整片塞进去）"是道算术题——1 小时视频 @1fps = 3600 帧 = 921,600 tok ≈ 0.92M，正好在 1M context 内（Gemini 招牌）；没有 1M 或超过 1M 就分段抽帧+段摘要级联。**
运行结果：
```
C1 1 小时 @1fps = 3600 帧 = 921,600 tok ≈ 0.92M < 1M → 整片塞（§10.5 原话）· 1 小时 @30fps 全量 = 108,000 帧 = 27,648,000 tok ≈ 27.6M（差 30×）
C2 2 小时 @1fps = 1,843,200 tok ≈ 1.84M（500K 模型放不下）→ 分 2 段每段 1h = 0.92M/段 → 逐段进 + 段摘要 · 段摘要级联保留帧序
C3 三足判别：①整片塞（≤1M）②分段摘要（超 1M/上下文受限）③定位检索（要"某句在第几分钟"）
```

**C1 1M context 整片塞**——这道算术是 Gemini"1M+ 长视频上下文"招牌的数值解释（04 篇锚点只引）：1 小时 = 3600 秒，1fps 抽帧 = 3600 帧 × 256 = **921,600 ≈ 0.92M**，小于 1M → **"整片塞进去"**（§10.5 原话）。对比全量 30fps：1 小时 = 108,000 帧 = 27.6M——**差 30×，所以"能看长视频"的第一功臣不是上下文，是抽帧。**

**C2 超 1M 分段**——如果模型 context 只有 500K，或视频 2 小时（1.84M）：没法整片塞，就分成 N 段（每段 1 小时 0.92M）逐段进，每段出"段摘要"，最后把段摘要级联喂给模型。**关键：段摘要要按帧序排列（段 n 摘要在段 n+1 前）——分段可以牺牲帧间细节，但不能丢时间线。**

**C3 三种策略判别**——看需求选：**① 整片塞**（视频 ≤1M，Gemini 路线）；**② 分段摘要**（超 1M / 上下文受限，级联）；**③ 定位检索**（你要答"被告在第几分钟出现"，不是全文摘要——先切片索引，检索命中的关键帧再细看）。**三种是"预算 × 任务"的二维解，不是一条路。**

## 7. 这篇怎么用（一页带走 + 掌握度检验）

**一页带走：视频 = 图像的时间序列；抽帧（每秒 1-2 帧或按场景）省 token、时序编码（M-RoPE t 管先后）省注意力、长视频分段（1M 整片塞 / 超长级联）省上下文——三层全是工程管道，不是模型能力。**

```
抽帧：10s@30fps = 300 帧 = 76800 tok（放不下）→ 2fps = 20 帧 = 5120 tok（省 15×）· 1fps = 10 帧 = 2560 tok（省 30×）
帧 token：224 图(patch14) → 256 tok/帧（02 锚点）
时序编码：M-RoPE (t,h,w)=20/20/20 · t 管第几帧、(h,w) 管帧内哪格 · 全局 self-attn 16.7M vs 帧内 1.05M（省 16×）
长视频分段：1h@1fps = 0.92M ≈ 1M → 整片塞（§10.5 原话）· 2h 无 1M → 2 段×0.92M + 段摘要级联
三策略：整片塞（≤1M）· 分段摘要（超 1M）· 定位检索（找某句在第几分钟）
代表：Qwen2-VL 开源视频标杆 · Gemini 长视频强 · GPT-4o 实时类 · 评测：VideoMME/LongVideoBench/VideoArena
```

**掌握度检验（不看代码，答得出才是真会）：**

1. 视频为什么不能像图片一样直接喂？（答：帧数 × 256 token——10s 30fps = 76800 放不下；抽帧是省 token 第一刀）
2. 每帧多少 token？怎么来的？（答：256 token/帧，02 篇"224 图 patch14→256"锚点只引）
3. 抽帧频率怎么定？（答：§10.5 原话"每秒 1-2 帧或按场景"——均匀抽帧 vs 按场景取帧；30fps 全喂爆炸、1 帧到底丢全程）
4. "帧间时序编码"编码的是什么？（答：谁先谁后——M-RoPE t 管第几帧、(h,w) 管帧内；没把"第几帧"写进位置就是丢了时序）
5. 16 帧视频的注意力为什么建议帧内而不是全局？（答：16 帧 = 4096 token，全局 16.7M pair vs 帧内 1.05M（省 16×）——全帧间太贵，纯帧内丢帧间，工程折中）
6. "1M context 后可以整片塞进去"是什么意思？（答：1 小时视频 @1fps = 0.92M token，1M context 装得下（Gemini 招牌）；再长就分段抽帧+段摘要级联，段摘要保持帧序）
7. 三种长视频策略各什么时候用？（答：≤1M 整片塞 · 超 1M/上下文受限 分段摘要 · 要"某句在第几分钟" 定位检索）

## 8. 常见坑（理解视频与文本的 6 个）

1. **把视频当"连续图片"直接喂**——30fps 全喂 token 爆炸（10s 76800 放不下）。视频进 LLM 的第一步永远是抽帧/降采样，不是模型层数（§9.7 无解：这是输入工程不是架构）。
2. **以为"抽帧 = 丢信息"是坏事**——每秒 1-2 帧丢的中间过程对"动作/事件理解"可接受（探针 D6 验证）；反而是 30fps 全喂把预算烧光、模型已经看不到全貌。抽帧是选择，不是损耗。
3. **把"拼 grid 大图"当视频理解**——8 帧拼成一张 4×4 图喂进去，模型看到的是"一页九宫格"——时间被压成空间，不知道谁先谁后。无帧序 = 无时序。
4. **以为"时序编码要新模型"**——M-RoPE 在 02/05 篇已经在了（t,h,w 三等分），视频只是把 t 当帧号用。时序编码是"位置怎么用"，不是"加一层网络"。
5. **把"1M context"当视频万能**——0.92M 能塞 1 小时，但 27.6M 全量照样塞不下；1M 的功劳一半属于抽帧（30× 压缩）。结论：上下文大 + 抽帧配合才长视频，单靠一个贵。
6. **用图片评测替视频评测**——VideoMME/LongVideoBench/VideoArena 测的是"跨帧时序理解"；图片基准测不出"谁先谁后"。视频能力的尺子在视频基准上量（§10.9/11-02 体系只引）。
