## 0. 为什么第 2 课是「分布式训练基础设施」？

13 章第一条主线是"资源怎么分"，13-01（算力账本）教的是**选卡**——单张卡能装什么、多快、多贵。但 70B 要的多机集群，只是"选 8 张 H100"吗？不是。**下一层的问题是：8 张卡怎么连、每步训练卡和卡之间要搬多少数据、跨一台机器要多付多少带宽税。** 这就是 §13.2。三个非讲不可的理由：

1. **分布式训练最贵的教训不是买卡，是"下单时算了 8 卡、落地发现没连成一台"——通信账单。** 04-07 教了"有哪些并行"（词汇），本篇教"每种并行走哪条链路、各自多少通信、跨机要付什么代价"（账单）。70B 满配 8 张 NVLink 是一台"大型训练机"；一旦拓扑把 TP 排跨机，逐层通信 9× 变慢，卡多少钱都白花。
2. **一页纸就能判"为什么慢"。** 13-01 账 B 讲"TP8≈8×，互联是隐变量"——这笔账的正式展开就在这里：互联三档（机内 NVLink / 机间 IB·RoCE / 消费级 PCIe）各差一个数量级；通信大头是每步的梯度 all-reduce（70B fp32 高达 280 GB）；跨机不分层通信占比就到 62%，分层后降到 6%。**会算这笔账，就能在排机器前问对问题。**
3. **它是 13 章"资源怎么分"的正式展开，并向下游喂料。** §13.2 三行给了整张基础设施的骨架：传输/通信库（NCCL）→ 并行框架（Megatron/DeepSpeed/Ray）→ 平台形态（裸机/Slurm/内部平台/托管）。13-03 K8s 调度要回答"哪台机器跑哪个角色"，答案就是本篇账 C 的排布与账 D 的平台。本章不带里程碑——它是后续所有"跑起来"的公共底账。

**读完这篇你会：（a）报带宽先报口径，背出互联三档（机内 3600 / 机间 400 / 消费 PCIe 16 GB/s 每方向），讲清 4090 无 NVLink「单机多卡≠分布式」（账 A）；（b）会用 ring all-reduce 公式算梯度同步时间，讲清"跨机为什么必须分层、分层怎么省 26×"（账 B）；（c）对三种并行说出各自通信量与拓扑归宿——TP 锁机内、PP 跨机可、DP 走分层树，给 8 机 64 卡排 3D 并行（账 C）；（d）按场景选库/框架/平台——库跟芯片栈、框架跟规模、平台跟运维（账 D）。（本篇 🟢 了解 = 13-02 分布式训练基础设施——联动 04-07 · 13-01 · 11-01 · 11-08 · §4.7，无专属里程碑。）**

## 3. 实验 A · 互联带宽账：机内 NVLink vs 机间 IB —— 互联是台阶

**账 A 回答"跨一档互联要付多少倍"，全篇的账本起点。先讲口径（11-01）：NVLink 报价通常是「双向」，IB/网口报价是「每口每方向」——比较前统一成「每方向 GB/s」。**

**A0 口径（探针实测）：H100 NVLink4 双向 900 = 每方向 450 GB/s；IB 400G = 每口 50 GB/s（每方向）。** 报带宽不报口径，就是拿单向比双向、把 900 和 50 放在一起——差 18 倍其实是 9 倍的好分数。

**A1 单口（探针实测）：NVLink / IB = 450 / 50 = 9.0×。** 机内一口顶机间九口——这是"TP 为什么锁机内"的第一块砖。

**A2 节点聚合（探针实测）：机内 8×450 = 3600 vs 机间 8×400G = 400 GB/s = 9.0×。** 一台 8 卡 H100 的腰，是它的上行带宽 400 GB/s：**整台机器内部想挪 3600，跨出去只剩 400——跨机一跳就是整台机器的腰。**

**A3 代际与档位（探针实测）：A100 NVLink3 每方向 300 → H100 NVLink4 450（双向 600→900，1.5×）；机间 200G 只 25 GB/s。** 200G 档是 AMD ROCm/昇腾跨机常见档（§13.2 RCCL/国产化跨机）——**互联不是越贵越好，是档位要跟模型规模匹配。**

**A4 消费者卡没有 NVLink（探针实测）：4090/消费级走 PCIe 4.0 x16，每方向 ≈16 GB/s，vs NVLink 450 = 28.1×。** 这是最容易踩的现实：**「单机多张 4090」的链路是 PCIe，不是 NVLink——多卡 ≠ 分布式，贴边级多卡的第一堵墙就是这把 PCIe 慢链路。**

**A5 权重复制账（探针实测）：70B fp16 权重 140 GB，NVLink 拷 0.31 s vs PCIe 8.75 s（28.1×）。** 训练第一步"把权重灌进每张卡"就刷出 28 倍——**多卡训练的墙，先出现在拷贝权重这一步。**

**账 A 三档台阶：机内 3600 / 机间 400 / 消费 PCIe 16（每方向 GB/s）——各差一个数量级。** 记住这张台阶，后面账 B 的 26× 和账 C 的 9× 都是它长出来的。

## 4. 实验 B · 通信原语账：ring all-reduce + 分层 —— 跨机为什么必须分层

**账 B 是分布式训练的算术核心：梯度 not 同步就白训。真实 NCCL 的 all-reduce 用 ring 算法（还有整机数感知的树），公式（工程惯例）：每 rank 移动 = 2(N-1)/N × 数据量。** NCCL 树/环的"拓扑感知"= 本篇账 B 的"分层"数学。

**B1 梯度是大头（探针实测）：70B fp32 梯度 = 280 GB（fp16 可 140 GB）；N=8 单机 ring 每 rank 移动 490 GB → 1.09 s；朴素 each-to-each 3920 GB → 8.7 s（ring ≈8×）。** ring 的胜利 = 把 O(N·D) 摊成 O(D)**；而 280 GB 是每步都在发生的固定开销——这是通信主账单，比权重拷贝（账 A5）大得多。**

**B2 裸跨机（探针实测）：64 卡每 rank 只 1×400G=50 GB/s → 11.0 s，单机 8 卡 1.09 s 的 10.1×。** **不分层没法跨机**——谁把 64 卡当"大单机"排，谁就白烧 10 倍时间。

**B3 分层 all-reduce（探针实测）：0.43 s ≈26×，还比单机 8 卡 1.09 s 快。** 三步：① 机内 NVLink reduce-scatter，每节点把 280 GB 聚合成 35 GB 部分和；② 机间 IB 只传 35 GB partial（节点聚合 400 GB/s）；③ 机内 NVLink all-gather 广播回来。**64 卡数据切得更薄 + 机间只传部分和 = NCCL 树/环的拓扑感知在讲同一件事：把贵的跨机带宽当一级缓存用。**

**B4 算力对照（探针实测）：70B 每步 1M token 计算 6.6 s（64×H100 989 TFLOPS）→ 裸跨机通信占比 62%（算力只动 38%）vs 分层 6.0%。** 这页数据就是 04-07 通信·计算比 3.6%→1025% 翻车曲线的**有解法版**：同一根曲线，加一层"机内聚合、机间 partial"的调度，就把算力从 38% 救回 94%。

## 5. 实验 C · 并行×拓扑账：TP 锁机内 · PP 跨机可 · DP 走分层树

**账 C 回答"我的集群怎么排机器"。三种并行的通信长得完全不一样，归宿也不同（04-07 词汇 + 本页通信量；探针实测）：**

| 并行 | 通信量（探针实测） | 频率/关键路径 | 拓扑归宿 |
|---|---|---|---|
| **TP** | 80 层 × fwd+bwd 2 次 activation all-reduce = **85.9 GB/步** | 高频：**160 次逐层阻塞**在关键路径 | **机内**（机内 0.19 s vs 跨机 1.72 s = 9×，每层都等） |
| **PP** | 每微批一次边界 P2P = **67.1 MB**，8 微批合计 537 MB 跨机 10.7 ms | 低频 · 量小 · 延迟敏感 | **跨机可容忍** |
| **DP** | 每步一次全梯度 all-reduce = **280 GB** | 低频（每步 1 次）· 量大 | **跨机分层树 + 与计算重叠**（账 B 同一个数 0.43 s） |

**C1 TP 为什么锁机内：85.9 GB 只看总量甚至比 DP 的 280 GB 小，但它散在 160 次逐层 all-reduce 里、卡在每层前向/反向后（关键路径）——跨机每口 9× 慢，等于整条流水线每层都被拉长 9×。** 这就是真实集群（Llama 3 等）把 TP 组放进单节点 NVLink 的原因，也是 13-01 账 B「TP8≈8×」成立的前提——**前提是 NVLink，不是任意互联。**

**C2 PP 为什么跨机可以：边界只传一个 activation（67.1 MB/微批），8 微批合计 537 MB 走 IB 也才 10.7 ms，相对每步计算 6.6 s 可忽略。** PP 的敌人是延迟（气泡）不是带宽——跨机可，但别跟 TP 抢机内带宽。

**C3 DP 为什么自由跨机：量大（280 GB）但每步只一次，交给分层树（账 B3：0.43 s）并用异步/重叠吸收，跨机是它的天然领地。** 三并行一句话：**TP 吃带宽且阻塞、PP 吃延迟量小、DP 吃总量但低频——三种病三个药。**

**C4 铁律与排布：TP 锁机内 · PP 跨节点组 · DP 走全局——3D 并行排布 = (TP=机内卡数) × (PP=节点组数) × (DP=全局其余)。** 8 机 64 卡 70B 的标准落法：TP8（每机 8 卡 NVLink 满）× PP 跨节点组 × DP 全局。**探针 5 场景判拓扑 5/5（判卡口诀 → 判拓扑口诀）：**

| 场景 | 拓扑 |
|---|---|
| 1×H100 跑 7B 微调（单卡装得下） | 不需要分布式：裸机脚本 + DeepSpeed 就够 |
| 70B 单机 8 卡（130 GiB 装不下 1 卡） | TP8 全机内（8 卡 NVLink），无需 IB |
| 70B 八机 64 卡 | TP8 机内 × PP 跨节点组 × DP 全局，需 IB≥400G + 分层树 |
| 4×4090 低预算（无 NVLink） | 别上 TP：DP + 梯度累积，接受 PCIe 慢链路（账 A） |
| 671B MoE 超大规模（fp8 625 GiB，账 A） | 多机 TP/EP 混合 + IB/Atlas 跨机 + checkpoint 容错 |

## 6. 实验 D · 库与平台账：NCCL/RCCL/HCCL · 框架六家 · 平台三级

**账 D 把 §13.2 最后两行装成决策树：库跟芯片栈走、框架跟规模走、平台跟运维能力走。**

**D1 通信库三家（要素事实）：NCCL（NVIDIA，GPU 集体通信事实标准，all-reduce 树/环拓扑感知，NVLink/IB/RoCE）· RCCL（AMD ROCm，MI 系列对标 NCCL）· HCCL+CANN（华为昇腾 Atlas）。** 库不挑任务、挑芯片栈——买了昇腾就别指望 NCCL 直接跑，国产化的通信账从这里就开始。

**D2 框架六家（要素事实 · 层位各管一段）：**

| 框架 | 管什么 | 谁在用 |
|---|---|---|
| Megatron-LM/Core | **3D 并行**（TP/PP/CP） | 大厂大规模训练标配 |
| DeepSpeed | **ZeRO / offload**（省显存第一） | 个人/单机多卡也省显存 |
| Ray | 弹性调度 + 数据/训练编排 | Agent 时代弹性任务 |
| Slurm | 科研批调度（排队/资源申请） | 科研集群事实标准 |
| Volcano/Kueue | K8s 算力调度（队列+配额+抢占） | 云原生多租（13-01 时间切片落点） |
| 托管服务 | Vertex / SageMaker / ModelScope Studio | 一键训练免运维 |

**D3 平台三级（要素事实）：裸机脚本（研究：python + torchrun 一把梭）→ 内部训练平台（作业提交→资源分配→监控→容错）→ 托管服务（云托管一键训练，价格/自由度换省心）。** 形态跟着人群走：个人先裸机、团队配平台、上线再托管。

**D4 决策 6 判 6/6（探针实测）：**

| 场景 | 决策 |
|---|---|
| 个人微调/小实验 | 裸机脚本 + DeepSpeed（ZeRO-2） |
| 科研实验室共享 GPU | Slurm 队列（排队/申请/休眠） |
| 20+ 卡大模型训练 | Megatron 3D 并行 + 内部训练平台 |
| 云上快速起步/无运维 | 托管服务（SageMaker/Vertex/ModelScope Studio） |
| 存量 K8s 基础设施多租 | Volcano/Kueue 队列调度（配额+抢占） |
| 国产化昇腾 | CANN/HCCL + Atlas 集群 |

**一句话：框架是"怎么并行"的装配厂，平台是"谁来运维"的选择题——先问规模（①多少张卡）和芯片栈，再问运维能力（②愿不愿管机器），答案就自带了。**

## 7. 这篇通信账怎么用（一页带走 + 掌握度检验）

**一页带走——给你的下一个集群排布置副请求写这笔账：**

1. **报带宽先报口径**（11-01）：NVLink 双向 900 = 每方向 450；IB 400G 每口 50。统一到"每方向"再比。
2. **互联是台阶**：机内 3600 / 机间 400 / 消费 PCIe 16（每方向 GB/s）——跨一档约 9~28×。
3. **通信大头是梯度 all-reduce**（70B fp32 每步 280 GB）：单机 1.09 s，裸跨机 11 s；**必须分层**——机内聚合成部分和、机间只传 partial → 0.43 s。
4. **三种并行三条路**：TP 锁机内（85.9 GB/步逐层阻塞）、PP 跨机可（每微批 67.1 MB）、DP 走分层树（280 GB 一次可重叠）——3D 排布 = TP 填满机内、PP 跨节点、DP 全局。
5. **选型两问**：问"哪种并行的通信走哪条链路"排机器，问"要跑在裸机/Slurm/内部平台/托管哪一层"选平台。

**掌握度检验（读完自答）：**

1. "H100 NVLink4 每方向带宽 vs 1×IB 400G？"（450 vs 50，9×——先报口径：每方向，账 A。）
2. "为什么跨机训练慢的第一嫌疑人总是通信？"（梯度 280 GB 裸跨机 11 s、占 62% 算力被压到 38%，账 B。）
3. "分层 all-reduce 机间只传什么？"（部分和 partial：机内先 reduce-scatter 聚合成 35 GB，账 B3。）
4. "TP 为什么不能跨机？"（85.9 GB 散在 160 次逐层阻塞 × 9×——这是真实集群把 TP 放机内的原因，账 C1；13-01 账 B 的 ≈8× 前提就是 NVLink。）
5. "4 张 4090 能直接组 TP 吗？"（不行：PCIe 16 vs NVLink 450 = 28 倍，链路是 PCIe 不是 NVLink，账 A4。）
6. "个人微调 70B 走哪层平台？"（裸机脚本 + DeepSpeed（ZeRO-2），别先上托管，账 D4。）
7. "科研实验室共享 GPU 用什么排队？"（Slurm——批调度、排队/申请/休眠，账 D2/D4。）

## 8. 常见坑（分布式训练算账的 7 个）

1. **报带宽不报口径**："NVLink 900 vs IB 400G"= 双向 vs 单向的鸡同鸭讲——先统一到每方向再比（账 A0，代价 2×）。
2. **把 PCIe 当 NVLink**：单机 8×4090 = PCIe 16 GB/s 链路的"8 卡分布式"，不是 NVLink 集群；权重灌卡 28 倍慢（账 A4/A5）。
3. **忘了梯度 all-reduce 是大头**：只算权重拷贝/激活——70B 每步 280 GB 才是主账单（账 B1，A5 的 140 GB 只是开场）。
4. **跨机不分层**：64 卡裸 ring 11 s = 通信占 62%，算力白烧；分层 0.43 s（账 B2/B3）。
5. **TP 跨机**：以为"TP 都快"，其实跨机每层阻塞 ×9×——TP 铁律锁机内；13-01 账 B 的"TP8≈8×"前提是 NVLink（账 C1/C4）。
6. **全用一套框架**：个人上 Megatron 太重、科研上托管太贵——库跟芯片栈、框架跟规模、平台跟运维（账 D2/D4）。
7. **忽略国产化互联**：昇腾 Atlas 跨机走 RoCE/定制网卡，带宽档常比 NVIDIA IB 低——跨机更要靠分层堆叠把铂发给补回来（账 A3/D1）。
