## 0. 为什么第 1 课是「算力资源·GPU/NPU 选型账本」？

13 章叫"工程化与基础设施"，§13.0 一句话点破本章的活儿——**本地 Demo（单卡、单请求）→ 生产系统（多租户、SLA、成本、安全、可观测）之间的差距，都是本章内容**。工程化有三条主线：**资源（GPU/NPU 怎么分）、流程（模型怎么发布更新）、观测（线上怎么发现问题）**。第一条主线"资源怎么分"的地基就是 §13.1：**你得先会算"一张卡能装什么、推理多快、微调要几卡、该买哪张"**——不会算账的人谈部署，只会两句话："上 A100"和"再买两张"。三个非讲不可的理由：

1. **资源是工程化的地基，选型错误是成本最大的错误。** 70B 模型塞进单卡 80G——装不下（账 A）；七卡 TP 跑带宽吞吐（账 B）；H100 单卡比 A100 贵 67% 但单位算力便宜 47%（账 C）——**选错卡不是慢 20%，是成本差一个数量级**。
2. **算账不贵，雇卡才贵。** 本页四本账 = 三条公式 + 一张硬件表，任何一台纯 CPU 笔记本 0.000 秒算完、永不联网；而"买错卡 / 租错档位"试错一次的钱够你算一万次账。**把决策前置到算账，就是 13 章的第一课。**
3. **它是全章的"参数底座"。** 后面 13-02 分布式训练要算多机用多少张卡、13-03 推理服务要算吞吐够不够、13-04 Ray 要算任务排队、13-05 MLOps 要算成本预算——**这些层的数字全由本页四账喂料**。本篇不带里程碑，因为它不是某一项工具，而是全章账单的共同口径。

**读完这篇你会：（a）背出关键四参数（显存/HBM 带宽/FP16 TFLOPS/卡间互联）与主流卡清单，会用"权重/KV"两条公式算一张卡能装什么模型（账 A）；（b）会用"tokens/s≈带宽/权重大小"估算任一张卡跑任意模型的速度，讲清"推理瓶颈在带宽不在算力"（账 B）；（c）会用 $/TFLOPS·h 给卡排单位成本，讲清"单卡价格贵 67% 但单位算力便宜 47%"的选型第一条，算全参 vs LoRA 的微调显存（账 C）；（d）对任意新任务问"带宽/显存/算力/互联谁卡脖子"四个问题就能判卡（账 D）。（本篇 🔴 会算账 = 13 章开篇——联动 02-10 · 03-04 · 03-02 · 04-06 · 04-07 · 11-01 · 11-08，无专属里程碑。）**

## 1. 先把选型账本拆开：四个参数 → 三本账（§13.1）

§13.1 知识地图原文，四条关键参数 + 三本账一条原则：

| 参数 | 是什么 | 卡在哪个决策 |
|---|---|---|
| **显存容量** | 一张卡装多少权重+KV+激活 | "单卡能装 7B 吗；70B 得几张卡"（账 A） |
| **HBM 带宽** | 每秒从显存搬多少数据 | "推理生成快不快"（账 B） |
| **FP16/BF16/FP8 算力** | 每秒算多少 FLOP | "训练/批量前向有没有算力余量"（账 B/C） |
| **卡间互联** | NVLink/NVSwitch/InfiniBand/RDMA | "多卡而是一台机还是集群"（账 B TP / 账 D） |

**三本账的原则（§13.1 原文）：训练看算力+集群互联 · 推理看带宽+显存 · 微调看显存；单位成本（$/TFLOPS·小时或单卡·小时）比单卡价格更重要。**

| 场景 | 谁卡脖子 | 用哪本账 |
|---|---|---|
| 训练 | 算力 + 互联 | 账 C（单位算力）+ 互联 |
| 推理 | **带宽** + 显存 | 账 B（带宽）+ 账 A（装不装得下） |
| 微调 | **显存** | 账 A（权重）+ 账 C 微调行 |

**"卡脖子"口诀：推理慢先查带宽、装不下先查显存、训练贵先查单位算力、多卡慢先查互联。** 这四个词就是四本账的四根主梁——本篇不是背卡参数，是把"谁卡脖子"问对。

## 3. 实验 A · 显存账：权重 / KV / 量化 —— 一张卡能装什么

**账 A 回答"这张卡能不能装下我"，是选型的门槛问题——装不下，一切免谈。** 两条公式（工程惯例，02-10-KV-Cache 同公式挂靠）：

```
权重 GiB = 参数(B) × 字节/参数 ÷ 2³⁰      # fp16/bf16=2B · fp8=1B · int4=0.5B
KV   GiB = 2(K、V各一份)×层数×KV头数×头维×序列长度×batch×字节 ÷ 2³⁰
```

**A1 权重账（探针实测）：**

| 模型 | 精度 | 权重 | 判 |
|---|---|---|---|
| 7B | fp16 | **13.0 GiB** | 单卡 A100 80G 装得下 = PASS |
| 70B | fp16 | **130.4 GiB** | 单卡装不下 → 须 TP≥2 = PASS |
| 671B MoE（03 篇） | fp16 / **fp8** | 1249.8 / **624.9 GiB** | fp8 官方发布 = 量化是超大规模唯一活路 = PASS |

**关键认知：显存 = 一张卡能装什么的唯一答案。** 7B 是"单卡都能捞"的甜点位；70B 立刻翻到单卡 80G 装不下（130>80）；671B 超大规模只有量化（fp8 半切）这一个活路。**参数每 10×，显存就 10×——"我哪儿有那么多卡"的数学公式长这样。**

**A2 KV 账（探针实测）：** KV 公式与 02-10 同式，7B GQA 32 层×8 kv头×128 维：seq 4k = **0.5 GiB**、seq **128k = 16.0 GiB**。**同公式、同结构，只把序列从 4k 拉到 128k，KV 就 32 倍**——长上下文的第一张账单不在模型权重，在 KV cache。

**A3 组合账（探针实测）：** 7B fp16 权重 13.0 + 128k KV 16.0 = **29.0 GiB** < 80 → 单卡 A100 能带"7B + 超长上下文"= PASS。**组合账才是生产真相**：部署申请显存 = 权重 + KV + 激活 + 框架开销，四条腿凑齐才算装得下。

**A4 量化账（探针实测）：** 7B fp8 = **6.5 GiB** / int4 = **3.3 GiB**——int4 把 13G 压到 3.3G，端侧 8G 卡（Gemma int4 挂靠）就入场了 = PASS。**量化不只省显存还提速（账 B 会算），它是"装不下"的通用解法，代价是精度账（非本页范围）。**

## 4. 实验 B · 带宽账：同一张卡不同模型多少 tokens/s

**账 B 回答"装得下之后，生成快不快"。** 一条公式（§5.8 工程惯例）：

```
tokens/s ≈ HBM带宽 × 10¹² ÷（参数 × 字节/参数 × 10⁹）
```

**B1 7B fp16 单卡带宽吞吐（探针实测）：A100 143 · H100 239 · H200 343 · B200 571 tok/s。** 四张卡算力天差地别（312 vs 989 vs 2250 TFLOPS），但**跑 7B 的 tok/s 只差带宽差**：H100 = A100 的 **1.67×**（3.35/2.0）——**同一张卡跑同一模型，速度≈带宽线性放大，算力帮不上忙**。

**B2 70B 比一比（探针实测）：A100 14 · H100 24 · H200 34 · B200 57 tok/s。** **模型从 7B 变 70B（10×），吞吐掉 10×**——因为权重是分母，分母 10× 结果 1/10。**别问"这张卡多少 tok/s"，先问"哪个模型"。报告吞吐永远带『哪张卡·什么精度』（11-01 先讲口径再讲数字），因为权重是分母。**

**B3 量化提速（探针实测）：70B fp8 A100 = 29 tok/s = fp16 14 的 2×。** 权重减半、吞吐翻倍——**账 A 说量化省显存，账 B 说量化还提速**，成本只是精度。这是"装不下也不一定要买更贵的卡"的第一个杠杆。

**B4 模型并行摊权重（探针实测）：TP8（8×A100，70B 每卡 17.5 GB）→ 114 tok/s ≈ 单卡 14 的 8×。** 把 130G 摊到 8 卡，每卡只扛 17.5G，吞吐近线性放大——**这就是 70B 多卡推理的数学动机**（挂 04-07 TP）。注意"≈8×"不是 8×：卡间互联 NVLink 是这台账的限速带（下一课）。

**B5 带宽 vs 算力（探针实测）：H100 跑 7B 的算力上限 71k tok/s vs 带宽限 239 tok/s——算力富余 295×，带宽先到瓶颈。** 这句就是知识地图 base line 111 的"推理瓶颈常在显存带宽而非算力"：**模型小、请求单条时算力根本不是瓶颈，钱花在带宽上才是买对了**。在线推理选卡：**看带宽不看算力（账 C 会把它折算成钱）。**

## 5. 实验 C · 算力账：$/TFLOPS·h —— 单位成本比单卡价格更重要

**账 C 把"该买哪张卡"从"贵不贵"拉到"单位贵不贵"。** 一条公式：

```
单位成本 $/TFLOPS·h = 单卡价格 ÷ TFLOPS
```

**C1 硬件表与单位成本（作者按公开资料预置 · 本机换算）：**

| 卡 | 显存 | 带宽 | FP16 算力 | 单价 | 单位成本 $/TFLOPS·h |
|---|---|---|---|---|---|
| A100 | 80G | 2.0 TB/s | 312 TFLOPS | $1.5/h | 0.00481 |
| H100 | 80G | 3.35 TB/s | 989 TFLOPS | $2.5/h | **0.00253** |
| H200 | 141G | 4.8 TB/s | 989 TFLOPS | $3.0/h | 0.00303 |
| B200 | 192G | 8.0 TB/s | 2250 TFLOPS | $5.0/h | 0.00222 |
| MI300X | 192G | 5.3 TB/s | 1307 TFLOPS | $2.8/h | **0.00214** |
| 昇腾910B | 64G | 1.7 TB/s | 376 TFLOPS | $1.8/h | 0.00479 |

**C2 选账本第一条（探针实测）：H100 vs A100——单价 +67%（$2.5 vs $1.5），但算力 3.17× → 单位算力 0.00253 vs 0.00481 = H100 便宜 47%。** 这就是"**单位成本比单卡价格更重要**"的白板版：**看报价单会得出"A100 便宜"，看 $/TFLOPS·h 会得出"H100 便宜 47%"**——算力敏感的负载，贵 67% 的单卡反而省钱。

**C3 训练态单位算力排序（探针实测）：MI300X 0.00214 → B200 0.00222 → H100 0.00253 → H200 0.00303 → 昇腾910B 0.00479 → A100 0.00481。** **训练看单位算力排卡**——MI300X 是训练态单位算力最低的一档，B200 次之；昇腾910B 0.00479 ≈ A100 0.00481：**国产化 = 渠道/合规考量，算力账不吃亏**（生态 ROCm/CANN 是另一本账）。这张排序表就是"训练预算一页账"的骨架。

**C4 微调账（探针实测）：7B 全参 fp16 ≈ 112 GB（权重+梯度+优化器 ≈16B/参数 → 需 ≥2×80G） vs LoRA ≈ 15 GB（单卡 A100 40G 即够）。** 16× 的显存差 = **微调选卡看显存不看算力**——7B 全参要两张大卡、LoRA 一张中卡就够。**微调预算不够？先上 LoRA，别先上算力**（挂 04-06 全参 vs PEFT）。

## 6. 实验 D · 选型账：5 任务判卡 × 虚拟化三档

**账 D 把前三账装成决策表：对任何新任务，问四个问题——带宽、显存、算力、互联，谁卡脖子就买谁的解药（§13.1 三本账原则 + 作者预置任务，探针实测）：**

| 任务 | 谁卡脖子 | 判卡 | 判定 |
|---|---|---|---|
| 7B 在线问答/Agent 流式（延迟敏感） | **带宽** | 单卡 H100/H200 | PASS |
| 70B 通用推理（130G 权重>80G 单卡） | **显存** | ≥2×H100 TP 或 H200 单卡+量化 | PASS |
| 7B LoRA 领域微调（显存小） | **微调显存** | 单卡 A100 40/80G | PASS |
| 70B 全参微调/SFT（≈1.1TiB 权重+梯度+优化器） | **算力+互联** | 8×H100 NVLink 集群 | PASS |
| 671B 超级 MoE 推理（fp8 625G） | **集群互联** | 多机集群（IB/Atlas），权重摊多卡 | PASS |

**判卡口诀 = 先问谁卡脖子：在线→带宽、装不下→显存、全参→算力+互联、超大规模→集群互联。** 5/5 命中 = 一本账对应一种解药：
- **在线流式 = 带宽账**（账 B：H100 带宽 3.35>2.0）；
- **70B = 显存账**（账 A：130>80，两法：≥2×H100 TP 或 H200 141G 单卡+量化）；
- **全参微调 = 算力+互联账**（账 C：8×H100 NVLink = 训练态单位算力第 2 名 + NVLink 机内直连）；
- **671B = 集群账**（账 A fp8 624.9G 摊多机 + IB/Atlas 跨机互联）——一张 8 卡机装不下、一台机器带宽是互联上限，多机就是账 D 的最后一张答案。

**虚拟化三档（§13.1 · 探针实测）：MIG（A100/H100 硬件切片，1 卡分 7 份）· MPS（进程级 GPU 共享，多任务同卡）· K8s 时间切片（设备插件配额+抢占，多人争卡）**——三种资源分配的粒度：**硬切片（隔离最硬）、进程共享（隔离中等）、时间分片（最软但调度最活）**。配额与抢占策略 = 13-03/04（K8s 与 Ray）的正式舞台，本篇先把三档名字和"谁更硬"钉住。

## 7. 这篇选型账怎么用（一页带走 + 掌握度检验）

**一页带走——给你的下一个部署请求算这笔账：**

1. **装不装得下（账 A）**：权重 = 参数×字节；KV = 2×层×KV头×头维×seq×字节；组合 = 权重+KV+激活。装不下→先量化（fp8 半切）或 TP 摊卡，别急着加预算。
2. **快不快（账 B）**：tokens/s ≈ 带宽 ÷ 权重大小；先定模型再加卡，报告永远带『哪张卡·什么精度』；在线推理看带宽不看算力。
3. **值不值（账 C）**：$/TFLOPS·h = 单价÷算力；训练按单位算力排卡、微调按显存选卡；H100 单位算力比 A100 便宜 47%，盯紧自己的目标别被报价单带偏。
4. **判卡四问（账 D）**：在线→带宽；装不下→显存；全参→算力+互联；超大规模→集群互联——问对问题再看表。

**掌握度检验（读完自答）：**

1. "一张卡能不能装这个模型，先算什么？"（权重=参数×字节 + KV=2×层×KV头×头维×seq×字节，组合账四条腿——账 A。）
2. "70B fp16 要几张 80G 单卡才装得下？"（130.4 GiB > 80 → 至少 2×；或 H200 141G 单卡+量化——账 A。）
3. "7B 在线流式该看哪个参数？"（带宽——tokens/s ≈ 带宽÷权重；7B fp16 H100 239 vs A100 143，带宽线性放大——账 B。）
4. "H100 比 A100 贵 67%，为什么训练还是选 H100？"（单位算力 $/TFLOPS·h 便宜 47%——账 C。）
5. "7B 微调预算不够，先做哪件事？"（先上 LoRA（15GB 单卡）别先上算力（全参 112GB 两卡）——账 C。）
6. "671B MoE 推理该买什么？"（多机集群 IB/Atlas，fp8 625G 摊多卡——账 D。）
7. "一张 A100 想让四个人同时用，用哪一档虚拟化？"（MIG 硬切片（隔离最硬）或时间切片（调度最活）/MPS（进程共享）中间态——账 D。）

## 8. 常见坑（选型算账的 7 个）

1. **只看报价单**：A100 $1.5 < H100 $2.5 → "买 A100 省钱"——$/TFLOPS·h H100 便宜 47%，训练选卡看单位成本不看单价（账 C）。
2. **只算权重不算 KV**：7B 装 80G 就说"能装"，结果 128k 长文 KV 16G+，加上激活框架超了——组合账四条腿（账 A）。
3. **不问模型就问速度**："你卡跑多少 tok/s"——7B 239 vs 70B 24，权重是分母，先定模型（账 B）。
4. **在线推理追算力**：H100 跑 7B 算力上限 71k vs 带宽 239，富余 295×——在线买算力=白花钱（账 B5）。
5. **70B 硬塞单卡**：130>80 装不下；非要"单卡"只能 fp4 量化+长文全废——要么 TP 要么 H200+量化（账 A/D）。
6. **忽略互联**：TP8 吞吐 ≈8× 成立的前提是 NVLink 线宽够；用 InfiniBand 跨机当训练机内用，等到账 C 的单位算力排序就崩了——互联是本账的隐变量（账 B/D）。
7. **把昇腾当"山寨 A100"**：单位算力 0.00479 ≈ A100 0.00481 不吃亏；它的成本是生态（CANN/ROCm 兼容性）不在算力（账 C）。
