## 0. 为什么第 6 课是「模型注册与版本管理」？

13 章主线是"资源怎么分、模型怎么上线"：13-01 选卡、13-02 多机互联、13-03 推理服务装配扩缩、13-04 Ray 弹性调度、13-05 MLOps 把模型"管起来"（数据版本/实验跟踪/模型注册/CI-CD + LLMOps 六新增）。但**有一件事前五篇都只点到、没展开**：一个训练好的模型，**到底以什么形态交出去？一个"模型版本"包含哪几样东西？往哪放？怎么从"旧版"换到"新版"？出事了怎么退、怎么追责？** 这就是 §13.6——模型注册与版本管理。三个非讲不可的理由：

1. **"模型文件"和"模型版本"是两回事。** 本地 `ls weights/` 里一堆 `.safetensors`，不代表团队能回答"线上跑的是哪个版本的权重、配的哪版 tokenizer、用的是哪份评测报告"。"文件"是散落的字节；"版本"是**一个受约束、可寻址、不可变、附带证据的打包单元**。模型注册中心就是把"文件"升级成"版本"的那道工序。
2. **13-05 给了你"注册中心"三个字，但这章还你一张能看的账。** 13-05 账 A 传统 MLOps 六件套里第 3 件就是"模型注册（MLflow Registry/HF Hub）"——只点了一格。本篇把这一格正式展开成四本账：打什么包（账 A）、放哪去（账 B）、怎么换（账 C）、出事怎么追（账 D）。MLOps 管流程，**注册中心管"版本这个物"本身**。
3. **它是审计与安全的地基。** 09-07 讲了 Agent 护栏，11 章讲了评测，13-05 讲了数据飞轮——但**线上出了幻觉、出了违规，你要能回答"线上这一版是谁、喂了什么数据、凭什么放行"**。没有版本号、hash、评测报告、上线记录的"版本链"，审计就是空话。模型注册是"能追责上线"的工程前提。

**读完这篇你会：（a）报出"模型版本"的 7 件套（权重 safetensors+config 元数据 + 配套五件），讲清缺哪两件会被注册中心拒（chat_template 无模板不可用 + eval_report 缺失禁上生产）（账 A）；（b）区分三个注册中心（HF Hub 开源 / MLflow Registry 团队内 / 云托管）与三种寻址，讲清内网镜像为什么是"合规常态"（账 B）；（c）背出四种发布策略各买什么：蓝绿买原子、金丝雀买稳、A-B 买数据、阴影买无感（账 C）；（d）画出一条 5 段溯源链（版本→权重 hash→数据版本→评测报告→线上记录），会算两步回滚（账 D）。（本篇 🟢 会做 = 13-06 模型注册与版本管理——联动 13-05·13-03·13-01·11-02/03/04·09-07·04-10，无专属里程碑。）**

## 3. 实验 A · 版本打包账：7 件套完整性 + 量化账 + 不可变 revision

**账 A 回答"一个可进生产的模型版本 = 哪 7 件"。§13.6『权重+配套』展开，探针按整件判定：**

**A0 7 件套清单（探针实测 7/7 归位）：① weight.safetensors = 权重本体（safetensors 内嵌 $metadata.format='pt' + header hash，7B fp16≈14.0 GiB）· ② config.json = 元数据（architecture/model_type/层数/头数/词表，读配置才能把权重加载对）· ③ tokenizer = 词表与 BPE 合代码（tokenizer.json / vocab.json + merges.txt）· ④ chat_template = tokenizer_config.json 里的对话模板字符串（Qwen/chat 模板，chat 服务没它发不出对话）· ⑤ quantized = 量化产物（int4 GGUF 3.3 GiB，账 D 上线可用 3.3 GiB 那版，13-01 同源只引）· ⑥ eval_report = 评测报告（eval_report.json，账 D 溯源链用）· ⑦ LICENSE = 许可（Apache-2.0/Qwen 许可，合规红线）。** 记住口诀：**权重+元数据是"模型本身"，tokenizer/chat_template 是"用得起来"，量化/评测/许可是一王三后配套**——七件缺一不可进生产。

**A1 完整性判定（探针实测）：完整版 7/7 件齐 → 允许进注册中心；缺件版 5/7（缺 chat_template + eval_report）→ 注册被拒。** 为什么恰好这两件拒？**chat_template 缺失 = chat 服务发不出对话（不是"能跑"的问题，是"对话能力根本没有"）；eval_report 缺失 = 没有评测证据 → 不合规。** 其余五件在，但这两件一缺就走不进 `echo` 生产。**完整性是"能不能进注册中心"的第一道闸**。

**A2 重量账（探针实测，13-01 同源只引）：fp16 14.0 GiB vs int4 3.3 GiB = 量化省 76% 显存（1 − 3.3/14.0 ≈ 0.76）。** 量化产物是 7 件套里的第 5 件，**版本打包时 weights + quantized 两套都随版本走**（省显存版落地推理、全精度版留作微调基准）——所以版本仓库大小 ≈ 14.0 + 3.3 ≈ 17 GiB 起步，不是只有一份权重。

**A3 版本识别账（探针实测）：revision e1f2a3b…（commit hash，不可变）锁内容寻址；tag `latest` 移动会漂移。** 生产中**任何依赖都必须钉 revision/version 数字，`latest` 只当快捷名**——`latest` 指向谁今天变了，明天线上跑的是不是你测的那版就没法说清。**不可变 = 可回滚；会漂移 = 不可审计。**（13-03 无会话粘性→KV 随请求生灭，横扩前提；本篇是同一个横向逻辑换到版本引用上。）

## 4. 实验 B · 注册中心寻址账：三中心 + 三寻址 + 内网镜像

**账 B 回答"版本放哪、怎么被引用"。§13.6『注册中心』一行，探针拆成三中心 + 三寻址 + 合规镜像：**

**B1 三个注册中心（探针实测 3/3 归位）：Hugging Face Hub（开源社区，拉新模型、公网镜像源，transformers/huggingface_hub 默认端）· MLflow Model Registry（团队内模型生命周期：None → Staging → Production → Archived，stage 晋升与回滚）· 各云 Model Registry（SageMaker / Vertex 等托管注册，训练-注册-部署闭环）。** 一句话分清：**HF 面向开源世界（你有别人也能拉），MLflow 面向团队内部（谁晋升谁回滚有记录），云 Registry 面向云上一条龙（训练/注册/部署同一个账号体系）。** 三选一与否不冲突——**常见是"HF 上游取 + 内部注册中心管"，两条线分开跑**。

**B2 三种寻址（探针实测 3 例归位）：HF → `Qwen/Qwen2.5-7B-Instruct:e1f2a3b…`（owner/repo:revision，revision=commit hash 不可变）· MLflow → `models:/qwen-7b/3`（models:/<name>/<version>，数字版本不可变）· 镜像 → `s3://models/qwen7b/v9`（对象存储内网镜像，路径含 tag）+ `registry.mirror=https://hf.local`。** 共同纪律：**寻址用不可变标识（revision hash / version 数字），tag 只做快捷名——三中心版本语义一致，你才敢在配置里钉死一个地址半年不慌。**

**B3 内网镜像 = 合规常态（探针实测）：上游不可达（外网 4xx/5xx 或被墙）→ 走 `registry.mirror` 内网缓存 → deploy 命中 → PASS。** 这是本篇最有判断力的一句话：**合规 + 断外网**往往不是"要不要镜像"的问题，而是**镜像就是唯一常态**——模型先落内网镜像再上线，**不依赖公网、不泄露依赖链、审计也能在纯内网闭环**。HF 是"世界仓库"，内网镜像是你这个组织的"合规闸门"：**要上线的版本，必须在镜像里找到，而不是临时去公网拉。**

## 5. 实验 C · 发布策略账：蓝绿 / 金丝雀 / A-B / 阴影

**账 C 回答"从注册好到全量上线怎么换"。§13.6『发布策略』四个词，探针每词一笔动作账（四策略 4/4）：**

**C1 蓝绿 Blue-Green（探针实测）：切前 green 100% / blue 0% → 切后 blue 100% 原子切换；回滚 = 再切权一次。代价 = 资源双份。** 蓝绿买的是**"瞬间换血 + 秒级回滚"**：blue 一直是暖着的一整套 7 件套（账号你的共有 K8s 副本于 13-03），上线=一个路由翻转。**为什么贵：双份资源常驻**——你要为"不确定会不会用到的 blue"付全份钱，这是 13-05 账 B 和本篇共同面对的成本结构（13-03 账 B 换快卡省副本同理）。

**C2 金丝雀 Canary（探针实测）：先切 8% 流量（§13.6 5-10% 取 8%）→ 观测错误率/延迟/评测分达标 → 20% → 50% → 100% 逐档；任一档告警 → 一键回零。** **金丝雀买的是"把坏事控制在 8% 里"**——全量前先在 8% 上让异常暴露（13-03 灰度 5% 同式只引 · 09-07 换护栏规则也是这个纪律：先 5% 看误杀率）。**渐进的代价是时间**：每档观测 = 一次等待，24h 观测×3 档 = 发布要两天，这就是你拿"稳"换来的"慢"。

**C3 A/B 对照（探针实测）：两版同跑 50/50 分桶（各 150 样本共 300）：A 命中 132（88.0%）· B 命中 141（94.0%）→ B 胜 +6.8%。** **A/B 买的是"数据"不是"切换"**——两版同时活着，用 11 章评测链拿数据（benchmark/judge/人工三档，11-02/03/04 口径），**证据说话才决定权重**。和蓝绿/金丝雀的区别：它们"已经选了赢家逐步放量"，A/B 是"还没决定谁赢，先分桶观测"。

**C4 阴影 Shadow（探针实测）：`record_only`——线上请求 100% 复制进新版本，输出只记录不返回用户 → 离线评测通过才转正。** **阴影买的是"用户完全无感知的试新"**：录流量不返回，等于把新版本放在真实流量里"模拟考"，不碰真实用户（账 D 就用阴影日志佐证事故）。代价：一份只录不发的算力、离线评测的延迟——"无感"是用"不敢上线"换来的，好处是**你可以在证据不足时先跑起来**。

**一句话记住四种：蓝绿买原子（快但贵）· 金丝雀买稳（慢但安全）· A-B 买数据（两版活）· 阴影买无感（只录不返）。**

## 6. 实验 D · 溯源与审计账：一条审批线 + 告警回滚

**账 D 回答"线上这版是什么、出事怎么追、怎么退"。§13.6 隐含的审计面，探针画成 5 段链 + 告警 + 回滚：**

**D1 一条 5 段溯源链（探针实测 5/5 PASS）：模型版本 `qwen-7b/v9`（tag 指向 revision e1f2a3b…）→ 权重 hash `a3f5c9d2…`（safetensors sha256，内容寻址不可篡改）→ 数据版本 DVC hash `4f8b1a2c…`（13-05 数据飞轮的『数据变更』落点）→ 评测报告 eval_report.json（MMLU 0.742 · judge 0.90 · 长尾人工 0.61，三档评测源自 11-02/03/04）→ 线上记录（service=qwen-chat · model=qwen-7b/9 · 上线 2026-09-20 · 策略=阴影转正）。** **审计=能回答三个问题：线上跑哪个版本？为什么放行（评测证据在哪）？何时怎么上去的（上线记录）？** 五段一环扣一环——权重 hash 锁住"内容没被换"、DVC 锁住"喂的数据没被换"、评测报告锁住"凭证据上线"，没有其中任一段，"审计"就是空壳。

**D2 告警与佐证（探针实测）：v9 上线后 P95 延迟 1.4x 告警 + judge 线上分 −0.08 —— 阴影日志佐证：长尾请求 judge 0.61 早于转正已暴露。** 这里演示的是**影子日志的二次用途**：不只在"该不该转正"时看，还在"上线后出事"时当复盘材料——shadow 的 0.61 出现的时刻早于告警，**这就是审计证据链的调用方式**（13-05 账 C6 Agent 日志同理：能回放才有根因）。

**D3 回滚两步封死（探针实测 2/2）：① 定位：production 记录 → qwen-7b/9（就是账 A 的 tag/version 寻址）· ② 切回：蓝绿切权 v8 立即生效，shadow 日志留证。** 回滚为什么只有两步？**因为版本是"不可变引用"——别的都不用改，只把线上指针从 v9 拨回 v8**（C1 蓝绿的原子切权）；而"留证"保证你能复盘。**两步能成立的前提，是 v8 还活着（没被"覆盖"）、且可寻址（production 记录能找到它）。**

## 7. 这篇模型注册账怎么用（一页带走 + 掌握度检验）

**一页带走——给下一个要上线的 7B 服务配"模型注册"：**

1. **打 7 件套包（账 A）**：weight.safetensors + config.json + tokenizer + chat_template + quantized + eval_report + LICENSE。缺 chat_template/eval_report → 注册被拒。重量 ≈ fp16 14.0 GiB + int4 3.3 GiB。
2. **挑注册中心（账 B）**：公网取新模型走 HF Hub，团队内部形态走 MLflow Registry / 云 Registry；**上线必走内网镜像**（断外网也 deploy，合规常态）。
3. **寻址钉 revision 不钉 tag（账 B）**：`owner/repo:revision`、`models:/name/version`、`s3://…/vN`——配置里写死的永远是不变标识，`latest` 只当快捷名。
4. **选发布策略（账 C）**：要秒级回滚→蓝绿（贵双份）；要稳→金丝雀 8%→20→50→100；胜负未明→A-B 分桶拿数据；证据不足→阴影先录流量。
5. **上线即留审计链（账 D）**：版本→权重 hash→数据版本→评测报告→线上记录五段；出事 2 步（定位→切回 v8），shadow 日志留证复盘。

**掌握度检验（读完自答）：**

1. "一个模型版本 = 哪 7 件？缺哪两件会被拒？"（权重 safetensors+config+tokenizer+chat_template+quantized+eval_report+LICENSE；缺 chat_template 无模板不可用、缺 eval_report 禁上生产，账 A1。）
2. "三个注册中心和三种寻址？"（HF Hub 开源 owner/repo:revision · MLflow Registry 团队内 models:/name/version · 云 Registry 托管，s3://…/vN，账 B1/B2。）
3. "为什么内网镜像是合规常态？"（版本必须先在镜像里找到才上线——不依赖公网、不泄露依赖链、审计纯内网闭环，账 B3。）
4. "四种发布策略各买什么？"（蓝绿买原子切权/花双份资源 · 金丝雀 8%→20→50→100 买稳 · A-B 分桶 132 vs 141=+6.8% 买数据 · 阴影 record_only 买无感试新，账 C。）
5. "为什么 revision 不可变、tag 会漂移？"（revision=commit hash 锁内容寻址，可能回滚可审计；tag `latest` 跟着走，改动今天变了明天线上跑的不是你测的那版，账 A3。）
6. "一条 5 段溯源链怎么串？"（模型版本→权重 sha256→DVC 数据版本→eval_report.json→线上记录；回滚=定位→切回 v8 两步，账 D。）

## 8. 常见坑（模型注册的 6 个）

1. **把"权重文件"当"模型版本"**：一份 `.safetensors` 扔进文件夹不打包——没有 chat_template/eval_report/LICENSE，注册中心拒收，也答不了"这版凭什么上线"（账 A）。
2. **配置里钉 `latest`**：`model: qwen2.5-7b:latest` 明天指向的就不是今天测的那版——生产必须钉 revision hash / version 数字，`latest` 只当操作台快捷名（账 A3）。
3. **全量依赖公网拉模型**：内网上线前临时去 HF Hub 拉——外网一断部署就死，绕开审计——**上线版本必须在镜像里找得到，不是临时去公网拉**（账 B3）。
4. **发布只有一条路就上**：金丝雀与否、A-B 与否、蓝绿与否都靠"发布策略"——**从"注册好"到"全量"从不默认一步到位**；证据不足先阴影，胜负未明先 A-B（账 C）。
5. **上线不留记录**：`service=qwen-chat · model=qwen-7b/9 · 上线 2026-09-20 · 策略=阴影转正` 上线后就没记录——出事故答不了"线上跑的是哪版"，回滚没目标（账 D1）。
6. **回滚要"重训一份"**：以为回滚=把旧权重重新部署一遍——**版本是不可变引用，回滚=把线上指针从 v9 拨回 v8**（v8 还活着可寻址就能两步退，账 D3）。
