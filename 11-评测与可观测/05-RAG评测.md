## 0. 为什么第 5 课是「RAG 评测」？

11 章三专项已经讲了"人力"（04 篇）。现在讲三专项之"**检索生成**"——也就是把 RAG 系统当成一把"系统层"的尺子来测。这是 01 篇"五层定界"里**系统层**最典型的一把尺：08-RAG 章搭过完整系统（008 管线、RAGAS 评测站在 08-07），但 08 章是从"RAG 有什么环节"的角度讲的；**本页换一个角度——从"系统层评测怎么设计"的角度，把 RAG 评测本身讲成一门完整课。** 有三个非讲不可的理由：

1. **RAG 不评测等于没做（§8.13 原话）。** RAG 的每个环节都是旋钮：分块多大、检索哪一路、融合权重、Reranker 用哪个、上下文塞多少、Prompt 怎么写。**每次调一个旋钮都可能"感觉更好了"——但感觉不作数，只有数字作数。** 08-07 讲过一个词：**RAG 是"检索工程"，唯一的刹车就是评测。** 没有刹车，你永远不知道改的是不是地板。
2. **它有三层指标，各量一件事。** 检索层（Recall@k/Hit/MRR）量"该有的信息进没进袋子"；生成层（Faithfulness/Answer Relevance）量"答案忠不忠、对不对题"；系统层（延迟/成本/端到端）量"整套系统给人用的体验"。**三层都要测，因为哪层出问题答案就死在哪层——只测一层，凶手永远找不准。**
3. **它有评测都有的三根避坑藤，本页用 04 篇铺好的口径一次解决。** 判别性对照（评测必须有耳朵）、回归机制（每次 swap 跑同一套集）、评委三档（规则/judge/人工）。**04 篇已经把"人工那一档"讲透了，03 篇把 judge 那一档讲透了——本页把它们装进 RAG 评测的流水线。** 这正是三专项（人力 / 检索生成 / Agent）里"检索生成"专项的设计：**先学会"用什么尺量"，再学会"每把尺有什么用、怎么判别、怎么回归、谁来判"。**

**读完这篇你会：（a）说出 RAG 评测三层指标各量什么、各自对应什么故障层；（b）会用 010 式判别性对照证明"评测真有耳朵"（正确样例高分、故意破坏的样例分必须掉）；（c）理解"每次换 embedding/rerank/chunk 都跑同一套评测集对比"为什么是 RAG 唯一的刹车，以及怎么把它做成门禁；（d）避开三类误区（只看答案对错/论文题凑数/只看平均分不看长尾），并把评委三档（规则/judge/人工）装配成一条评测流水线。（本篇 🔴 会跑——教学主线三专项之检索生成，联动 08-07 RAGAS；无专属里程碑。）**

## 1. 先把 RAG 评测拆开：三层指标体系 + 谁是尺子

§11.4 和 §8.13 五句话讲完 RAG 评测的全貌。先拆成一张地图：

| 地图原文（§8.13/§11.4） | 拆成什么 | 本篇哪账 |
|---|---|---|
| 三层指标 | **检索/生成/系统三层尺子**，各量一件事、各指一个凶手 | 账 A（指标账） |
| 回归机制：每次换 embedding/rerank/chunk 都跑同一套评测集对比 | **替换组件 = 重新点火刹**，改坏立刻知道改坏 | 账 C（回归机制账） |
| 常见误区 3 条 | **只看答案对错/论文题凑数/只看平均分**——三条都是把评测做盲的动作 | 账 D（误区与评委账） |
| 评委：规则/LLM-judge/人工抽样 | **谁来打分**三档，联动 03 judge + 04 人工 | 账 D（评委三档） |
| 工具：RAGAS/DeepEval/LangSmith/Langfuse/TruLens | **生产里跑真库**（本页用词面 proxy 教原理，生产用真工具） | 账 B（附生产入口） |

**先把『三层指标』说清（§8.13 指标行）——每层量一件事，哪层出问题答案就死在哪层：**

- **检索层**（Recall@k / Hit Rate / MRR / nDCG）：**"袋子问与排位问"**。该有的信息到底进没进袋子（Hit / Recall）、进得快不快（MRR）。**凶手：分块、embedding、查询改写。**
- **生成层**（Faithfulness / Answer Relevance / Context Precision/Recall / Noise Robustness）：**"答案忠于证据吗 + 答案贴问题吗"**。答对了没（Faithfulness 忠不忠）、答得对不对题（Answer Relevance 贴不贴）、噪声块多少（Noise Robustness）。**凶手：生成没忠于证据 / 噪声块混入 / 问题理解。**
- **系统层**（延迟 / 成本 / 端到端质量）：**"线上体验与账单"**。整套系统给人用的体验与开销。**凶手：检索调太多 k / 模型太大 / 缓存没做。**

**再说『回归机制』（§8.13 回归行）——为什么它是 RAG 唯一刹车：**

> RAG 是"检索工程"，唯一的刹车就是评测。**每次换 embedding / rerank / chunk 都跑同一套评测集对比**——改坏了，立刻知道改坏了；改好了，立刻知道好在哪。这是 RAG 独有的：**大模型调参你可以靠"感觉"，RAG 换一个组件带来的变化是跨模块传导的**（换 chunk 大小 → 检索召回变 → 上下文变 → 答案变），感觉根本追不上。**只有"同一套评测集 × 固定环境跑"才能把这种传导变成可比的数字。** 这就是 11 章 01 篇"环境固定四件套"（同 prompt 模板·同 temperature=0·同 judge 版本·同语料子集）在 RAG 场景的落地。

**最后是三根『避坑藤』（§8.13 误区行 + 评委行）：**

1. 只看"答案对错"不看检索漏洞 → **分层指标**才是指认凶手的最小单位（账 A）；
2. 评测集用论文题目凑数 → 用**生产真实问题**每条标 `(gold 上下文, gold 答案要点)`（账 D 误区 2）；
3. 只看平均分不看长尾类型 → **按 query 类型分组**看（专名/口语/多跳），平均分把塌方组藏起来了（账 D 误区 3）。
4. 评委三档：**规则便宜快（$0/毫秒）· LLM-judge 规模化（$0.0012/条）· 人工只在国内门禁与校准**（账 D）。

| 本账 | 地图锚点 | 探针实测量 | 一张表看清什么 |
|---|---|---|---|
| **A 指标账** | §8.13 指标行 | 三层 ×（各指标 + 量什么）+ MRR@5 算例（Hit 2/3 · Recall 0.333 · MRR 0.444）+ 症状归层 5/5 | 三层尺子各指哪个凶手 |
| **B 判别性对照账** | §11.4/§8.13 · 010 同法 | 10 条样例 pure 词面 proxy：good 0.93/0.46 → miss 0.46/0.34 · halluc 0.42/0.37 · off 0.18/0.14 | 评测必须有耳朵（掌握度检验） |

## 3. 实验 A · 指标账：三层指标 × MRR 算例 × 症状归层

账 A 先把 §8.13 "三层指标" 一行扩成三行（断言 PASS）——**每层答两件事：量什么、对应什么凶手**：

| 层 | 指标 | 量什么 | 凶手 |
|---|---|---|---|
| 检索层 | Recall@k / Hit@k / MRR / nDCG | 袋子问与排位问 | 分块 / embedding / 查询改写 |
| 生成层 | Faithfulness / Answer Relevance / Context Precision·Rec/Noise Robustness | 答案忠于证据吗 + 答案贴问题吗 | 生成没忠于证据 / 噪声块混入 |
| 系统层 | 延迟 / 成本 / 端到端质量 | 线上体验与账单 | 检索调太多 k / 模型太大 / 缓存没做 |

**第一个读数 = 三个具体指标的第一性（MRR@5 本机算例）**：用 3 条 query 的 gold 排位 `[1, 3, 7（top-5 外）]`、各 2 个 gold 文档 → 本机确定性计算：

- **Hit@5 = 2/3**（Q1、Q2 命中，Q3 没进袋子）
- **Recall@5 = 2/6 = 0.333**（命中的 gold 文档 / 全部 gold 文档）
- **MRR@5 = (1/1 + 1/3 + 0)/3 = 0.444**（黄金文档进袋子了、还要看排得快不快；排位越靠前 MRR 越高）

**读点：三个指标问的是三件事。** Hit 问"袋子有没有"，Recall 问"该有的都进来了吗"，MRR 问"翻得快不快"。**同一个检索，Hit 满分不代表 MRR 满分**（都进 top-5 但 gold 全排在 top-5 末尾，MRR 就低）——所以 08-07 原话"评测集没张力时两者都满分，别误读成系统无敌"。

**第二个读数 = 症状归层表（哪层出问题答案就死在哪层，5/5 断言）：**

| 症状 | 哪层指标掉 | 凶手 |
|---|---|---|
| 答非所问（答案在袋子里但不贴问题） | 生成层 · Answer Relevance | 问题理解 / 生成跑偏 |
| 答案与文档矛盾（睁眼说瞎话） | 生成层 · Faithfulness | 生成没忠于证据 / 噪声块混入 |
| 该有的信息根本没进袋子 | 检索层 · Recall@k / Hit@k | 分块 / embedding / 查询改写 |
| 袋子里有、但翻袋子太慢 | 检索层 · MRR | 融合权重 / 重排器没把 gold 顶上 |
| 响应太慢 / 账单太贵 | 系统层 · 延迟 / 成本 | 检索调太多 k / 模型太大 / 缓存没做 |

**读点：分层指标的唯一意义 = 指认凶手。** 答案错了，第一件事不是"骂模型"，是**看哪层指标掉了**——检索层掉了改检索，生成层掉了改生成/上下文，系统层掉了改部署。**这正是 08-14 诊断手册的"指标—故障层"接口**（08-13 篇的症状→根因→修复），也是 01 篇"选错层结论极性反 4/4"的正向版。

**账 A 的总结论（三层各 ≥2 指标 + MRR 算例 + 归层 5/5）：**

> **RAG 评测三层尺子各指一个凶手：检索层（Recall/Hit/MRR）量袋子里有没有、翻得快不快，凶手在分块/embedding/查询改写；生成层（Faithfulness/AR/Noise）量答案忠不忠、对不对题，凶手在生成与上下文质量；系统层（延迟/成本/端到端）量整套体验，凶手在部署旋钮。哪层出问题答案就死在哪层——分层的意义不是"多打几个分"，是"坏了知道去哪儿修"。**

## 4. 实验 B · 判别性对照账：评测必须有耳朵（掌握度检验）

账 B 是**本页的掌握度检验**（plan 316：仿照 010 给自己的评测集写一个判别性对照样例，证明"评测真有耳朵"）。10 条样例，每条 `(问题, 证据, 答案)`，分成四组——**正确组（good）+ 三组故意破坏（miss 检索错位 / halluc 答案编造 / off 答非所问）**。用词面 proxy（Faith = 答案在证据里的字符覆盖率；AR = 答案与问题共词比例）为每条打分：

| 组 | 样例 | Faith | AR |
|---|---|---|---|
| good · 正确检索 + 忠实答案 | 4 条（入职年份/违约金/运费险/退款天数） | **0.93** | **0.46** |
| miss · 检索错位（把别的文档拖来做证据） | 2 条 | **0.46** | 0.34 |
| halluc · 答案编造（证据对、答案开始胡说） | 2 条 | **0.42** | 0.37 |
| off · 答非所问（证据对、答案根本不是答这个） | 2 条 | **0.18** | 0.14 |

**判别性断言 3/3 PASS：三种破坏都让指标掉。** good 组 Faith 0.93 vs 最差 off 组 0.18，检索错位（miss）从 0.93 掉到 0.46，编造（halluc）0.42，答非所问（off）双掉到 0.18/0.14。

**这就是"评测有耳朵"的证明（010 同法）：正确的样例分高，故意破坏的样例分必须掉，且每种破坏掉的是"它该掉的维度"。** 三门独门读点：

1. **miss 和 halluc 掉的主要是 Faith（忠于证据），off 掉的主要是 AR（贴问题）**——判别性不仅要"听见破坏"，还要"分清破坏种类"，**这才是 010 那一课说的『好指标必须能抓住坏答案』**。
2. **和 08-07 的实测同构（只引不重测）**：08-07 在 009 语料上实跑 RAGAS 风格三层指标，正确基线 Faith 1.00 / AR 0.74 → **故意给"错来源"答案 0.17 / 0.40**——本页用词面 proxy 复现了同一现象（0.93 → 0.46），**机制同源：错误输入（错证据/错答案）必须让分数掉**。
3. **这是你自检评测集有没有张力的标准动作**：如果某个评测集"怎么改都 0.9"（用完 08-07 原话：没张力的评测集三两个满分）——**加一组故意破坏的对照样例，指标不掉就说明评测集没耳朵，换了破坏改不成。**（08-07 坑 #2 "评测集没有张力"的正解。）

**账 B 的总结论（判别性断言 3/3）：**

> **评测必须有耳朵：正确样例高分（good Faith 0.93/AR 0.46）、三组故意破坏必须让对应指标掉（检索错位 0.46 · 编造 0.42 · 答非所问 0.18）——判别性对照（010 同法）是给评测集自检张力的标准动作，与 08-07 实测（正确 1.00/0.74 → 错来源 0.17/0.40）同构。评测集没张力 = 怎么打都 0.9 的装饰分，不是评测。生产里跑真 RAGAS（claims-based 分解论断 + 生成虚拟问题算相似）就是把这套 proxy 换成两步 LLM 调用——原理一样、口径更硬（08-07 第 4 节）。**

## 5. 实验 C · 回归机制账：RAG 是检索工程，唯一的刹车就是评测

账 C 回答最实操的问题：**改了一次组件，怎么知道改坏了？** 答案 = §8.13 回归机制——**每次换 embedding / rerank / chunk 都跑同一套评测集对比。** 本机做确定性演示：**同一 10 条评测集（gold 排位表）跑三个版本引擎**：

| 版本 | gold 排位（top-5 内位置） | Hit@5 | vs 基线 |
|---|---|---|---|
| v2 基线（chunk=384） | [1,1,1,1,1,2,3,4,5,5] | **1.00** | — |
| v3 换 chunk=1024 | [1,1,1,5,7,9,11,13,15,15] | **0.40** | **Δ-0.60 回退 · 低于闸线** |
| v4 换 embedding | [1,1,1,1,5,7,9,9,15,15] | **0.50** | **Δ-0.50 回退 · 低于闸线** |
| v5 加 rerank | [1,1,1,1,1,1,2,2,3,3] | **1.00** | Δ+0.00（顶回第一页） |

**回归断言 PASS：2/3 非基线版本中 2 次回退被门禁拦下**（v3 换 chunk 掉了 0.60、v4 换 embedding 掉了 0.50——分数当天就告诉你改坏了）。四个读点：

1. **v3 换 chunk 为什么掉**：块从 384 → 1024，信息被大块稀释、gold 文档被挤到 top-5 之外（排位 5→7→9→11），Hit 摔到 0.40。**这恰是"改了个旋钮改了全链"的跨模块传导**——光看预测"感觉差不多"是看不出来的，只有同一套评测集的数字能看出来。
2. **v5 加 rerank 为什么没掉反而顶回第一页**：rerank 把 gold 全顶回 top-3（[1,1,1,1,1,1,2,2,3,3]）。**这证明"哪一步改好了要有数字"**——没有回归表，你只知道"好像快了"，不知道"其实检索质量也变好了"。
3. **把它做成工程（不只是脚本）**：PR 附一行"最近一次基线 vs 本次"对比；CI 挂门禁"关键指标不得低于闸线 X%"（本页 GATE=0.80 → v3 的 0.40 直接合并失败）。**这就是 08-13 篇的"回归=每次换 embedding/rerank/chunk 都跑同一套评测集对比"落地成自动化。**
4. **配套纪律 = 环境固定四件套**（11 章 01 篇 §11.9.2）：同 prompt 模板 · 同 temperature=0 · 同 judge 版本 · 同语料子集——**否则两版分数差可能是"换的是评测环境"而不是"换的是组件"**（03 篇说了：judge 换版本 20 样本翻转 6 条，版本锁定是保命）。

**账 C 的总结论（回归断言 + GATE）：**

> **RAG 是"检索工程"，唯一的刹车就是评测：每次换 embedding / rerank / chunk 都跑同一套评测集对比（基线 Hit 1.00 → chunk=1024 0.40 → embedding 0.50 → rerank 1.00，2 次回退被门禁拦下）——改坏立刻知道改坏、改好立刻知道好在哪。落地成工程 = PR 附基线对比行 + CI 门禁（关键指标不得低于闸线 X%）。没有这套机制，RAG 的旋钮全靠感觉，而感觉追不上跨模块传导。**

## 6. 实验 D · 误区与评委账：三类误区 + 长尾分组 + 评委三档

账 D 是"别把评测做盲"+"谁来打分"课——把所有"把评测做盲的动作"点名，再把评委三档装成流水线。

**D1 三类误区（3/3 断言）：**

| 误区 | 为什么是坑 | 怎么破 |
|---|---|---|
| 只看"答案对错"不看检索漏洞 | 端到端答对 8/10，但检索层 Hit@5 = 6/10——那 2 条"答对但 gold 没进袋子"是生成层靠模板蒙对的，一换问法就裂；不测检索层你不知道这两条是借来的 | **分层指标**（账 A 的归层表） |
| 评测集用"论文题目"凑数 | 论文题（MMLU 式单选）测的是模型常识；生产 RAG 问法（"退货要几天？"）多口语、多隐含前提、gold 答案要点要靠文档验证 | **用生产真实问题**，每条标 (gold 上下文, gold 答案要点)（08-07 第 6 节） |
| 只看平均分不看长尾类型 | 同一集按类型分组：专名 1.00 · 口语 0.67 · 多跳 0.33 → 总分 0.70 全绿，但"多跳类型"整组塌了——平均分把塌方组藏起来了 | **按 query 类型分组看**，长尾是排查的前线（08-07 第 6 节） |

**长尾实测（10 条 = 专名 4/4 · 口语 2/3 · 多跳 1/3）：总分 0.70 全绿 → 但多跳组 0.33 整组塌。** 这就是 §8.13 误区 3 的数字版：**平均分把多跳类型塌方藏得严严实实，一换问法就裂。** 排查的正确姿势 = 把评测集按 query 类型（专名/口语/多跳）分组看分数表，而不是只看一个总分。

**D2 评委三档（5 场景 5/5）：** §8.13 评委行说"规则 / LLM-judge / 人工抽样"——正是 03 篇（judge）+ 04 篇（人工）装进 RAG 评测的接线：

| 场景 | 给谁 | 理由 |
|---|---|---|
| 快速回归 / CI 门禁（高频、要便宜快） | **规则** | 词面覆盖/指标公式，$0 且毫秒级（账 C 的 Hit 闸线就是规则判的） |
| 规模化定期打分（千条级、budget 有限） | **judge** | 03 账 C：LLM judge $0.0012/条 · 0.92 判准，但先做人工校准 |
| judge 的校准标定（小样本盯准） | **人工抽样** | 04 账 B：关键门禁 + judge 校准用人工（15 条 3→1 那档） |
| 感受维度（风格 / 冒犯感 / 品牌） | **人工** | 04 账 A：不可自动化替代的"真实感受"，盲评去掉品牌光环 |
| 对发布前最后一道门禁打分 | **人工复核临界子集** | 04 账 D：judge 全扫 + 人工复核临界 50 条 $75.60 = 全人工价 10 分之一 |

**读点：评委要分档，因为各档的钱和时间是数量级的差距（03 账 C/04 账 B 锚点）。** 规则 $0/毫秒级，judge $0.0012/条，人工 $1.50/条（1250×）——**所以默认排序永远是"规则先扫 → judge 大规模 → 人工只在门禁与校准"。** 这正呼应 04 篇"人工用在刀刃上"：**RAG 的日常迭代打分交给 judge，发布前最后一道门禁留人工。**

**账 D 的总结论（三误区 + 长尾 + 评委 5/5）：**

> **别把评测做盲：三层都要测（别只看答案对错），评测集用生产真实问题（别论文题凑数），按 query 类型分长尾看（平均分把塌方组藏起来）。谁来打分 = 评委三档：规则便宜快（账 C 门禁）、judge 规模化（$0.0012/条，03 账 C）、人工只在门禁与校准（04 账 D 混合流水线 $75.60 = 全人工价 10 分之一）——默认对每套 RAG 评测集装配"规则先扫 → judge 大规模 → 人工守门禁"。**

## 7. 这篇 RAG 评测怎么用（一页带走 + 掌握度检验）

**一页带走：**

- **三层指标**（账 A）：检索层（Recall/Hit/MRR）量袋子里有没有、翻得快不快 · 生成层（Faithfulness 忠不忠 / AR 贴不贴 / Noise 噪声多少）· 系统层（延迟/成本/端到端）。**哪层出问题答案就死在哪层——分层意义在指认凶手。**
- **判别性对照**（账 B）：正确的样例高分（good Faith 0.93）、三组故意破坏必须让对应指标掉（错位 0.46 · 编造 0.42 · 答非所问 0.18）——**评测必须有耳朵，与 08-07 实测（1.00/0.74 → 0.17/0.40）同构。**
- **回归机制**（账 C）：**每一次换 embedding / rerank / chunk 都跑同一套评测集对比**——基线 Hit 1.00 → chunk=1024 0.40 → embedding 0.50 → rerank 1.00，2 次回退被门禁拦。**RAG 是检索工程，唯一刹车就是评测。**
- **别做盲 + 谁来判**（账 D）：三误区（只看答案对错/论文题凑数/只看平均分）——按 query 类型分长尾看；评委三档（规则便宜快 / judge 规模化 / 人工守门禁）。

**掌握度检验（自问自答）：**
1. "RAG 答错了，第一件事该看什么？"（答案：看哪层指标掉了——分层指标的唯一意义是指认凶手；检索层掉改检索、生成层掉改上下文/生成、系统层掉改部署。账 A。）
2. "怎么证明我的评测集真的有耳朵？"（答案：加一组 010 式判别性对照——正确样例高分、故意破坏的样例对应指标必须掉；不掉就说明评测集没张力。账 B。）
3. "换了 chunk 大小觉得'好像更好'，怎么确认？"（答案：跑同一套评测集对比基线——跨模块传导感觉追不上，只有数字能追上；CI 挂门禁"关键指标不得低于闸线"。账 C。）
4. "总分 0.70 全绿，能上线吗？"（答案：不能——先按 query 类型分组看长尾，多跳组可能只有 0.33；平均分把塌方组藏起来了。账 D 误区 3。）
5. "RAG 评测打分到底用谁？"（答案：评委三档——规则先扫（$0/毫秒，账 C 门禁）、judge 大规模（$0.0012/条，03）、人工只在门禁与校准（04：judge 全扫 + 人工复核临界子集 $75.60）。账 D。）

## 8. 常见坑（做 RAG 评测的 7 个）

1. **只测端到端"答案对不对"，不测分层指标**（§8.13 靶子）：坏在检索还是坏在生成，看不出——改都不知道改哪。**修法**：三层指标各落一个带回路的数字（账 A 归层表）。
2. **评测集没有张力，怎么改都 0.9**（08-07 坑 #2 的复发）：全是有唯一答案的事实题，Hit@5 永远 1.0。**修法**：加 010 式判别性对照自检（账 B——故意破坏样例指标掉才算有耳朵）；评测集按类型（专名/口语/多跳）配比，别全是简单题。
3. **没固定 seed / 没固定环境就对比**（08-07 坑 #3 的复发）：两次采样不同 → 分数差全是噪声。**修法**：环境固定四件套（01 章 §11.9.2：同 prompt 模板·同 temperature=0·同 judge 版本·同语料子集）。
4. **拿 judge 裸奔**（08-07 坑 #4 的复发）：LLM-judge 不做人工校准，长度/位置偏置直接污染分数。**修法**：03 账 D 的人工子集校准（15 条 3→1）；先跑 20 条人工标注一致性 >0.85 才信 judge。
5. **只跑一次不当回归**（08-07 坑 #5 的复发）：改了一次 chunk 不重跑旧评测。**修法**：账 C——每次组件 swap 必须对同一套评测集对比 + CI 门禁（关键指标不得低于闸线）。
6. **用论文题目当代测集**（§8.13 误区 2）：测的是模型常识不是检索质量。**修法**：生产真实问题，每条标 (gold 上下文, gold 答案要点)；造不齐先 20 条起步好过没有（08-07 第 6 节）。
7. **只看平均分不看长尾**（§8.13 误区 3）：总分 0.70 全绿但多跳组 0.33。**修法**：按 query 类型分组出分数表（专名/口语/多跳），长尾才是排查前线（账 D）。
