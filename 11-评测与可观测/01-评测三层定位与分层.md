## 0. 为什么第 1 课是「评测三层定位与分层」？

你已经在 04 章装好过"评测门禁"（三道闸：过拟合早停、旧能回归、泄漏 hold-back）、在 08 章把 RAG 的忠实度量到 88.2% 压缩率不掉证据纯度、在 09 章把 Agent 的评测台三件套钉上生产（04-10 / 08-07 / 09-06）——**但"评测"这件事自己还没有一张图**。11 章开篇章补的就是这张图，而且它要先于一切数字：

1. **评测是"地基工程"，不是收尾动作。** §11.0 一句话点透：没有评测 = 无法做技术决策（选模型/调 prompt/改 RAG 全靠感觉），也无法防止回归（新版本悄悄变笨）。你手里那些第 N 章的分数之所以能信，恰是因为每篇都先说了"同一语料、同一断言、固定环境"——也就是**先讲口径再讲数字**。这篇把这条纪律从"各篇自律"升级成"显式的开篇肌肉"。
2. **"你在量哪一层"是所有评测问题的第一问。** §11.0 给了五层：能力层（模型本身多强）/ 任务层（你的业务任务）/ 系统层（RAG·Agent 端到端）/ 安全层 / 工程层。同一个动作（比如 RAG 加重排、服务切流式、换个模型），在不同层量会得到**方向相反**的结论——不先把层定住，后面的 02–10 篇学到再多数字也会被"用错尺子"毁掉。
3. **它把 11 章后九篇串成一张地图。** 11.1 Benchmark（能力层的榜单尺）→ 11.2 LLM-judge（规模化判分的器件）→ 11.3 人工评测（关键门禁）→ 11.4 RAG 评测（系统层专项）→ 11.5 Agent 评测（系统层专项）→ 11.6 安全与幻觉（安全层专项）→ 11.7 工程指标（工程层专项）→ 11.8 可观测工具链（把测量搬进生产）→ 11.9 最佳实践（收束）。**本篇只立坐标系，坐标里每格的正文在 02–10 篇逐篇长肉。**

**和 09 章开篇（01-Agent定义）的关系？** 09-01 钉的是"Agent 是哪一类"，本篇钉的是"评测是在量哪一层+哪种角色"——都是**先画坐标系再谈内容**的开篇姿势。对走路线 B 的你，这是主干的下一站：09 章把 Agent 的"评测台"用起来了（09-06），本篇把它拆成"为什么要有评测台、评测台放在坐标系哪一格"。

## 1. 先把开篇章拆开：五层一张图 × 三种角色 × 一条肌肉

§11.0 原文三句话，拆成三块各有用途：

| §11.0 原文 | 拆成什么 | 本篇哪账 |
|---|---|---|
| 评测分层：能力层→任务层→系统层→安全层→工程层 | **五层坐标系 = "先归层再读数"**，核心三层（能力/任务/系统）各管一段 | 账 A（定界✓）+ 账 D（归档✓） |
| 评测的三种角色：选型/开发/上线 | **三种评测是三类决策**，各看各的层 | 账 C（角色矩阵✓） |
| 没有评测 = 无法做技术决策 + 无法防回归 | **口径先于数字的动机**，选错层结论会反过来 | 账 B（错配✓） |

**首先把『五层坐标系』说清——先分「三大主层」和「两翼」。** 计划 §2.11 把这一篇定为"三层定界"——核心就是中间三层：

1. **能力层（知识/推理/代码/数学）管"模型本身多强"**：问的是"这个模型不带你的系统，在通用能力上几斤几两"。尺子是 Benchmark（MMLU/C-Eval/GSM8K/SWE-bench…）。**你的 RAG/Agent/prompt 一概不接**，只看模型裸能力。仓库锚点：03-11 八要素横向对比（14 模型同表并排）、03-03 Qwen 中文词表 −52%（词表=中文能力层的地基）。
2. **任务层（你的业务任务）管"换到你的场景里好不好用"**：问的是"把模型的输出放进*你的*业务评测集，对不对"。尺子是**自建业务评测集**（同断言、同语料、固定环境）。**这是 04-10 评测门禁、06-02 prompt 评测闸、06-03 上下文路由闸所在的层**——"业务好用"只能在这一层回答。
3. **系统层（RAG/Agent 端到端）管"整套系统跑起来的结果"**：问的是"检索+重排+分块+生成"或"循环+工具+护栏"整条链一起跑，端到端答案对不对、稳不稳、贵不贵。尺子是 RAGAS（忠实度/相关度/上下文三维，08-07）与 Agent 评测台三件套（固定环境+可验证终结+成本，09-06）。**改 RAG 检索、改 Agent 编排，都在这一层量。**

再加上两翼（一起看才完整）：
4. **安全层（威胁与护栏）**：会不会被注入、越权、吐出有害内容——红线单独一层，能力层再高也覆盖不了它。09-07 六护栏 20→12→2 就是这层的账。
5. **工程层（延迟/吞吐/成本）**：跑得快不快、贵不贵——TTFT/TPOT/$。06-01 流式 TTFT 0.010s vs 0.850s 就是工程层。

> **五层与"三种角色"怎么对？** 选型评测在能力层为主（横向比能力）→ 开发评测在任务层+系统层为主（迭代对比）→ 上线评测在系统层+安全层+工程层为主（线上效果与护栏）。**三种角色管三类决策，别混着拍板**——账 C 把这张矩阵钉死。

**最后看『先讲口径再讲数字』这条肌肉**——它是本仓库"真实数字纪律"（§3.3：正文指标必须是实际跑过的结果）在评测层面的总闸：读任何一个数字之前先验三句——它在量哪层？这层对得上我要决策的事吗？它的环境定死了吗（同 prompt 模板/同 temperature/同 judge 版本）？**账 B 证明这三句不是洁癖：不问，会得到相反的结论。**

**类推 10/10 断言全过 · 五层全有代表 · 核心三层（能力/任务/系统）各 ≥2。** 三个读数：

**第一个，同一个动作在不同层用不同的尺子，答案本就不该一样。** 一个在前 10 题里反复出现的例子：MMLU 88 的模型"很强"（能力层判的），但接上你的客服业务评测集可能只有 0.43（任务层判的）——**不是模型骗你，是你量的层换了**。能力层尺子问"模型裸能力"，任务层尺子问"放进我的场景好不好用"，两者是两回事。这个例子的极端版就是账 B 的第四个错配。

**第二个，问题的『主尺度』自动指向答案的『主场馆』。** 问"谁能解更难代码题"→ 能力层（榜单）；问"我改了 prompt 有没有变好"→ 任务层（业务评测集）；问"加了重排整体涨没涨"→ 系统层（端到端）；问"切流式快不快"→ 工程层（TTFT）；问"越权拦得住吗"→ 安全层。**先归层，你才知道该跑哪一把尺——不归层，你会拿 MMLU 尺去量 prompt 改动，得出"改动无效"的假结论（账 B 第 1 例）。**

**第三个，两翼（安全/工程）别忘，它们不在"三层"标题里但一样重要。** 三层定界是骨架（计划 §2.11 的命名），安全层与工程层是两翼——九个问题里第 8/9/10 三个正是它们：再聪明的模型没护栏会闯祸（安全层），再准的系统太慢太贵也上不了线（工程层）。**判断一个"评测问题该归哪层"的快捷方式：看它要决策的事落到哪一层。** 层定错了，后面每章的数字都会跟着错位。

**账 A 的总结论（断言 10/10）**：

> **先归层再读数是评测的第一纪律：能力层（模型本身多强，MMLU/C-Eval 类榜单尺）→ 任务层（你的业务任务，自建业务评测集）→ 系统层（RAG/Agent 端到端，RAGAS/评测台三件套）→ 安全层（威胁与护栏，越权/注入拦截）→ 工程层（延迟/成本，TTFT/$/query）。10 个典型问题 10/10 归对层、核心三层各 ≥2，问题的『主尺度』指向答案的『主场馆』——选模型进能力层、调 prompt 进任务层、改 RAG/Agent 进系统层、动部署进工程层、上护栏进安全层。**

## 4. 实验 B · 错配账：选错层＝结论反过来

账 A 证明了"每层有其尺"，本账证明**为什么你不问层就会吃大亏**——4 个"这章后面会频繁遇到"的场景，每个都给"正确层结论"和"错配层结论"两版，看极性怎么翻：

| 场景 | 正确层→结论 | ↯ 错用某层尺子（读数） | 误判结论 | 极性 |
|---|---|---|---|---|
| RAG 加重排（08-03） | 系统层→端到端 Top-1 提升：改动**有效** | 能力层尺子（MMLU 分 0 变化） | 『改动无效』（白做） | 反 |
| 服务切流式（06-01） | 工程层→TTFT 0.850s→0.010s：**大改善** | 任务层尺子（答案正确率 0 变化） | 『没改善』 | 反 |
| 两版 Agent 拍板（09-06） | 系统层→六指标账本：A 取胜率但 token 2×+安全 2→**别选 A** | 成功率单指标（9/10>8/10） | 『选 A』 | 反 |
| MMLU 88 模型空降客服 | 任务层→业务评测 0.43：**不合格** | 能力层尺子（MMLU 88 高分） | 『能用』 | 反 |

**断言 4/4：全部极性相反。** 三个读数：

**第一个，"数字没错，尺子用错了层"是结论翻车的根源。** RAG 加重排明明让端到端 Top-1 涨了（08-03 的实测量），但如果你拿能力层尺子（MMLU 分）去量，读数 0 变化，结论就成了"白干"——**重排本来就该在系统层量，MMLU 分 dong 不 dong 与它无关**。同理，切流式 85× 提速是工程层的大成就，拿任务层正确率去量它当然"没改善"——**两种尺子回答的是两个不同的问题**。

**第二个，"单指标"是最隐蔽的错配。** 09-06 的最硬教训就是账 B 第 3 例：单看成功率 A 9/10 > B 8/10，六指标齐看 A token 2× + 安全事件 2——**评测台三件套之所以要"成本指标"，就是为了拦住这种"被单成功率骗过"的选择**。把"系统层决策"降成"能力层式的单指标对比"，结论就反了。

**第三个，四个例子合起来，就是"先讲口径再讲数字"的最短证明。** 没有一个是数字造假——MMLU 88 是真的、9/10 是真的、0.850s 是真的——错的都是**没先问"在量哪层"就套尺子**。**读到任何一个数字，先问三句：它在量哪层？这层对得上我要决策的事吗？它的环境定死了吗？** 三句问完，结论不会再翻车。

**账 B 的总结论（断言 4/4）**：

> **选错层＝结论反过来：4 个场景『正确层结论』与『错配层结论』极性全反——RAG 加重排有效≠MMLU 涨、切流式大改善≠正确率变、别选 A≠成功率输了、MMLU 88≠业务好用。数字没错，尺子用错了层；『单指标』是最隐蔽的错配（09-06 六指标账本的动机）。这就是『先讲口径再讲数字』不是洁癖、是保命。**

## 5. 实验 C · 三角色×五层矩阵账：每种评测角色，主要量哪一层

§11.0 给了三种角色，本账把"角色→层"钉成矩阵——每种评测是哪种决策，就主要看哪几层：

| 角色 | 能力 | 任务 | 系统 | 安全 | 工程 | §11.0 定位 |
|---|---|---|---|---|---|---|
| **选型评测** | 主 | 次 | 空 | 次 | 空 | 横向比能力（看榜单挑模型） |
| **开发评测** | 空 | 主 | 主 | 空 | 次 | 迭代对比（每次改动回跑同一套） |
| **上线评测** | 空 | 次 | 主 | 主 | 主 | 线上效果与护栏（生产真数据） |

**断言：三角色主层 3/3 与 §11.0 定义匹配 · 五层全被某角色当『主』= 没有哪一层不重要。** 三个读数：

**第一个，三种角色是三类决策，各看各的层，别混着拍板。** 选型评测的任务是"横向比能力"——你在挑模型，当然以能力层为主（另外搭一眼任务层抽查与安全层底线）；开发评测的任务是"迭代对比"——你每次改 prompt/改 RAG/改 Agent，主战场在任务层（业务集）+ 系统层（端到端回归）；上线评测的任务是"线上效果与护栏"——真用户进来了，系统层 + 安全层 + 工程层三头抓。**把上线评测的脚手架（成本/护栏）用去做选型、把选型的榜单用去做上线门禁，都是错配。**

**第二个，"没有哪一层不重要"是矩阵自带的结论。** 五层每一层都至少被某角色当主：能力层（选型）、任务层（开发）、系统层（开发+上线）、安全层（上线）、工程层（上线）。**所以别问"哪层最重要"——要问"我现在这种决策，主要看哪层"。** 层不一定要全跑，最小回归省时间（见下方规则）；但没有任何一层可以长期不看。

**第三个，"改动→最少要回跑哪把尺"是这条纪律的落地形态（5 条规则 5/5）：**

| 你改了 | 最少要回跑 | 用哪把尺 |
|---|---|---|
| prompt/示例 | 任务层 | 06-02 prompt 评测闸 |
| 模型/版本 | 能力层+任务层 | 04-10 三道门禁 |
| RAG 检索/分块 | 系统层 | 08-07 RAGAS + 端到端 |
| Agent 编排/循环 | 系统层 | 09-06 评测台三件套 |
| 部署/服务 | 工程层 | 06-01 TTFT/吞吐/$ |

**每次改完先想清楚动了哪一层，再选尺子回跑**——prompt 改动不用重跑 MMLU 榜单（能力尺量不到你改的层）、切流式不用重跑业务评测集（正确率不变是必然）——**层不用全跑：最小回归省时间，口径不丢不漏。**

**账 C 的总结论（断言 3/3 角色 + 5/5 规则）**：

> **三种角色管三类决策：选型评测主量能力层（横向比能力）· 开发评测主量任务层+系统层（迭代对比）· 上线评测主量系统层+安全层+工程层（线上效果与护栏）；五层全被某角色当『主』=没有哪一层不重要。落地形式=『改动→最少回跑哪把尺』5 条规则（prompt→任务层·换模型→能力+任务·RAG→系统层·Agent→系统层评测台·部署→工程层）——先定决策角色，再定层，再选尺，这就是『先讲口径』的完整链路。**

## 8. 常见坑（先讲口径的 7 个）

1. **拿能力层尺子量系统层改动**（账 B 第 1 例的靶子）：RAG 加重排后用 MMLU 分看"有没涨"。**修法**：先归层——重排是系统层的事，端到端 Hit@1 才是它的尺；能力层分数不 dong 是正常的，不是"白做"。
2. **把『单指标』当『评测』**（账 B 第 3 例的靶子）：只比成功率就拍板换 Agent。**修法**：评测台三件套（固定环境+可验证终结+成本指标）六指标齐看——A 9/10 但 token 2×+安全事件 2 就是"被成功率骗过"的实况（09-06）。
3. **用任务层正确率去验证工程层优化**（账 B 第 2 例的靶子）：切流式后质疑"答案质量没变耶"。**修法**：流式是工程层动作，看 TTFT/成本（0.850s→0.010s 就是 85×）；答案正确率本来就不该变，变了反而说明你动错了地方。
4. **上线才想起评测**（§11.0 的靶子）：模型都上了真用户才问'它到底行不行'。**修法**：评测是地基工程——开发期就建业务评测集（账 C 开发主量任务+系统），上线只要把同一套尺搬到生产真数据（上线主量系统+安全+工程）。
5. **环境不固定就比数字**（账 D 四件套的靶子）：今天 temp=0.7、明天 temp=1.5，两个数字放一起比。**修法**：评测一律 temperature=0 + 同 prompt 模板 + 同 judge 版本 + 同语料子集；任何一对数字在比较前先验这四件。
6. **五种角色×五层混用"分位数"**（账 C 的靶子）：拿选型榜单（能力层）当上线门禁（系统+安全+工程）。**修法**：三种角色是三类决策——选型看能力+抽查任务、上线看系统+安全+工程+护栏；不同角色同一模型得分没有直接可比性。
7. **以为"评测=榜单"**（§11.0→11.1 的靶子）：背 MMLU/GSM8K 就当学会了评测。**修法**：榜单只是能力层的一把尺，任务层（业务评测集）与系统层（RAGAS/评测台）才是你产品的真裁判；榜单刷分是常态（11.1 详解），业务自建评测集才是最终裁判。
