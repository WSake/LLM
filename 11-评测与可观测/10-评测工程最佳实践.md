## 0. 为什么第 10 课是「评测工程最佳实践」？

01-09 把「评测」这件事实战了一整遍：01 篇教你五层定界（先讲口径再讲数字）、02 篇教你 benchmark 尺子大全、03-07 篇把四个专项（人力/RAG/Agent/安全）各做成评测台、08 篇把六把工程尺做出预算回归门禁、09 篇把 trace 打进生产观测。**但九篇各自是"一把把尺子"——没有一个地方把"评测这件事"在开发流程里到底怎么安排"讲成一整套规范。** §11.9 在知识地图里被标为 **🔴 总结**，是整章最后一课里的"五条纪律"：评测集怎么分层、评测环境怎么固定、每次改动要不要重跑、线上数据怎么回流、产品到底该用什么指标评价。本篇就是把这五条纪律 + 前九篇的锚点数字，编成**一张可以直接照着做的装配手册**。三个非讲不可的理由：

1. **评测不是"最终的报告"，是"开发流程的门禁"。** §11.9 的地图位置是 🔴 总结，因为它回答的是前九篇没有正面回答的那句："这套评测系统，平时怎么用？"——答案就一句：**嵌进开发流程，每次改动过闸**。05-RAG 有回归闸线 GATE 0.80、07-安全有"安全事件>0 不上生产"、08-工程有预算回归门禁、09-可观测有 SLO 闸线——**这些散在各篇的"红线"，本篇收成一条四道闸的门禁链：冒烟 → 回归 → 安全 → 工程**。评测从"选型时跑一跑"变成"提交时必过"。
2. **评测集不是"一次性建好"，是"分层 + 每次改动滚动喂"。** 冒烟、回归、大榜单三层各有各的规模与时机（账 A）；每次改动只回跑该层尺子（账 B）；线上不满意/重试/纠错/慢请求回流成新样本（账 C）——**评测集是活的**，这正是 01 篇"等权不看业务"、09 篇"最慢 trace 回注"的工程化收口。
3. **评价产品用"每任务完成"，不是"每 token 质量"（§11.9⑤）。** 前九篇都在量质量/性能，最后这篇回答"老板看什么数"——同一个 RAG 机器人，稠密嵌一堆 single-shot 的 0.90 和一个六轮协作啃下来的 0.80，**单轮打分前者赢、每任务完成率后者赢；而烧 token 的成本差是 23.8×**。揭穿"蔓胖"陷阱（账 D），是整章最后一个也是最重要的一个认知。

**读完这篇你会：（a）说出评测集三层（冒烟/回归/大榜单）各自规模与时机，5 个真实场景判对层（账 A）；（b）会把环境固定四件套（§11.9②）背出来，知道缺 judge 锁定=0.30 漂移，每改一处只回跑对应那层尺子 5/5 命中（账 B）；（c）会搭"采集→判定→标注→进集"回流管道，5 条线上日志 4 回流 1 不回，三个锚点号全对（账 C）；（d）会用「每任务完成」给产品下结论（×23.8 复算），把评测装成冒烟→回归→安全→工程四道门禁，5 个开发动作对上闸 5/5（账 D）。（本篇 🔴 总结 = 11 章收官——联动 01-09 全部九篇与 §11.9，无专属里程碑。）**

| 本账 | 纪律锚点 | 探针实测 | 一张表看清什么 |
|---|---|---|---|
| **A 分层账** | §11.9① 评测集分层 | 三层（冒烟 5-10/回归 100-500/大榜单千级）× 时机 × 成本，规模递增 3/3 + 5 场景判层 5/5 | 评测集分三层，量级差一个数量级 |

## 3. 实验 A · 分层账：评测集三层 × 场景判层

**账 A 的套路 = 「先给评测集分胖瘦」**——把"评测集"从一团"很多题"拆成三层，每层管一段（§11.9①）。探针实测的规模·时机·成本表：

| 层 | 规模 | 时机 | 成本 | 回答的问题 |
|---|---|---|---|---|
| **冒烟 smoke** | **5-10** 条精选用例 | **每天 / 每次提交** | 秒级 · 免费量级 | 核心路径还活着吗 |
| **回归 regression** | **100-500** 条业务集 | **每周 / 每次改动** | 分钟级 · $0.1-$1 | 这次改动没把业务弄坏吧 |
| **大榜单 leaderboard** | **千级** 基准题 | **选型时** | 小时级 · $10+ | 该不该换底座模型 |

**三个量级各差一个数量级 = 纪律①的"为什么是三层"**：冒烟秒级所以每天跑（保底）；回归分钟级所以每次改动跑（§11.9③的载体）；大榜单小时级只在"要不要换底座"这种决策时烧（02 篇'大榜单选型时跑'）。

**5 场景判层（探针实测 5/5 PASS）：**

| 场景 | 判 | 为什么 |
|---|---|---|
| 改了 NL2SQL 提示词后怀疑流式路径断了，只想确认核心路径没被破坏 | **冒烟** | "核心路径还活着吗"就是冒烟的题 |
| 上个季度结束想换底座模型，需要重新选型 | **大榜单** | 换底座=能力层决策，只有大榜单给结论 |
| 换了 embedding 模型准备上线，想知道业务任务还能不能打 | **回归** | embedding 改变的是业务任务的答案，回归集是业务集 |
| 改了 chunk 大小，只改了检索那段 | **回归** | 改 RAG=改系统，回归集才覆盖检索→答案的整条链 |
| 每天早晨例行体检核心路径三件事（登录/问答/RAG） | **冒烟** | 例行体检就是每日冒烟的同义词 |

**判层口诀：大题（选型）上大榜单，中题（每次改动）上回归，小保底（每日体检）上冒烟。** —— 冒烟 5-10 / 回归 100-500 / 大榜单千级，三倍进账：规模、时机、成本三层递进，一个都不要混。

## 4. 实验 B · 固定环境账：四件套 × 每改一处只回跑该层

**账 B 回答两个问题：环境怎么固定（②）、改动了跑哪把尺（③）。**

**B1 环境固定四件套（§11.9②，01 篇环境固定四件套的纪律面）：**

| 件 | 缺了会怎样（探针实测 3 条缺件后果） |
|---|---|
| 同 prompt 模板 | prompt 一改，分数变的可能不是模型是措辞 |
| 同 temperature（**评测用 0**） | temperature≠0 而 judge 又敏感 → **同输入两次跑分不同=测的不是同一个东西** |
| 同 judge 版本 | judge 悄悄升版本 → **同 20 样本翻转 6 条=漂移 0.30**（03 篇账 C 的账面数字，锁版本是保命） |
| 同语料子集 | 子集换一批 → 前后跑的水不同=给平台白找背锅 |

**为什么四件套是"数据可比性"的地基：** 评测的本质是"前后两次数字能不能比"——四件套缺任何一件，比的都不是同一个东西。03 篇"锁版本"那课 6/20=0.30 的漂移，就是缺第二件的现报。

**B2 改动→最小回跑矩阵（§11.9③ 的"每次改动跑同一套回归"要跑哪一套的答案，01 篇账 C 五条规则挂靠，探针实测 5/5）：**

| 你改了什么 | 最小回跑哪层 |
|---|---|
| 改了 prompt 模板 | **任务层** |
| 换了底座模型 | **能力 + 任务** |
| 改 RAG 的 chunk / embedding / rerank | **系统层** |
| 改 Agent 的编排 / 工具 | **系统层评测台** |
| 动部署 / 切流式 / 换硬件 | **工程层** |

**这几条规则的价值 = 评测贵在刀刃上：** 换 embedding 只回跑系统层（chunk→答案的链），不必重刷 MMLU；换底座模型必须能力+任务一起跑（模型变了能力地基也变了，08 篇预算回归就是这么规定的）。**每改一处只回跑该层 = §11.9③ 的工程化**——不改模型却回跑了大榜单，是烧钱秀；改了模型只回跑冒烟，是裸奔。

## 5. 实验 C · 回流账：遥测回流 × 日志判定 × 锚点账

**账 C 回答最后一个"评测集从哪来"——线上遥测回流（§11.9④）。** 前九篇把回流这件事散着量了四回：06-Agent 遥测回流 4→204、07-安全 红队 4→50→54、08-工程 慢请求回注 100+8=108、09-可观测 最慢 8 条 trace→回归集。**本篇把它们收成同一条管道（探针实测）：采集（trace/日志）→ 判定（不满意/重试/纠错/慢）→ 标注（期望答案）→ 进评测集。**

**C2 5 条线上日志判定（探针实测 5/5，4 回流 1 不回）：**

| 这页日志 | 判 | 为什么 |
|---|---|---|
| 用户点踩了这条回答 | **回流** | §11.9④ 第一类：不满意 |
| 同一个问题被重试 3 次 | **回流** | 第二类：重试（不点踩也意味着没答好） |
| 用户明确说『你答错了』 | **回流** | 第三类：纠错 |
| 这条请求 P95 超了 SLO | **回流** | 慢请求是工程层证据（09 篇账 C4 同号，成本/延迟也要考） |
| 用户复制粘贴答案没动作 | **不回** | **无反馈=没信号，不制造样本** |

**回流判定的关键 = "用户反馈才是信号，静默不是"。** 点踩/重试/纠错是明确的"这题没答好"信号；复制粘贴没动作=用户满意（或没意见），不构成样本。**而慢请求也被算进回流**——评测集不是只有"答得好不好"，还有"慢不慢/贵不贵"（08 六把尺的题也在回流范围）。

**C3 锚点账（只引不重测）：** 探针把前九篇量过的四条回流号并排对账，4 条全 PASS：

| 锚点 | 数字 | 出自 |
|---|---|---|
| 慢请求回注回归压测集 | **100 + 8 = 108** | 08 篇账 D4 / 09 篇账 C4（同号） |
| Agent 评测集遥测回流 | **4 → 204**（+4 条线上样本） | 06 篇 |
| 安全红队回流 | **50 → 54**（+4 条红队样本） | 07 篇账 D |
| 可观测最慢 trace 回注 | 最慢 8 条 → 回归集 | 09 篇账 C4 |

**这四条号全部一致 = 遥测回流是同一根管线的不同口味：** Agent 回的是"任务成败样本"，安全回的是"越狱样本"，工程回的是"慢请求样本"——管道同一根（采集→判定→标注→进集），口味各不相同。**线上数据是评测集最该喂的活样本**（09 篇账 C4 那句：回归时永远看不见线上那 8 条的坑，本篇给治）。

## 6. 实验 D · 门禁账：每任务 vs 每 token × 门禁链 × 过闸

**账 D 篇末把五条纪律里的最后两条（⑤每任务指标 + 装配）钉成"评测是门禁"。**

**D1 每任务完成 vs 每 token 质量（§11.9⑤，06 篇账 D 挂靠复算，×23.8）：**

| | X 蔓胖 | Y 精瘦 |
|---|---|---|
| 烧了多少 | **10000 tok ≈ $1.50** | **420 tok ≈ $0.063** |
| 单轮打分 | 2.10（过程侧好看） | 1.70（过程侧难看） |
| **每任务完成** | **0/1 任务做成** | **1/1 任务做成** |

**用单轮打分（每 token 质量）看：X 赢；用每任务完成看：Y 赢——而总成本差 23.8×。** §11.9⑤ 给的裁决：**评价产品用每任务完成，不是每 token 质量**——X 是"蔓胖"（烧成蔓胖的 token 秀，任务没做成就是零成）；Y 是"精瘦"（六轮协作把它啃下来了才是真本事）。**过程指标拿到内部找瓶颈，产品指标交给老板看账本。**

**D2 门禁链四道闸（一次提交从开发到上线，探针实测时序）：** **冒烟 → 回归 → 安全 → 工程**

| 闸 | 什么过 | 前九篇的红线 |
|---|---|---|
| 冒烟 | 每日/每次提交 | 核心路径三件事还活着吗 |
| 回归 | 每次改动 | 05-RAG 回归闸线 GATE 0.80 · 06-Agent 回归台账 2/2 |
| 安全 | 上线前 | 07-安全 安全事件>0 不上生产（v1 acc 0.82 事件3 ⛔ / v3 acc 0.80 事件0 ✅） |
| 工程 | 上线前 | 08-工程 预算回归门禁 · 09-可观测 SLO 闸线 P95≤2200ms |

**四道闸时序固定 = 01 篇五层定界的装配顺序：** 先量功能（能力/任务/系统 在冒烟+回归），再量兜底（安全），最后量工程（部署上了还稳不稳）。**评测不是最终的报告，是开发流程的门禁**：门禁的立场是"不过不放行"，跟打分器的立场（打个分了事）完全不同。

**D3 5 个开发动作过闸（探针实测 5/5）：**

| 动作 | 该过 | 为什么 |
|---|---|---|
| prompt 文案微调 | **冒烟** | 只碰了话术，核心路径活着就行 |
| 换 embedding 模型 | **回归** | 改了检索+生成链条，业务集要重跑 |
| 漏斗里有安全事件 > 0 | **安全** | 红线永远是闸不是分：>0 不上生产 |
| 切流式架构 | **工程** | 部署形态变了，SLO/成本要看过不过 |
| 新模型选型 | **大榜单** | 决策性换底座，只有大榜单给结论 |

## 7. 这篇评测工程怎么用（一页带走 + 掌握度检验）

**一页带走——给你的系统按 §11.9 五条纪律装这套评测工程：**

1. **评测集分三层**（账 A）：5-10 条精选用例每日冒烟 · 100-500 条业务集每次改动回归 · 千级大榜单只在选型时烧——三个量级各差一个数量级。
2. **环境四件套固定住**（账 B）：同 prompt 模板 · temperature=0 · 同 judge 版本 · 同语料子集；judge 缺件=6/20 漂移 0.30，锁版本是保命。每改一处只回跑该层尺子（prompt→任务 / 换模型→能力+任务 / 改 RAG→系统 / 改 Agent→评测台 / 动部署→工程）。
3. **线上数据回流成考题**（账 C）：采集→判定→标注→进集；点踩/重试/纠错/慢请求回流，无反馈不回；锚点 100+8=108 / 4→204 / 4→50→54。
4. **评价产品看每任务完成**（账 D）：X 蔓胖 $1.50 烧 10000 tok 任务 0/1 vs Y 精瘦 $0.063 六轮 1/1——×23.8 的成本差，过程指标留在内部，产品指标给老板。
5. **评测当门禁不当报告**（账 D）：冒烟→回归→安全→工程四道闸时序固定，不过不放行。

**掌握度检验（读完自答）：**

1. "评测集有哪三层，各什么时候跑？"（冒烟 5-10 条每天/提交跑；回归 100-500 条每周/每次改动跑；大榜单千级选型时跑。账 A。）
2. "环境固定四件套缺一件会怎样？"（缺 judge 版本=同 20 样本翻转 6 条漂移 0.30——测的不是同一个东西。账 B1。）
3. "我改了 chunk 大小，该回跑什么？"（系统层——回跑 chunk→答案的整条检索生成链，不必刷大榜单。账 B2。）
4. "线上日志哪些该回流成考题？"（点踩/重试/纠错/慢请求 4 类回流，复制粘贴无反馈不回——用户反馈才是信号。账 C2。）
5. "产品上线前，评测要过哪几道闸？"（冒烟→回归→安全→工程四道，安全红线安全事件>0 不上生产。账 D2。）
6. "新模型选型该看什么指标？"（能力层用大榜单，但产品买单看每任务完成——蔓胖 $1.50 烧 10000 tok 任务 0/1 就是不及格。账 D1。）

## 8. 常见坑（做评测工程的 7 个）

1. **评测集一层到底**：只有"好多题"没有分层——冒烟回归大榜单一套题跑到底，慢的抱团快的也抱团。分三层、量级各差一个数量级（账 A）。
2. **环境没锁**：judge 版本飘=20 样本翻转 6 条漂移 0.30，前后数字对不上账（账 B1、03 篇锁版本那课）。
3. **一改动就重跑大榜单**：改 prompt 去烧小时级大榜单=烧钱秀；该回跑任务层就回跑任务层（账 B2）。
4. **改了模型不回跑**：换底座模型必须能力+任务一起跑——模型换了你以为的回跑找不到了（账 B2）。
5. **线上数据不回流**：用户点踩/重试/纠错/慢请求都当空气，评测集永远看不到线上那 20%——回流管道四步一搭就有（账 C）。
6. **把无反馈当信号**：复制粘贴没动作=用户没意见，不构成样本——只有明确信号（点踩/重试/纠错/慢）才回流（账 C2）。
7. **看每 token 打分下产品结论**：蔓胖 2.10 单轮好看但任务 0/1=零成，差 23.8×——产品买单看每任务完成，过程指标留在内部（账 D1）。

- **复习链 vs 重测**：账 A 三层规模·时机·成本、账 B 缺件后果与改动→回跑矩阵、账 C 回流管道与锚点号、账 D 门禁链四道闸 = **§11.9 五条纪律 + 01 篇五层定界的复习链——锚点数字（GATE 0.80·安全事件>0·P95≤2200ms·100+8=108·4→204·4→50→54·×23.8）一律挂靠前九篇探针 stdout 只引不重测**；每条锚点都能在对应篇探针里找到出处。
- **判定表 vs 真实评测**：5 场景判层、3 条缺件后果、5 条日志判定、5 动作过闸 = **作者按五条纪律预置的确定性判定表 + 本机确定性计算**（真实评测的"判"靠的是你的评测系统在 CI 里跑，不是规则机）。
- **本页不搭真实 CI 流水线**：全篇为纯 stdlib 三独立进程复现机制；真实"冒烟/回归/安全/工程"门禁 = 读者在自己 CI 里把本页四账的数字换成自家模型/评测集后的实操（账号需要联网 + 服务端，本机不实测）。
- **统计 = 本机确定性计算**：四账判定全 PASS（36 行 = 全 PASS，0 FAIL），stdout 三个独立进程 md5 恒一 `80809cd5a44c01bf89e732d6e75c96df`，墙钟 ≈0.000 s 仅进 stderr——不依赖随机种子、网络或第三方库。
- **边界不自留坑**：没有把五条纪律当本机实测（§11.9 纪律标『要素事实』、判定表标『作者预置』、锚点标『只引不重测』）；没有把锚点数字当新测（账 C3 四条回流号全部挂靠前九篇）；没有把判定表标成本机实测（标『作者按纪律预置』）；没有跳过『真实 CI 流水线=读者实操』的诚实边界。
