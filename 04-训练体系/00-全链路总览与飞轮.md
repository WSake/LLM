## 0. 为什么先把全图画给你

学完 `02-核心原理` 的 22 章，你手里有一大把**单独能打的招式**：预训练会把语料压成知识（`12`）、SFT 把续写掰成问答（`13`）、RLHF/DPO/GRPO 把"被喜欢/答得对"变成优化目标（`14/15/16`）、蒸馏跟 CPT 在算力和数据都不够时偷能力换水（`22`）。

但如果你现在就想"训练一个大模型"，会发现一个落差：**招式和产线之间隔着一条整合的河**。招式回答"这一步怎么做"，产线回答"这些步骤先后怎么串、每站吃什么数据、卡点在哪里、怎么让它循环起来"。多数初学者有第二个问题时会慌——不是因为难，是因为**没见过那张全图**。

本章把全图画出来：**一条五站流水线 `数据 → 预训练 → 对齐 → 后训练 → 评测`**。`04-训练体系` 目录的每一章，都是这张图里某一站的深挖；提醒自己"现在是图里的哪一站"，比记住任何单个 API 都值钱。

> 一句话（为什么有本章）：**流水线不缺招式，缺路标。你先拿到一张图，后面 10 章往里填细节，读起来才有坐标感。**

## 1. 一条流水线：五站通关

一条今天真实存在的训练产线，通常会走这五站（顺序在业界有微妙差异，但主干如此）：

```text
① 数据     采集/清洗/去重/配比 → 决定模型能力上限（数据墙时代的命门）
   ↓
② 预训练   万亿 token 上自监督猜下一个词 → 语言 + 本金周知识
   ↓
③ 对齐     SFT 掰成助手 → RLHF/DPO/GRPO 把"被喜欢/答得对"变成优化目标
   ↓
④ 后训练   领域 CPT / 蒸馏做成端侧版 / LoRA 低成本精调 → 专精与落地产物
   ↓
⑤ 评测     基准 + 人类偏好 + 门禁 → 决定"能不能上线"（不是事后报告）
```

**站①数据**：直接决定上限。`21-Scaling-Law与数据墙` 已量到数学模型统计胃口大约 10¹² token、而自然文本的统计分辨率有限——数据就是产线的天花板。这一站最难的不是"多"，是"干净 + 配比"：重复、脏、污染会把预算白烧（robust 证据：`13` 章多样数据 6/6 vs 重复数据 3/6，同预算同批数，**决定泛化的是数据多样性不是条数**）。

**站②预训练**：把语料变成参数里的规律。`12-预训练` 的 `pretrain_demo.py` 实测量到了一件最"便宜"的事——894 个 token 的语料一次错位就给出 893 个训练样本，零标注；同一个事实换 5 种写法入语料后，模型能在第 6 种全新句式上 6/6 续对，随机初始化对照 0/6。这一站的成本结构被 `21` 章的幂律锁住：参数幂律 N^-0.090、数据幂律 D^-0.164——**玩具里"先补数据"比"先加参数"更划算**。

**站③对齐**：预训练产物是"什么都会续写的脑袋"，对齐把它掰成"听话的助手"。`13` 章实测：16 万参数玩具 200 步 SFT，全新问法命中率 1/6→6/6；但 SFT 只能模仿金标准，于是 `14-16` 章再把"被喜欢"（RLHF 平均 RM 奖励 -5.2→+5.6、全新问三票 38%→67%）、"答得对"（GRPO 三票 38%→83%）搬成优化目标。

**站④后训练**：把通用模型变成自己的产品。三条主流：**领域 CPT**（`22` 章量到纯领域续训 114K 通用 eval 崩 1.8752→3.8913、回放 9:1 按住到 2.6992）、**蒸馏瘦身**（8× 小模型被教师软监督收回 35% 参数墙）、**LoRA 低成本精调**（冻结权重只训低秩增量，把微调成本降两三个数量级——这是 `04` 目录后面要细讲的）。

**站⑤评测**：不是最后跑个分，是**训练过程中的闸门**。`13` 章的"全新问法正确率"、`14-16` 章的"训练/全新两列"、`20` 章的"覆盖率 vs 投票"，全是把评测钉进训练的自检习惯。`04-训练体系` 的最后一篇专门讲"评测门禁"怎么当闸门用。

> 一句话（五站）：**数据设上限、预训练攒知识、对齐掰行为、后训练做产品、评测发通行证——顺序不能乱：给没预训练的模型做 SFT，就像给没上学的人出试卷。**

## 2. 五站各自的"数据"长什么样

流水线每站吃不同的数据，四张表先立住"数据质量决定上限"的直觉：

| 站 | 数据形态 | 一手要解决 | 仓库里量过的证据 |
|---|---|---|---|
| ① 预训练 | 海量网页/语料，去重去脏 | 覆盖 + 干净 | `13` 章重复数据只到 3/6 |
| ①' 合成 | 模型自己造的样本（含领域/推理） | 数据墙的"新水" | `22` 章教师/回放就是合成路 |
| ③ SFT | (指令, 金标准回答) 对 | 掰成对话 | `13` 全新问法 1/6→6/6 |
| ③ Preference | (好答, 坏答) 偏好对 | 教"更喜欢哪个" | `14` RM 留出判别 79% |
| ③ RL | 可验证题目/规则奖励 | 教"答没答对" | `16` 三票 83% vs 二值 0% |

三条要点，都是从已被实测的对照里长出来的：

1. **同一批原始材料，改造形态不同，训练目标就不同**——问答对喂给 SFT、偏好对喂给 RM/DPO、可验证题目喂给 GRPO。`04` 目录的 `03/04/05` 三章就是教"同一批问答怎么改造成三种形态"。
2. **数据多样性 > 数据条数**（`13` 章 6/6 vs 3/6），合成数据也不是"要多"而是"要覆盖 + 要质检"。
3. **最伤人的数据是"看似正确实则错的"**——`22` 章 B 段量过：教师文本（一种合成数据）无 logits 硬学 2.6655，比真数据 2.6230 还差。**合成数据的价值不在"多"，在"每一批都要能说清它为什么能教对"**。

## 3. 数据飞轮：流水线怎么自己转起来

五站是"一次训练"。真实产品里的版本是**飞轮**：让它转了一圈之后，自己能烧出下一圈的原料。

```text
模型上线 → 收集真实反馈 / 自动打分 → 筛选出高质量样本 → 训练下一代
              ↑                                        │
              └──────────── 更强的模型再上线 ←───────────┘
```

- **第一圈**：用现有模型（可以是强模型或已有模型）**生成**候选数据，然后靠**筛选**留质量——这是飞轮的灵魂。真实世界三条成熟打法（非本机实测）：**Self-Instruct**（种子指令 → 模型自写指令+答案 → 过滤 → 训练，2022）、**Evol-Instruct/WizardLM**（把简单指令一步步"演化"成复杂指令）、**ReST**（用 RL 验证过的输出回流成训练数据，闭环训练）。
- **飞轮和蒸馏/合成的关系**：`22` 章的定义在这张图里直接复用——**合成数据 = 给"新领域"换的水，蒸馏 = 把"密模型"浓缩成"端侧版"**；而飞轮正是这两件事的工业化循环版本。真实模型（如 Claude 的 RLHF、各家推理模型的 RL 数据）几乎都靠"模型产出+筛选"获得，因为人类写不出可验证推理题的规模。
- **飞轮失效的最常见方式**：只转不筛。第一圈生成的样本质量不稳，不筛选（或筛错）就喂回去，会一代代把错误当燃料——**飞轮烧的是"筛选出的质量"，不是"生成的体积"**。

> 一句话（飞轮）：**流水线是"一次做功"，飞轮是"做功的同时在产出下一次做功的原料"——而原料质量由筛选守门，不是由生成量决定。**

## 6. 常见坑

1. **把"总览"当"全部"**：本篇只有路标，没有配方。想复现任何一行数字，去对应章节按脚本一键跑；想学任何一站，去 `§4` 地图找那一章。
2. **把不同玩具的数字拼成"同一模型曲线"**：§5 旅程表是**全景拼图**，不是连续测量。写文章/做演示时引某行的数字，要对准它出处的脚本与口径（全新问 vs 训练问、分布级 eval vs 采样 eval），跨口径不并表。
3. **飞轮"只转不筛"**：合成数据流程里筛选是灵魂（`22` 章黑盒 2.6655 比真数据 2.6230 还差就是"未筛选的教师文本"的代价）。第一圈不设质量门禁 = 把噪声当燃料。
4. **跳过数据工程直接调参**：产线五站里"数据"是天花板（`21` 章数据幂律斜率近两倍、`13` 章多样性 6:3）。先问"数据干净吗、覆盖够吗"，再动模型——除非你只想在玩具上验证机制。
5. **把"上线 = 训练结束"**：飞轮视角下上线是新一轮训练的起点（反馈回流）。`04` 目录后面两个"工程章"（07 并行 / 09 精度）和"门禁章"（10 评测）共同决定了产线能不能长期转。
