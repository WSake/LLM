## 0. 为什么 RL 数据不是"存答案"，是"存裁判"

`13-SFT` 教模型"答得对"（03 章造的对）、`14/15` 章教"答得更好"（04 章造的偏好）、`16-GRPO与RLVR` 教"**赌对**"——RL 每一步都要给当前策略采出的若干个候选输出打分，然后沿"高分候选、离开低分候选"的方向更新。打分这件事，就是**奖励信号**。

`16` 章把它实测得很极端：同一份 SFT 起手（全新问 38% 三票）、同一个玩具，**GRPO-三票**（可验证奖励 r=0/1/2/3）跑到全新问 83%、KL 1.33；**换二值**（只有 r=3 → 1）只剩 10%/0%。两者唯一的区别，是"对/错"被拆成几档。所以 RL 数据侧的第一公理不是"有多少答案"，而是：

> **奖励函数的分辨率，直接决定 RL 学不学得动。** 数据五连前四篇都在问"造什么样本"，本篇从"造样本"切到"造裁判"——因为 RLVR 里样本是每个训练步现场采的，**真正离线造的是那把尺子**。

本篇三问恰好对应 RL 数据构造的三大旋钮：**粒度**（A 段：二值/接近度/分维三种打分）、**可信**（B 段：确定性与偷懒判据的假阳/假阴）、**取材带**（C 段：不同难度档的信息占比）。

## 1. 一站全景：三元流不给答案，给裁判

数据五连的五种数据形态：

```text
01 预训练：纯文本（无标签）                    ← 学分布
02 合成：   经质检的干净样本                   ← 学"可进池"
03 SFT：    (指令, 回答)                       ← 教"答对"
04 偏好：   (指令, chosen, rejected)           ← 教"更优"
05 RL：     (指令, 候选输出×N, 可计算奖励)     ← 教"赌对"
```

三处递进，是从"答案"到"裁判"：

1. **03 存答案，04 存对，05 存尺子。** SFT 数据里回答是最终资产；偏好数据里 (chosen, rejected) 是最终资产；RL 数据里**最终资产是奖励函数**——候选输出是训练时在采样循环里现场滚出来的（`16` 章实测：GRPO 每步在线采样 32 条），不可能像 03/04 那样先囤一库。离线能造、能验证、能审计的，只有 reward。
2. **偏好判"更"，奖励判"几分"。** `04` 章的 RM 学的是 pairwise 的"哪个好"；RLVR 的奖励学的是 pointwise 的"这答对了多少"。`04` 章 §4 的教训（RM 学长度捷径）在本篇升级：reward 的每一处"偷懒"，RL 都会顺着它卷。
3. **噪声定性不同。** 03/04 的噪声是**静态标错**（一条错样本教坏一个方向，可筛查）；RL 的噪声是**动态误判**（同一输出，reward 一段给高分一段给低分，梯度在抖）。所以 B 段质检的重点落在"确定性"和"正例必放行"。

> 一句话（形态切换）：**SFT 数据回答是资产、偏好数据对子是资产、RL 数据唯一值得囤的是"能算分的尺子"——尺子造错，在线采多少候选都是按错的方向喂。**

## 2. 怎么构造：把"答对没有"翻译成可计算函数

"可验证"的本质是**任务自带真值**：数学有标准答案、代码有测试用例、SQL 有执行结果、多选题有选项。真值在手，奖励函数就是把"候选输出 vs 真值"的比较翻译成数字。翻译有三个自由刻度，本篇 A/B/C 每段测一个：

| 旋钮 | 问什么 | 本篇实测段 |
|---|---|---|
| **粒度** | 全对才 1 分，还是错 1 和错 300 要分三六九等？ | A 段（V1/V2/V3） |
| **可信** | 判据会不会把错答案放行（假阳）、把对答案误杀（假阴）？ | B 段（确定性 + 两类偷懒判据） |
| **取材带** | 数据该落在哪个难度档，reward 才有信息？ | C 段（易/中/难信息占比） |

工业界最常见的构造不是单点 0/1，而是**多条规则加权**：`DeepSeek-R1` 在用"正确性 + 格式"两条规则给分（答对一维、思考段/最终答案格式一维）——这正对应 `16` 章 §6 那句"把对/错拆成部分学分"。这个做法在原理层已被 ch16 实测（三票 vs 二值差 83pp），本篇只给"数据侧的那把尺子怎么设计、怎么验"。R1 的具体权重与线上实现**非本机实测**，本篇引它只是为了说明：**真实的可验证奖励是拆开的、加权的，不是一拍脑袋的 0/1。**

构造的三条底线（后续小节逐条给实测）：

1. **粒度条**：reward 必须能给"对、半对、错"至少三档，否则就是 ch16 的二值臂（10%/0%）。
2. **正例条**：判据对"真正的正确答案"必须放行。偷懒可以放水（假阳性伤的是别处），**误杀正确答案（假阴性）会让 RL 把正确输出当负样本压下去**。
3. **确定性条**：同一输出在哪步跑都得是同一个分。规则函数天然如此，LLM-as-judge 不是（见 §4 ①）。

## 3. 奖励函数构造实测：粒度=档数，2 vs 76（A 段）

`rl_data_demo.py` 的 A 段：60 道两位数乘法（21–45 × 2–9），每道用固定种子模拟策略采样 4 个候选（精确命中/近失/中程/远错四态），对同一批 240 个输出跑三种奖励函数，看它们能表达几个分数档：

| 奖励函数 | 一句话 | 240 输出上的分数档数 | 信息样本占比 |
|---|---|---|---|
| V1 二值（精确匹配才 1 分） | 对=1，其他=0 | **2**（{0,1}） | 90.0% |
| V2 数值接近度（partial credit） | 越近真值分越高 | **76**（连续折线） | 91.7% |
| V3 分维（|差|≤10 → 半对） | 半对/对两档 | **2**（{0.5,1}） | 80.0% |

看一道真实题就懂"档数"是什么：

```text
39×2=？  真值 78，候选 [78, 63, 55, 77]

V1 二值：      [1.0, 0.0, 0.0, 0.0]
     ← 63、55、77 全是 0 分。模型看不出"77 快对了，55 差得远"。
V2 接近度：    [1.0, 0.81, 0.71, 0.99]
     ← 越接近真值越接近 1：77 拿 0.99，63 拿 0.81，55 拿 0.71——错的程度被保留。
V3 分维（±10）：[1.0, 0.5, 0.5, 1.0]
     ← 把候选压进 {0.5, 1.0} 两档，只留下"在不在 ±10 内"。
```

三个数对应 `16` 章那句"**奖励密度是最凶的旋钮**"的数据侧样子：

- V1 的 2 档不是"严格"，是**信息量丢尽**。RL 靠"离开低分、靠近高分"的梯度更新；V1 下 63（偏 15）和 55（偏 23）没有区别，模型收不到"77 这条路比 55 这条路值得走"的信号，只能盲试"整段答案恰好全对"。这正是 ch16 二值臂 0% 的来源。
- V2 的 76 档是"折线"：错误也留梯度，RL 每走一步都知道"往真值方向挪，分在涨"。ch16 的三票（0–3 四档）是它的离散薄版，已经能让全新问 38→83%。
- V3 是刻意示弱的"半对窗口"：信息样本 80.0%（低于 V1/V2 的 90%+），因为它把"半错"压成一档，中间地带的信息又被吃掉一部分。
- 信息样本占比 = 单题 4 候选间 reward 标准差>0 的题比例（reward 全恒零=这题怎么答都一个分=没梯度）。三版在中档都高，因为中档候选"有对有错"——**难度恰好让"半对"能出现**，这正是 C 段取材带的核心。

> 一句话（A 段）：**奖励的粒度是 RL 数据的"坐向盘"——二值只有 2 档，把"错 1"和"错 300"判成同罪；连续折线留 76 档，错误里每一步都有方向。档数不是"越严越好"，是"能给 RL 留多少渐进的学分"。**

## 4. 奖励质检：确定性 100% 与假阳/假阴象限（B 段）

奖励函数是"造"出来的尺子，就得质检。B 段对同一批 240 个候选（真值判对 136、判错 104）跑三项检查：

**① 确定性：规则函数同输入必同输出，确定性 100%（构造保证）。**
`r_v1/v2/v3` 都是无随机状态的纯函数：同一个候选在任何一步、任何一次运行里回报同一个分。本机三遍运行科学数字逐位一致（只有墙钟 20/21/18ms 浮动）就是这点的实证。对照下来，**LLM-as-judge 的游移是 RL 数据的头号毒药**：同一输出这次 judge 打进 0.9、下次打进 0.4，RL 的梯度在抖，学的是"裁判的心情"而不是"答得对"（judge 游移为业界常态，**非本机实测**，本靶场只展示规则函数的确定性一面）。

**② 偷懒判据的假阳性/假阴性：判据不是内容，是代理。**
构造两类"偷懒判据"，量化它们的放行/误杀：

```text
偷懒① 只查末位：c 与真值末位相同（模 10 同余）就放行
      判对 136 / 判错 104 → 假阳性 4 · 假阴性 0
      假阳性率 3.8%（4/104）：错答案末位撞车被当对的放行

偷懒② 只认 ≤99：答案超 99 一律不信任
      判对 136 / 判错 104 → 假阳性 34 · 假阴性 104
      假阴性率 76.5%（104/136）：正确答案因为"超 99"被全杀
```

两组判据暴露两半象限：

- **假阳性（错答案放行）**：偷懒①的 4/104 = 3.8%。错答案被当对的放行，损失在"噪声"。放行率低时 RL 尚可忍受——它收不到"这是错"的负信号，但至少没把对的往下压。
- **假阴性（对答案误杀）**：这正是偷懒②的灾难——**104 个真值正确的候选，因为答案数值超过 99 被全部判 0 分**（中档题真值 42–405，超 99 的占比就是 76.5%）。RL 看到的是"正确答案=0 分的低reward"，于是把正确的输出当成要远离的样本往下压。**训练方向整个反了**，而且越训越对。
- 一句话判据底线：**判据可以偷懒（假阳性），但正例必须放行（假阴性必须为 0）。** 任何"格式先决条件"（必须 ≤99、必须是偶数、必须是指定长度）如果会误杀真值，就是给 RL 的正确答案扣分。

> 一句话（B 段）：**奖励质检三件事——规则函数确定性 100%（构造保证）所以可复现；偷懒判据的假阳性只是放水该防，假阴性（对答案误杀率 76.5%）是反噬，会把训练方向整个打反。判据写错一行，RL 就在往反方向飞。**

## 5. 难度配比：信息带在山口（C 段）

A/B 段造尺子、验尺子，C 段回答"**这道题该不该进 RL 池**"。同一把 V1 二值尺、同一种候选生成，只在题的难度档上动手（易：9–20×2–3，命中率高；中：21–45×2–9；难：90–99×6–9，命中率压到 0.08），量各档"信息样本占比"：

```text
易 档 40 题 → 信息样本 30.0%  近乎全对，reward 饱和=没梯度
中 档 40 题 → 信息样本 92.5%  中间带，reward 抓得住
难 档 40 题 → 信息样本 15.0%  近乎全错，reward 恒定=没梯度

均匀三档混批 46.7% → 只取中档 92.5%（+45.8pp，取材搬向信息带）
```

一条山口曲线：两头塌、中间隆。

- **易档（30%）**：候选几乎全对，reward 几乎全 1——样本没梯度。RL 在这批上"什么都学不到"，纯浪费采样预算。加再多数据也如此，reward 不对难度露出任何口子。
- **难档（15%）**：反面版——候选几乎全错，reward 几乎全 0。RL 只知道"这些都错"，不知道"哪个更可取"，同样没梯度。**全对和全错在 RL 数据里是同一种病：reward 恒定 = 没信息。**
- **中档（92.5%）**：候选里有对有错、有近有远，reward 有差——RL 每步都收到"往哪边挪分在涨"。信息带正在山口。
- 重采样对比：均匀三档混批信息样本只有 46.7%，**把取材搬向中档能提升 45.8pp**——同一模型、同一尺子，Data Mixer 一换，可学样本几乎翻倍。

这与前面三处对账是**同一条"中间带才有信息"哲学**：

1. `02-核心原理/21-Scaling-Law与数据墙`（数据墙实测：8K 池预算翻倍 best eval 只动 0.003）——为什么预算翻倍没用？因为多出来的预算堆在"模型已经学完/学不动"的样本上，**无信息样本再翻倍也是零**。RL 数据集同样：往易/难档灌数据，信息占比反而被稀释。
2. `01-预训练数据工程` C 段 token 配比（按 token 预算重采样）——配比决定"信号落在哪"，RL 数据把这条升级成"按信息占比取材"。
3. `16` 章实测"三票 83% vs 二值 0%"是**训练侧**的粒度；本篇 C 段是**数据侧**的取材。两者合起来才完整：尺子要有档（粒度），题要在山口（取材），RL 才学得动。

> 一句话（C 段）：**RL 数据取材不吃"全对率"也不吃"难度"——吃"reward 信息占比"。全对和全错都是没梯度的同义词，信息带在山档。取材搬向中档，同一池子的可学样本 +45.8pp。**

## 6. 常见坑

**① 把 RL 数据当离线答案集囤。**
03/04 是离线集，05 是"离线造尺子 + 线采样流"。RL 每次更新都要采一批候选，reward 必须能跑进采样循环。真值一直在的简单任务可以一次性生成候选囤着（flip 精化），环境交互型任务必须在线。判断标准：**你的 reward 能不能在采样那一刻调用？不能，就换规则式。**

**② 判据假阴性不归零。**
B 段偷懒②的对答案误杀率 76.5%——判据带了"格式先决条件"（≤99/必须偶数/指定长度）却不验证先决条件对真值成立。落地自查：把 100 条正确答案过一遍判据，假阴性必须为 0；有任何 1 条正确答案被扣分，RL 就会把正确答案当负样本往下压。

**③ 用全对率挑题。**
C 段易档"全对率最高"，信息样本却只有 30%。挑 RL 题的正确指标是"这道题 4 个采样候选的 reward 标准差>0 吗"——统计上就是信息占比，不是正确率。

**④ 二值奖励当"更干净"用。**
VC1 档数 2 vs V2 档数 76，满差 74 档；`16` 章实测二值臂全新问 0%。"答对了给钱、没答对不给钱"听着干脆，实际上把"半对→对"的渐进学分全删了。至少拆三档（错/半对/对），工业界拆到"正确性+格式"两维加权。

**⑤ judge 打分直接进 RL 循环，没查确定性。**
LLM-as-judge 打分在同一输出上会游移（业界常态，**非本机实测**），RL 梯度在抖。落地方案：规则可验证任务用规则函数（确定性 100%）；规则盖不全的场景，至少在进 RL 前对 judge 做一致性复测，把游移大的题剔除。

**⑥ ±1 当"对"处理成满分。**
B 段候选里的"近失"（真值 ±1）在 V1 精确匹配下是 0 分——差 1 和差 300 同罪。V2/V3 才不会把它误杀。如果你的领域"差不多就行了"，奖励函数就要把"宽容窗口"做进去（V3 的 ±10 就是示例），而不是假装精确匹配代表严谨。
