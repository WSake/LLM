## 0. 为什么全参微调在 7B 上是笔显存账

`13-SFT`、`14/15/16` 章的所有引擎都在 0.18M 参数上随便全参跑——0.18M 参数的权重加优化器状态还装不满一个注释变量。可一旦换个真实规模，**同样"梯度下降"四个字，先开口的是显卡容量**：7B 的权重（fp16）就要 13 GiB，而训练时每个参数还要陪跑一份梯度和两份 Adam 状态。全参微调 7B 的内存账（A 段实测口径）= **78 GiB**，这还不算激活值。

`07-GPU` 章已经教过读模型：先看“每参数 12 字节”这几个字。本篇把这条账从"算得出来"推到"省得下来"：LoRA 凭什么能省？本篇的答案是本机实测的低秩谱——**Full 微调收敛后的更新 ΔW，99.9% 以上的谱能量集中在前几个奇异值（本例 3 个）**。模型自己想改的方向本就不多，LoRA 就把"可训练参数"限制在这些方向的张成空间里，于是梯度/优化器状态只需为这极小一部分参数记账。

> 一句话（为什么有本篇）：**全参微调的问题不在"准确率"，在"每参数 12 字节"这道乘法；LoRA 的底气不在理论，在 ΔW 的谱实测——先量出更新是低秩的，再谈省显存。**

## 1. 一站全景：全参四件套 vs PEFT 两件套

一次标准的全参微调，显存被四件套瓜分（A 段账本逐项在 §3）：

| 显存件 | 每参数字节 | 7B 规模（GiB） | 谁的活 |
|---|---|---|---|
| 模型权重 | 2（fp16） | 13.0 | 前向 + 反向都要用 |
| 梯度 | 2（fp16） | 13.0 | 反向算一次、更新用完即弃 |
| 优化器一阶矩（Adam m） | 4（fp32） | 26.1 | 跨步记忆 |
| 优化器二阶矩（Adam v） | 4（fp32） | 26.1 | 跨步记忆 |
| **合计** | **12 字节** | **78.2 GiB** | 不含激活 / 中间量 |

PEFT 的思路只有一句：**权重动不了（或不想动），所以梯度与优化器状态也不需要为全参准备——把它们只记给"真正要动的子集"。**

```text
全参微调   : 权重 13.0 + 梯度 13.0 + Adam 52.2 = 78.2 GiB
LoRA       : 权重 13.0（冻结）+ 每层 B·A 少量可训练参的梯度/Adam ≈ 0.02 GiB
QLoRA      : LoRA 之上把冻结权重压成 4-bit（NF4）≈ 3 GiB 级（量化落地属业界，非本机实测）
```

这就是本篇三段的骨架：**A 记账（78.2 GiB 怎么来）、B 问凭什么低秩行得通（ΔW 谱）、C 问秩给到哪够（自然秩刻度）**。

> 一句话（形态切换）：**全参微调给"每一个参数"都留一份梯度一份优化器状态；LoRA 只给"刚想改的那一小撮参数"记。省下来的量级差异，看 §3 的账。**

## 2. 怎么构造：本篇为什么用秩-3 合成任务

真实模型的 ΔW 是否低秩，业界有观察但**线上不可直接测量**（拿不到更新前后的完整权重分奇异值再对账的算力）——所以在玩具里我们直接把"真值更新"设计成已知秩（r=3），一量便知。

合成任务的构造（`peft_ft_demo.py` 段 0）：

```text
d = 32（输入输出维度）
ΔW* = U·Vᵀ，其中 U、V 各取 3 个正交随机列 → ΔW* 的奇异值 = [1, 1, 1]（自然秩 3）
目标 Wt = W0 + ΔW*，W0 = I（单位阵，即"微调的起点"）
数据 X ∈ ℝ^{256×32} iid 正态，标 Y = X·Wt
```

为什么这个任务能同时撑起 B、C 两段：

1. **真值谱已知**：ΔW* 只有 3 个非零奇异值。Full 微调如果"学得对"，收敛后的 ΔW 也应几乎落在这个秩-3 子空间里——于是"模型自己学低秩"变成可对账的实测（B 段：前 3 奇异值谱能量占比、σ₄/σ₁）。
2. **自然秩可从真值读出**：这个任务的最佳秩-2 逼近（r=2）会留下 ~1/3 的残差（第三维没法表示），r≥3 后逼近就零残差。于是"秩给到哪够"变成一条曲线（C 段：r=2 欠参 vs r=4/8 够）。
3. **参数可数**：Full 可训练参 1024（32×32），LoRA r=4 只有 256（r×d×2）——省 75% 的同时，基准对齐全可量化。

> 一句话（构造选择）：**真实任务的"自然秩"看不见，合成任务把它写成题目的一部分——真值谱=3 是阅卷答案，Full 学出来的谱对得上，LoRA 学出来的谱也对得上，低秩成立的证据就落在纸上。**

## 3. 全参微调显存账本：12 字节/参数，7B=78 GiB（A 段）

`peft_ft_demo.py` 的 A 段把 7B 账完整摊开（**账算口径，本机不训 7B**，来自第 1 节那张表；GiB 按 2³⁰ 计，与 `07-GPU` 章同口径）：

```text
[A] 全参微调显存账本（7B 账算）
    模型权重 fp16      2 字节/参数 →   13.0 GiB
    梯度 fp16         2 字节/参数 →   13.0 GiB
    AdamW 一阶矩 fp32  4 字节/参数 →   26.1 GiB
    AdamW 二阶矩 fp32  4 字节/参数 →   26.1 GiB
    ────────────────────────────────────────────
    全参微调合计      12 字节/参数 →   78.2 GiB（不含激活/中间量）
    LoRA（r=8、每层 65,536 可训练参、32 层）：梯度+AdamW 状态 ≈ 0.01 GiB
        → 全参 ≈78 GiB vs LoRA ≈13+0.02 GiB；4-bit NF4 量化主权重再压到 3 GiB（QLoRA，非本机实测）
```

三处记账要点：

- **权重只占 1/6**：13 GiB 的权重只是 78 GiB 里的零头。全参微调不吃在"存模型"，吃在"为每个参数存优化器状态"（52.2 GiB，占 2/3）。这就是为什么 LoRA 的收益巨大——它把 Adam 两矩从"全参"切到"只记可训练子集"。
- **LoRA 增量可忽略**：r=8、一层 d=4096 的线性层，可训练参数 = r×d×2 = 65,536；32 层合计的梯度 + Adam 状态只有 0.01 GiB 量级。代价是冻结权重仍占 13 GiB（推理也要背这份账）。
- **QLoRA 再砍一份权重存储**：把冻结权重压成 4-bit（NF4）→ 13→3 GiB 级。它是"两层偷"：LoRA 偷掉优化器/梯度，QLoRA 偷掉权重存储。量化与反量化实现属业界做法（bitsandbytes NF4/double-quant/paged-optimizer），**非本机实测**，本章只在账上演示。

> 一句话（A 段）：**全参微调的 78.2 GiB 里，67% 是 Adam 优化器状态、17% 是权重、17% 是梯度；LoRA 让"优化器+梯度"只给可训练子集记账，QLoRA 再把权重压成 4-bit——省的全在"不重要的那几件"。**

## 4. 低秩谱：Full 学出的更新本来就低秩（B 段）

账本说了"LoRA 为什么省"，本节是"LoRA 凭什么能省而不丢能力"。核心量：**Full 微调收敛后 ΔW 的奇异值谱**——Full 有全部 1024 个自由维，它"有权"把更新铺成满秩，实际学出来是什么形状？

`peft_ft_demo.py` B 段实测（Full 用最小二乘闭式解 = 满秩最优基线）：

```text
[B] Full 微调收敛后 ΔW 的奇异值谱（它有权学满秩，实际只学到 3 维）
    前 3 奇异值谱能量占比 100.0% · σ₄/σ₁ = 2.62e-15
    → 模型自己学出的更新是低秩的（谱偏置）

    LoRA r=4：相对 MSE 1.5e-16 · Full 1.3e-15（同进机器精度）
         ΔW 与真值对齐 cos(ΔW_lora, ΔW*) = 1.0000（Full 1.0000）
    可训练参数 1024 → 256（-75.0%），且只记这些参数的梯度/优化器状态
```

两个读数：

1. **谱能量塌进前 3 维**：σ₄/σ₁ = 2.62e-15，即第四个奇异值只有第一个的 10⁻¹⁵ 倍。Full 用满秩自由度和同样的数据，学出来的更新**依然只铺在前 3 个方向**——这就是"谱偏置"的实测形态：梯度下降天然喜欢先动少数大方向。LoRA 把更新锁进"秩 r 子空间"，掐的正是这个谱。
2. **r=4 的对齐度满格**：LoRA 的 ΔW 与真值 ΔW* 的 cosine = 1.0000，与 Full 一模一样（Full 也 1.0000），相对 MSE 同进机器精度——**可训练参数 -75%，任务层面一个子集的损失都没有**。因为子空间把"要改的方向"包住了。

> 一句话（B 段）：**Full 微调有权学满秩，实测却把 100.0% 的谱能量压进前 3 维（σ₄/σ₁=2.62e-15）——模型自己学低秩，LoRA 的低秩就是在为这个天然稀疏付费，而不是"近似妥协"。**

## 5. 秩的刻度：跌到自然秩就够（C 段）

低秩成立不等于随便给个 r 就行——**秩也有刻度**。同一任务把 LoRA 的 r 从 2、4、8 换成各种档位（自然秩=3）：

| 秩 r | 相对 MSE | 读法 |
|---|---|---|
| r=2 | 1.68e-01 | **欠参**：秩不够跨出三维，第三维方向完全表达不了，残差 ~1e-1 |
| r=4 | 1.53e-16 | 够用：更新稳稳包进秩-4 子空间 |
| r=8 | 1.17e-16 | 够用：再多一倍的秩，MSE 也没再降（都一样是机器精度） |
| Full | 1.29e-15 | 满秩基线：额外 1024 维零性价比 |

结论很干净：**r 踩到任务自然秩（3）就喂饱了**。r=2 差一个维度就多出 10⁻¹⁷ vs 10⁻¹ 的鸿沟；r=8 把秩翻倍，MSE 纹丝不动（1.17e-16 vs 1.53e-16）——多出来的 256 个可训练参数同样只吃优化器状态，却没贡献任何任务增益。

把这条映射到真实场景（**非本机实测，仅"秩要踩到任务内在复杂度"的类比**）：SFT/偏好微调在一类任务的更新块上，能容纳的语义量远低于全秩容量，所以实践中 r=8~64 已是常见区间，而全参微调试图表达的全部 1000+ 维里，绝大多数维度的梯度长期近零——这正是 §4 谱的事实。

> 一句话（C 段）：**秩不是越大越好，是"够任务的自然秩就好"——r=2（差一维）掉到 1.68e-01，r=4/8（够）都进机器精度；多给的秩付了优化器状态的账，换不回 MSE。挑 LoRA 秩就是找"任务自然秩"的刻度，不是盲目加码。**

## 6. 常见坑

**① 把 LoRA 当"更省版本的微调"，忘了它省的是账、不是能力。**
LoRA 在秩够的场景（SFT/领域偏好）几乎不损质量（§4/§5 实测：r≥4 贴机器精度），但在需要"大规模重组知识"或模型更新本身高秩的场景会碰壁——不要拿"省了 75% 参数"当"应该和全参一样好"的通行证，先在你自己任务上扫一次 r。

**② 秩给得脱离任务复杂度。**
r 太小欠参（本机实测 r=2 就差了 10¹⁵ 量级）、r 过大浪费优化器显存。合理动作：扫 r∈[2,8,32,64] 看 eval 饱和点，取"刚喂饱就收手"的那档（§5 就是演示）；别从 64 起步一刀切。

**③ 忘冻结原权重 / 忘把 B 从 0 起步。**
LoRA 的语义是"W 冻结 + ΔW=B·A"。A、B 初始化必须保证起点 ΔW=0（本脚本惯例 A=0/B 随机，或反之），否则微调前的输出分布就已经被破坏；一起反传的是"假 LoRA"（实际在训一整片非线性残差）。

**④ 把 QLoRA 的"省"理解成省计算。**
4-bit 只是省权重存储（13→3 GiB），NF4 反量化到 fp16 前向照常在跑（甚至多一层解包开销）——账上它解决的问题是"模型装不装得进显存"，不是"跑得快"。（量化实现非本机实测。）

**⑤ 显存账只算权重。**
回到 §3 的教训：7B 全参微调的 78.2 GiB 里 67% 是 Adam 状态。报显存需求永远按"权重+梯度+优化器"三本账相加（再容激活与中间量），"13 GiB 的模型"并不等于"13 GiB 能训"。

**⑥ 用 LoRA 直接套所有层，不做靶向。**
不是每层都值得注入适配器：大量注意力/FFN 层更新天然低秩的话，rank 分摊（某些层 r 大、某些层 r 小）比每层均匀给一份优化器显存更合算；真实部署可以做"目标层筛选"（哪些层任务相关性最高）。玩具里我们只演示了"子空间够用"，目标层筛选属工程调优，非本机实测。

## 7. 衔接下一章：训练并行的显存分摊

单个卡装不下 78 GiB，两个省法：PEFT 把训练状态变薄（本篇）、**并行把状态摊到多卡**（下一章）。这周 `07-训练并行-DP-ZeRO-FSDP-TP-PP-SP-EP`（§17.3.6）要回答：DP 被梯度同步卡住的通信账、ZeRO 把它切散的预算账、FSDP 的"分片在哪一层生效"——显存账本的复用恰好收敛在一个问题上：**PEFT 和并行可以叠加**（LoRA 把每卡状态变薄，ZeRO/FSDP 再把薄状态摊匀），两者同款账本的直观是为什么它们是一对好搭子。

`04-训练体系` 的递进也从"怎么造数据（01-05）→ 怎么喂进模型（本篇）"进入"多卡怎么一起喂"。
