## 0. 为什么数据是训练的第一站而不是第一个决定

`04-训练体系/00-全链路总览与飞轮` 把训练拍成五站，第一站就是数据。这一站的特殊之处在于：**它的上限不是一个方法决定的，是整个产线的天花板**。`21-Scaling-Law与数据墙` 已经量到两件底层事实：

1. **数据端幂律 D^-0.164 的斜率几乎是参数端 N^-0.090 的两倍**——在玩具世界里"往数据里砸预算"比"往参数里砸预算"更划算（`21` 章 A/B 段实测）。
2. **模型统计胃口约 10¹² token，自然文本的统计分辨率有限**——数据墙来了。而墙的位置由**池子里的信息量**决定，不是由池子的字节数决定：同一池子循环训练会在"池的统计分辨率"处直接撞墙。

所以数据工程回答的根本问题不是"怎么把文件搬进内存"，而是**"怎么让你认为的 corpus 约等于真实的统计分辨率"**——爬下来的字节里有噪声、有重复、有配比失衡，这些东西不删，你烧的是换算力买到重复信息。本篇用一个小型爬池把四步**各量一遍**：粗爬 104 条里，最后能进训练池的只有 43 条、token 只剩 **43.0%**。

> 一句话（为什么有本章）：**别急着加数据，先看看你"以为"的数据里有多少是真信息。清洗决定你到底喂了多少个有效 token。**

## 1. 一站全景：爬取 → 清洗 → 去重 → 配比

一条真实的预训练数据线通常四步（本篇第 2~4 节各有一份实测）：

```text
联网爬取 (Common Crawl 级别)
   ↓ ① 爬取本身：指纹/内容类型/语言识别，把 PDF、图片、JS 挑出去
清洗与质量过滤 ------------ 删"不能教的"：超短、乱码、HTML 残留、广告、重复堆砌
   ↓ ②
去重 ---------------------- 删"已经教过的"：跨页面近重复（新闻转述、模板站）
   ↓ ③
配比/采样 ----------------- 按知识意图定比例：网页/教科书/代码/多语/数学
   ↓ ④
最终训练池（tokenizer → pretrain）
```

顺序有讲究：**先滤噪再去重**（噪声会让"相似度"失真）、**先清洗再配比**（配比按"干净 token"算）。本篇演示脚本 `pretrain_data_demo.py` 用 104 条微型爬池把 ②③④ 三步各量一遍；① 爬取为止步于脚本之外，因为爬取是工程不是算法（真实第一步是尊重 robots.txt 与版权，这里只给路径不跑网）。

## 2. 质量过滤：先把"不能教的"删掉（A 段实测）

### 2.1 粗爬池长什么样

脚本里汇编了一个 104 条 / 1414 token 的"粗爬池"，标注来源以便算账：

| 类别 | 条数 | 说明 |
|---|---|---|
| clean | 40 | 干净的中文常识句 + 英文知识句（应保留） |
| neardup | 30 | 干净项的近重复变体（程序化生成：换字 / 插空格 / 截断，应被 B 段去重删掉） |
| noise | 34 | 真实网页三类垃圾（HTML 残留 2、超短 2、纯符号 10、连续重复堆砌 10、混合乱码 10） |

### 2.2 四条启发式规则与实测命中

| 规则 | 判据 | 概念对应（真实做法） | 本池命中 |
|---|---|---|---|
| 太短 | token < 6 | 长度过滤（min len 基线） | 17 |
| 有效字符占比低 | 汉字/字母/数字 < 50% | 语言熵/字符集检查 | 0 |
| 连续重复堆砌 | 连续 >=4 字符的 run 覆盖 > 40% | 去"啊啊啊啊""------" | 10 |
| HTML 残留 | 含 `<` `/` `>` | 标签剥离与过滤 | 7 |

**A 段实测输出**（脚本原文）：

```text
[A] 质量过滤          剩 70/104 条，token 1414→1077
    删除分类: {'high_repeat': 10, 'too_short': 17, 'html': 7}
    垃圾召回率（noise 被删 34/34）: 100.0%
```

- 34 条噪声**全部**被规则命中，40 条干净与 30 条近重复**一兵未损**（`clean kept=40`、`neardup kept=30`）——质量过滤只删"不能教的"，把"能教的"留给去重。
- token 1414 → 1077，第一刀砍掉 **23.8%** 的噪声字节。注意"html:7"里不止真 HTML：三条规则有重叠，`<` `>` 也出现在部分混合乱码里——**规则之间的截胡是常态**（见 §6 坑 2：low_valid 在本池为何 0 命中）。
- **诚实声明**：垃圾召回率 100.0% 是构造保证——脚本把每种噪声设计成至少命中一条规则，真实爬虫池永远达不到 100%（乱码会伪装、广告会穿长文本）。本篇报"100.0%"是告诉你**规则集与噪声集对齐时能达到什么效果**，不是真实召回率的承诺。

### 2.3 为什么"连续重复"要用 run 而不是全局限频

本脚本最早的 `repeat_ratio` 用**全局限频**（某字符出现 >2 次就计）——结果干净英文句全部误杀：`the nervous system transmits signals…` 里 t/s/e 天然高频，heavy/len >0.4。改用**连续 run>=4** 后健康句子归零、`"啊啊啊…"(40 连)` 归 1.0。这条踩坑值得记住：**真实工程的启发式看似是"阈值"，实则是"对什么形态敏感"的选择；阈值错、形态也对不上。**

## 3. 去重：把"已经教过的"删掉（B 段实测：n-gram → MinHash → LSH）

### 3.1 问题：一篇文章重复 10 遍，模型还是只学了一遍

预训练语料的重复比噪声更隐蔽也更毒：转述、模板站、新闻聚合会把同一事实以 90% 相似度复制 N 遍。**每一次重复都在吃掉 token 预算，却不增加统计分辨率**——这正是 `21` 章数据墙的机制在数据侧的镜像。逐对比较 100 亿文档不现实，真实做法是三步：

```text
n-gram 特征 → MinHash 签名（固定长度指纹） → LSH 分桶（只比可能近似的对）
```

### 3.2 三步原理（脚本里的实现）

- **字符 4-gram**：`norm[i:i+4]`，先去掉空白与标点（让"黄 河发 源"能对上"黄河发源"）。一个文档 = 一组 gram 的**集合**。
- **MinHash 签名**：给全集每个 gram 分配 K=64 个随机权重（列），文档签名 = 它的 gram 集合在每一列的最小权重。两文档签名相同的列数 ≈ 它们 Jaccard 相似度（Broder/MinHash 的随机权重实现）。
- **LSH 分桶**：把 64 维签名切成 B=16 个 band、每 band R=4 行；同一 band 内签名完全相同的文档进同一桶 = "候选近似对"。理论召回阈值 ≈ (1/B)^(1/R) = (1/16)^0.25 = **0.5**——只对 Jaccard ≥ ~0.5 的对花力气。

### 3.3 B 段实测输出

```text
[B] MinHash+LSH 去重   候选对 30 对，过 Jaccard≥0.6 阈值 27 对
    近重复变体被删 27 条：token 1077→608（省 43.5%）
    被候选对里 Jaccard 中位 0.89 · 最大 1.00
```

- LSH 从全部 1225 个文档对里只挑了 **30 个候选对**（~2.4%）交二次确认，二次确认用真 Jaccard（集合精确算），`≥0.6` 判重复 → 27 对坐实。
- 30 个近重复变体被删 **27 条**（3 条与各自簇的 Jaccard 略低于 0.6 的边界个案没删）——真实工程里阈值是 recall/precision 的旋钮，**不存在"全删干净"**。
- 候选对里 Jaccard **中位 0.89 · 最大 1.00**：1.00 是"插空格变体"去空白后与原句逐字相同（`" ".join(d)` 变体）——一个完美的伪装者，n-gram 去空白把它打回原形。
- token 1077 → 608，第二刀砍掉 **43.5%**——**重复比噪声更烧预算**。

### 3.4 端到端账本

```text
104 条 / 1414 token（粗爬池）
  → A 质量过滤：丢 34 噪声        → 70 条 / 1077 token
  → B MinHash 去重：丢 27 近重复  → 43 条 / 608 token
净剩 43.0% —— 粗爬池一大半字节是噪声 + 重复
```

一句话：**同样 1414 个 token 的预算，清洗前只能买到 608 的有效信息，清洗后是全额的。**

## 4. 配比：按 token 花钱，不按篇数（C 段实测）

### 4.1 三源池与目标

三源模拟一个"网页 + 教科书 + 代码"的混合意图池，目标配比 **70 / 20 / 10**：

| 源 | 篇数 | token | 每篇平均 token |
|---|---|---|---|
| 网页 | 648 | 10,296 | ~15.9 |
| 百科/教科书 | 120 | 1,755 | ~14.6 |
| 代码 | 80 | 728 | ~9.1 |

### 4.2 两种采样口径的实测差距

```text
[C1 按篇数 100 篇采样]  实际 token 占比 70.4% / 23.8% / 5.8%   (网页被代码稀释)
[C2 按 token 预算 2000] 实际 token 占比 69.4% / 20.6% / 10.0%  (贴近目标)
```

同一个"70/20/10"，换成**按篇数**采样：代码篇短（~9.1 token/篇），100 篇里 10 篇代码只贡献 **5.8%** 的 token——预算里少了 4.2 个百分点的代码，百科反而偏到 23.8%。**模型看到的 token 占比（信息占比）才是它学的，不是篇数占比**。按 token 预算采样（C2）每源分得 `目标 × budget` 的 token、文档随机满取 → 69.4 / 20.6 / 10.0，贴合目标。

### 4.3 配比为什么值得抠到百分位

- `21` 章的幂律是**按 token 计的**：D^-0.164 里的 D 是 token。配比失真 = 你以为给了 10% 的预算，实际只给了 5.8%——幂律照收不误。
- 而配比不是万能：`13` 章实测同预算下**多样性 6/6 vs 重复 3/6**——配比解决"各给多少"，多样性解决"每个意图内部别重复自己"。**配比管数量、多样性管质量，两个都要算。**

## 5. 数据墙时代：四步的优先级重排

`21` 章把"数据墙"量成**池的统计分辨率**：有限池 P0 循环训练的终点是 `CE(真实分布‖池经验频率)`，池翻倍墙约减半。站在这个结论上回头看数据工程，四步的优先级全部被重排：

1. **去重变成第一生产力**：墙的分子是"池重复了多久"。两个 1TB 池，一个去重后 600GB、一个不去重 1TB，后者在同一 token 预算下有效信息更少、提前撞墙——**去重不是省存储，是把预算还给统计分辨率**。真实工程里 >90% 的"语料"可能只是几十% 的信息（业界 Common Crawl 级别管线的经验，非本机实测）。
2. **质量过滤从"删垃圾"升级成"挑任务相关"**：2024 起的真实做法是用**小模型打分**做两阶段过滤（`FineWeb-Edu` 的"教育相关度"、代码/数学任务集的启发式，均为业界公开方法、非本机实测）——把"能不能教"变成"是不是你想让它会的"。
3. **合成数据是"新水"**：`22` 章的三份实测全在这张图里——教师系统（一种有监督合成）、CPT 回放（领域新水 + 记忆保持）、连"教师文本无 logits 2.6655 比真数据 2.6230 还差"都是**配比和质量过滤的照妖镜**：合成样本不是天生高质量，要过了"为什么能教对"的质检才值得进池。
4. **配比科学化**：按 token 预算采样（§4）是基线；真实产线还会加"上采样低资源语言 / 数学 / 代码"的去重后重配比。

> 一句话（数据墙时代）：**数据工程从"能跑就行"变成"统计分辨率管理"——去重还它、过滤挑它、合成生它、配比分配它。21 章给了墙的解析表达式，本篇给的是墙这边的四把铲子。**

## 6. 常见坑

1. **以为"更多数据 = 更好模型"**：`21` 章池世界测得预算翻倍 best eval 只动 0.003——重复数据不增加分辨率。加数据前先问"这里面有多少新的统计信息"。
2. **规则阈值选错形态**：`repeat_ratio` 用全局限频会误杀健康英文（t/s/e 高频）；用连续 run 才对准"啊啊啊"型堆砌。**启发式是"对什么形态敏感"的选择，不是随便一个阈值。**
3. **规则互相截胡会掩盖探测**：本池 `low_valid`（有效字符<0.5）0 命中不是规则没用，是被 too_short / html / high_repeat 先删光了。调试时用"按类别×删除原因"交叉表看（脚本诊断段就是这么跑的），别对单个计数下结论。
4. **去重阈值当 Deadline**：`≥0.6` 的 Jaccard 是 recall/precision 旋钮，27/30 那 3 条没删是特征，不是 bug。真实管线会按"这些 edge 值不值得留着"做二次判定。
5. **按篇数配比**：实测代码源从 10% 稀释到 5.8%（§4）。配比永远按 token；每篇长度悬殊时篇数配比必失真。
6. **清洗误删多样性**：太激进的规则会把低资源语言/代码/方言整段删掉，等于亲手把 `13` 章"多样性 6/6"的动态抹掉。**过滤是保"留"的判断，不是删的竞赛。**
7. **可复现性杀手的跨进程哈希**：本脚本 MinHash 的 gram→id 映射最初遍历 `set()`，Python 跨进程 set 迭代序随机 → 候选对 29/30 漂移。**凡顺序敏感的下游，先 `sorted` 再建映射**（与 `reasoning_demo` 平的投票破序坑同源）。
