## 0. 为什么指令集是 SFT 的"配方"而不是"原料"

`13-SFT-监督微调` 在**原理层**已经量过训练本身：掩码让 loss 只算回答区（A1）、全新问法从 1/6 涨到 6/6（A2）、多样重复样本的泛化差是 6/6 vs 3/6（A3）。但原理层那个玩具引擎吃的是**现成的样本**——那些样本是怎么来的？什么样的形态、什么样的质量、什么样的构成，训练才真的有效？

答案是 **SFT 的成败一大半在数据侧定死了**，而且这部分几乎不消耗 GPU。指令集（instruction set）就是这一侧的载体：它不是"一堆文本"，而是 **[(指令, 回答), …] 的配对集合**，外加一个配比方案（哪些主题占多少权重）。`00-全链路总览与飞轮` 里说的"喂什么决定长成什么"，在 SFT 这一站就具体成这三件事：

1. **形态**：语料是不是被组装成了 (指令, 回答) 对，能不能直接灌进训练循环；
2. **质量**：有没有重复、有没有多样性塌成一块、回答长短分布是否合理；
3. **配比**：各主题/难度/领域的份额，是按什么口径在算——条数还是 token。

> 一句话（为什么有本章）：**预训练数据决定"能力底座"，SFT 指令集决定"你说上句、它接哪句的下半句"——形态不规范模型学不了，质量差了学歪，配比错了学不全。**

## 1. 一站全景：三问 + 回答是样本的重

一道 SFT 样本在训练循环里长这样（`13` 章 A1 的掩码口径，`01` 章白话版是 [Q][A] 拼装）：

```text
[BOS] 指令(不贡献 loss) [SEP] 回答 1 [SEP] 回答 2 … (每个回答 token 都贡献 loss)
```

三件事一一对应三个问题，也是本脚本 A/B/C 三段的靶场：

| 数据侧问题 | 要动的手 | 本篇实测段 |
|---|---|---|
| 建得对吗 | 把语料组装成 (指令, 回答) 对，钉死形态 | **A 段**（90 条 = 算术 60 / 常识 18 / 翻译 12，可验证:开放式 = 2:1） |
| 质量怎么样 | 去重、量多样性、看长度分布 | **B 段**（去重 4 条 → 剩 86/90；4-gram 唯一率 75.4%；回答平均 5.6 token） |
| 配比均衡吗 | 按 token 而非条数谈主题份额 | **C 段**（算术 66.7% 条数 → 只有 29.6% token） |

这里先立下本篇最核心的一个公理（来自 `13` 章 A1 实测）：**SFT 的 loss 只对回答区求，所以一条样本对梯度的贡献 ≈ 它的回答 token 数**。回答短的样本"轻"，回答长的样本"重"——而指令区的措辞再华丽也不贡献一丁点梯度。这个公理贯穿 B 段的长度解读和 C 段的配比口径，是"数据五连"从 `01` 的 token 预算一路带过来的记账单位。

## 2. 怎么建：从语料到 (指令, 回答) 对的三种形态（A 段实测）

### 2.1 三种形态，成本与可验证性各异

真实的指令集构建不只有一条路，`00-构建指令数据集-旧提纲` 列的 Alpaca 式合成、Evol-Instruct 扩写、人工筛数据在这里可以归成三类（后两种业界口径，**非本机实测**）：

| 形态 | 怎么得到样本 | 成本 | 可验证性 |
|---|---|---|---|
| 人工金标准 | 人写 (q, a) | 最高，质高量小 | 开放式为主，靠人复审 |
| 模板合成 | 规则模板 + 数字/槽位填参 | 最低，量随参数化爆炸 | **天然的自动可验证** |
| 模型合成 | LLM 生成候选 + 评审 | 中，接 `02` 章飞轮 | 靠规则/自洽检查把关 |

本篇靶场三路并用：**算术 60 条走模板合成**（自动可验证，接 `02` 章的规则验证 qc_rule 同款对账）、**常识 18 条走百科句改写**（开放式）、**翻译 12 条走人工金标准**（开放式）。

### 2.2 三种来源的组装（A 段实测输出）

```text
[A] 指令对构建       共 90 条 (q, a)（指令, 回答）对：{'算术': 60, '常识': 18, '翻译': 12}
    可验证（算术）60 条 / 开放式（常识+翻译）30 条
    例：q=计算：5乘12等于多少？  →  a=60（算术）
```

三个值得盯的点：

- **可验证:开放式 = 2:1**。这不是巧合而是构造上的选择：模板算术的答案能被**重算对账**（`02` 章 qc_rule 原样逻辑），质检可以全自动；开放式答案只能上人工或 LLM-judge。数据侧第一条纪律：**能自动验证的那一路，是产线最省力、最不容易带病的一路**。
- **模板合成的形态差**。算术只用了 3 个模板 × 9×11×3 种参数组合，就能生成形态一致、答案必定正确的样本——代价是**形态单一**，这正是下一段 B 段多样性格 4 条的导火索（模板碰撞）。合成数据的量与质从来是两本账，`02` 章的账本到这里继续生效。
- **人工金标准的 12 条翻译不可替代**：没有模板能自动"翻对"，也没有规则能对账开放式答案，金标准是开放式能力的硬地板。

## 3. 怎么质检：去重、多样性、长度 三件套（B 段实测）

### 3.1 三件套输出

```text
[B] 质量三件套       指令去重 4 条 → 剩 86/90
    指令多样性：4-gram 唯一率 75.4%（1091/1447）
    回答长度：平均 5.6 token / <10 token 占 73.3% / 最长 26
```

### 3.2 ① 指令去重：4 条模板碰撞

90 条里 q 完全一致的有 4 条，删掉后剩 86 条。这 4 条全来自算术池：绕满数字域 2..13 × 3 算符 × 3 模板只有 **36 种**合法指令串，60 次抽样往 36 个格子里放，碰撞是概率必然（诚实声明：这个数字是构造使然，不是"真实指令集都长这样"）。

> 指令去重不能只靠字符串相等。同一道题、"计算 5 乘 12" 和 "5乘12是多少" 字面不同、意图却几乎重叠——生产里常用 embedding/N-gram 相似度作同义判重（|N-gram Jaccard| ≥ 阈值），`02` 章的多样性判重就是这个思路，这里是同一工具的两种用法。

### 3.3 ② 指令多样性：4-gram 唯一率 75.4%

把 86 条指令的字符 4-gram 全并起来：1447 个 gram，去重后剩 1091 个，唯一率 **75.4%**。它是"指令区说人话的覆盖面"的供给侧指标——`13` 章 A2 那个 `全新问法 1/6 → 6/6` 之所以有效，靠的就是**训练时见过的指令形态够散**；指令全部是同模板的孪生兄弟，模型学到的就是"答模板，而非答意图"。指令多样性低的时候，唯一率数字掉得比任何质判都快。

### 3.4 ③ 回答长度分布：平均 5.6 / 最长 26

回答平均 **5.6 token**，73.3% 的样本回答 <10 token，最长一条（常识句子）26 token。这个分布不是随机噪声——**短回答 = 可验证任务**（算术答案就 1-2 个 token），长回答 = 开放式任务（常识/翻译的整句解释）。所以"回答太短要不要过滤"不能开一条全局规则：对一个以算术为主的指令集，短是**正常**的；把"短回答率"当独立指标砍，等于在砍掉整片能力区。长度分布要**跟任务类型挂钩解读**。

## 4. 怎么配比：条数占比 ≠ token 占比（C 段实测）

### 4.1 一个标签的两个视角

90 条原始指令集的构成，用两种口径看完全是两本账：

```text
[C] 三主题配比：条数占比 ≠ token 占比（loss 里真实权重按 token）
    目标 token 预算 900：算术 40 / 常识 30 / 翻译 30，重采样后：
    算术    60 条 / 条数占比 66.7% → token 占比 原始 29.6% → 平衡后 38.8%
    常识    18 条 / 条数占比 20.0% → token 占比 原始 49.9% → 平衡后 31.8%
    翻译    12 条 / 条数占比 13.3% → token 占比 原始 20.5% → 平衡后 29.4%
```

**算术拿了 66.7% 的条数，却只贡献 29.6% 的 token；常识只占 20.0% 的条数，token 占 49.9%。** 这对直觉是反的：我们通常按"条数"组织数据集（Github/CK 导出的 CSV 都是按行数数的），但训练循环里 loss 是按 **token** 加总的（§1 公理）——于是"配比"必须问 token、不是问条数。

### 4.2 按 token 预算重采样

把预算 900 token，按目标 40/30/30 切（算术 360 / 常识 270 / 翻译 270），逐类随机重采样到凑够预算为止（跟 `01` 章 C2 同一个口径）：

- 算术 token 重采样后占 38.8%（对照 40% 目标）；
- 常识 31.8%（对照 30% 目标）；
- 翻译 29.4%（对照 30% 目标）。

**三管基本回到预算线上**——这就是"配方"的动作：不删不做，抽一遍样就把它拉回均衡。而 `01` 章 C2 的池地板在这里同样成立：如果把预算加到 1500，算术池 300 token 力所不及、翻译池也到顶——**喂不饱就说明这一路样本不足，该走 `02` 章的扩池/合成，而不是在池子里硬凑**。

## 5. 与 13 章原理对账：掩码 → 梯度权 → 泛化

`13` 章原理层的三个实测数字，到这里都能反推成数据层的行动项：

| 原理层数字（`13-SFT` 实测） | 数据层的对应行动（本篇） |
|---|---|
| 掩码只算回答区（A1） | 一条样本的梯度权 ≈ 回答 token → 配比按 token（C 段），长度分布按任务解读（B 段③） |
| 全新问法 1/6 → 6/6（A2） | 指令多样性是泛化的燃料，4-gram 唯一率就是供给侧仪表（B 段②） |
| 多样 vs 重复 6/6 vs 3/6（A3） | 去重不是洁癖是止损：重复样本把梯度预算反复花在同一块（B 段①） |

还用 §1 公理做一个演算（依据 B 段实测的 26 与 5.6）：**一条 26 token 的常识样本，梯度权 ≈ 26 / 5.6 ≈ 4.6 条平均样本**。所以"按条数堆算术题、指望它改变行为"的低效是结构性的：不是算术题答案不对，而是每条只贡献一两个 token 的梯度，无论如何也该用"回答 token 预算"来配比——这个认知在末尾钉死：**SFT 是按 token 学习的模型，请用 token 的语言跟你谈配比**。

## 6. 常见坑

1. **按条数谈配比**。90 条里算术占 66.7%、token 只占 29.6%——条数账和梯度账是两本，最终决定训练行为的是后者。先算 token 再采样（C 段）。
2. **只看"不重复"不看多样性**。字符串去重拦不住同义改写。多样性塌了，`13` 章的 3/6 vs 6/6 就是下场。用 4-gram 唯一率 / 相似度判重看趋势，别当一次性的洁癖检查。
3. **"回答太短"当坏样本一刀切**。算术答案本来就是 1-2 token，短是特性不是污染。长度分布必须挂上任务类型解读（B 段③）。
4. **把 Chosen/Rejected 塞进指令集**。指令集是 (指令, 回答) 对，偏好数据是 (指令, 好的, 差的) 三元组——结构完全不一样，混着灌会把两个训练目标搅在一起。偏好是下一章 `04-Preference数据` 的活。
5. **模板合成只顾量不顾形态**。三个模板 × 小数字域就能造出一批孪生指令，数量爆表、多样性塌方（B 段①那 4 条碰撞就是前兆）。合成要同时盯量、质、形态三个维度。
6. **把"可验证"当"全部"**。可验证那一路（算术）质检最省力，但开放式能力（常识、翻译、对话）没有模板可抄，只能靠人工金标准/reviewer——只会造算术题的产线教不出会聊天的模型。

## 7. 衔接下一章

指令集解决的是"**教对**"：给定指令，回答该是什么。但人类对模型的期待不只"答对"，还有"**答得像人喜欢的样**"、在几个都合理的答案里挑"更好的那一个"。下一章 `04-Preference数据与Reward-Model`（§17.3.3 的 Preference 分篇）把 (指令, 回答) 对升级成 **(指令, 好的回答, 差的回答)** 三元组，回答"怎么收集偏好信号、怎么把偏好炼成奖励模型"——数据五连从"造干净、造出形态、按配方配比"推进到"**判出好坏**"。`13` 章预告的 `RLHF` 那条线，在这里接上数据侧的管。
