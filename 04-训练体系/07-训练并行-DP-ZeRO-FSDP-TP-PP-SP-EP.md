## 0. 为什么单卡装不下 7B：一切并行的起点

回到 `06` 章那张账：7B 全参微调要 78.2 GiB（权重 13.0 + 梯度 13.0 + Adam 两矩 52.2），不含激活。拿一张 40 GiB 的卡，**78.2 ÷ 40 = 1.95 倍，超桌**。两条路：

1. **把状态变薄**（`06` 章）：LoRA/QLoRA 让"梯度 + 优化器"只为可训练子集记账，全参 78 → ~13+0.02 → 再量化主权重 ~3 GiB。省的是"不重要的那几件"。
2. **把状态摊到多卡**（本篇）：78.2 GiB / 8 卡 = 9.8 GiB，40 GiB 卡稳坐还多 4 倍余量。这就要引入**并行**——而并行从不免费：摊开就要运货，运货就有通信账、就有气泡。

并行的第一性问题是三道选择题，本篇 A/B/C/D 每段答一道：

| 问题 | 答它的段 | 灵魂 |
|---|---|---|
| 切哪份状态、摊给谁装 | **A 显存三档账** | DP 不省、ZeRO 逐档切、FSDP 与 ZeRO-3 同级 |
| 摊开后每步要搬多少货 | **B 梯度货运账** | 通信量与卡数几乎无关；ZeRO 省的永远是显存 |
| 把"时间"也切片（流水线）会空等多久 | **C 气泡仿真** | 公式是上界；1F1B 不减气泡、省的是驻留激活 |
| 层内还能再切（TP/SP/EP）各付什么 | **D 层内三把切刀** | 切矩阵/切序列/切专家，通信都不一样 |

知识地图 §17.3.6 给本篇的实践作业是"**用 FSDP 把 7B 放两张卡**"——读完 A 段你就知道为什么 FSDP 是这句话里的不二之选：它是唯一把三件套都切散、还把通信摊进层计算的方案（§3 末尾会落到这笔账上）。

> 一句话（为什么有本篇）：**PEFT 把训练状态变薄，并行把训练状态摊匀——本篇不发明新调料，是把"单卡装不下"这道除法题做完，再数清楚每一刀的通信代价与气泡代价。**

## 1. 一站全景：七种切法一张表

并行家族全是"切 + 拼"的变体。看张表记住七种切法（也即 `05-推理并行` 要复用的同一套词汇）：

| 切法 | 切哪一维 | 每卡省什么 | 付什么代价 | 代表 / 出处 |
|---|---|---|---|---|
| **DP**（数据并行） | batch 数据 | 省时间（吞吐↑），显存一分不省 | ring all-reduce 同步梯度 | DDP |
| **ZeRO-1** | 优化器状态 | 优化器 ÷P | reduce-scatter 后的梯度同步 | ZeRO 论文 2020 |
| **ZeRO-2** | 优化器 + 梯度 | 再省梯度（÷P） | 同 ZeRO-1 通信量 | ZeRO 论文 2020 |
| **ZeRO-3** | 权重 + 梯度 + 优化器 | 三件全分片，显存 ÷P | reduce-scatter + all-gather 两段（通信回到 DP 量级） | DeepSpeed |
| **FSDP** | 与 ZeRO-3 同语义 | 同 ZeRO-3，且按层物化省激活驻留 | 通信摊进每一层的前向/反向 | PyTorch |
| **PP**（流水线并行） | 层的时间轴 | 单卡只驻留一段层（+1F1B 压激活） | 流水线气泡 (S-1)/(M+S-1) | GPipe / Megatron 1F1B |
| **TP**（张量并行） | 层内矩阵 | 单层权重 ÷P（激活也 ÷P） | 每层 fwd 2 次 + bwd 2 次 all-reduce | Megatron-LM 2019 |
| **SP**（序列并行） | 激活的序列维 | 激活 ÷P（权重不省） | 与 TP 复用同一套通信、分布前移 | Megatron-SP |
| **EP**（专家并行） | MoE 专家 | 专家参数 ÷P（激活不省） | 每次激活 all-to-all 全量过网 | Switch / Megatron-EP |

读法就一句话：**竖着看三族——数据族（DP→ZeRO→FSDP）摊"训练状态"，时间族（PP）摊"运行时段"，层内族（TP/SP/EP）摊"一层里的矩阵和它流过的数据"。** 族内可以叠加（ZeRO + PP + TP 同台，Megatron-DeepSpeed 就是），族间各有各的通信与气泡，正是本篇 A/B/C/D 要逐段量化的东西。

> 一句话（全景）：**七种切法不是七个黑箱，是把"78.2 GiB 的账本 + 每秒几 GB 的梯度 + 一段一段的时间"分别切开的三种手艺——记住"切哪份、省什么、付什么"三栏，之后任何新并行的名字都只是这三栏的排列组合。**

## 2. 怎么构造：显存账、通信账、气泡仿真三问

真实训练 7B 并行需要真实多卡，本篇在纯 CPU 上把三问各做成一个"能重算的账本/仿真"——**能得出数字的就真跑，跑不了的诚实标账算**：

- **A/B/D = 账算（非本机实测）**：口径沿用 `06` 章的 7B 四件套（78.2 GiB/12 B 每参数，GiB=2³⁰）；B 段的通信/计算比值需要一条假想平台——单卡有效算力 100 TFLOPS(bf16)、互连单向带宽 400 GB/s，并声明假设，结论看形状不看绝对值。
- **C = 本机离散事件仿真（真跑）**：真实流水线无法在 CPU 上跑，但"气泡"本身是一个**调度问题**——每卡每时刻有活却没活可派时 tick 就是空转。把流水线建模成 F=B=1 单位时间、依赖复刻真实反向传播（`B(m,s)` 要等下一段的反向 `B(m,s+1)` 做完才能算），再用两种派活策略（fill-flush 先推全体前向再逆序回传；1F1B 回传优先）真跑一遍整个调度，就能逐 tick 数出气泡、makespan、驻留激活。**确定性：无随机，三遍运行科学数字逐位一致（只有墙钟 12/13/14 ms 浮动）。**

> 一句话（构造选择）：**账算回答"省多少"，仿真回答"等多久"——A/B/D 是能辩护的假设算术，C 是把 PPT 上的公式变成能数格子的真实调度；四段共用同一个 78.2 GiB 起点，保证横竖都对得上。**

## 3. 显存三档账：DP 不省、ZeRO 渐进、FSDP 同级（A 段）

`parallel_demo.py` A 段把 7B 四件套 78.2 GiB 按三种切法逐档摊开（**账算口径，非本机实测**）：DP 每卡仍是整份；ZeRO 按"切优化器 → 再切梯度 → 三件全切"三个档位递减；FSDP 与 ZeRO-3 同语义、按层物化：

```text
单卡整份      : 78.2 GiB（40 GiB 卡坐不下，超桌 1.95×）
DP（8 卡）    : 每卡仍是 78.2 GiB（整份拷贝，只摊数据，显存一分没省）

ZeRO-1（8/16/32 卡）: 权 13.0 + 梯 13.0 + 优化器 52.2/P → 32.5 / 29.3 / 27.6 GiB/卡（只切优化器）
ZeRO-2（8/16/32 卡）: 权 13.0 + 梯 13.0/P + 优化器 52.2/P → 21.1 / 17.1 / 15.0 GiB/卡（再切梯度）
ZeRO-3（8/16/32 卡）: 78.2/P               →  9.8 /  4.9 /  2.4 GiB/卡（三件全分片）
FSDP（8 卡）        : 与 ZeRO-3 同语义、按层物化，稳态每卡同为 9.8 GiB 级
```

三个读数：

1. **DP 省时间不省显存**：每卡整份拷贝 78.2 GiB。DP 的"P"切的是 batch，不是账本——所以单卡坐不下时 DP 救不了你，这正是并行族要往 ZeRO 走的原因。
2. **优化器是逃不掉的大头**：52.2 GiB（占 2/3）要摊到最后。ZeRO-1 切它、ZeRO-2 再切梯度、ZeRO-3 连权重也切。8 卡时 ZeRO-1 就到 32.5 GiB（40 GiB 卡已经能坐）、ZeRO-3 直接 9.8 GiB——**同是 8 卡，档位不同差出 23 GiB**。
3. **FSDP 的三点不同**：① 与 ZeRO-3 语义相同（三件全分片）；② 按层物化——某一层做前向/反向时才把它 materialize（取回整数据）并临时驻留 2× 单层权重，其他层恢复分片，省的是每卡住一整层；③ 通信因此是**摊进每一层算的**（§4 还会用到这个）。知识地图 §17.3.6 的实践作业"用 FSDP 把 7B 放两张卡"：两张卡 FSDP → 78.2/2 = 39.1 GiB/卡，40 GiB 桌恰好够，且按层物化把峰值的"另一张卡"也避免了——这就是它被点名的那一档。

> 一句话（A 段）：**DP 不骗显存、ZeRO 按三档逐级切、FSDP = ZeRO-3 语义 + 按层物化；把 78.2 GiB 摊开，8 卡就从"装不下"走到"9.8 GiB，余量 4 倍"。**

## 4. 梯度货运账：摊开就要运货（B 段）

显存摊开了，新的账来了：**每次更新前，梯度要在卡间对齐**。B 段算每步要运多少货、为此空转多少（假想平台：算力 100 TFLOPS、带宽 400 GB/s；`t` = 每卡每步 token，即全局 batch ÷ 卡数）：

```text
每步梯度 = 14 GB（7B × 2B fp16）
DDP ring all-reduce：每卡净传 2(P-1)/P × 14 GB   （P=8 → 24.5 GB → 61.2 ms）
ZeRO-1/2 reduce-scatter：(P-1)/P × 14 GB         （P=8 → 12.25 GB → 30.6 ms，减半）

    P     t │  DDP 通信/步   DDP 计算比 │  ZeRO1/2 通信/步  ZeRO1/2 计算比
    8  4096 │    61.2 ms       3.6% │     30.6 ms        1.8%
    8   512 │    61.2 ms      28.5% │     30.6 ms       14.2%
   64   128 │    68.9 ms     128.2% │     34.5 ms       64.1%
   64    16 │    68.9 ms    1025.4% │     34.5 ms      512.7%
```

三个读数：

1. **通信量 ≈ 1~2 份梯度，与卡数几乎无关**：`2(P-1)/P` 和 `(P-1)/P` 在 P≥8 后都贴着 1、2 收敛。也就是说**扩卡只能减每卡的显存，减不了每卡的梯度通信量**（P=64 时 DDP 61→68.9 ms 只是略增）——这是"并行不免费"的根。
2. **通信·计算比翻车曲线**：P=8·t=4096 时计算 1720 ms、通信 61 ms → 3.6%，DP 是隐形开销；`t` 掉到 512 就 28.5%（每四步空转一步）；P=64·t=128 直接 128.2%——**通信主导，这就是"批压不上去、卡再翻倍 TPS 反而缩水"的机制**：卡多了全局 batch 摊到每卡的词变小，计算端变薄，通信账原样压上来。
3. **ZeRO 省显存，不省通信**：ZeRO-1/2 用 reduce-scatter 取代 ring all-reduce，通信恰好减半（30.6 vs 61.2 ms；比例列也减半：1.8 vs 3.6%）；**ZeRO-3 的通信回到 DDP 量级**（reduce-scatter + all-gather 两段运货）——它换的是显存自由，运营商本来就要传的那份梯度照样传。反直觉但关键：**"ZeRO 更省通信"是错的，ZeRO-3 别拿"省通信"当卖点。**

联系 `06` 章：LoRA 把每步要同步的梯度从 14 GB 级砍到"只记可训练子集"，是与 B 段平行的第二部省法——PEFT 省净重、并行省摊薄，两者叠加才是完整答案（§8 衔接）。

> 一句话（B 段）：**DP 的甜区只在 batch 充沛（计算时间 ≫ 通信时间）；通信量近似等于 1~2 份梯度、和卡数无关；ZeRO-1/2 把通信减半、ZeRO-3 回到 DP 量级——并行摊的是显存，运货的成本一分不少。**

## 5. 流水线气泡仿真：公式是上界，1F1B 省的是驻留（C 段）

PP 不摊显存/运货，它**把时间切成段**：S 段流水线、M 个微批。教科书说气泡比 = `(S-1)/(M+S-1)`——本篇不用背，直接离散事件仿真把价格数出来（**本机真跑**，F=B=1 单位时间，fill-flush vs 1F1B 两种派活策略，确定性无随机）：

```text
     S   M policy │ makespan    气泡实测     F公式     F偏差 │   s0驻留    全局在飞
     2   2  naive │        7   28.6%   33.3%  -4.8pp │      2       2
     2   2   1f1b │        7   28.6%     --      -- │      2       2
     2   4  naive │       11   18.2%   20.0%  -1.8pp │      4       4

     8   2  naive │       19   73.7%   77.8%  -4.1pp │      2       2
     8   2   1f1b │       19   73.7%     --      -- │      2       2
     8   4  naive │       23   60.9%   63.6%  -2.8pp │      4       4

     8   8  naive │       31   45.2%   46.7%  -1.5pp │      8       8
     8   8   1f1b │       31   45.2%     --      -- │      8       8
     8  16  naive │       47   29.8%   30.4%  -0.6pp │     16      16
     8  16   1f1b │       47   29.8%     --      -- │     15      16
```

四个读数（s0驻留 = stage0 缓存着的微批数，即第一段的激活驻留量；全局在飞 = 调度窗口里同时在途的微批数）：

1. **公式是"上界"，不是逐位真理**：M 小（=2）时公式高估最多（S=4 差 −5.5pp，因为逆序回传的排空段比公式假设的浅）；M 一大就贴死——M≥8 偏差 ≤1.5pp，M=16 只剩 ≤0.6pp。**教科书公式适合估算量级，真要抠几个点就得跑一遍调度。**
2. **气泡吃 S 不吃数据量，M 翻倍约减半**：S=8·M=16 仍 29.8%，S=2·M=2 只要 28.6%——**深流水线贵**；同一 S 列里 M 每翻倍气泡几乎砍半（S=4：54.5 → 40.0 → 26.1 → 15.4%）。实用话：流水线深度 S 别贪，微批 M 至少数倍于 S（业界口头"S 的 4 倍起"）。
3. **1F1B 与 fill-flush 的 makespan 与气泡完全相同**——这是本仿真的核心诚实读数：**1F1B 不减出米率**。它的功劳全在右栏：s0驻留从 naive 的"=M"（4 卡档 M=16 时 16 份）降到随 S 封顶的值（S=2 → 3、S=4 → 7，≈ 2S-1），于是**M 可以放心做大（气泡才减半）而不爆单卡激活**——这正是 Megatron 用 1F1B 让大 M 可行的机制（对应真实世界的"1F1B 激活峰值与微批解捆"）。
4. **两个诚实边界**：① S 逼近 M 时 1F1B 驻留红利消失（S=8·M=16：15 vs naive 16）；② 全局在飞两种策略同为 M——**1F1B 压的是"单卡同时存几份"，不是"调度窗口里有多少个微批"**。

> 一句话（C 段）：**气泡吃 S 不吃数据量（公式是上界、M≥8 才贴死）；1F1B 与 fill-flush 的 makespan 完全相同，它省的是 stage0 驻留激活（从 M 档降到 ~2S-1 档），让 M 能大胆加倍——读表别只看气泡列，1F1B 的赛道在 s0驻留列。**

## 6. 层内三把切刀：TP 切矩阵、SP 切序列、EP 切专家（D 段）

前两段切的是跨卡（数据族）与跨段（时间族），D 段切的是**一层内部**。它们不省整本账，而是把"单独一层也装不下"的最后半步补完：

```text
TP 切矩阵：每层 fwd 2 次 + bwd 2 次 all-reduce；例 seq=2048·d=4096：
           激活 16.8 MB/次 ×4 = 67.1 MB/层/步；32 层 ≈ 2.1 GB/步
SP 切序列：长上下文例 seq=32k（B=1·d=4096·fp16）：激活 256 MB/层
           → SP p=8 每卡 32 MB/层（÷8）；32 层 8.0 → 1.0 GiB 级
EP 切专家：token 去 top-k 专家所在卡 → all-to-all ≈ D×topk×d×2B（fwd）再同量 bwd；
           例 D=1M token·topk=2·d=4096：每层每步 30.5 GiB（两趟合计），专家驻留按 K 摊
```

三个读数：

1. **TP 通信按"激活"走，每层固定 4 次 all-reduce**：TP 把注意力/FFN 的矩阵按列切开，每层的前向输出、反向梯度各要 all-reduce 一次。16.8 MB 的单次看着小，32 层累成 2.1 GB/步——**TP 对互连带宽最敏感**，P 太大就在层内通信上空转。
2. **SP 专治长上下文**：注意力激活和序列长度成正比，seq=32k 一层就有 256 MB（激活本身跨 8.0 GiB/步）；SP 把激活按序列维摊到 P 卡，32 层 8.0 → 1.0 GiB——**长上下文场景的激活就是靠 SP 摊开的**（权重它不切、也不省）。
3. **EP 的 all-to-all 是激活全量过网**：MoE 让每个 token 去 top-2 专家所在卡，专家计算摊开了，**激活却要整体搬到对端**——每层每步 30.5 GiB（fwd+bwd 两趟），量级上是 TP 的 15 倍。EP 的价值在专家驻留（按 K 摊），代价是每次激活全量过网；这也是 `18-MoE` 章"专家切开放跨机要设计"的通信侧原因。

> 一句话（D 段）：**TP 切矩阵（每层 4 次 all-reduce）、SP 切序列（长上下文激活 8.0→1.0 GiB）、EP 切专家（驻留省了、激活 30.5 GiB/层/步全量过网）——层内三把刀省的都是"单层放不下"，付的都是那句已经听熟的"通信"。**

## 7. 常见坑

**① 以为"并行就省显存"。**
DP 一分不省（A 段：8 卡仍是每卡 78.2 GiB）。把 DP 当显存解药的直接后果是"扩卡的卡都白买"——先问一句"我卡在哪一档"，单卡装不下是数据/时间/层内的问题，DP 只管吞吐。

**② 拿"ZeRO 更省通信"当卖点。**
ZeRO-1/2 通信确实减半（reduce-scatter），ZeRO-3 回到 DDP 量级（B 段：reduce-scatter + all-gather 两段）。ZeRO 的全部卖点是显存自由；按"省通信"选 ZeRO-3 会得到一份与 DDP 相同的通信账却多一层复杂度。

**③ 扩卡就默认 TPS 线性涨。**
通信·计算比曲线（B 段）在 `t` 小时翻车（P=64·t=16 → 1025%）。扩卡前先看每卡每步词数 `t`：全局 batch 摊薄到计算端不够厚，通信账就盖过计算。诊断口径是"每卡 `t`"，不是"总 batch"。

**④ 流水线 M 给太小。**
C 段 S=4·M=2 气泡 54.5%——一半时间在空转。把 M 做到 S 的数倍以上（气泡随 M 翻倍约减半），同时别让 S 贪深（S=8 哪怕是 M=16 也压不出 <29.8%）。

**⑤ 把 `(S-1)/(M+S-1)` 当逐位真理。**
公式是上界：M=2 时实测低到 5.5pp（C 段偏差列）。做预算用手算公式，验证调参用仿真/真跑，别在 M 很小的设计里去抠公式的两位小数。

**⑥ 层内切分不区分 TP/SP/EP 的通信形态。**
TP 是每层 4 次 all-reduce（对带宽敏感）、SP 是激活按序列维摊开（长上下文专用）、EP 是 all-to-all 全量过网（最重，30.5 GiB/层/步）——统一按"并行=免费"记账，会在链路带宽上翻车。

## 8. 衔接下一章与参考资料

数据族的显存账、通信族的货运账、时间族的气泡账、层内族的三把刀——本篇讲的是**切法**；下一章 `08-训练框架横向对比`（§17.3.8）讲把这些切法**组装成工具**：DeepSpeed（ZeRO/PP 基建）、PyTorch FSDP + torch.distributed（原生路线）、Megatron-LM（TP/PP 范式出处），以及 TRL/LLaMA-Factory/verl 之类上层框架，回答"我该把哪几张切法表叠起来、谁帮你叠"。`05-推理与部署` 的 `05-推理并行-TP-PP-DP-EP` 复用本篇的同一套并行词汇（推理侧再加 KV 分片的账）；`04-训练体系` 走向 `09-训练工程-精度-显存-检查点`（BF16/FP8、checkpoint）与 `10-训练闭环中的评测门禁`。

与 `06` 章合起来才是完整答案：**PEFT 把每卡状态变薄，并行把薄状态再摊匀**——LoRA + FSDP 是生产里最常搭档的一对（LoRA 让每卡梯度小到通信近乎白送，FSDP 让基座权重也能进 40 GiB 桌），两者用的都是 `07-GPU` 的显存账本、`02-10` 的算账技能。
