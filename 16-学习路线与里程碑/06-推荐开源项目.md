## §1 六组合一总表：工具清单不背，但要会定位

**是什么**：把所有值得知道的开源落点按"学习用途"分成 **六组**：**理论 / 实现入门 / 训练微调 / 推理部署 / RAG 知识 / Agent 与评测可观测**。每组列主落点 + 一个或两个代表库，标注类别定位。

**为什么会出现**：因为真实工程里你不会"用到整个生态"，而是**某个具体痛点到某个工具**。六组分类 = 你遇到"我该上哪个库解决眼下这个"时的第一级检索。

**机制表：六组 × 代表性工具 × 定位**

| 组 | 代表库 | 定位（一句话） |
|---|---|---|
| 理论 | Attention/Transformer 论文解读、[02-核心原理/01-Transformer.md](../02-核心原理/01-Transformer.md) | 回到机制本源，配合 02 章对比读 |
| 实现入门 | [nanoGPT](https://github.com/karpathy/nanoGPT) · [minbpe](https://github.com/karpathy/minbpe) | 手把手从零写 Transformer 与 Tokenizer |
| 训练微调 | LLaMA-Factory · Unsloth · TRL · DeepSpeed/Megatron | 复现 04 章预训练/微调/对齐流程 |
| 推理部署 | vLLM · SGLang · llama.cpp · Ollama | 复现 05 章推理两阶段与 Serving |
| RAG 知识 | LlamaIndex · RAGAS · [08-RAG体系/07-RAG评测-RAGAS.md](../08-RAG体系/07-RAG评测-RAGAS.md) | 复现 08 章检索流水与评测 |
| Agent 评测可观测 | LangGraph · OpenAI Agents SDK · lm-eval-harness · OpenCompass | 复现 09 章 Agent 与 11 章评测 |

**边界与坑**：这是**清单不是排行榜**——列出来是为了"要用时知道去哪拿"，不是为了让你背。工具半年迭代一轮，别把头埋在 2026 年的名字里；十六 章教你的是**机制**，工具是机制的载体。看到新库先问它属于六组哪一组、能替代清单里谁，而不是刷新收藏夹。

## §2 逐组映射：读它 / 用来验证仓库哪一篇

**是什么**：对每组库回答同一个问题——**它验证仓库哪一篇、哪个结论**。让"开源工具"和"你已学过的章节"接上头，避免"学完十六 章手里的工具还是一张白名单"。

**为什么会出现**：因为一条 GitHub 仓库 5 万 star 不等于你能用。映射的价值：你把 [16-04](04-里程碑-实践项目清单.md) 的项目往上升级时，**知道该开哪个库来替代/验证**自己在哪篇学过的判断，而不是从零研究生态。

## §3 怎么挑、怎么用：三个原则

**是什么**：面对六组几十个库，挑选与使用遵循三条原则：**① 按需取用不背目录；② 优先自己跑得动的；③ 用 map 代替收藏。**三原则把"清单"变成"决策规则"。

**为什么会出现**：因为开源项目最不缺选择、最缺判据。三原则是"我这个项目此刻需要验证什么 → 我该取哪个库"的**检索优先级**，防止把时间花在"扫库"而不是"用库"上。

**机制表：三原则 × 判据**

| 原则 | 判据（怎么判断符合） | 与已有章节的链接 |
|---|---|---|
| 按需取用不背目录 | 能否说出"某个库在哪个项目里用到、解决什么" | 只在你的一格里找，不横向全扫 |
| 优先自己跑得动的 | 能否在本机跑通最小 demo（1 卡/小于家庭带宽也行） | 先用 [16-04](04-里程碑-实践项目清单.md) 的 009/010/011 热身 |
| 用 map 代替收藏 | 新库进来先问"它对应哪篇、替代清单里谁" | 对照本文 §1 六组 / §2 映射表 |

**边界与坑**：最大误区是**先收藏后学习**——收藏本身不产生学习，真正产生的是"下次推进项目时知道来这把清单里拿哪把"。另一个误区是**追求最新**：工具选 type "mature 够用"，别追 weekly release。16 章收束时如果定义"学完了"= "仓库里每篇的知识我都亲手跑过对应探针 + 至少在工具清单里接触过一个真实落点"——这才叫学习闭环。

📎 **关联代码**（`open_source_projects_demo.py` 账 C，大纲 3）——三原则成对校验，确保"按需/跑得动/map 替代"都落在本文判据上。
