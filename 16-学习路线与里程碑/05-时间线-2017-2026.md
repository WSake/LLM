## §1 年度里程碑总表：2017-2026 十年十站

**是什么**：一张 10 行的年度表，每行 = 年份 + 当年最值得记住的一个事件 + 一句"它改变了什么"。它不追求完整编年史，只追求**每一年都有一个范式锚点**——能让学生在看任何材料时快速定位"这在时间线上的哪一站"。

**为什么会出现**：因为 2026 年看回 2017，最容易产生的错觉是"大家一直是这么训模型、这么用模型的"。时间线把"为什么今天长这样"拆成十次跳变——没有哪一步是注定的，每一步都在改变游戏规则。

**机制表：十年十站**

| 年份 | 里程碑事件 | 范式锚点（一句话） |
|---|---|---|
| 2017 | Transformer（Attention Is All You Need）发布 | 序列建模从 RNN 的串行步进跳到**全并行注意力**，规模化顺理成章 |
| 2018 | GPT-1 与 BERT | 「预训练 + 微调」成为万能配方，下游任务不再需要从头训 |
| 2019 | GPT-2 / T5 | 「极大模型 + 文本续写目标」凭自我监督就够强，few-shot 初现 |
| 2020 | GPT-3（175B） | 规模直推通用能力：**In-Context Learning** 让"提示即编程"成为可能 |
| 2021 | 多模态与 Scaling Laws 落地 | 单一 scoring 目标 + 数据规模的正反馈成为训练 pw，多模态起步 |
| 2022 | ChatGPT / InstructGPT | RLHF 让模型**对齐人类偏好**，对话产品把 LLM 推到大众面前 |
| 2023 | Llama 开源 + GPT-4 | 开源权重打破闭源垄断，社区进入"人人可微调/可部署"时代 |
| 2024 | 长上下文 / 多模态 / Agent 初兴 | 上下文工程与工具调用把"生成文本"变成"完成任务" |
| 2025 | 推理模型（DeepSeek-R1 等） | **推理时计算**规模化：RL 训出"先想后答"，测试时缩放成为新 axis |
| 2026 | 推理模型普及化 + 端侧/Agent 落地 | 推理 cost 不再是壁垒，小模型与端侧 Agent 让推理能力下沉到产品 |

**边界与坑**：这是**教学骨架**，不是编年史。每年只挑**一个**事件——SKIP 掉的同一年还有几十个大事实，别把表当全部历史。尤其中间 2021-2022 之间的 SLM/蒸馏/合成数据的铺垫，被压到一行之外，详见 [15-前沿技术/06-合成数据与数据飞轮-进阶.md](../15-前沿技术/06-合成数据与数据飞轮-进阶.md)。年份的归属以**事件主时间**为准（例如 Scaling Laws 论文 2020 年发表但工程落地在 2021，表里放 2021 取"落地"用途）。

## §2 十年逐行：为什么它是必要的

**是什么**：对 §1 每个里程碑回答同一句"为什么它是必要的一次跳变"——不是"它很大所以重要"，而是"没有它，今天会卡在哪一步"。

**为什么会出现**：因为学时间线最常见的误区是背年份。逐行讲"为什么必要"，是把**技术动机链**讲清楚：每个范式都是为了解决上一步留下的瓶颈，因此今天的每个能力都能在时间线上溯源。

**机制表：跳变动机 2017 → 2026**

| 年份 | 上一步留下的瓶颈 | 这一年怎么解的 | 解完后剩下的新问题 |
|---|---|---|---|
| 2017 | RNN 串行 + 长程依赖差 | 注意力全并行，架构可规模化 | 大规模 pretrain 怎么训？ |
| 2018 | 下游任务数据太少 | 预训练通用表示 + 微调 | 真·通用是否只在面积足够大时出现？ |
| 2019 | 更大模型能否通用 | 扩大规模验证 self-supervised | 指示 / few-shot 能力随规模涌现 |
| 2020 | few-shot 不稳定、需要欠采样 | 千亿参数 + In-Context Learning | 模型太大，私有部署不可行 |
| 2021 | 单点模态有天花板 | 多模态联合 + Scaling Laws 直觉 | RLHF / 指令对齐缺失，AI 不够"听人话" |
| 2022 | 模型知识够了但不愿意 (safe/honest/helpful) | RLHF 对齐人类偏好 | 闭源黑箱 + 能力外泄问题 |
| 2023 | 仅少数公司可训练超大模型 | 开源权重（Llama）拉平分发门槛 | 推理部署与量化成为个人/企业必经 |
| 2024 | 文本生成 ≠ 完成任务 | 长上下文 + 工具调用 (Agent) | 上下文花销 + 幻觉/安全新面 |
| 2025 | 模型直出答案不够准/不够深 | 推理时计算 + RL 训练"先想后答" | 推理成本（token 数）上升 |
| 2026 | 推理很贵 = 普及受限 | 小模型 + 端侧 + 蒸馏让推理下沉 | 端侧安全与隐私责任前置 |

**边界与坑**：这张表是**一种**叙事线（规模 → 对齐 → 开源 → Agent → 推理），不是唯一正确史观；时间线上同样有合成数据、蒸馏、评测方法各自的支线。教学上的坑是把"200 亿美金级团队才做得了的事"误读成"个人路线必须覆盖"——时间表用来**定位**，不用来**恐慌**。重要的不是记住年份，而是能对任意一篇文章说出"它属于这条动机链的哪一环"。

📎 **关联代码**：本篇无探针（能算=无）。动机链的机制侧验证分布在对应章节探针里（如 [16-GRPO与RLVR](../02-核心原理/16-GRPO与RLVR.md) 的 `grpo_demo`、[15-前沿技术/04-SSM-Mamba与混合架构.md](../15-前沿技术/04-SSM-Mamba与混合架构.md) 的 `mamba_hybrid_demo`，时间线只做"何时/为什么"，不重造机理。

## §3 季度回炉：把项目挂到年份上

**是什么**：时间线不只在初学时读一遍，它是**季度回炉的坐标系**。做法：把你 [16-04](04-里程碑-实践项目清单.md) 的 2-3 个活项目，按"它们依赖哪个年份的能力"挂到年份旁；每季度把「新学的章节 + 时间线」再过一遍——查出"我新学的技术属于哪个年代"，并更新项目锚点。

**为什么会出现**：因为 16-01 到 16-04 给的是**静态路线**（学什么、做什么），而学习是**动态的**——季度回炉把"学了 16 章"从累计进度变成**每季度重定位**，避免学到深处才发现初级项目早已过时（例如 2026 年的 RAG 工程已经默认推理模型做检索重排，2024 年初的教程就不再适用）。

**机制表：季度回炉三步**

| 步骤 | 动作 | 判据 |
|---|---|---|
| ① 对齐 | 新章节 → 属于年份哪个范式 | 能对该章说出至少 1 个年份锚点 |
| ② 重估 | 我的 2-3 个项目还依赖哪些年份 | 每个项目能指出最主要的 1-2 个年份 |
| ③ 更新 | 过时/新生技术 → 修订项目里对应模块 | 至少改掉 1 处依赖的旧做法 |

**边界与坑**：回炉不是"再看一遍表"，是**拿项目当探针**——只有当你**动手改旧项目**（例如给知识库 RAG 换上 2025 推理检索重排、把定长窗口换成长上下文压缩）才算完成回炉。对不真实的年份归属别硬套：某些技术（如 [15-前沿技术/07-其他方向跟踪.md](../15-前沿技术/07-其他方向跟踪.md) 的长时 Agent）仍处"早期"，就把项目锚在"跟踪"而不是"落地"。
