## 0. 为什么单列一章："参数量"和"算力"凭什么能解耦

`01` 章讲过 Transformer 的骨架，`06` 章证明了 FFN 承载了大部分参数与"知识"。这两件事凑在一起给了一条被迫之路：

**Dense 模型涨参数 = 涨算力。** 想学得更多 → FFN 加宽 → 每个 token 都要算过全部新权重 → 训练/推理成本线性跟着涨。古典时代（2018–2022）"更大"和"更贵"是一回事。

MoE 打破这个等式：**把每层 FFN 换成 N 个并行的"专家"FFN，每个 token 只激活其中 Top-k 个**（比如 8 个专家只选 2 个）。于是：

- **总参数**（要常驻显存）可以很大——8 个专家、每个都是独立的 FFN；
- **单 token 算力**（推理真正花的时间）只烧被激活的 Top-k ——和只有 2/k 参数的 Dense 一样。

**参数量**与**算力**从此分账。这不是某个小技巧，是 2024 年之后 30B 以上开源模型的事实默认：Mixtral、DeepSeek-V3、Qwen3-MoE、Llama-4、Kimi K2 全是 MoE，Gemini 也被普遍认为是大 MoE。知识地图 §2.14 的判词就是本玩具的第一条纲：**"MoE 的'总参数'很大，但'激活参数'决定推理速度；看模型先看 Active Params 而不是总参数量。"**

先给工作台：

```text
本玩具语境：声明式文本 77 句（6 组知识共 33 句 + 通用 44 句，每句带主题标签 0-6）· 词表 V=354 · 总 token 894
块 (B,T,C) = (8,48,96) · 引擎 = 01 章 1-block 仅解码器（LN→因果 MHA→残差→LN→FFN→残差→头）
MoE：E=4 位专家 · Top-2 · 每专家中间维 M=2C=192
Dense 对照组：经典 4C 中间维，全部激活
```

## 1. 参数账本：总参数 vs 激活参数

对 MoE 的第一笔账，永远是**两本账**：总参数 vs 单 token 激活参数。本玩具形状直算（`param_account`，绝不走 `init_params` 数——那会消耗 RNG 流，并让复现种子失真）：

```text
实验 A
MoE   总参 =  257,280   单 token 激活参 =  183,168   （激活/总 ≈ 0.712）
Dense 总参 =  183,168   单 token 激活参 =  183,168   （激活/总 = 1.000）
FFN 稀疏比：每 token 只激活 2/4 家 → 73,728/147,456 = 50%
关键：激活参 183168 = 183168（恒等）——MoE 的激活参数和 Dense 一模一样，
      但总参多出 74,112（全来自专家的驻留权重）→ 单 token 算力相同、「总量更大」
```

读这张表，三个要点：

1. **激活参恒等**（183,168 = 183,168）：Toy 里 **MoE 的激活参数 ≡ Dense 的全部参数**。这是选型的物理出发点——同算力、同批大小、同时长下，俩模型的 forward/backward 墙钟几乎一样（本玩具整个实验 F 正是踩着这条恒等线做的）。
2. **总参的差额 74,112 全在专家 FFN**：非 FFN 部分（embedding、Wpos、注意力、输出头）完全一样，4 组专家只是多出来"驻留"的权重。它们不参与单 token 计算，但要贷款现金——**显存**。
3. FFN 稀疏比 = k/E = 50%，这正是"总参倍率 vs 算力倍率"的最初分岔。

放大到真实模型（**公开配置的简单换算，非本机实测**）：

| 模型 | 总参数 | 激活参数 | 活跃比 |
|---|---|---|---|
| Mixtral-8x7B | ≈ 47B | ≈ 13B（8 选 2） | ≈ 27% |
| DeepSeek-V3 | ≈ 671B | ≈ 37B（8 路由 + 1 共享） | ≈ 5% |
| Qwen3-235B-A22B | ≈ 235B | ≈ 22B | ≈ 9% |
| Llama-4 Maverick | ≈ 400B | ≈ 17B | ≈ 4% |

读完这张表，"看模型先看 Active Params"就不是口号了：**DeepSeek-V3 的 671B 里，单 token 真正流过 37B 权重，≈5% 的活跃比把"巨大"和"划算"缝在了一起。**

## 2. 路由机制：softmax 门控 + Top-k 硬选，第一手的梯度代价

### 2.1 前三行代码：门控、硬选、加权和

本玩具的路由层就三行（Shazeer 2017 的稀疏门控拼图；Mixtral 的变体是在 Top-2 上再 softmax——等价教学：**k=E 时 MoE 退化为 Dense**）：

```python
wg = n2 @ params["Wg"]              # (B,T,E) 门控 logits：Router 给每个 token 打分
gates = softmax(wg)                 # 全局 softmax → (B,T,E) 门控概率
gmask = topk_mask(gates, TOP_K)     # Top-2 硬选 → 0/1 掩码（边界不可导）
g = gates * gmask                   # 稀疏门控权重：未被选中的专家，g 严格为 0
# 逐专家 FFN：out_e = relu(n2·Wf1_e)·Wf2_e
# h = Σ_e g_e · out_e               # 只有被选中专家贡献输出
```

**Top-k 硬选是这张图的唯一非光滑点**：`gmask` 沿"第 k 大"处跳变，gate 突跳到另一位专家——在这个边界上梯度没有定义。这是 MoE 反向的第一条诚实限定：**对账（或任何依赖光滑性的数学操作）必须冻结路由拓扑**，否则中心差分会撞上翻转点。

### 2.2 对账：冻结拓扑后，全参数 ≤ 1.3e-9

B1 段的做法：固定 `gmask`（冻结选中集合），对参数做中心差分（eps=1e-6，112 个采样点），比对手写反向：

```text
实验 B · 手写前向/反向对账 + 路由稀疏性的两个硬事实
  B1  中心差分（冻结路由拓扑）共 112 个采样点：max|数值−手写| = 1.30e-09
      worst = Wf1_3[82,49] → 注意力/头/专家权重全部通路一致
```

冻结拓扑后，MoE 的全条反向链（注意力 + 路由 + 四位专家）和数值微分对到 1e-9 量级——**说明手写反向在"选中的局部"是正确的**。而边界之外的行为，就是下面两个硬事实的地盘。

### 2.3 硬事实①：未选中专家的 Wf 梯度严格为 0

构造一个单 token 语料，强偏 Router 使它**只选中索引 1 的专家**（`Wg[:,1] += 3.0`，再手动钉死 `gm1[...,1]=1`），反传后看四位专家 FFN 输入的梯度（日志输出里 B2 行的"专家1"是 0 基索引 = 下面的"专家 E2"；专家名 E1–E4 是 1 基）：

```text
B2  单 token · 固定只选专家1 → 未选专家 E1 Wf1 的 max|梯度| = 0.00e+00
B2  单 token · 固定只选专家1 → 被选专家 E2 Wf1 的 max|梯度| = 2.12e-02
B2  单 token · 固定只选专家1 → 未选专家 E3 Wf1 的 max|梯度| = 0.00e+00
B2  单 token · 固定只选专家1 → 未选专家 E4 Wf1 的 max|梯度| = 0.00e+00
```

未选中的专家 Wf 梯度**严格为 0.00e+00**（量化到底）。这不是"近似 0"，是几何事实：`g=0` 位乘掉了一切回传。它带来一个硬推论——**没被选中的专家，这一批训练里原地不动**。稀疏不是约等于，是精确的零。

### 2.4 硬事实②：Router 的 Wg 对未选中专家依然有梯度

同一 batch、同一强偏配置，看 Router 权重 `Wg` 每一列的 max|梯度|：

```text
B3  同一 batch，Router Wg 各专家列的 max|梯度| = [7.53e-02, 1.25e-01, 3.07e-02, 1.93e-02]
```

**专家 2–4 的 Wf 梯度严格 0，但 Wg 梯度非 0、全是 1e-2 量级。** 为什么？softmax 的分母把所有人耦合在一起：`d_wg` 的正确反向是

```python
d_g  = np.sum(d_x3[..., None, :] * stack, axis=-1) * gmask   # 门控权重梯度（mask 只留选中位）
d_wg = gates * (d_g - np.sum(d_g * gates, axis=-1, keepdims=True))   # 必须用【全】gates
```

`gates` 是全局 softmax 的完整概率，未选中者的概率值通过分母（`-Σd_g·gates`）打进这一项——**Router 这一侧，专家之间是耦合的**。C 段会出现这套账的后果：Wf 被冻结的专家，Wg 一路被推，路由于是滑向"少数专家越膨胀、其他人越闲置"的不归路。

> 本组对账的知识点：把反向写到 1e-9 的关键是**残差直通**。`x3 = x2 + h` 让 `d_x2` 必须包含 `d_x3` 直通、`x2 = x + y_out` 让 `d_x` 必须包含 `d_x2` 直通——两处漏掉任何一处，注意力段全部参数梯度都会错 1e-3 量级，而 Wout/Wf 因留在残差合并前反而正确，**症状藏匿性极强**（ch17 也踩过同一类坑）。

## 3. 负载均衡：aux loss 与"均衡是买来的"

### 3.1 失衡从哪来：B3 不归路的必然结果

B3 说了 Wg 一定把梯度喂给所有专家（软耦合），B2 又说了 Wf 只喂给被选中者（硬冻结）。两件事合起来只有一个去向：**胜者通吃**。裸跑 400 步（无任何约束）验证：

```text
实验 C · 裸跑 400 步（无 aux）→ 门控熵 + 专家载荷
    step  100  loss  2.144  门控熵H=0.215  载荷[0.50, 1.00, 0.14, 0.37]
    step  400  loss  0.063  门控熵H=0.088  载荷[0.44, 1.00, 0.22, 0.34]
  → 门控熵 H: 0.215 → 0.088（均匀界 1.386）；载荷方差 0.0995 → 0.0892
    裸跑 400 步 CE 末值 0.063
```

载荷由近均匀（0.50/0.37/0.14/0.37）演化成**挤向 E2**（载荷 1.00），门控熵从 0.215 一路跌到 0.088（均匀界 ln4=1.386，跌到 1/15 的量级）。这就是论文里"某些专家被饿死"的 toy 版：**不是设计上想让 E2 独大，是 Wg/Wf 的梯度不对称天然把路由推向这里。**

### 3.2 Switch 式均衡 aux：剂量-效应曲线

经典解法是给目标函数加个负载均衡辅助项（Switch Transformer 2021）：

```python
def aux_loss(wg, gmask, alpha=0.01):
    gates = softmax(wg)
    f = gmask.mean(axis=(0, 1))            # 实际载荷占比（硬计数，视常数不直通）
    Pbar = gates.mean(axis=(0, 1))         # 平均门控概率（唯一梯度通路）
    aux = float(alpha * E_NUM * np.sum(f * Pbar))
    d_P = gates * (f[:, None] - np.sum(f * gates, axis=-1, keepdims=True))
    d_wg = alpha * E_NUM * d_P / (Bb * T)
    return aux, f, Pbar, d_wg
```

直觉：`f_e·P̄_e` 在"载荷大且门控概率大"时高，惩罚它 → Router 被推向均匀。**关键工程细节在 f**：载荷不参与直通梯度链（当前专家自己是计数的结果），`P̄` 才是唯一梯度通路——否则会引入跨 token 的高阶耦合，训练就不稳。Switch 论文 α=0.01 相对"数万亿 token"的规模调过，本玩具 400 步等不到那个量级——**先把剂量-效应扫出来再定演示强度**（0 / 0.03 / 0.10 / 0.30 四档扫描，选定 α=0.10，注释写明"演示强度"）：

```text
实验 D · 同种子同起点 + Switch 均衡 aux(α=0.10) → 400 步对照
    step  100  CE 2.356 (含aux 2.678)  门控熵H=0.931  载荷[0.52, 0.98, 0.09, 0.40]
    step  400  CE 0.053 (含aux 0.264)  门控熵H=1.292  载荷[0.59, 0.71, 0.36, 0.34]
  → 门控熵 H: 0.931 → 1.292（均匀界 1.386）
    载荷方差 0.0892(裸) → 0.0247(+aux) · CE 末值 0.063(裸) → 0.053(+aux)
```

对照 C/D 两个 400 步，一条剂量-效应读法：

| 指标 | C（裸） | D（+α=0.10） | 方向 |
|---|---|---|---|
| 门控熵（末） | 0.088 | 1.292 | 大幅回升，贴均匀界 |
| 载荷方差（末） | 0.0892 | 0.0247 | 压到 1/3.6 |
| 载荷形态（末） | `[0.44, 1.00, 0.22, 0.34]`（E2 一骑绝尘） | `[0.59, 0.71, 0.36, 0.34]`（全被用上） | 摊平 |

### 3.3 "均衡是买来的"：代价写在哪本账

诚实地说，**aux 不是免费的**。这句话在这个 toy 上有两层，一层看 CE，一层看总目标：

1. **CE 反而略降**（0.063 → 0.053）——四位专家都被用上、拟合更充分。别因此误读成"均衡白赚"。
2. **优化目标里多了一块 aux 项**：step400 时总损失 `CE+aux = 0.264`，而裸跑全局只有 `0.063`——**训练预算被均衡分走了一大截**。这才是"买"的账本。

而真实大模型的账本和 toy 相反（理由见 §11）：数据足够多时，"拟合更充分"的红利吃不到，aux 常常伴随**最终 loss / 训练效率的轻微上升**——所以 DeepSeek-V3（2024-12）专门改用了 **『无辅助损失的负载均衡』**：给每个专家维护一个偏置 bias，前向时按载荷动态加减、反向时 bias 只收载荷反馈不收 loss 梯度——**同一目标、省掉 aux 全部开销**。路线是对的，手段是越来越轻。

## 4. 专家专业化：分工是学出来的，不是设计出来的

装卸工直觉会问：MoE 到底把什么"分"给了谁？答案必须在语料上分组找。本玩具给 77 句打了主题标签（0=通用，1–6=六组知识：g≈9.8 / π≈3.14 / e≈2.72 / 光速≈300000 / 沸点=100 / 公转≈365），训练后按主题统计各自 token 的路由份额：

```text
实验 E · 专家专业化：6 组知识 + 通用句 → 谁偏向了谁（裸模型 vs +aux 模型）
  [公转365 ] 裸  E1:0.19 E2:0.50 E3:0.10 E4:0.21  → 主投2(50%)
          +aux E1:0.31 E2:0.27 E3:0.20 E4:0.22  → 主投1(31%)
  [π≈3.14 ] 裸  E1:0.19 E2:0.50 E3:0.04 E4:0.27  → 主投2(50%)
          +aux E1:0.32 E2:0.30 E3:0.18 E4:0.20  → 主投1(32%)
  [光速    ] 裸  E1:0.10 E2:0.46 E3:0.12 E4:0.32  → 主投2(46%)
          +aux E1:0.04 E2:0.37 E3:0.25 E4:0.35  → 主投2(37%) / E4(35%)
```

两张表的读法完全不同：

- **裸模型**：所有主题行都主投 E2（46–50%），行间差异被集中掩盖——E 段和 C 段是同一个故事的两种观测：**路由失衡 → 载荷挤爆一两家 → 其它专家的差异根本没机会露出来**。
- **+aux 模型**：各主题行被摊开，主投专家出现分化（公转→E1、π→E1、光速→E2/E4……），E3/E4 的占比明显起来。**分工是在 aux 的保护下（防止饿死）才"学出来"的。**

这直接解释了 DeepSeek 系为什么引入『**共享专家**』：均衡 aux 负责"保命"（没人被饿死），再额外留一个 **always-on 的通用专家**专门承载跨主题语法与通用模式，路由专家们就彻底解放出来、专心分化成领域专家。**共享 = 把"通用"与"专用"分开记账，各得其所。**

## 5. Dense vs MoE 怎么选（含诚实结论）

### 5.1 决策表（知识地图 §2.15 落地）

| 维度 | Dense | MoE |
|---|---|---|
| 结构 | 每个 token 过全部参数 | 每个 token 只过 Top-k 专家 |
| 总参数/激活参数 | 相同 | 总参数远大于激活参数 |
| 单 token 推理成本 | 高（全算） | 低（只算激活部分） |
| 显存占用 | 相对小 | 大（全量专家须常驻显存） |
| 训练成本 | 随参数线性涨 | 同算力下可做得更大更强 |
| 适合场景 | 中小模型、端侧、延迟敏感 | 超大模型、极致性价比、云端 |
| 代表 | GPT-4（推测）、Llama-3、Qwen3-Dense、Gemma | Mixtral、DeepSeek-V3、Qwen3-MoE、Llama-4、Kimi K2 |

> 2025–2026 趋势：30B 以上开源基本都 MoE 化，Dense 仍是 1B–32B 主力；"MoE 化 + 蒸馏"是开源把大模型做强、再把能力搬回小模型的两条腿。

### 5.2 本玩具的诚实测量：Dense 反而拟合更强

F 段做同激活对照——**Dense（4C 全激活） vs MoE（E=4 × 每专家 2C，总参 2×、激活参数恒等）**，同一个种子、同一语料、各 400 步：

```text
实验 F · 同激活算力：Dense vs MoE
    Dense step  400  loss  0.035
  MoE(裸) CE 末值 0.063 vs Dense 0.035
  全新句式 top-1 命中：MoE 5/6 · Dense 5/6
    e≈2.718  期望首tok=「2」 MoE✅  Dense❌（答"9"）
    光速      期望首tok=「300000」 MoE❌（答"2"） Dense✅
  → 诚实结论：本玩具规模下 Dense 反而拟合更强（CE 0.035 < MoE 0.063），
    泛化持平（5/6·5/6 平手）——MoE 的收益不是更低 loss，而是更大的参数容量
```

把结果说透，不掺水：

1. **同激活下，Dense 训练 loss 更低（0.035 < 0.063）**。这完全不该是 bug 不是例外——MoE 的 2× 参数只"驻留"不"激活"，浪费在玩具数据上毫无价值（数据量太小，参数容量没有用武之地）。
2. **全新句式泛化 5/6 对 5/6 打平**；且两人错的方向不同（e→MoE 对着 Dense 错；光速→Dense 对着 MoE 错）——模型间没有"谁天赋更高"，各有各的盲区。
3. **结论的阶级性**：MoE 的收益在"**参数容量 → 数据足够多时才兑现**"。真实世界动辄 1T+ token，超大 MoE 让 671B 参数以 37B 激活的算力预算去吸收 1T 语料——这时 §1 的账本才真正被用满。**玩具让人看清机制，不代表玩具复刻了卖点**（§11 诚实声明第 2 条）。

## 6. 现实架构：共享专家 / 细粒度专家 / MLA / FP8 / EP 与显存

### 6.1 共享专家（Shared Expert）：通用/专用分账

`04-MLA` 章那个 DeepSeek 的反复出现又来了。V2/V3 的 FFN 结构是 **N 个细粒度路由专家 + 1 个 always-on 共享专家**：每个 token 激活"共享专家 + Top-8 路由专家"。共享专家承载语法、通用模式（§4 末已推演），路由专家专心做领域分化——顺带缓解了 aux 的分裂压力。

### 6.2 细粒度专家（Fine-grained Experts）：把专家切小

把"少数巨无霸专家"改成"大量细粒度专家（如 256 个）再加 Top-8"，组合自由度从"选 2 个大块"变成"拼 8 个小块"。小组合的假设空间更细腻：不同领域的相似子模式可以**部分共享**，这是 DeepSeek-V2 报告里"更小专家数量反而效果更好（4×→8×）"的工程依据。本玩具 E=4·M=2C 就是把"细粒度"往小的方向走了一步。

### 6.3 MLA：KV 是 MoE 的邻居账

`04-MLA-多头潜注意力` 与 MoE 是 DeepSeek-V2 的双连（报告标题直呼 *MLA+MoE，the next frontier*）：MLA 压 KV 显存、MoE 压 FLOPs，两位一起把"单请求显存 + 单 token 算力"同时打薄——这是"极致性价比"路线的一对核心搭档。

### 6.4 Expert Parallel（EP）：显存放不下时的抄盘手

MoE 总参常驻显存，远超单卡。EP 把不同专家分到不同 GPU：**每个 token 在该层都要把激活向量广播给所有含它专家所在卡（All-to-All），聚合后再回来**。通信量 ∝ token 数 × 专家数，于是在层次薄路由薄、层多专家多时，通信就变成瓶颈——这也正是 vLLM 在 2025 年推出 **EP 推理优化**（比早期版本实用化）的原因。显存通条链：EP 摊专家 → 通信上升 → 细粒度/共享专家在降低单请求成本的同时压低通信规模。

### 6.5 FP8：训练与推理的账一起做

DeepSeek-V3 是首个全面 FP8 预训练的大模型（参数/激活/梯度混合精度），把"671B 总参 + 1T+ token"这台巨型训练机压进预算。FP8 是 MoE 时代规模主线的另一条腿：**参数越大，越低比特的代表越省**。

## 7. 演化链与模型账表

```text
Shazeer 2017（稀疏门控 MoE 鼻祖：softmax Router + Top-k —— 本玩具 B 段的直接出处）
  → GShard / Switch Transformer 2021（MoE 进大规模 Transformer；Switch = Top-1 + aux loss）
  → Mixtral-8x7B 2023（首个开源走红：8 选 2，47B 总/13B 激活）
  → DeepSeek-V2 2024（MLA + 细粒度专家的双连，MoE 极致化样板）
  → DeepSeek-V3 2024-12（671B/37B ≈5% 活跃 · FP8 训练 · MTP · 无辅助损失 bias 均衡）
  → Qwen3-MoE 2025（30B-A3B / 235B-A22B，开两条腿卖）
  → Llama-4 2025（原生多模态 MoE，Scout 109B-A17B / Maverick 400B-A17B）
```

读法（知识地图的"八要素"提醒）：不要背参数，按统一框架拆任一模型——**架构 → Attention → FFN/MoE → 训练 → 推理 → 上下文 → 多模态 → Reasoning**。MoE 只是八要素里第 3 格的一种分支；DeepSeek-V3 的完整配置是"MLA + 细粒度 MoE + 共享 + FP8 + MTP + 无 aux 均衡 + GRPO"，七件套彼此咬合。

## 8. 常见坑

1. **看参数不看 Active Params**。看到 671B 就报"贵"，不知道它是 37B 激活的性价比选手；反过来把"总参倍数"当"算力倍数"也是同一类错误。**先看激活参数，再看总参量级。**
2. **把 top-k 硬选当光滑层反传**。若把 0/1 掩码当指示函数直接求导，导数几乎处处为 0（只在翻转点为冲击、无定义），会把 Router 的梯度整个抹掉——Wg 的梯度必须来自 softmax 门控（B3 的耦合正是这么保住的）；对账/分析则必须冻结路由拓扑跳过翻转点（本玩具 B1 的诚实限定）。
3. **误以为"未选中专家没被训练"= 路由没问题**。B3 已证明 Wg 对每个专家都保留梯度（softmax 分母耦合）——**这恰恰是失衡的养分之一**，需要在训练里显式防（aux / bias 均衡）。
4. **aux 开小了白开、开大了伤身**。α 有剂量-效应（§3.2 扫描）；玩具需要放大到 0.10 才看得到，真实规模沿用 Switch π 的 0.01。**宣称"加 aux 没效果"前先确认剂量，并同时记录 CE 与 CE+aux 两本账。**
5. **把 toy 上"aux 使 CE 还降"外推成"均衡免费"**。toy 的红利是"全专家被用上、拟合更充分"；真实大数据下 aux 常伴随最终 loss/效率轻微让步——DeepSeek-V3 换 bias 调节正是为了省掉这份 aux 开销（§3.3 / §11）。
6. **把 toy 上"Dense 拟合更强"外推成"MoE 没用"**。MoE 的卖点不在 loss 更低，在参数容量 + 数据足够多时的兑现（§5.2 结论 3）——两个方向的外推都要加引号。
7. **忽略 Expert Parallel 的通信账**。模型越好、专家越多，All-to-All 通信越痛；"越窄越细的专家组合 + GPU 拓扑"是推理框架（vLLM）里真正的战场。

## 10. 衔接下一章：推理模型与 Test-time Scaling、Dense-vs-MoE 选型

MoE 讲完的是"**横向把参数摊薄**"：同算力、更大参数、激活 5%–30%。下一条主线是"**纵向把答案想深**"——推理模型 / Test-time Scaling（`20`）：

- MoE 改变了推理成本结构：**算力不随总参涨，省下来的预算正好投给 test-time 的思考 token**——`Qwen3-30B-A3B` 这类 30B 总/3B 激活的 MoE 在推理任务上会正面挑战更大 Dense，这就是"纵向"吃掉了"横向"红利的例子。
- **Dense-vs-MoE 选型**（§2.15）与"推理模型"交叠成一个三选决策：同预算下，Dense 大窗 vs MoE 大参数 vs 推理预算，怎么分？这是 2025–2026 架构选型真正的成本问题。
- 两者共享同一条测量哲学：**看激活不看总参、看推理时算力投向不看前向 FLOPs**——本玩具 §1 的账本在推理模型章节继续当尺子。

## 11. 诚实声明：四件套 + 一次测量教训

1. **这是 0.18M 级玩具，不是 671B。** MoE 的价值（大数据下参数容量的兑现）在玩具上恰恰相反（Dense 拟合更强，§5.2）。全文的"机制"（路由、aux、梯度不对称、专业化）是真实模型的缩小版，**所有收益性结论必须带"大数据才兑现"的引号**。
2. **真实模型的参数账是"公开配置换算式"，不是本机实测。** Mixtral 47B/13B、DS-V3 671B/37B 来自官方发布与社区规格的换算（8 选 2 = ×1/4 之类），不是我们用真实权重跑出来的。凡此数字，正文都标了"非本机实测"。
3. **α=0.10 是演示强度，不是 Switch 论文的 α=0.01。** 剂量随规模缩放（§3.2 扫描）；把"0.10 才起效"外推到真实模型是错的。同为玩具，CE 略降的效应（§3.3）不能当作"均衡无代价"的证据——真实的代价在 CE+aux 总目标，以及大数据下 aux 的轻微走损。
4. **语料是 77 句声明式知识，无对话、无代码、无长依赖。** 6 组知识仅 33 句（组内 5–6 句），E 段专业化只能看到"摊平"级别的分化；更尖锐的"领域分家"需要更多同主题语料（§9 任务 2）。泛化数据（5/6 对 5/6）只证明"句式措辞不变时两模型都能抓到知识锚"，不证明推理能力高低。

5. **一次测量教训：断了残差、报错却先在远段。** 全模型对账早期 Wo/Wpos/Wte 全线错 1e-3 量级、而 Wout/Wf/Wg 全对——若不先隔离，很自然会以为是"注意力公式写错了"。本批用**先独立分块**定位：单独验证 MoE-FFN 段（max|num−手写| = 1.76e-12）与极简 attention 标准公式（3.28e-12）两项都干净，于是把怀疑点缩到两块拼接处，最终钉住两处**残差直通被漏**：`x3 = x2 + h` 的 `d_x2` 必须含 `d_x3` 直通、`x2 = x + y_out` 的 `d_x` 必须含 `d_x2` 直通——都补上之后全参数 ≤ 1.3e-9。这个教训写进正文，是因为症状**藏匿性极强**：残差合并之前就算完的参数（Wout/Wf）天然正确，只有穿过残差回传的参数（注意力全组 + Wpos/Wte）被污染，单看错项会一路追进注意力公式的歧路。
