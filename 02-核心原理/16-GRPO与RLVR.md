## 0. 为什么还要"砍掉 critic"：GRPO 改的是价值网络这一层

`14` 章把 RLHF 讲完时，账本上有三份驻留：

```text
RLHF 的三份资产（玩具实测驻留参数）：
  策略         163,392      （被优化的那个）
  冻结参考 π_ref  163,392      （"离 SFT 多远"的锚，corpus 自适应）
  RM 奖励模型    139,393      （学出来的裁判，判别率只有 79%）
  ─────────────────────────────────
  合计 ≈ 62.9 万，外加每步在线 rollout（采样→打分）与一堆 RL 超参
```

`15` 章把 **RM 和在线采样** 一起省了（DPO 家族只吃一份离线偏好对）。但 RLHF 工程里还有一个常被忽略的重资产：**PPO 的价值网络（critic）**。PPO 的 advantage `Â_t = r + γV(s') − V(s)` 需要一个学出来的 `V(s)` 来当"这个状态接下来能拿多少"的基线；critic 是又一个可训练模型，又要驻留、又要每一步跟着学。

DeepSeekMath (2024) 的 GRPO（Group Relative Policy Optimization）问的是：**如果 baseline 的目的只是"消掉'这个问题整体好坏'的偏移、保留'组内谁更好'的信号"，为什么不能让 K 条回答自己当彼此的基线？** 于是 GRPO 的结构长这样：

| 组件 | PPO (ch14 里的 RLHF) | GRPO |
|---|---|---|
| 基线 / advantage | 价值网络 `V(s)`（要训） | **K 条回答的组内均值**（白拿） |
| 驻留模型 | 策略 + 参考 + RM + critic | **策略 + 冻结参考**（无 critic、无 RM） |
| 采样 | 在线 rollout | 在线 rollout（照样要） |
| 奖励来源 | 学出来的 RM（判别率 79%） | **规则**（RLVR，零训练） |

玩具里 GRPO 的驻留是本批最轻的：**策略 + 冻结参考 = 326,784 参数**，对比 RLHF 的 ≈629,569——省掉的不只是显存，是"价值网络 + 裁判"一整条训练与维护链。

> 一句话（为什么还有本章）：**DPO 家族省掉"裁判和在线"，GRPO/RLVR 再省掉"价值网络和裁判本体"——对齐的每一块重资产都有人拆，拆到极致就是 R1 那套"规则判对错 + 组内相对优势"。**

## 1. GRPO 核心：K 条回答组成一组，组内归一就是 advantage

GRPO 每步对**同一个问题**采样 K 条回答（`K=8`，`G=4` 组 → 每步 32 条采样），然后定义组内归一化的 advantage：

```text
组内相对优势：
  A_i = (r_i − r̄_group) / (σ_group + ε)
```

- `r̄_group` 是这 K 条回答的平均奖励：它把"这题本身是简单还是难、整体普遍能拿几分"消掉；
- `σ_group` 把不同问题间的奖励尺度对齐——一题全是 3 分和一题全是 1 分，advantage 的尺度相同；
- 于是模型学到的信号就是纯素的"**在这题、这组的语境下，我比我还差的那几条好多少**"。

这跟 `14` 章 REINFORCE 的均值基线是同一族思想（减基线压方差），但有一个本质差异：**REINFORCE 的均值基线是全局的**（所有问题混在一起平均），简单题整体偏高、难题整体偏低，基线会偏；**GRPO 的基线是逐题的**——每个问题自己有 K 条回答当参照，没有跨题污染。`15` 章的 DPO 把 batch 里的参照点搬进池均值（KTO 的 `z_ref`）就吃了批质量不稳的亏；GRPO 的参照点锁死在问题内部，不存在"被别的题拉偏"。

玩具里这一层直接可测：K 太小，组内基线噪声大，默认 K=8 起逐步扫（§6，K=2 全新问 69% → K=16 到 78%）。**组内回答数是 GRPO 的"视野半径"：半径越大，'谁更好' 看得越准，但采样账单也线性变长。**

## 2. RLVR 核心：裁判从"学出来的 RM"变成"规则断言"

RLVR（Reinforcement Learning with Verifiable Rewards）回答的是 `15` 章末尾埋的那个箱子：**奖励信号从哪来？**

- RLHF：奖励来自一个**学出来的 RM**——从偏好对里学"哪条答案更像被喜欢的"，判别率 79%（`14` 章留出实测）。它是**猜**裁判：可能判错、可能被过优化骗（Gao et al. 2023）。
- RLVR：奖励来自**一条规则断言**——数学答案是否等于标准解、代码是否通过测试、SQL 结果集是否相等、JSON 是否符合 schema。零训练、零驻留、不可能"被骗到长得像"。

玩具里我们把判官直接搬成 `14/15` 章同款 **三票 judge**（它就是"规则"）：

```text
规则三票（RLVR 玩具版）：
  v1 答得对：答案首 token == 标准答案首 token        → 对/错
  v2 答得全：按序覆盖标准答案 ≥ 半数（逐位顺序匹配）   → 对/错
  v3 答得干净：一个词都不碰该问的"污染词表"（别的知识词=脏） → 对/错
  奖励 r = v1 + v2 + v3 ∈ {0,1,2,3}   二值版：只有 r==3 → 1
```

**B 段实测**：同一个 SFT 起手，把这三条规则直接数命中率，零训练：

```text
SFT 起手 · 训练问三条规则命中：答得对 100% · 答得全 100% · 答得干净 63% · r均 2.63/3
SFT 起手 · 全新问三条规则命中：答得对 100% · 答得全  83% · 答得干净 52% · r均 2.36/3
```

两份账一次读完：
1. **训练问的真正短板只剩"答得干净"**（63%）——v1/v2 已经 100%，因为模型的回答几乎总是首 token 正确且覆盖足够。所以"三票奖励在训练问上"本质上只剩"别带脏尾巴"这一个自由度。
2. **全新问是泛化前沿**（v1 100% / v2 83% / v3 52%，r 2.36）——换了问法后"答得全"和"答得干净"都开始漏，**规则还有 0.64 分的肉**。GRPO 的任务，就是拿这份零训练的规则，去推这两个缺口。

这跟真实 R1 的 rule-based RM 是同一件事的两种实例：数学题比对"最终答案是否等于标准解"、代码题比对"能否通过测试用例"、格式规则（保险起见只给"Yes/No"+ 思考过程分节）——**都是一条 if/else，不需要一个模型来学"什么叫好"。**

> 一句话（RLVR 的第一次账）：**RM 要训 500 步、驻留 13.9 万、判别率只有 79%；规则三票零训练零驻留，直接在 SFT 起手就把"训练问的短板"和"全新问的肉"都量给模型看——裁判费变成零。**

## 3. 实测 GRPO + RLVR：C 三票 / D 二值 / E 去锚

底盘与 `14/15` 章完全同源：同一个 0.18M 参数 1-block 引擎、同一份 47 句语料预训练、同一份 200 步 SFT 起手（**基线 62% / 38% 逐位对齐前两章**）。三个 arm 从同一 `p_sft` 出发：

| arm | 奖励 | β（KL 系数） | 步数 | 种子 |
|---|---|---|---|---|
| **C** | 三票 r=0/1/2/3 | 0.1 | 250 | 20 |
| **D** | 二值（只有 r=3 → 1） | 0.1 | 200 | 21 |
| **E** | 三票（**去锚** β=0） | 0.0 | 200 | 22 |

共同配置：`K=8 · G=4`（每步 32 采样）、`ε(PPO clip)=0.2`、`U=2` 内循环、`lr=3e-4` 预热 50 步、冻结参考 π_ref=p_sft。实测输出：

```text
C · GRPO（可验证奖励 · 三票 r=0/1/2/3）· β=0.1 · 250 步
  规则奖励曲线(训练问均值 r)：1:2.70 → 50:3.00 → 100:3.00 → 150:3.00 → 200:3.00 → 250:3.00
  perfect 率：训练问 100%（前 62%）· 全新问 83%（前 38%） · KL→SFT 1.33
  末步统计：训练问平均 r 3.00 · mean|A| 0.00 · clip 命中率 0% · 回答区 KL/token 0.27
  耗时 156s

D · GRPO（二值奖励：只有 r=3 算 1）· β=0.1 · 200 步
  规则奖励曲线(训练问均值 r)：1:1.37 → 50:1.87 → 100:1.87 → 150:1.90 → 200:1.90
  perfect 率：训练问 10%（前 62%）· 全新问 0%（前 38%） · KL→SFT 2.66
  末步统计：训练问平均 r 1.75 · mean|A| 0.00 · clip 命中率 0% · 回答区 KL/token 0.15
  耗时 150s

E · GRPO（去锚：β=0 无 KL 安全带）· 200 步
  规则奖励曲线(训练问均值 r)：1:2.67 → 50:3.00 → 100:2.97 → 150:3.00 → 200:2.90
  perfect 率：训练问 96%（前 62%）· 全新问 82%（前 38%） · KL→SFT 无锚(β=0)
  末步统计：训练问平均 r 2.25 · mean|A| 0.00 · clip 命中率 0% · 回答区 KL/token 0.58
  耗时 140s
```

三臂两个对照，一正一反：

**C vs E：KL 安全带在你"不需要它有"时也在干活。** 去锚的 E 在 200 步几乎追平 C（96/82 vs 100/83）——这个结果**必须诚实读**：玩具里奖励=裁判真值（不是判别率 79% 的 RM），没有"RM 可被骗"的缝隙，所以去锚不会立刻灾难。但这不代表锚没用：**回答区 KL/token，C 是 0.27，E 是 0.58**——隔着"离 SFT 多远"的距离账，C 把策略钉得更近。真实世界两个条件（RM 判断有错 + 长程优化压力）都存在时，这条带的角色才显形（`14` 章 β=0 的诚实结论在这里原样重建）。

**C vs D：奖励密度比你想的凶。** 把三票 `r=0/1/2/3` 压成二值 `r==3→1`，同样是 β=0.1、同样 200+ 步，D 几乎原地：训练问 10%、全新问 0%，而且 KL 反而飘到 2.66（比 C 的 1.33 还高——稀疏信号下策略不是"不动"，是**在噪声里漂**）。三票给"答得对"和"答得全"也发学分红利，二值只给"全对"发——而全对在 SFT 起手只有 63% 干净（训练问 v3），模型收不到足够多的正梯度。**这不是"更难的奖励更好"，是"更稀疏的奖励更学不动"。**

> 一句话（实测 C-D-E）：**同一次可验证奖励、同一个起手，三票 GRPO 训练 62→100%、全新 38→83%、KL 1.33；换二值就只剩 10%/0%；把 KL 摘了就 96/82（贴 C 但不守漂移账）——奖励密度是本段最凶的开关。**

## 4. 梯度怎么落地：精确 KL 梯度 + 一个会把策略推出去的符号坑

工程实现沿 `15` 章的 mask 惯例：引擎 `backward` 返回 `Σ mask·(−logp)` 的梯度，**想下降/上升某个量 L，mask 取 −(∂L/∂logp)**。GRPO 的 d_logits 由两块拼成：

```text
d_logits = (p − onehot) · mask_PG +  d_KL

① 策略梯度（升奖励）：mask_PG = +A_i·(ratio_i) ·(是否 clip)
   下降 −Â·ρ·logπ ⇔ 升 Â·ρ·logπ；clip（Â>0 且 ρ>1+ε，或 Â<0 且 ρ<1−ε）时系数归零
② KL 惩罚（贴近 SFT 锚）：d_KL = +β·p·(f − K̄)
   这是精确 KL 梯度的落地点，见下
```

**KL 这一项是本章最大的坑**，可以展开写：

对单 token 的类别分布，`KL(p‖q) = Σ_b p_b (log p_b − log q_b)`。把它对 logits z 求导，需要用恒等式 `∂p_c/∂z_b = p_c (δ_cb − p_b)`，一条链下来得到**精确解**：

```text
f   = 1 + log p − log q              （逐类）
K̄   = Σ p·f = 1 + KL                 （p 下的期望）
∇z KL = p·(f − K̄) = p·( log(p/q) − KL )
```

有限差分对账：解析 −0.1540 vs 中心差分 −0.1519，同 `12/15` 章的精度规格。**符号**：托引擎"adam 下降"的福，要**下降 β·KL**，喂给引擎的 d_logits 必须是 **+β·p·(f−K̄)**：

```python
dkl = +beta_k * pv * (f - Kbar)   # 符号写反 = 最大化 KL，策略被推出 SFT 锚外
```

`−β·p·(f−K̄)` 会**最大化** KL。这不是纸上谈兵——run1 就是整批踩过：C/D 两臂 KL 冲到 197–209（策略被推离 SFT 锚后 PG 塌成 1 条退化回答，三票 0/0），而 E（β=0，没有这一项）却一切正常——**正好把锅炸到这一项的符号上**；改回 `+β·p·(f−K̄)` 后 C 走到 100/83、KL 1.33（§3）。落地规范：
1. 只对**回答区**加 mask（问题区不该挨 KL——那是 SFT 已学会的"问法"）；
2. 前 50 步打印 KL 方向，升了就是符号反了。

> 一句话（梯度段）：**PG 部分沿 ch15 的 mask 惯例（`mask=+Â·ρ·(未clip)`），KL 精确梯度 `∇zKL=p·(log(p/q)−KL)` 落地时是 +β 符号——负号会把策略推出锚外，run1 三臂对照实锤。**

## 5. 同台对照：RLHF / DPO 家族 / GRPO 一张 H 表

用同一份评估口径（全新问三票 `RandomState(3)` n=20、KL seed=5 60 采样），把 `14/15/16` 三章的 arm 拉进一张表（ch14/15 数字从各自 canonical 输出抄录，ch16 来自 F 段输出）：

```text
方法                        训练问三票     全新问三票   KL→SFT      墙钟
SFT 基线                      62%      38%      0.00       —
RLHF (C14)                    70%      67%     10.65    153s（整脚本）
DPO (β=0.5)                  93%      72%      2.72     30s
IPO (m=2.0)                  93%      82%      3.07     30s
KTO (β=0.5)                  93%      65%      9.02     35s
ORPO (λ=1.0)                 97%      78%        免      23s
SimPO (β=2)                  87%      67%        免      23s
GRPO 三票 (C)               100%      83%      1.33    156s
GRPO 二值 (D)                10%       0%      2.66    150s
GRPO 去锚 (E)                96%      82%        无锚    140s
```

横着读三层：

1. **全新问三票（谁能把没见过的题答好）**：GRPO-三票 `83%` 登顶，其次 IPO 82% / E 82% / ORPO 78% / DPO 72% / RLHF 67%。GRPO 比 RLHF 高 16pp、比 DPO 家族最好的还高 1pp——**而且它从头到尾没见过任何"偏好对"或"留出标注"，唯一的信号是规则断言。**
2. **KL→SFT（离起手多远）**：GRPO-三票 `1.33` 全场最紧（RLHF 10.65、DPO 2.72、KTO 9.02），说明它在"把问题答对"的同时，几乎没跑偏出 SFT——这是"规则奖励天然指向唯一正确答案"的形状优势。
3. **墙钟与驻留**：GRPO 需要一个在线采样 loop（每步 32 条），一段就 156s，是 DPO 家族单段的 5-7 倍、和 RLHF 的 RL 段同档——**省的帖子在"资产"（不驻留 RM/critic），不在"算力"（在线采样照付）**。DPO 家族才是省算力的那家，但它是**离线**（吃偏好对）；GRPO 是**在线 + 免裁判**。三条路线的代价结构互不重叠：

| 路线 | 免什么 | 付什么 | 玩具全新问 |
|---|---|---|---|
| RLHF (ch14) | 无 | RM+critic 驻留、在线采样、偏好对 | 67% |
| DPO 家族 (ch15) | RM+在线采样 | 偏好对（383 组）、一份参考 | 65–82% |
| **GRPO (本章)** | RM+critic | **在线采样**（每步 32 条）、可验证规则 | **83%** |

> 一句话（H 表）：**同一起跑线上，免全部裁判类资产的 GRPO 交出最高全新问三票和最紧 KL——但前提是奖励真的可验证、真的能免费数对错。**

## 6. 旋钮晾衣线：K / β / 奖励密度，谁最凶

用临时探针（`_probe_grpo.py`，150 步口径、独立种子每 arm、共用一份 62/38 的 SFT 起手）扫三根旋钮（**读趋势用，逐位以 §3/§5 主表为准**）：

```text
第一轮 · K 组内回答数（β=0.1）
  K=2  → 全新 69% · KL 0.8      ← 基线噪声大
  K=8  → 全新 72% · KL 1.6
  K=16 → 全新 78% · KL 1.1      ← 视野越宽越准，账单线性涨

第二轮 · β KL 系数（K=8）
  β=0    → 全新 84% · 无锚       ← 玩具里"不用带"反而跑得快（见 §7）
  β=0.05 → 全新 75% · KL 1.2
  β=0.1  → 全新 78% · KL 1.4     ← canonical
  β=0.3  → 全新 69% · KL 1.0     ← 安全带勒太紧，学不动

第三轮 · 奖励密度（K=8 · β=0.1）
  r三票  → 全新 83% · KL 1.1     ← 给部分学分
  r二值  → 全新  0% · KL 4.6     ← 只给全对发钱：几乎学不动还漂
```

三根线的教训：

1. **K 是单调的"精度旋钮"**：2→8→16，全新 69→72→78%，组内基线越准、advantage 越稳。代价 = 采样算力线性涨（K=16 每步 64 条 vs K=2 的 8 条）。真实管线里 K 也是显存/吞吐直接挂钩的常数（verl/TRL 的 `n_samples_per_prompt`）。
2. **β 不是单调的**：0.3 反而掉（勒死），0.05/0.1 之间只有噪声级差异——玩具的"优区"落在 β≈0.1 上下。注意 **β=0 在 150 步里跑得最快（84%）**：这是玩具的诚实图景，不是现实（§7 展开）。
3. **奖励密度是全场最凶**：三票 83% vs 二值 0%，差 83pp——比 K 从 2 拉到 16（+9pp）和 β 全区间（±15pp）都猛。**RLVR 设计的第一优先不是旋钮，是把"对/错"拆成"部分学分"。** R1 实际就是这么拆的：正确性奖励 + 格式奖励两条规则的加权，而不是单点 0/1。

## 7. 诚实声明：玩具里的 RLVR 优势被高估了

本章数字很漂亮（C 100/83、KL 1.33），但必须把五条限定词写死，否则读者会拿去过度外推：

1. **玩具的"RLVR"= 裁判真值，GRPO 对 RLHF 的优势在此被系统性高估。** RLHF 的 RM 只有 79% 判别率（ch14 留出），会判错；三票 judge 是公式，永远判对。真实世界只有数学/代码/SQL 这类"答案可验证"的场景才有这份免费裁判；凡是规则测不全的（开放问答、创意写作），RLVR 就退回"规则+近似"。所以**别把"GRPO 打败 RLHF"读成一般性定理**——它在这个玩具里更多是"弃用裁判成本"的胜利（69 万→33 万驻留），是账本层面的赢。
2. **没有 CoT，就没有 R1 式"顿悟"（aha）**。DeepSeek-R1 最惊艳的其实是 RL **长出长思考链**（问题越难想的越长）。玩具回答恒长 8 token、无思维链环节，"长思考"这条主线完全缺席——本章只讲"规则奖励能推动质量"，不讲"思考会涌现"。
3. **没有 EOS → 长度惰性**（同 14/15 章因）：回答恒长，长度偏好/长链奖励都测不出，任何"证明 GRPO 治偏科/治长度"的数字在玩具里都不存在。
4. **KL 安全带在玩具"不救分"**：β=0（E）全新 82% 与 β=0.1（C）83% 几乎一样，去锚没崩是因为没 RM 可骗。但漂移账在（回答区 KL/token 0.58 vs 0.27）；真实世界过优化曲线（Gao et al. 2023）的两个条件——RM 判别有错 + 长程优化压力——这里都不具备。**"β 是安全带"是从别处继承的结论，不是本章实测的结论。**
5. **训练问已饱和**：B 段 v1=v2=100%，三票在训练问上只剩"干净票"（63%）；所以 C 的"训练问 100%"主要来自把脏尾巴治干净，真正的泛化英雄在全新问（38→83%）。写任何"GRPO 全面变强"前，先分训练/全新两半再说话。

> 一句话（诚实声明）：**这份实验证明的是"规则奖励 + 组内归一能把已会题答干净、把全新问推高"，以及"奖励密度 > 旋钮"；它不证明没有 RM 可骗的世界里 KL 没用，也不证明思考链会涌现。**

## 8. 放大账：玩具 → DeepSeek-R1 的真实 GRPO+RLVR 管线

玩具一行是 0.18M 参数、K=8、2 内循环；真实 R1 是把同一套思想放大几千倍：

**正确的组件对应**：

| 玩具（本章） | 真实 R1 管线 |
|---|---|
| 三票 judge（公式） | rule-based RM：数学答案比对 / 代码测试用例 / 格式正则（思考段、最终答案分节） |
| 冻结参考 π_ref（SFT 锚） | 参考策略（上一步 SFT/上一回合 RL 的策略） |
| per-token 精确 KL 梯度 | per-token KL 惩罚项（实现常用 KL 代理/裁剪估计，玩具用了精确解析式以便讲解） |
| 组内归一整组 advantage | GRPO 官方：组内归一整组 + **滞一步更新**（第 K 条用第 K−1 回的分布更新，省内存，玩具 K=8 未用） |
| 2 内循环 | PPO-ish 多 epoch + clip ε=0.2 |

**R1 的流水线骨架（公开已知结构）**：seed 数据冷启动（少量长 CoT exemplar 的 SFT 起手）→ RL 第一回合（rule RM：正确性 + 格式）→ 第二轮 SFT 汇入（收敛后把 RL 出的好样本回炉当 SFT 数据）→ 再两回合 RL（交替提升）→ 最后合成数据 + 全科 SFT 收口。关键在**规则先于模型**：R1 从不训练一个"数对错的 NN"，对错由测试用例/标准解当场判定——这正是 RLVR 在 §2 那层"零训练裁判"的规模版。

**成本账本（玩具侧实测口径）**：GRPO 驻留 326,784（策略+参考），对比 RLHF ≈629,569——省的是"资产"，但**在线采样一分不少**（玩具每步 32 条，C 臂 250 步 ≈ 8,000 次采样/问×30）。真实模型这个赤字更大：R1 的 RL 计算大头就是采样推理（rollout），训练 forward/backward 反而是小头。这也解释了为什么 R1 的后训练全是"采样→判对错→只回传对的错"这类吞吐敏感工程，和 DPO 家族"一份离线偏好对就能跑"的算力画像完全不同——**GRPO 用采样算力换掉了裁判成本**。

## 9. 常见坑

| 坑 | 症状 | 对策 |
|---|---|---|
| **KL 符号写反**（本章 run1 实踩） | KL 冲到 197–209、策略塌成退化回答、三票 0/0 | `d_KL = +β·p·(log(p/q)−KL)`（引擎下降语义下"+"号最小化）；前 50 步打印 KL 判方向 |
| KL 不 mask 回答区 | 问题区也被拉离 SFT，问法塌 | 只对 `answer_region` 加 KL/梯度 mask |
| 二值奖励当"更干净"替代 | 玩具全新问 0%（§3 D、§6 三票价差 83pp） | 把"对/错"拆成部分学分（三票/正确性+格式加权）；稀疏奖励是最贵的 |
| β 取太大 | 全新问回吐（β=0.3 → 69%） | 扫 β 晾衣线，玩具优区 ≈0.1；真实从 0.01–0.1 起扫 |
| K 取太小 | 组内基线噪声大（K=2 → 69%） | 平衡采样预算与 advantage 精度；至少 K=8 起 |
| 忘记"训练问已饱和" | 拿训练问三票当真进展（v1/v2 早 100%） | 报告分训练/全新两列，进步只看全新问 |
| 把玩具 KL 结论搬给真实 | "β 没用"（玩具 β=0 反最高） | 玩具无 RM 可骗；真实有 overoptimization，β 是硬安全带 |
| 无 EOS/无 CoT 还谈长度与思考 | 捏造"GRPO 治长度偏置/长出思考" | 诚实声明：回答恒长 8、无思维链，这两个主题测不出 |

## 10. 实践任务：用 TRL / verl 在可验证题上跑 GRPO

`17.2.17` 的实践项是"**用 GRPO 在数学/代码可验证题上对齐一个小模型**"。玩具已把机制讲清，搬到真模型上时刻意选"答案可判对错"的任务，别选开放问答：

```text
目标：Qwen2.5-0.5B（或 SmolLM2-360M）上，数学题 → GRPO → 对比"答案正确率"训练曲线。
① 数据：取 1000 条"构造题"（如 GSM8K 子集），答案裁剪成标准形式（数字/算式），
   让 judge 可以字符串精确比对——这就是你的 rule reward（先保证"可验证"，再谈建模）。
② 采样配置：每个问题采样 8–16 条回答（K），embedding 预算内取大。
③ GRPO（TRL 骨架）：
   trl grpo --model Qwen/Qwen2.5-0.5B \
            --reward_funcs correctness format \
            --n_samples_per_prompt 8 \
            --beta 0.04 --max_steps 200 ...
④ 对照：把 correctness 奖励换成"二值：全对才 1 分"，重跑一遍——
   你会看到（玩具 §3 的规模版）稀疏奖励下正确率曲线更缓、KL 更飘。
⑤ 报告三根线：答案正确率 / KL→参考 / 平均长度——**长度线必须报告**，
   真模型有 EOS，GRPO 的"长思考"可以在这条线上现形（R1 的主线）。
```

> 注：命令为骨架示意，以 TRL / verl 当前文档为准。跑完把三根线抄回玩具核对：奖励密度关过没有？K 和 β 扫的哪档最好？长度线是长了还是偏了？——玩具里的每一个限定词在真实模型上有对应物，唯独"长度惰性"在真模型上会解除，正好是接上"推理模型"那章的门。

## 11. 衔接下一章：推理模型与 Test-time Scaling

GRPO/RLVR 是训练侧的第一根杠杆：**让模型在"奖励可验证"的世界里学会把概率往"对"上押**（玩具全新问 38→83%）。但 R1 真正轰动的另一半，是"押对概率"生长成了"多算几步再回答"——**思考链的长度第一次成了训练出来的、可消费的资产**。`17.2.20` 的《推理模型与 Test-time Scaling》接过的正是这根接力棒：

- R1 的 RL 为什么**长出长 CoT**（而不是只调答案概率）？长思考在玩具里测不出（无 EOS），到了真模型上才有对应物；
- **Test-time scaling**：推理时多花计算（长思考/采样多数表决/搜索）换正确率，是训练期 RLVR 的镜像——一条把"计算"换"质量"的曲线；
- 衔接还有平行的两支：`长上下文技术`（思考长了，上下文窗口和 KV 账要跟上）与 `MoE`（R1 671B 的 MoE 推理是"思考算力"工程化的另一半）。

玩具到这里的收尾句：**GRPO 证明了"对齐可以不需要裁判也能向前走"，推理模型那章要看的是"不需要裁判之后，计算到底被花到哪里去了"。**

> 一句话（下章预告）：**GRPO/RLVR 把"奖励"变成规则，推理模型把"思考"变成商品——'对'不再需要人点头，下一步是大模型自己会多算几步再答，而这几步有它自己的成本与杠杆。**
