## 0. 一个公式，三个出身：家族是怎么长出来的

`01-Transformer` 里你见过一次完整的注意力计算——它背后只有一行公式：

$$
\text{att}=\text{softmax}\!\Big(\frac{QK^{\top}}{\sqrt{d_k}}+M\Big),\qquad y=\text{att}\,V
$$

这一章不是讲新公式，而是告诉你：**同一个公式，因为 Q/K/V "出身"不同，就长成了三个不同的成员**。好比同一套做饭流程，食材一变菜名就变：

| 成员 | Q 来自 | K / V 来自 | 一句话直觉 | 用途 |
|---|---|---|---|---|
| **Self** | 序列 A | 序列 A（同一个） | 自己跟自己开会：每个词吸收同句里其它词的信息 | 编码器、解码器的第一层 |
| **Masked** | 序列 A | 序列 A + 因果掩码 M | 开会但不许偷看后面的发言稿 | 任何"生成型"模型的默认 |
| **Cross** | 序列 A | 序列 B（另一个） | 一个来源提问，另一个来源回答 | 多模态桥、编码-解码 |

判断一个注意力是哪一种，**永远先问一句：Q 的向量来自哪，K/V 的向量来自哪？** 来源相同就是 Self（家族里的"我们仨"），来源不同就是 Cross（两拨人的对话），再加上掩码就是三分支的完整划分。

> 全章地图：三个成员共用同一行公式，差异只在"喂进公式的是谁的 Q、谁的 K/V、有没有掩码"。

## 1. Self-Attention：自己跟自己开会

### 1.1 定义与直觉

对同一个输入序列 `x=(x₁,…,x_T)`，三份投影都由它自己产生：

```text
q = x·Wq     ← "我在找什么"（每个位置各自发问）
k = x·Wk     ← "我能提供什么"（每个位置提供线索）
v = x·Wv     ← "找到后给什么内容"（每个位置的实体内容）
att_ij = softmax(qᵢ·kⱼ/√d)           ← 位置 i 问位置 j：你跟我相关吗？
yᵢ     = Σ_j att_ij · vⱼ              ← 按相关度收集大家的内容
```

关键点：**`att` 矩阵的每一行都来自同一条序列，但每一行可以"看"所有位置。** 这让长距离信息不用经过中间跳转——`01` 篇第 0 节说过这正是 RNN 被替代的原因。

### 1.2 复杂度：为什么 Self 天生 O(T²)

看形状就明白：第 `i` 行的打分要跟**全部** `T` 个 key 各算一次点积，`T` 行就是 `T×T` 次——**对第 `t` 个词建索引的每一步，都要对全历史做一遍**（`10-KV-Cache与显存账本` 就是围绕这笔账的系统工程）。

```text
点积次数 = T × T = O(T²)          ← 序列翻倍，计算量×4
```

## 2. Masked（因果）：开会不许偷看未来的发言稿

### 2.1 它是什么

Self-Attention 默认**全可见**——但如果用在"生成"上就犯罪了：预测第 `i+1` 个词时看到了答案。所以解码器给打分矩阵加一个**因果掩码 M**：位置 `i` 只许看 `j ≤ i`：

$$
\text{att}_{ij}=\text{softmax}_j\Big(\frac{q_i k_j}{\sqrt{d_k}}+\underbrace{M_{ij}}_{\substack{0\ \text{if}\ j≤i\\ -\infty\ \text{otherwise}}}\Big)
$$

实现就是 `01` 篇那行老代码：把不该看的位置打分替换成 `-inf`，softmax 后权重归零：

```python
att = softmax(q @ k.T / sqrt(DH) + np.where(mask == 1, 0.0, -np.inf))
```

### 2.2 正反例对比

| 做法 | 掩码 | 后果 |
|---|---|---|
| ✅ 因果 | 位置 `i` 只看 `1..i` | 学的是"基于历史预测未来"，预训练目标成立 |
| ❌ 无掩码 | 位置 `i` 偷看全部 | 模型直接"复制粘贴"答案，续写目标崩坏 |

> 一句话带走：**Masked = Self 的"单行道版本"**。它不是新机制，只是给 Self-Attention 设了路障。

## 3. Cross-Attention：一个来源提问，另一个来源回答

### 3.1 定义：两个序列、三种角色

Self 的两个序列是同一个；Cross 是**两个不同来源**：

```text
q = A · Wq     ← 提问方（比如文本 token）
k = B · Wk     ← 回答方提供的线索（比如图像 patch）
v = B · Wv     ← 回答方提供的内容
y =       att(A·Wq, B·Wk) @ (B·Wv)      ← 输出长度 = 提问方 A 的长度
```

两个立刻能读出来的事实：

1. **输出 shape = Q 的长度**——提问方进来多少个 token，融合后还是多少个；多层 Cross 就是"让文本每层都从图像里再捞一遍信息"。
2. **它把"换来源"的复杂度讲清了**：打分矩阵是 `T_a × T_b`，其中 `T_a` 是提问长度、`T_b` 是回答长度。这比 Self 的 `O(T²)` 多一个维度选择——谁当 Q、谁当 K/V。

### 3.2 在真实模型里它长在哪

- **早期 VLM / 编码-解码**（T5、Flamingo）：文本 token 当 Q，图像特征当 K/V → 文本逐步"读懂图"。
- **Q-Former**（BLIP-2）：用一组"查询 token"当 Q，从图像特征里**只挑相关的** K/V → 相当于给长图像做一次"注意力压缩"再送给 LLM。这正好是 `04-MLA`（把 K/V 压进低维）思想的前身。
- 通用规则：**谁更需要"主导"，就把它放 Q 侧**；谁更"资料库"，就放 K/V 侧。

## 4. 实测：三兄弟的长相、学到的选择、与复杂度账单

`code/scripts/attention_demo.py` 用一组微型数字把三兄弟的区别全部量出来（`B,Ta,Tb,C = 2,4,6,8`：4 个文本 token + 6 个"图像 patch"）。以下为**本机真实输出**（seed 固定，`RandomState(0)`，三次运行中位数为准，速度类数字有一定波动）。

### 4.1 长相：三种注意力权重的"指纹"（实验 A、B）

```text
Self·全可见  第 0 行: [0.25 0.25 0.25 0.25]        ← 无掩码、随机初始化 → 近似均匀
Masked·因果  第 0 行: [1. 0. 0. 0.]                  ← 只能看自己 → one-hot
Masked·因果  最末行: [0.25 0.25 0.25 0.25]           ← 能看全历史 → 又近似均匀
Cross·跨源   第 0 行: [0.167 ×6]                     ← 对 6 个 patch 近似均匀 → 注意力进了另一来源
```

三行归一比对，三个数字各说一件事：**掩码把"均匀分布"截断成 one-hot；跨源把注意力从"同序列"带进"另一个来源"。** 随机初始化下注意力都近乎均匀——因为此时 Q/K 还没学出谁更重要（这恰好是 `01` 篇"模型还很懵"的注意力版）。

### 4.2 学到的选择：注意力是"对找什么的打分"（实验 A 后半）

随机初始化时注意力均匀，**训练后 Q/K 会学会"谁该看谁"**。脚本用一个"学习后"场景直接演示打分的力：让 patch #2 的 key 与查询 #0 的 Q 强对齐，其余 patch 随意——

```text
学习后 Cross：查询 #0 与 patch #2 强对齐 → 注意力: [0.102 0.073 0.538 0.101 0.07  0.116]
→ 峰值 0.538 落在 patch 2（均匀分布只有 0.167）
```

**权重从 1/6≈0.167 抬到 0.538**——注意力不是玄学，是**由 Q·K 点积决定的可学习打分**；谁提供的 key 与查询最匹配，谁就分到最大权重。学会这一句，后面读 `12-预训练`（它学的就是这组 Wq/Wk）、`03-模型家族`（各家只换了这组矩阵的实现）都不费劲。

### 4.3 复杂度账单：Self≈O(T²)，Cross≈O(Ta·Tb)（实验 C）

脚本在 T ∈ {128, 256, 512, 1024} 上真实计时，并对 log(T)-log(时间) 做线性拟合，斜率就是复杂度指数（理论 Self=2.0，Cross=1.0）：

```text
Self  计时:  0.22 / 1.35 / 5.54 / 21.59 ms  → 拟合指数 ≈ 2.18（O(T²)）
Cross 固定 Ta=16 计时: 0.08 / 0.11 / 0.20 / 0.37 ms → 拟合指数 ≈ 0.76（O(Ta·Tb)）
```

两个指数把"为什么长文档贵、为什么多模态问答可行"讲明白了：

- **Self 平方项**：把序列从 128 涨到 1024（8 倍），Self 时间涨了约 **98 倍**（理论 O(T²) 应约 64 倍，小规模 numpy 有开销，方向一致）——`19-长上下文` 的技术路径，一半是在对抗这个平方项。
- **Cross 线性**：固定提问侧，回答侧多长都只按线性走。**这就是多模态问答能"图像越来越清晰/分子越来越长"而代价只线性增长的理由**——谁当 K/V 谁出线性账。

> 里程碑抓手：想亲手把 Self 改成 Cross，只需把 `q` 换成序列 A 的投影、`k,v` 换成序列 B 的投影——脚本实验 A 就是这两行。做完再做"给 mini-GPT 加一层图像 cross-attention"（知识地图 §17.2.3 实践目标）。

## 5. 常见坑

| 坑 | 症状 | 修法 |
|---|---|---|
| 以为 Self 和 Cross 是两个机制 | 背了两套公式、两套实现 | 回到一个公式：**区别只在 Q/K/V 的来源**，代码只差喂给谁 |
| 分不清输出长度取谁的 | 问"Cross 输出是图像长度还是文本长度" | 输出永远取 **Q 的长度**（`y = att·V` 的矩阵乘法形状会自动保证） |
| 掩码忘加回打分层 | 生成时模型偷看未来 | `M`（-inf）必须加在 softmax **之前**的 `QKᵀ` 上 |
| 把 Cross 当成"另一个输入叠加" | 以为 Cross 就是 concat 两个序列 | concat 是让所有 token 互相 Self；Cross 保持"问方保留自己身份、只去借鉴答方" |
| 忘记掩码放在哪一侧 | Cross 里也乱加因果掩码 | 因果掩码只约束**同序列内的时间顺序**；跨序列的 Cross 是否掩码取决于答方顺序是否有意义（如音频按时间对齐时也用） |

## 6. 衔接下一章

家族里的每个成员，单独一个头只能学"一种关系"（比如"修剪"这个词该看"树"还是"指甲"？），真实模型需要**同时学到很多种**。下一章就是"把头复制成 N 份，各学各的关系"：

> [**03-多头注意力-MHA-MQA-GQA.md**](03-多头注意力-MHA-MQA-GQA.md)：多头 ≠ 重复计算，而是**把 `C` 维拆成 `NHEAD` 份并行打分**；从"每头一份 K/V"的 MHA，到"几头共用 K/V"的 GQA、再到"全部共用"的 MQA——同一件事的三档显存账。你会看到 `03` 里那张 KV Cache 账本（LLaMA-2-7B 在 8k 上下文下 1 GB vs 4 GB）是怎么一步一步减出来的。

同时给后面几章挂好锚点：

- `02` → `03`（多头，最大成本项）→ `04-MLA`（把 K/V 压进低维，`02` 里 Q-Former 那行提示在这里变成正式的 Dense 压束）。
- `01` 篇的迷你 Block、本篇的三分支 → 都是 `10-KV-Cache与显存账本` 的"被缓存对象"。
- 本篇的复杂度指数 → `19-长上下文` 四层路径的"症状描述层"。

> 一句话带走：**Attention 公式只有一个，三兄弟的区别只在 Q/K/V 的出身；`att` 矩阵的每一次数值都回答"谁该看谁"——它学得出来，是因为点积打分在训练中变得可学习（0.167 → 0.538）。**
