## 0. 它解决什么问题 · 为什么在 02 里排第一

`00-技术演化时间线.md` 里接力 #2 的病因为：RNN 必须**一步步串行**读完句子，训练慢（`t` 步输出要等 `t-1` 步），而且距离越远信息越难传递。Transformer 的处方便是——**彻底取消循环，让任意两个词在一次计算里直接交互**：用"注意力"决定看谁、看多狠，然后把看来的东西一起变成输出。

`02-核心原理` 把它排第一，因为后面 21 章全在它的骨架上生长：

```
01 Transformer（本篇·骨架）
 ├─ 02 Attention 家族 → 03 多头 MHA→GQA → 04 MLA      ← 换注意力形状
 ├─ 05 位置编码（RoPE）· 06 FFN（SwiGLU）· 07 归一化     ← 换零件
 ├─ 10 KV Cache · 11 采样                                ← 管推理代价
 ├─ 12 预训练 · 13 SFT → 14–16 对齐                      ← 教它"该做什么"
 └─ 17–22 规模化 · 能力边界                              ← 变大变快变聪明
```

`01-基础/06` 已经给了你"注意力很直观"的概念；本篇**不再重复直觉**，而是把一条**精确到每个 shape 的数据流**从 token 走到概率，并用可以跑的迷你 Transformer 亲手验证。跑完这一步，你看任何 GPT 论文的架构图都会觉得"只是这张图的缩放"。

## 1. 一张图看懂完整数据流

全文的地图（每个框旁是迷你版本的真实 shape）：

```text
token 索引 tok                (2, 5)            ← 句子被分词后的数字
   │ x = Wte[tok] + Wpos[None]（查表 + 位置）
   ▼
   x                         (2, 5, 8)         ← 每个 token 一个 8 维向量
   │ LN1：归一化到零均值 · 单位方差
   ▼
   n1                        (2, 5, 8)
   │ 拆成 Q / K / V 三份，各自投影（Wq Wk Wv，各 8×8）
   ▼
   q, k, v（每头 4 维, 2 个头）
   │ att = softmax( q·kᵀ / √4  +  掩码(-∞) )    ← 因果：只看左边
   │ y = att · v                                ← 加权求和收信息
   │ y → 拼头 → @ Wo → y_out                    (2,5,8)
   ▼
   x2 = x + y_out                               (2, 5, 8)   ← 残差 1
   │ LN2 → h = ReLU(n2@Wf1) → @Wf2 → h_out
   ▼
   x3 = x2 + h_out                              (2, 5, 8)   ← 残差 2
   │ @ Wout → logits = x3@Wout                  (2, 5, 24)
   ▼
   softmax(logits) → 每个位置"下一个词"的概率    (2, 5, 24)
```

中心公式只有两行（其余全是线性层）：

$$
\text{att}(Q,K,V)=\text{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}} + M\right)V ,\qquad
\mathbf{h}=\text{ReLU}(\mathbf{x}_2 W_{f1}+b_{f1}),\quad \mathbf{x}_3=\mathbf{x}_2+\mathbf{h}W_{f2}
$$

> 读图顺序：**先问形状，再问内容**。只要你能在一张白纸上把这个从 `(2,5)` 到 `(2,5,24)` 的过程默画出来，Transformer 于你就是"常识"而非"黑盒"。本篇下面四节就是逐段放大这张图。

## 2. 入口：token 索引如何变成向量（Embedding）

### 2.1 机器只认数字，词只能查表

句子先被分词变成整数序列（`ticks` 不爱教，但行这一步藏在整个预训练成本里）：

```text
"猫 最爱 睡觉"  →  tok = [7, 11, 5]   ← 每个数字 = 词表里的一个词项
```

从整数到向量，Transformer 用的是一张**可学习的查表**：

```python
x = Wte[tok] + Wpos[None]        # Wte: 词表 V × 隐层 C；Wpos: 位置 T × C
# Wte[tok] 是"按索引查行"，得到一个 (B, T, C) 的稠密矩阵
```

- `Wte[tok]`：把每个 token 索引"查"成它的 8 维向量（模型自己决定把相近语义的词放在向量空间相近处）。
- `Wpos[None]`：把"这是第几个位置"也变成向量加上去——因为**注意力对顺序毫无概念**（"猫咬狗"和"狗咬猫"的注意力张量一模一样），位置信息必须显式注入（真正的尺度与细节留给 `05-位置编码`）。

### 2.2 实测：形状跟着走（实验 A）

```text
token 索引 shape: (2, 5) → 嵌入+位置后 x shape: (2, 5, 8)
```

`(2,5,8)` 的三个数字就是：**2 句话 · 每句 5 个 token · 每个 token 一个 8 维向量**。从这一步起，后面每一步都只是改这几个数字的形状。

> 一句话带走：**Embedding 不"理解"词，只是把离散整数查成稠密向量**；理解发生在它进入注意力之后。

## 3. 因果注意力：右边的词不许偷看左边

### 3.1 注意力在算"谁该看谁"

对每个词（查它的 Q），问整个上下文（比 K）、加权混合（取 V）：

$$
\text{att}_{ij}=\text{softmax}_j\!\Big(\frac{\mathbf{q}_i\cdot\mathbf{k}_j}{\sqrt{d_k}} + M_{ij}\Big),\qquad \mathbf{y}_i=\sum_j \text{att}_{ij}\,\mathbf{v}_j
$$

- **Q（要在找什么）· K（我能提供什么）· V（找到后给什么内容）** ——沿用 `01-基础/06` 第三节的三件套。
- $\sqrt{d_k}$：Q·K 点积会随维度增大而方差变大 → softmax 饱和、梯度消失；除以它把方差拉回 1（"让打分规模与维度无关"）。
- **M：因果掩码**。位置 `i` 只能看 `j ≤ i`。实现就是"把不该看的位置的打分变成 $-\infty$"，softmax 后那些位置的权重退化为 0：

```python
att_logits = q @ k.transpose(0,1,3,2) / math.sqrt(DH) + np.where(mask==1, 0.0, -np.inf)
att = softmax(att_logits, axis=-1)
y = att @ v
```

### 3.2 为什么必须掩码（正反例）

| | 掩码 | 结果 |
|---|---|---|
| ✅ 正确 | 第 `i` 个位置的注意力只能落在 `1..i` | 预测"第 `i+1` 个词"时看不到答案，训练目标才有意义（学的是"续写能力"） |
| ❌ 错误 | 允许看全部（不看未来） | 位置 `i` 直接偷看后面的词 → softmax 把正确词权重抬到接近 1 → 模型学成"复制粘贴"，预训练目标崩坏 |

### 3.3 实测：掩码在数字上长什么样（实验 A）

迷你模型里第 0 位只能看自己，所以它的注意力权重**退化成 one-hot**；第 4 位能看整个历史（5 个位置），随机初始化下**近似均匀**：

```text
单头 attention 权重 · 第 0 位（只能看自己）: [1. 0. 0. 0. 0.]
单头 attention 权重 · 第 4 位（看全历史→近似均匀）: [0.2  0.2  0.2  0.199  0.2 ]
```

这两个数字就是掩码的"指纹"：**最左的词永远自己扛，越靠右越能"集百家之长"**。等你学完 `12-预训练`，会看到训练后这些分布从"均匀"变成"把多数权重放给真正相关的词"。

## 4. 完整 Block 前向：一个 Block 学完后 logits (2,5,24)

把入口、注意力、（另一份）归一化与前馈拼成一个 Block，一次前向的完整骨干如下（`transformer_demo.py` 实验 B）：

```python
n1, m1, s1 = ln(x)                       # LN1：无参归一化
q, k, v = n1@Wq, n1@Wk, n1@Wv           # 三投影
att = softmax(q@k.T/√d + np.where(mask==1, 0.0, -np.inf))
y_out = (att@v 重排拼头) @ Wo             # 头内计算 → 拼回 → Wo 投影
x2 = x + y_out                            # 残差 1：注意力块的"记住自己"
h = np.maximum(0, ln(x2)@Wf1)            # FFN：逐 token 的非线性变换
x3 = x2 + h@Wf2                           # 残差 2
logits = x3@Wout                          # 输出头：每个位置对"下一个词"打分
loss  = 交叉熵(logits, 真下一个词)         # 训练信号
```

三个关键设计，每个都有"为什么"：

- **残差**：`x2 = x + y_out`。梯度"抄近路"直达其他层，训练深层不回退；这也是"越堆越多层"能成立的地基。
- **FFN 是"知识存储"**：每个 token 独立做 `ReLU(...)`，容量占模型约 2/3 参数（`06-FFN` 会细讲）。
- **归一化在残差之前（Pre-Norm）**：稳定深层训练的现代默认；`07-归一化` 会对比 Pre/Post 的训练曲线。

### 实测（实验 B）：随机初始化的模型"还很懵"

```text
一个 Block 前向后 logits shape: (2, 5, 24)     ← 2 句 × 5 位置 × 24 个候选词
概率分布第 5 个词（随机初始化 → 近似均匀）: [0.044 0.043 0.041 ... 0.042]   ← ≈ 1/24
```

- shape `(2,5,24)` 就是"每个位置对 24 个候选词打了一轮分"。
- 权重视角下模型**还没有学习**：第 5 个词的概率 ≈ 0.042 ≈ $1/24$（均匀瞎猜），对应损失 ≈ `3.20`，与"均匀分布"的理论值 $\ln 24 \approx 3.18$ 只差 0.02。
- 这一步证明："Transformer 架构本身不包含知识，知识来自 `12-预训练` 在它身上跑的每一次梯度更新。"

## 5. 它必须"能学"：手写反向传播，用数值梯度做终极裁判

会用够了，但要**动手让它学**，就必须把梯度算出来。`05-深度学习` 已经手写过一次 BP；这里多一个关键点——**Transformer 有 9 组参数**（嵌入/位置/Q/K/V/Wo/两段 FFN/输出头），每一组都有"查表 + 残差 + 扁转 + 掩码"这些容易写错的细节。

`transformer_demo.py` 的做法是把整个**反向链手写出来**（每步一行注释），然后用**中心有限差分**做裁判：逐参数扰动求 `(loss+ − loss−)/(2ε)`，如果手写梯度与它一致到 1e-5 以内，链就是对的。

### 实测（实验 C）：全元素对账

```text
全部 9 个参数（嵌入/位置/注意力/FFN/输出头）最大误差: 5.81e-11
阈值 1e-5 → ✅ 通过
```

**5.81e-11 ≈ 浮点极限**——不是"抽样看起来对"，而是**每一个参数、每一个元素都与数值梯度一致**。手写链的任何一处错误（漏掉某条残差、投影方向转错、softmax 反向公式写反），误差都会立刻跳到 1e-1 量级。

> 这是本仓库反复强调的纪律：**"跑过的数字"和"听说的数字"是两种不同的知识。** 上面这个 `5.81e-11` 不是背书来的，是亲手（或复现脚本）量出来的——它才是"这个迷你 Transformer 真的能学"的证据。

**真实教训（正反例）**：写这条链时，实际踩过两个坑，恰好都是"最容易犯、最考察你对数据流是否有直觉"的地方：

1. **LayerNorm 反向漏了均值归一**。把 `mean(dy·d)` 误写成 `sum(dy·d)`，于是导数被整体放大 `T` 倍——有限差分立刻抓到，最大误差从 `5.8e-11` 跳到 `1.5e-1`。
2. **输出投影 Wo 的梯度用错了激活**。梯度 `dW₀` 必须乘"乘 Wo **之前**的 `(att@v)` 重排"，最初误用了乘 Wo **之后**的缓存——同样是有限差分一招揪出。

这两个坑在 `backward()` 的注释里都留下了警示行。**数值梯度就是这样一面照妖镜**：它不像断点调试那样需要你猜"哪一步错"，只要最大误差不收敛到 1e-5 以内，就说明链里有问题——这是从零实现 Transformer 最省心的验收方式。

## 6. KV 复用：推理时"已经算过的别算第二遍"

训练阶段可以重算整个序列；但生成时是**一个一个地往外吐词**。吐第 `t+1` 个词时，前 `t` 个位置的 K / V **完全没变**——全量重算（`O(T²)`）就白算了一遍。KV Cache 的做法是"把历史 K/V 存下来，只算新一行的注意力"。

`transformer_demo.py` 实验 D 直接把这笔账量给你看（`T=96`，本机三次运行中位数）：

```text
全量重算单步: 0.19 ms | 增量 KV 单步: 15.6 µs
→ 复用后单行注意力快约 12 倍（本机实测，T=96）
```

序列越长，省得越多（因为重算是平方级）。**这就是 vLLM 的 KV Cache 存在的数学理由：结果完全相同，只是不算第二遍。** 显存账怎么精算、PagedAttention 怎么管它，是 `10-KV-Cache与显存账本` 与 `05-推理与部署` 的主题——本篇只要你记住"缓存 ≠ 换结果，只是换成本"。

## 7. 从迷你 Block 到 GPT：缩放四件事

迷你是肉眼可读的 `(2,5,8,24)`；真实的 GPT 只是把这四个维度放大：

| 维度 | 迷你（本脚本） | GPT-2 small（公开规格示意） | 为什么变大 |
|---|---|---|---|
| 序列 T | 5 | 1024 | 精彩长文/长对话 |
| 隐层 C | 8 | 768 | 每个词的表示更细腻 |
| 层数 | 1 | 12 | 更深的抽象层级 |
| 词表 V | 24 | 50,257 | 覆盖全部常见子词 |

缩放不是白来的，最直接的代价是**参数账**。迷你模型的参数可以从本脚本的 shape 直接累加：

```text
Wte 24×8=192 + Wpos 5×8=40 + Wq/Wk/Wv/Wo 各 8×8=64×4=256
  + Wf1 8×32=256 + Wf2 32×8=256 + Wout 8×24=192  → 共 1,192 个参数
```

到了 GPT-2 small，光是嵌入层 `Wte: 50257×768 ≈ 38.6M`，就接近总参数的 1/3（输出层通常与它共享权重，tied）。**以后每次读模型卡的"7B / 13B / 70B"，你心里应该浮现的就是这张"shape→参数"的账本**——这也是 `17-MoE`（把 FFN 拆稀疏）与 `05-推理与部署`（显存账本）的起点。

## 8. 常见坑

| 坑 | 症状 | 修法 |
|---|---|---|
| 以为注意力是"替换成出现最多的词" | 把 `y = att@v` 理解成"把词替换掉" | 记住 `y` 是**加权混合后的每个词的向量**——它"借"了别人的信息，但仍然是自己的表示 |
| 掩码加在 softmax 之后 | 掩盖无效、模型照样偷看未来 | `-inf` 必须在 softmax **之前**加入打分（公式里的 M 直接在 $QK^{\top}$ 上） |
| 忘除 $\sqrt{d_k}$ | 深层训练不稳定/梯度消失 | 打分规模与维度无关，必须缩放 |
| 看到"LayerNorm"以为都有参数 | 混淆无参教学版与真实 RMSNorm/LayerNorm | 归一化方向三者一致；真实 GPT 用带 γ/β 的版本（`07-归一化`） |
| 认为"用了残差/Norm 就懂 Transformer" | 迁移到新模型依然懵 | 能默画数据流 + 能写出 shape 链，才算懂；本篇第 5 节的手写链是验收标准 |
