## 0. 为什么 RLHF 之后还想"省掉裁判"

`14` 章把"喜欢"搬进了损失函数——先养一个奖励模型 RM，再用 REINFORCE+KL 让策略去挣 RM 的分数，全新问三票 38%→67%。但这条路的账本很重，`14` 章 §7.5 已经列过：

```text
RLHF 的三份账：
  ① 驻留三份模型        ：策略 163,392 + 冻结参考 163,392 + RM 139,393 ≈ 62.9 万参数
  ② 在线 rollout        ：每步都要现场采样回答再打分，策略一变采样分布就作废
  ③ 一堆 RL 超参        ：lr 要比预训练慢 10 倍、advantage 归一化、clip、KL 预算……
```

Rafailov et al. (2023) 问了一个更省的问题：**目标无非是"让 π_θ 比 π_ref 更偏向 chosen、更远离 rejected"，既然这个方向已经写死在偏好对里，那……RM 是不是可以整个消失？** 于是 DPO（Direct Preference Optimization）出生了——它把 RLHF 的最优解（奖励 + KL 的优化问题）从数学上解开，**用一个闭式监督损失同时干掉"训 RM"和"在线 rollout"两大头**。

`14` 章的 §10 已经把 DPO 损失公式挂了出来作为钩子，本章把它兑现，并带着它的一家人（IPO / KTO / ORPO / SimPO）一起上场。这些变体不是论文表演赛——它们各自揭开了"偏好对齐成本"的不同位置：

| 方法 | 年份 | 驻留几份模型 | 用的偏好形态 | 主打改动 |
|---|---|---|---|---|
| **DPO** | 2023 | 策略 + 冻结参考 | 成对 (chosen, rejected) | 闭式消 RM，不回传在线采样 |
| **IPO** | 2024 | 策略 + 冻结参考 | 成对 | 损失从 logistic 换成长方误差（带目标 margin），抑制 DPO 的过优化 |
| **KTO** | 2024 | 策略 + 冻结参考 | **单标签**（好/坏，不成对） | Kahneman 参照点：不用"谁比谁好"，只要"这一条好不好" |
| **ORPO** | 2024 | **只策略一份** | 成对 | SFT 里直接加 odds-ratio 惩罚，参考模型也省了 |
| **SimPO** | 2024 | **只策略一份** | 成对 | 也免参考，改比"平均 token 概率"的超额（含边距 γ） |

一句话版：**DPO 到 IPO 是"换损失形状"，DPO 到 KTO 是"换数据形态"，DPO 到 ORPO/SimPO 是"把参考模型也省掉"——省钱的方向一层比一层激进。**

> 记忆抓手：**RLHF 请外教（RM）+ 请教练（PPO）；DPO 家族背公式自学，最省的 ORPO/SimPO 连"参考答案（π_ref）"都合上。** 省掉的不止是算力，还有一整套 RL 的超参敏感度——但代价是换了一批新旋钮（§7）。

## 1. DPO 家族四兄弟：同一条 DNA，四种省钱思路

五个 arm 用**完全相同**的三样东西起步（这也是本章能与 `14` 章直接对账的前提）：

```text
① 同一个 SFT 策略 π_SFT 当起点与冻结参考（ref_params = π_SFT 的拷贝）
② 同一份偏好对：383 组（高温采样 30 问 × 24 条，judge 当人类裁判挑 chosen/rejected），留出 58 组
③ 同一个玩具引擎与预算约束：0.18M 参数 1-block 解码器，BERT 性判据见 `12`/`13`/`14` 章
```

五份里只有一件事不同——**损失函数把"偏好"变成梯度的写法**。本章实测里它们被分成三类来读：

- **DPO / IPO / ORPO / SimPO 用成对数据**：每题给两条回答（chosen 更好）。DPO 与 IPO 需要一份冻结参考（算"离 SFT 多远"）；ORPO 与 SimPO 不要。
- **KTO 用单标签数据**：每题只问"这一条算好（judge=3 分）还是不好（judge<3 分）"。我们复用它同一轮的采样池：720 条里 337 条"好"、383 条"坏"，`λ_u/λ_w = 0.88`（按类别数量配平，`14` 章的裁判三票天然给出这个标签）。

模型仍是 `12`-`14` 章那个引擎：LN → 因果 MHA（3 头）→ 残差 → LN → FFN → 残差 → 输出头；词表 251，`n_pol = 163,392`。DPO/IPO/KTO 驻留"策略 + 冻结参考"两份共 326,784；ORPO/SimPO 只驻留策略一份（163,392）——这本身就是账：**同一个对齐任务，驻留从 RLHF 的约 62.9 万降到了 32.7 万（DPO 档）甚至 16.3 万（ORPO/SimPO 档）。**

> 一句话：**四个主意共享"用偏好对代替人工金标准"的 DNA，差别只在'把喜欢变梯度'时谁还要带作业本（参考模型）、谁连作业本都不带。**

## 2. DPO 的核心推导：从 RLHF 最优解里把奖励模型"消掉"

`14` 章的 RLHF 目标（带 KL 安全带）写做：

```text
max θ  E_{y ~ π_θ(x)}[ r(x,y) ]  −  β·Σ_t D_KL( π_θ(y_t|x) ‖ π_ref(y_t|x) )
```

标准结论（`14` 章 §4）：对固定的奖励 r，这个问题的**最优策略**有一个既像概率又有指数奖励的闭式形状：

```text
π*_r(y|x) ∝ π_ref(y|x) · exp( r(x,y)/β )
```

把它翻过来就得到"**给定最优策略 π_θ，奖励必长这样**"：

```text
r(x,y) = β · log π_θ(y|x) / π_ref(y|x)          （+ 与 y 无关的归一化项，成对相减时消掉）
```

DPO 的关键一步是"**把 r 代回 Bradley-Terry 偏好模型**"（`14` 章 §2.2 用过的那条：`P(chosen ≻ rejected) = σ(r_c − r_l)`）。把上式里的 r 换成"策略自带的隐式奖励"：

```text
r_θ(x,y_w) = β·log π_θ(y_w)/π_ref(y_w)   ；  r_θ(x,y_l) = β·log π_θ(y_l)/π_ref(y_l)

L_DPO = −log σ( β·logπ_θ(y_w)/π_ref(y_w) − β·logπ_θ(y_l)/π_ref(y_l) )
```

于是奖励模型被**消掉了**——训练时只需要 π_θ、冻结的 π_ref、和偏好对。更妙的是，这个被推出"奖励长这样"的关系反过来成立：DPO 训出来的任何 π_θ，其隐式奖励函数**就是一个 Bradley-Terry 奖励模型**（论文标题就叫 *Your Language Model is Secretly a Reward Model*）。

损失里出现两个量的减法，务必记住它们的角色：

```text
δ(x,y) = log π_θ(y|x) − log π_ref(y|x)     # "当前策略比 SFT 更顺还是更不顺"，DPO 的隐式奖励 = β·δ
L_DPO  = −log σ( β·δ_w − β·δ_l )            # 让 chosen 该量的净优势为正
```

β 在这里就是 `14` 章那条"KL 安全带"——它控制"策略允许离 SFT 多远"。`14` 章 β=0 的实验告诉我们没有锚会怎样；DPO 把同一把 β 直接搬进闭式损失里（§7 会测它的形状）。

> 一句话：**DPO = 给 RLHF 的最优解关系两边各除一次，让奖励模型自己从"偏好对 + 参考模型"里长出来——它不叫'RM'了，但每一条策略里都藏着一个隐式裁判。**

## 3. 实测 DPO：真能免 RM 把"喜欢"学进参数吗

把 L_DPO 接到 `14` 章同款流水线后面就是实测 C。复用的是完全相同的数据（383 对 / 58 留出），起点完全相同（同样 SFT 62% / 38%），只给 300 步、lr=3e-4（与 `14` 章 RL 步长同一档——低位偏好损失吃不了预训练那档 3e-3）。

```text
实测 C（DPO：β=0.5 · lr=3e-4 · 300 步 · batch 8）：
  留出偏好对判别率（DPO 隐式奖励 r_θ=β·(δ_w−δ_l)）：
    step  50 → 训练 95%  留出 95%
    step 150 → 训练 100% 留出 91%
    step 300 → 训练 100% 留出 91%          （显式 RM 训 500 步 = 79%）
  perfect 率：训练问 93%（前 62%）· 全新问 72%（前 38%）
  KL(π ‖ π_SFT) ≈ 2.72                      （RLHF 组的终态 KL = 10.65）
  DPO 300 步墙钟 30s
```

三个数各有说法：

1. **留出判别率一步到位 91%-95%**，比显式 RM 训 500 步的 79% 还高。为什么？RM 是"学一个裁判再去判"，DPO 的隐式奖励**直接就是**偏好对训练出来的函数，没有"裁判校准"那一层的损耗；而且它连 RM 的 500 步预算都省了（DPO 300 步、其中前 50 步就追上 RM 终态）。这就是"策略即裁判"（implicit reward）带来的效率。
2. **完美率 38%→72%**，跟 RLHF 的 38%→67% 打平甚至略高，但：
3. **KL 只有 2.72**，相比之下 RLHF 组是 10.65——DPO 用"偏好对 + 冻结参考"的监督，比 REINFORCE 的在线高方差路径把策略锚得更紧。**省掉在线采样后，KL 不是失控了，而是更稳了。**

> 一句话（实测 C）：**DPO 在玩具上完整体现了它的卖点：不动 RM、不动在线采样、300 步 30 秒，全新问三票 38%→72%、KL 只有 2.72——'喜欢'真的只靠一份偏好对就进了参数。**

## 4. 梯度怎么落地（以及一个会反向优化的符号坑）

### 4.1 手写引擎的"mask 惯例"是本章最大的坑

`13` 章以来我们的 `backward(params, cache, loss_mask)` 约定是：**它返回 `Σ mask·(−logp)` 的梯度**。也就是说，你想让损失函数降到最低，必须先问"这一项在 logp 上的系数是什么 c"——然后把 `mask` 设成 `−c`。这是本章五个 arm 最容易集体翻车的地方：**mask 符号写反，等于把 loss 当 maximize 在跑。**

用 DPO 推一遍（其他四家的推导在 §5）：`L = −log σ(z)`，`z = β(δ_w − δ_l)`。链式法则（`{a, σ} = sigmoid`）：

```text
dL/d logπ_w = −β·σ(z)·(1−σ(z))/σ(z)·… = −β·(1−σ(z))      # chosen 回答区每个 token
dL/d logπ_l = +β·(1−σ(z))                                  # rejected 回答区每个 token
→ mask_w = +β·(1−σ)；mask_l = −β·(1−σ)     （因为 mask = −dL/dlogp）
```

我们第一版脚本把符号写反了（`mask_w=−β(1−σ)`、`mask_l=+β(1−σ)`），症状非常有戏剧性：DPO/IPO/KTO/SimPO 四个 arm 的 z_mean 一路冲到约 −22，进一步被 40 剪辑成 −40、KL 涨到 85-215、perfect 归零——优化器在**最大化** DPO 损失；而 ORPO 却"看起来成功"（89%/64%），因为它的 SFT 锚项（mask=+1/K）符号正确、恰好把（符号反了的）偏好惩罚项**盖住了**。**这个 bug 的第一个教训是反直觉的：五个 arm 同病相怜，但你不能因为有一个幸存就觉得布局没错**——收敛的 ORPO 恰恰是唯一一个"错的项被对的项压住"的，纯偏好损失里 mask 一旦写反就是反向优化。

（如何验证方向：每个 arm 的前 50 步打印 `z_mean`。DPO 是 383 对里 z=β(δ_w−δ_l) 的平均——若 z_mean 持续为正约 +5~+14，方向对；若一路 −20~−40 那就是反向优化。我们的修复把 DPO β=0.5 的 z_mean 从 −40 量级翻正、KL 从三位数收回 2.7。）

### 4.2 每个 token 区权重 = 整个回答的"该涨/该降"再摊回每 token

DPO 损失只作用在**回答区** token 上（`answer_region_mask`，问题和 padding 不背锅，与 `13` 章 SFT 的 mask 思想一致）；chosen 整句拿到一个标量权重 `+β(1−σ)`、rejected 整句 `−β(1−σ)`，摊到回答区每个位置。这个"整句一个系数、再逐 token 摊"的模式四个成对方法共用——区别只在计算 σ 的输入（§5）。

> 一句话：**"mask = −(∂L/∂logp)"写错了就反向优化；本章每个 arm 都先把 z_mean 的符号跑正，再谈 KL 与完美率。**

## 5. 四兄弟各自在省什么：IPO / KTO / ORPO / SimPO

### 5.1 IPO（2024）：换成长方误差，治过优化

DPO 的 logistic 损失**饱和**了——一旦 `β·(δ_w−δ_l)` 很正，σ 贴在 1 上，梯度趋零，过优化放缓但**不会停**（接近零的梯度×足够步数仍在漂）。IPO（Gorbatovski et al. 2024 / 同题工作 IPO 2023 版）把"提升直到哪个分数差"讲得更明：

```text
L_IPO = ( z − m_target )² ，  z = β(δ_w − δ_l)   （z 超过 m_target 后损失开始回落，不再无限偏爱）
梯度：dL/d logπ_w = +2β(z−m_target) → mask_w = −2β·(z−m_target)；rejected 取反
```

`m_target` 是"目标边距"（target margin）。本章实测里它是 IPO 的**总开关**（§7 的晾衣线），而在同一玩具上：margin=0.25 时几乎学不动（留出 52%≈随机起手），margin=2.0 时冲到全场最高（见 H 表）——**IPO 的正确姿势是"把 margin 推到模型自然能到的差距"，而不是取个顺手的小数**。

### 5.2 KTO（2024）：只用"好/坏"单标签

几乎所有偏好方法都要成对数据；KTO（Ethayarajh et al. 2024）从行为经济学借了 Kahneman 的参照点思想：**"好不好"是相对参照点而言的**。它把损失改成：

```text
好样本（label=good）：  L = β·σ( z_ref − β·δ(x,y) )     # 好样本的奖励应高于批内均值参照 z_ref
坏样本（label=bad）：   L = β·σ( β·δ(x,y) − z_ref )
z_ref = 本批 8/32 条样本 r=β·δ 的均值                        （批均值当参照点）
```

它不挑 chosen/rejected，只要"这条算好/算坏"，坏样本还能用 λ_u 配平压权。玩具里 `judge=3 分 ⇔ 好`，天然给出 337 好 / 383 坏。**但它把"参照点"搬进批均值后，样本量的重要性陡增**：batch=8 时批均值噪声大、KL 直接失控（§7 晾衣线：batch=8 β=0.1 KL 失控到 126，三票归零）；batch=32 + β=0.5 + 早停（150 步）才稳出 65% 全新问。KTO 是五家里面算账最费嘴的一个——**它省掉了成对标注，但把稳定性押在了批大小与参照点估计上。**

### 5.3 ORPO（2024）：连参考模型都省

ORPO（Hong et al. 2024）说：**参考模型也是驻留成本，直接砍掉**——在 SFT 的（θ 对 chosen 的金标准）目标里，加一个 odds-ratio 惩罚：

```text
p̄(y|x) = exp( Σ_logp / |y| )                          # 整句平均 token 概率（几何平均）
odds(y) = p̄(y)/(1−p̄(y))
L_ORPO = −logπ_θ(y_w) − λ·log σ( log oddsw − log oddsl )
```

梯度出来是（`1−σ(odds差)` 同时作用在两边，系数里挂着 `1/(1−p̄)` 与 `1/K` 的摊匀项）——它没有参考模型、没有 z_ref，只有一个超参 λ。本章实测 λ=0.5→全新 68%、λ=1.0→78%。ORPO 的代价在另一个地方：**省了参考模型，等于把"离 SFT 多远"的锚也松了**——它靠 odds 天然不会被推成无敌高分（log-odds 有界），但策略一旦走远没有显式就坡站，只能靠 SFT 项拽着（§7 讲它 KL 不可直接测）。

### 5.4 SimPO（2024）：也免参考，但换成"平均概率 + 边距"

SimPO 更绝：连"隐式奖励 = β·δ"中的参考差都不算，直接用**策略自己的平均 token 概率**（长度归一）当奖励：

```text
L_SimPO = −log σ( β·mean_logp(y_w) − β·mean_logp(y_l) − γ )
```

γ 是"目标边距"（target margin），就是从奖励里抠掉"自动增益"（implicit reward），逼策略在**自己**的概率上也拉开差。它省到最后：**只驻留一张策略模型**。本章实测 γ=0.5 时 63%，去掉 γ（=0）反而 67%（§7 晾衣线），而 β 调小一档（β=1）直接翻车到 5%。

### 5.5 一张表把四家的"在省什么"钉死

```text
                   数据形态      参考模型    超参        实测(留出判别/全新三票/KL)※
DPO   2023    成对          策略+冻结参考   β=0.5       91% / 72% / KL 2.72
IPO   2024    成对          策略+冻结参考   β=0.1,m=2.0  97% / 82% / KL 3.07
KTO   2024    单标签好/坏   策略+冻结参考   β=0.5,b=32   98% / 65% / KL 9.02
ORPO  2024    成对          仅策略         λ=1.0       90% / 78% / 免KL
SimPO 2024    成对          仅策略         β=2,γ=0     95% / 67% / 免KL
（对照）RLHF  14章          RM+在线outroll  β=0.1,lr3e-4 79%(RM判别)/70%-67%·KL 10.65
※ 本表各行是"各自调到优质区"的数字；默认超参一跑会翻车，见 §7 晾衣线
```

> 一句话：**DPO 到 IPO 换损失形状（饱和→有界目标）、到 KTO 换数据形态（成对→单标签）、到 ORPO/SimPO 砍参考模型（驻留 33 万→16 万）——省钱方向层层加码，但每一层都换走一样你原来有的东西（锚/参照点稳定性/显式 KL）。**

## 6. 同台对照：留出判别率 vs 三票 vs KL（实测 C-H）

把五个 arm 放在**同一张表**里（H 段输出，全部与 `14` 章同一流水线、同一预算、同一 SFT 起手）：

```text
方法           留出判别率     训练问三票     全新问三票   KL→SFT     墙钟
SFT 基线       50%       62%       38%      0.00       —
显式RM(B14)     79%       62%       38%      0.00       —
DPO (β=0.5)   91%       93%       72%      2.72     30s
IPO (m=2.0)   97%       93%       82%      3.07     30s
KTO (β=0.5)   98%       93%       65%      9.02     35s
ORPO (λ=1.0)  90%       97%       78%         —     23s
SimPO (β=2)   95%       87%       67%         —     23s
RLHF(C14)     79% RM    70%       67%     10.65    153s
```

读这张表要横着看四列，**不要只看中间一列**：

1. **留出判别率（谁更能分好坏）**：四个 arm 全部 90%-98%，全盖过显式 RM（79%）。原因是§3 那条——偏好对直接训练判别函数，免去"学裁判再代判"的损耗；KTO/IPO 甚至到 97-98%。
2. **全新问三票（谁会回答得好）**：38% → 65%-82%。按这个轴排序：IPO 82% > ORPO 78% > DPO 72% > SimPO 67% > KTO 65%——**没有谁一骑绝尘，都是"同一起跑线的不同分头"**，差距来自各自旋钮线的形状（§7）。
3. **KL（策略离 SFT 多远）**：DPO 2.72、IPO 3.07、KTO 9.02（交显著漂移税）；ORPO/SimPO 无参考模型、没有可对比的 KL——这是它们"省掉锚"的直接成本，没法免单。
4. **墙钟**：单段 23-35s，是 RLHF 单段（整脚本 153s 含预训练/SFT/RM 与两组 RL）的零头——账本上全面轻。

**最扎眼的一组对读：留出判别率 KTO 98% > DPO 91%，但全新问三票 KTO 65% < DPO 72%。** 判别率高、会说好话，并不自动等于采样质量高——这正是 `14` 章结束时埋在观察里的那个道理（奖励判得好 vs 生成好是两件事），DPO 家族把它放大成了可测量的差距。

> 一句话（实测 H）：**同一个起点、同一份数据，五个 arm 在'判别谁更好'上全员 90%+，但在'实际说出好话'上四分五裂——判别率与生成质量的解耦，是对齐实验最容易误读的一根分界线。**

## 7. 诚实声明：旋钮晾衣线、'过优化'长在哪、长度偏置为什么测不出

### 7.1 旋钮晾衣线：每个方法都有"翻车区"

`14` 章最重要的教训之一是"β 安全带"；DPO 家族把这种超参敏感度放大成了每个方法的晾衣线。我们在固定 lr=3e-4、固定数据、只动一个旋钮的条件下扫出来的（**与正文同一流水线的探针**）：

```text
DPO  β 扫描（300 步，统一 lr=3e-4）：
  β=0.05 → 留出 72% · KL 111.7 · 全新三票 0%     ← 安全带太松：疯狂漂移，质量崩
  β=0.3  → 留出 93% · KL 4.4  · 全新 61%
  β=0.5  → 留出 91% · KL 2.7  · 全新 72%         ← canonical
  β=1.0  → 留出 91% · KL 1.5  · 全新 59%         ← 安全带太紧：动得少，改进回吐
IPO  margin 扫描（β=0.1 固定）：
  m=0.25 → 留出 52% · KL 1.5  · 全新 48%         ← 目标太小，等于不推
  m=1.0  → 留出 79% · KL 2.1  · 全新 61%
  m=1.5  → 留出 95% · KL 2.8  · 全新 78%
  m=2.0  → 留出 97% · KL 3.1  · 全新 82%         ← canonical
KTO  batch/β 扫描（150 步，统一 lr=3e-4）：
  b=8  β=0.1 → KL 126 · 全新 0%                  ← 批均值参照点在噪声里，直接发散
  b=32 β=0.1 → KL 63  · 全新 0%                  ← 小 β 也压不住，参照点没写到
  b=32 β=0.3 → KL 20.5· 全新 50%
  b=32 β=0.5 → KL 9.0 · 全新 65%                 ← canonical（见正文）
ORPO  λ 扫描（300 步）：
  λ=0.5 → 留出 90% · 全新 68%    ；  λ=1.0 → 留出 90% · 全新 78%   ← 最温和的晾衣线
SimPO  (β,γ) 扫描（300 步）：
  β=2,γ=0.5 → 留出 97% · 全新 63%  ；  β=2,γ=0   → 留出 95% · 全新 67%   ← canonical
  β=1,γ=0.5 → 留出 97% · 全新 5%                                           ← 又一条翻车线
```

三件事值得记住：

> 统计口径说明：上面的晾衣线是"探针逐一扫"的口径——每次只动一个旋钮，三票/判别率用**独立种子**逐个 arm 评估；H 主表（§6）则是**共用**一串评测种子的口径。两者在几个百分点内有差（例如 ORPO λ=1.0 探针报全新 71%、主表报 78%），用于**读趋势与形态**，逐位对账一律以 H 主表为准（`14` 章多种子表也是同一处理）。

1. **每一条晾衣线的两端都是"翻车区"，不是起点。** DPO β=0.05 挂 111 的 KL、质量 0%；SimPO β=1 全新掉到 5%；KTO batch=8 直接发散——**"给一个看起来合理的默认值"在这套玩具里五次里有三次翻车**。真实世界同理：Zephyr 的 DPO 论文明确说 β 是"对结果最敏感的单一超参"。
2. **判别率几乎永远不下滑**（DPO β=0.05 时留出仍有 72%、SimPO 翻车时 97%）——**"还能判好坏"不代表"没在过优化"**。判断过优化的仪表盘要看三票/KL，不是判别率。这就是 §6 那句"判别 vs 生成解耦"的旋钮版。
3. **'过优化'在这套玩具里长在 KL 上，不长在留出判别上。** 三个证据：如果 KL 失控（DPO β=0.05：111、KTO batch=8：126），质量崩；KL 受控时（DPO 2.7、IPO 3.1），300 步内没有出现"留出判别率见顶回落"——因为 383 对偏好对把留出的可分性快速学满（91-97% 已是上限区间），玩具里没有足够的"错位偏好"供过优化去找准。真实世界 Gao et al.(2023) 的 overoptimization 曲线（对 RM 优化越狠、人类质量先升后崩）这里对应的是**KL 轴**：**KL 越涨，三票越崩**。这是同一根曲线的玩具映射。

### 7.2 长度偏置：为什么这里测不出来（诚实声明）

知识地图的实践项要求"评估长度偏置"。玩具里我们**诚实说测不出来**，原因是结构性的，不是没做：

- 玩具词表**没有 EOS token**，每条回答都在 max_n=8/10 处硬截断——**所有回答恒长 8 或 10 token**，"回答越长分越高"的长度偏置根本没有可供它作用的长度差异。
- SimPO 的**长度归一化**（把奖励除以回答长度）在恒长回答下是恒等变换；ORPO 的 odds-概率摊匀在恒长下也无差异化空间。
- 因此"SimPO 治长度偏置"的卖点在玩具里是**惰性臂**（inert），和 `14` 章说"长度奖励代理测不出"是同一条成因。

真实 LLM 里 `Rejected/longer` 这类长度偏置是 DPO 迭代派（Zephyr、Tulu 3）的标配调试项——因为它真实存在、且 β 与长度归一确实在起作用——但那要等有真实词表/EOS 的模型才能测（§8→§10 的实践项正好把它立起来）。

> 诚实结论：**'旋钮晾衣线'是这个家族与 RLHF 同样真实的超参税；'过优化'在玩具里体现为 KL 失控→三票崩（而非留出判别崩）；'长度偏置'因无 EOS 恒长回答而测不出来——这三个声明的每一条都被实测支撑，别把玩具结论夸大成真实模型的。**

## 8. 放大账：玩具 → Zephyr / Tulu 的真实 DPO 管线

### 8.1 真实 DPO：Zephyr 的教训——"偏好对不够，迭代凑"

Zephyr-7B（Tunstall et al. 2023）说明真实 DPO 的落地不只是一次闭式损失：它对 Ultrachat 两次迭代 DPO（dpo → 再产数据 → 再 dpo），并**专门把 β 定成对结果最敏感的超参去调**（论文原文推荐 β∈[0.01,0.1] 量级与 lr 之比联动）。这与本章 §7 的一条晾衣线完全同构：**DPO 不是"省了 RM 就一劳永逸"，它是把 RL 时代的繁琐换成了数据/β 时代的新繁琐。** Tulu 3（2024）则走了另一个方向——把 DPO 与在线策略（vSFT/vDITTO, VR）融合，用"在线生成 + 即时偏好"绕过离线偏好的分布偏移，这条线把 DPO 家族的"省"重新接回 RL 的"活"。**家族每一代变体都是在'省在哪'和'把什么问题省出来'之间重新定价。**

### 8.2 成本账：从"三份驻留 + 在线"到"一份驻留 + 零在线"

```text
RLHF（14章玩具实测）：驻留 62.9 万参数 · 每步现场采样 · 整脚本 153s
DPO/IPO/KTO（本章） ：驻留 32.7 万参数 · 无在线采样 · 单段 30-53s（含300步）
ORPO/SimPO（本章）：驻留 16.3 万参数 · 无参考模型 · 单段 23s
```

省下的还有 RL 调试面：没有 rollout 种子敏感性（`14` 章 §6 的"无锚漂移方向交给运气"在 DPO 里被"偏好对 + 冻结参考"系统性消掉了）。**代价**是 lr 只能取 3e-4 这个低档（我们试 3e-3 直接发散——DPO 的离线偏好梯度虽无在线噪声，但同样吃不了大步长），而且对 β/margin/λ/γ 的高度敏感换来了"一张调参表比一套 RL 超参更挑"。**真实部署建议：先跑 3 次小步号扫 β，再定长训；把 lr/β 的比例当成稳定性开关。**

### 8.3 验证：别只盯 RM 分数

`14` 章说验证别只放一个仪表盘；DPO 家族更甚——**判别率在过优化时不反应**（§7.1），所以玩具里验证三路：①采样三票（质量）②KL→SFT（离锚多远）③留出对判别率（偏好信号是否真的学到了）。真实管线里把 ②换成 PPL/评估集、把 ①换成人类评测，思想不变：**奖励信号涨不代表文本质量涨**（Gao et al. 2023）。

```text

```

## 11. 衔接下一章：GRPO 与 RLVR

DPO 家族已经把"裁判（RM）"和"在线采样"省掉了，但还有一个箱子：**奖励的信号从哪来？** 到 `17.2.17` 的 GRPO 与 RLVR（Reinforcement Learning with Verifiable Rewards），DeepSeek-R1 直接把"奖励模型"换成**可验证规则**（数学答案对错、代码能否通过测试）——连偏好标注都省了，信号变成"对就是对"的二进制。GRPO 去掉了 online RLHF 的 value head（每步省一张 critic 的驻留与 rollout），RLVR 把"谁更好"的裁判从可训练 RM 换成了可验证的规则。这条线从 DPO 家族的"省 RM"一路走到"省标注"，正是 `16` 章（[`16-GRPO与RLVR.md`](16-GRPO与RLVR.md)）要讲的：**当奖励是规则可验证的时候，对齐的终局状态会简化到什么程度。**

> 一句话：**DPO 家族省掉 RM 与在线采样，GRPO/RLVR 再把裁判换成规则——'喜欢'从人打分的比较，变成规则可验证的断言，RLHF 时代的每一块重资产都在被人反复拆解。**
