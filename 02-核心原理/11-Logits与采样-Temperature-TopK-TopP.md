## 0. 为什么要采样：argmax ≠ 最佳生成

`10` 章把生成推进到："decode 每步用 KV Cache 算出下一个 token 的 logits 向量"。本章接手最后 10 米：**logits 怎么变成实际吐出的那一个 token**。

最直觉的方案是 **greedy/argmax**：挑分数最大的。可它有两个由生成过程本身造成的问题：

1. **前向误差会累积**：某一步觉得"第二好"才对的场景，argmax 直接锁死，更差的选择一错到底（因为生成是自回归的，一步错、步步错）；
2. **永远同一条路**：同一 prompt 每次生成一模一样（无多样性），任务一旦存在多个合法答案（翻译、创意、规划），就卡死在一个解上，还可能陷入**循环重复**（A4 演示）。

所以现代推理默认**从概率分布里采样**，而不是取峰——`do_sample=True` 时，`transformers.generate()` 内部就是本章这三样旋钮的流水线：`temperature → top_k → top_p → 采样`。

> 一句话：**"挑最大"只是采样在温度趋零时的极限；真实生成是"按概率抽签"——scenario 正确时抽签反而更稳、更多样。**

---

## 1. logits → 概率：softmax 是全部决策的地基

回到 `09` 的出口、`01` 的 shape 链尾巴：输出头把隐藏向量投回 `(…, V)` 的 logits。logits 只是"相对分数"（可能很大、可正可负），每次决策前都要软化成概率：

```
p_i = exp(z_i / T) / Σ_j exp(z_j / T)
```

`T=1` 就是原始 softmax。本章所有旋钮做的事本质只有两类：**改这个公式的 T**（温度），或**改"从哪些 i 里抽"**（截断/惩罚）。采样器从不发明分数，它只决定"在哪些候选、以什么比例"抽签。

---

## 2. temperature：熵的杠杆（实测 A1）

`z/T` 里 T 一插进来，**相对差距**就被改变：T<1 放大差距（高的更高、低的更低）、T>1 抹平差距（趋近均匀）。注意它**不改变排名**——只是把分布拨尖或拨平，所以叫"熵的杠杆"。A1 实测同一套 V=30 的合成 logits：

```text
实测 A1 温度影谱（同一套 logits，T ∈ {0.2, 1.0, 2.0, 5.0}）：
  T=0.2  top1=0.666  H=0.901 nats  PPL≈  2.5     ← 收缩：高分更集中
  T=1.0  top1=0.200  H=2.671 nats  PPL≈ 14.5     ← 原始温度
  T=2.0  top1=0.100  H=3.182 nats  PPL≈ 24.1
  T=5.0  top1=0.055  H=3.364 nats  PPL≈ 28.9     ← 摊平：逼近均匀（上限 lnV=3.40）
```

三件实测事实可以带走：

- **温度 = 熵的上限开关**：T 从 0.2 → 5.0，熵从 0.90 单调爬到 3.36，上限是「完全平均」时的 `ln V = 3.40`（V=30）——温度低温时"利用"（赌高位），高温时"探索"（摊均匀）；
- **PPL≈exp(H)**：这是采样分布的"有效困惑度"——T 越高，模型"每个 token 平均面对多少种可能"。T=1 的 14.5 意味着"平均 14 个左右候选在竞争"，低温压到 2.5；
- **绝不改变排序**：T=0.2 和 T=5.0 的 top-3 顺序一样——**温度改的是清晰度，不是答案本身**。

> 记忆抓手：**temperature = 熵的杠杆。T<1 把分布压尖（确定性↑、多样性↓），T>1 摊平（反之），上限 ln V。**

## 3. Top-k：硬截断保留局（实测 A2）

Top-k 是"只有分最高的 k 个 token 有资格被抽"。它**砍掉的不是概率，是候选**：砍掉后剩下的重归一（A2 实测）：

```text
实测 A2 Top-k（T=1 原分布，前 5 名分别占 0.200/0.154/0.148/0.075/0.044）：
  top-1  覆盖原概率 0.200 → 漏掉 0.800（重归一后 top1=1.000）
  top-5  覆盖原概率 0.620 → 漏掉 0.380（重归一后 top1=0.322）
  top-10 覆盖原概率 0.818 → 漏掉 0.182（重归一后 top1=0.244）
```

两个注意点：

- **k 太小的代价**：top-1 直接退化成贪心（覆盖 0.2、漏 0.8）；top-5 时"概率最高的强词"从 0.20 被抬到 0.32——**截断会悄悄改变相对概率**，k 小则 long tail 被全部吞掉；
- **硬截断的毛病**：k 固定，但分布**宽窄是变动的**——都截 50，分布窄时可能全在候选里、分布宽时要砍掉一堆"本来该有资格"的词。这就是 top-p 想修的地方。

## 4. Top-p / nucleus：动态涌现集（实测 A3）

Top-p（2019，Holtzman；也叫 nucleus 采样）不锁个数，锁**累积概率**：从高到低累加直到覆盖 p，只在这个「涌现集」里采样。A3 用「尖锐 vs 平坦」两套 logits 实测集合大小怎么浮动：

```text
实测 A3 涌现集大小（v 词 vs 累积概率）：
  logits 尖锐： p=0.70→ 4 词   p=0.90→ 8 词   p=0.95→11 词  p=0.99→19 词
  logits 平坦： p=0.70→20 词   p=0.90→27 词   p=0.95→29 词  p=0.99→30 词
  → 同一 p=0.90：尖锐分布只需 8 词，平坦分布要 27 词
```

这组数字就是把 Top-p 和 Top-k 分开讲的主角：**Top-p 的候选集随分布置信度自动伸缩**——置信度高（尖锐）时集合小、保持强词权重；置信度低（平坦）时集合大、给长尾机会。k 固定则做不到这件事。

> 记忆抓手：**Top-k 锁"个"，Top-p 锁"概率/置信度"——涌现集随分布宽窄自动伸缩（实测同 0.9：8 vs 27 词）。**

## 5. 采样实践：旋钮怎么组合、顺序怎么排

工程上（`transformers.generate()` 内部）它们按固定顺序流水：**`temperature → top_k → top_p → multinomial choice`**。生产直觉大致是：

- **贪心 / `do_sample=False`**：确定、快，适合对错分明的复盘/评测；重复、单调是它的毛病（A4 演示）；
- **低温 (0.1–0.3) × Top-p (0.9)**：对错不太分明的任务（数学、结构化抽取）常用的"近贪心但有质感"组合；
- **T≈1 × Top-p 0.9–0.95**：创意/对话的常用档——保持长尾表达又滤掉明显离谱的；
- **Top-k ≠ Top-p 哪个更常用**：实际很多实现默认 `top_p=0.95` 并保留 top_k 兜底（如 vLLM/OAI 兼容层）——两者非二选一。

（温度还有"冷却调度"的用途：思考/长生成中把 T 从高往低调，细化后阶段采样更笃定——这是 `19-长上下文/20-推理模型` 会用到的场景。）

## 6. 重复惩罚：治"无限循环"（实测 A4）

贪心/低温最容易翻车的一幕：某个 token 分数过高，模型每步都选它 → **同一 token 无限重复**。之所以发生，正是因为自回归上一步的结果又喂回下一步，argmax 的"最安全"选择自我加强。标准对策是在 **logits 层**对"已经出现过的 token"压分——这就是重复惩罚（`repetition_penalty`）。A4 用"token0 领先、其余~N(0,1)"的构造演示脱困：

```text
实测 A4 重复惩罚（贪心逐 token，token0=3.0 一直领先）：
  无惩罚（β=0）：前 8 步 = [0,0,0,0,0,0,0,0]       ← 无限循环
  惩罚（β=4） ：前 8 步 = [0,17,23,20,16,26,22,12]  ← 压分后把机会让给其他词
```

原理一句话：**每选中一个词，就把它在 logits 上的分数往下压**（实测减法式 β=4 一次就足以把 3.0 拉出榜首），下一个位置它就不再"必胜"。注意它是在 logits 上动刀而不是改分布——这正是本章的通用思路：**一切旋钮都在"分数"层面操作，然后才软化、才开抽**。

## 7. 实践题：温度 0 vs 1 的效果与困惑度（实测 A5）

知识地图的实践题直接照做：对同一套 logits 的分布，采样 200 条长 5 的序列，统计唯一序列数与有效困惑度 PPL=exp(H)：

```text
实测 A5 温度 vs 多样性（同一分布 200×5 采样）：
  T=0.0  1/200   条唯一序列（多样性   0%）  PPL≈  1.0   ← 贪心，永远是同一条
  T=0.2 82/200   条唯一序列（多样性  41%）  PPL≈  2.5
  T=0.7 199/200  条唯一序列（多样性 100%）  PPL≈  9.1
  T=1.0 200/200  条唯一序列（多样性 100%）  PPL≈ 14.5   ← 原分布，全屏多样化已解锁
  T=1.5 200/200  条唯一序列（多样性 100%）  PPL≈ 20.7
```

两个结论（也是"温度=熵的杠杆"的闭环）：

- **温度 0 = 确定性**：200 次生成全是同一条，PPL=1（分布是 0/1）；温度 0.2 已经恢复到 PPL 2.5 / 41% 独样；
- **多样性阈值在 T∈(0.2, 1) 之间解锁**：T=0.7 已是 199/200（几乎全不重复）、T≥1 全部唯一；之后温度升高不再改变"是否唯一"——它改的只是**候选多宽**（PPL 从 9.1 → 20.7），即"抽签的池子多大"。**"不一样"在 T≈0.7 就达标了，"更丰富"还要往 1 以上走。**

## 8. 衍生：约束解码与结构化输出

知识地图把「约束解码、结构化输出」列为采样衍生（`06-应用开发` 展开）。思路是：**既然每个 token 都过采样器，在采样那一刻插进"规则"就能逼出结构化**。例如输出 JSON 时，对 `:` `"` 等 token 强制高权重、在冒号后把候选锁死到合法字段——这就是 `json-schema` 冷解码（constrained decoding / grammar-constrained）的原理：**不变的是"每步从 logits 采一个 token"，多出来的是"候选集被语法过滤器硬性缩小"**。采样器 + 语法约束 = 一切结构化输出的地基。

## 9. 常见坑

| 坑 | 症状 | 修法 |
|---|---|---|
| 把 temperature=0 当"低温" | 输出突然变僵硬 | T=0 是贪心/确定性，不是"低温"——区分"更冷"(0.2)与"确定"(0) |
| 以为温度改变答案排序 | 低温时 k 选出的 top 还是原 top | T 只改相对差距不改排序（实测 A1 top-3 顺序不变） |
| Top-k 用太小 | 高质量候选被硬砍、概率被重分布到奇怪的主（实测 top-1 覆盖 0.2） | 看覆盖概率：top-10 覆盖 0.82；k 与词表规模/任务匹配 |
| 不知道 Top-p 的集合会动 | 以为 p=0.9 的候选数是固定的 | 实测尖锐 8 词 vs 平坦 27 词——集合随置信度浮动（A3） |
| 把 Top-k 当 Top-p 用 | 宽窄分布一视同仁地截尾巴 | Top-k 锁个数、Top-p 锁累积概率（能自动伸缩） |
| 贪心/低温无限重复不设防 | 生成卡在"对对对…" | 加 repetition_penalty，或自查是否 do_sample=False |
| 把"多样性高"当"质量高" | 高温度下跑分下降 | 温度是熵/探索度旋钮，不是质量旋钮；上喘看 PPL exp(H) 给定量 |
| 直接用温度调下重复 | 重复没消失只是变烫 | 重复是"分数自我加强"，对症下药用惩罚/截断（A4） |

## 10. 衔接下一章

`10` 的 decode 循环在这一章真正闭环：`prefill → 循环 { KV Cache 出 logits → 采样出一个 token → 追加 }`。至此，**"模型怎么生成一句话"讲完整个原理链**（00 时间线的 0–10 篇）。下一章起，叙事转向**这些能力从哪来**：

> **`12-预训练-Next-Token-Prediction`**（下一章, 规划）：本篇的"softmax → 采样一个 token"只是**推理时**，而预训练问的是"怎么把'预测下一个 token'当成训练目标，让模型从语料里长出这个能力"——接住本篇的分布语言，讲最大似然/交叉熵与自回归目标的等价关系。

> 一句话带走：**采样把 decode 的 logits 变成 token——temperature 拨熵的上限（实测 0.90→3.36 nats、PPL 2.5→28.9）、Top-k 硬截取尾（top-10 覆盖 0.82）、Top-p 涌现集自动伸缩（同 0.9：尖锐 8 词 vs 平坦 27 词）、重复惩罚拉回收死（[0…]→脱困序列）、温度 0 vs 1 是"确定性 vs 100% 多样化 + PPL 从 1 到 14.5"；一切旋钮都在 logits 层，先改分数再软化、再抽签。**
