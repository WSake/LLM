## 0. 为什么 SFT 之后还要"对齐喜欢"

`13` 章结束留了个钩子：SFT 把模型从"续写者"掰成了"对话者"——它会按指令回答了。但你去细看它**采样**出来的回答，会发现格式对了、事实开头对了，质量却还飘着。用一个玩具"人类裁判"（§2 细讲）把每个回答打成"三票"（答得对 + 答得全 + 答得干净 = 3/3），SFT 之后的模型只有这个水平：

```text
实测 A（SFT 之后，temp=1.0 每问采样 20 次）：
  训练问 perfect 率 62% · 全新问 perfect 率 38%

  例1（问 g 值）「9 . 8 meters per second squared . pi is」              judge 2/3
  例2（问 π 值）「3 . 14159 . mathematicians approximate pi as 3 .」      judge 2/3
  例3（问沸点）「100 degrees celsius . water reaches its boiling point at」judge 3/3
```

看懂这三个例子，就懂为什么需要 RLHF：

- 例1 是答"g 是多少"——开头"9.8 meters per second squared"对了，但尾巴"pi is"把 π 的公式扯了进来——**答得不干净**。这是玩具模型典型的翻车形态：跟 `12/13` 章预训练语料里的一样，它会把"9.8"后接"pi 出现"这类语料里的共现尾巴顺出来。人类一眼就烦。
- 例2 是答"π 是多少"——"3.14159"开头对，但后面没把金标准答完整——**答得全**这一票丢了。
- 例3 是答"水的沸点"——"100 degrees celsius . water reaches its boiling point at"对、全、干净，3/3。

所以 SFT 的真实产出是**会说但 62%/38%（训练问/全新问）**。它缺的是把"格式正确"升级成"回答被喜欢"的最后一层——这正是 RLHF 的领地。

> 一句话：**SFT 对齐"会不会说"，RLHF 对齐"说的好不好、人喜不喜欢"。错位的事实（开头对、尾巴脏/不完整）正是 RLHF 要修的教材。**

## 1. RLHF 三步：先养裁判，再让策略对裁判负责

RLHF（Reinforcement Learning from Human Feedback）不是单点技巧，而是一条**三步流水线**，因 InstructGPT（2022）而普及：

```text
① SFT      ：拿 (指令, 金标准回答) 微调 → 得到"会说话的模型"          ← `13` 章已经做完
② 奖励模型  ：让人类比较成对的回答，学一个打分器 RM（哪个更被喜欢）    ← 本章 §2-3
③ PPO      ：让策略去挣 RM 的分数，同时用 KL 惩罚别跑偏              ← 本章 §4-6
```

三句话分别对应三个思想转变：

1. **监督信号变了**。SFT 的标签是"人类写出的金标准答案"；RLHF 的标签是"两条回答里人类更喜欢哪条"。人类很擅长**比较**，但不擅长**写**出对每个问题都完美的话——让标注员打分比让标注员写答案便宜得多、可靠得多。这是 RLHF 能在 GPT-3 之后把"有用性"做上去的根本原因。
2. **优化目标变了**。SFT 最大化"金标准词的对数概率"；RLHF 最大化"裁判给出的奖励"——奖励是一个**可变的、由另一个模型算出来的标量**，不是固定标签。
3. **代价变了**。训练时要同时驻留三份模型：正在优化的策略 (`π_θ`)、冻结的 SFT 参考策略 (`π_ref`，判 KL)、冻结的 RM（给奖励）。这就是 RLHF 比 SFT"重"的来源。本章玩具实测里，三份驻留的参数量 ≈ 62.9 万（策略 16.3 万 × 3 + RM 13.9 万），而 SFT 阶段只有 16.3 万。

> 记忆抓手：**RLHF = SFT + 买了个裁判（RM）+ 请了个教练（PPO，但每次出手都先问'这次偏离 SFT 多远'）。**

## 2. 第一步 · 奖励模型：把"哪个更好"变成打分（实测 B）

### 2.1 偏好数据：高温采样，拉开差距才有得挑

奖励模型的原始材料是**偏好对**：`(指令, 更好的回答 chosen, 更差的回答 rejected)`。真实世界里括号里的人类标注，在玩具里由"人类裁判"扮演——一套写死的三票规则（答得对/答得全/答得干净）。它不学、不变，负责"像人一样"给任何回答一个 0-3 分。

关键问题：**怎么才有得挑？** 如果只用 SFT 策略在 `temp=1.0` 下采样，所有回答质量都挤在一堆（早期版本里同一问采 40 条，得分分布几乎全是"1 分"，凑不出差分对比）。解法是**高温采样**——用 `temp=2.0/3.0` 各采样 12 条，把"差回答"逼出来，让裁判有偏爱可挑：

```text
实测 B1 偏好对构建（每问采样 24 条）：
  for temp in (2.0, 3.0):
      for _ in range(12):
          a = sample_ans(p_sft, pref_train[i], rng, temp=temp, max_n=10)
          sc.append(judge_score(gold_ids[i], a, tox_i))     # 人类裁判打 0-3 票
  hi_idx = argmax(sc)                        # 最好的当 chosen
  for k with sc[k] < sc[hi_idx]: pairs.append((i, ans[hi_idx], ans[k]))   # 其余更差的当 rejected

  结果：383 组偏好对（留出 58 组做验证）
```

高温把"错开头的、扯脏尾巴的、答不全的"都采出来了——`chosen` 都是 3 分左右，`rejected` 分布在 0-2 分。**没有差异就没有监督信号**，这是奖励模型能不能学起来的前提。

### 2.2 奖励模型的损失函数：Bradley-Terry 排序损失

奖励模型给它一条回答，就要输出一个标量分数 `r(指令,回答)`。让它学"chosen 应该比 rejected 分高"，用 Bradley-Terry 假设——"chosen 更被喜欢"的概率是两条分数差的 sigmoid：

```text
P(chosen ≻ rejected) = σ(r_chosen − r_rejected)
L = −log P = log(1 + e^(r_rejected − r_chosen))
```

梯度会拉开两条分差：`chosen` 分数上调、`rejected` 分数下调，直到 σ 接近 1。这跟分类交叉熵是一家人，只是"类别"换成了"哪边更优"。

### 2.3 结构与初始化：同一个引擎，多一个标量头

玩具 RM 不另起炉灶：直接复用 `12/13` 章那个 1-block 解码器，读到 block 输出 `x3` 为止（扔掉 `Wout` 词头），把最后一格真实位置（去掉 padding）的 `x3` 接一个线性标量头 `wr · x3 + br`，就是一条回答的奖励。参数占位：**策略 163,392 / RM 139,393**（少一个词头、多加 wr+br 一维）。

这里藏着一个真实管线的重要惯例（以及我们踩过的坑，§8 详谈）：**RM 用 SFT 训练后的参数初始化**，而不是随机初始化。冷启动的 RM 在同等微调预算下判别率做不上去（实测 43%），从 SFT 出发则稳定做到 80% 上下——因为"哪种话更顺、更接近人话"的先验已经躺在 `π_SFT` 里了，RM 只需要在这个基础上调出"偏好"方向。

```text
实测 B2（RM 训练：SFT 初始化 · 500 步 · 每步 8 组对比）：
  留出偏好对判别率：79%（58 组留出对里，RM 判"哪条更被喜欢"与人类三票一致的比例）

  → RM 学到的"谁更被喜欢"与人类三票裁判高度一致
```

注意一个容易误读的点：**RM 分数的绝对值没有跨运行可比性**（它随 RM 随机初始化/训练轨迹漂移，本 run 起步 -5.2，别的 run 起步 -0.9）。我们只追踪相对爬升——这正是 RLHF 评测里要用"判别率"而不用"分数本身"的理由。

> 一句话：**奖励 = "另一个可训练的小头，学会说哪条更好"；它的生产资料是高温采样逼出的偏好对，它的出生方式是 SFT 参数继承。**

## 3. 第二步 · PPO 真正在优化什么（REINFORCE 视角，诚实简化）

裁判有了，下一步是让生成分布往高分处走。问题立刻出现：**采样是离散的，梯度传不回去。** 下一步选哪个词这个动作不可导，"奖励高"和"这句话长得怎样"之间没有可链式求导的路径。

教科书解法（REINFORCE / 分值函数梯度）：不试图把梯度传进采样，而是**用"朝某个词走，期望奖励变化多少"来估计梯度**：

```text
策略目标：J(θ) = E_{y ~ π_θ}[ r(x, y) ]
∇J(θ) = E[ r(x,y) · ∇log π_θ(y|x) ]        ← 分值函数（score function），无偏
```

等式右边没有对采样求导，而是给**被采到的词乘以奖励的权重**再去求普通对数似然梯度。翻译成人话：**这轮样本里哪句话挣的分高，就把"让我更像这句话"的梯度放大；试了烂句子，就把它压低。**

REINFORCE 的方差很大，玩具里用两个标配手段压它（真实 PPO 还有三样，见 §7）：

```text
① 均值基线减差：adv = r − mean(r)          ← 让"高于平均"而非"奖励绝对值"影响梯度
② 优势归一化：   adv = adv / (std(adv) + 1e-6)   ← 把步长尺度钉死，防止一两个高分样本主宰一步更新
```

下面是本章玩具实际在跑的 RL 骨架（伪代码，维护 `rlhf_ppo_demo.py` 的 A-C-D 结构）：

```text
for step in 1..150:
    # 1) 策略采样 8 条回答（temp=1.0；采样长度固定 8，词表没有 EOS 所以靠截断）
    ys = sample_ans(π_θ, prompts)
    # 2) 对每条：RM 给分 + 参考策略算 KL
    r      = RM(x, y)
    lp_pol = logπ_θ(y) ;  lp_ref = logπ_ref(y)        # ref = 冻结的 SFT
    r_eff  = r − β·(lp_pol − lp_ref)                   # β 加权 KL 惩罚（§4）
    # 3) 优势与归一化
    adv = (r_eff − mean) / (std + 1e-6)
    # 4) 回答区每个 token 的损失权重 = adv − β，再走标准的 forward/backward
    lm[P-1+k] = adv − β   （对每条回答的每个 token）
    θ ← Adam(θ, ∇(−Σ lm·logπ_θ), lr=3e-4)
```

**诚实声明（很重要）**：真实 PPO 在三号位还会做 ratio clipping（单步更新幅度裁剪）、用 GAE 做多步优势估计、以及训一个 value head（critic）来降方差。本章玩具省略了这三样、用均值基线 + 归一化替代，因为这一个"REINFORCE + 基线 + KL"的最小闭环已经足以把"喜欢变梯度"的机制讲清楚；玩具规模上三样东西在数值上并非必须。**别把本章误解成完整 PPO 的实现**——§7 会把缺的三样补齐讲清。

> 一句话：**离散采样不可导 → 用"采到的词 × 奖励权重"的分值函数梯度，把 RM 的分数翻译成每个 token 的方向。**

## 4. KL 惩罚：给策略系一条"别离 SFT 太远"的安全带

RLHF 原始目标只有一个（最大化 RM 分数），但它有两个致命边角：

1. **RM 不是真值**（判别率只有 79%，真实世界里更只有 7-8 成）——冲着它的分数猛冲，会冲进它"过拟合的区域"（reward hacking，§6/§7 细讲）。
2. **REINFORCE 高方差**——自由漂移时梯度噪声很大，步子容易踩出悬崖（§8 的翻车实测：步长回到 3e-3 时 KL 冲到 108、perfect 归零）。

对策是一句熟话：**别让新策略离"原本那个可靠的 SFT"太远。** 给它每步计"离 SFT 分布距离"的账——用每 token 的 log 概率差作 KL 惩罚：

```text
r_eff(x, y) = r(x, y) − β · (log π_θ(y|x) − log π_ref(y|x))

梯度落地：每个回答 token 的损失权重 = (adv − β)
```

β 是"安全带松紧"旋钮：

- β 太大 → 策略被钉死在 SFT 附近，几乎不动（对照 `12` 章里 KL 奖励的含义）。
- β 太小（0）→ 安全带没收，完全冲着 RM 去（§6 D 组）。
- 本章 `BETA=0.1`：**允许在 KL 允许范围内挣分，但每挣一分都付"离 SFT 的距离税"。**

实现上这就是为什么 PPO 阶段要**三份驻留**：正在优化的 `π_θ`、冻结的 `π_ref`（算 KL）、冻结的 RM（给 reward）。SFT 只需要一份模型，RLHF 需要三份——"重型"不是形容词，是必须的账。

> 记忆抓手：**KL 惩罚 = 把"离 SFT 多远"按每 token 定价；β 越大越保守、β=0 等于没系安全带。**

## 5. 实测 C：把 RM 分数换成梯度之后

```text
实测 C（PPO · REINFORCE + 均值基线 + KL 惩罚，β=0.1，150 步）：
  平均 RM 奖励（固定评测 30问×12 采样）：前 -5.181 → step50 -1.056 → 后 +5.610
  终态 KL(π ‖ SFT_ref) ≈ 10.653（有界——没滑向'只管吃奖励'）

  RLHF 后采样 perfect 率：训练问 70%（前 62%）· 全新问 67%（前 38%）

  C 组采样示例（RLHF 后，temp=1.0）：
    例1（问 g 值）「9 . stars are born inside clouds of gas that」     judge 2/3
    例2（问 π 值）「3 . 14159 . falling near the ground objects accelerate」judge 3/3
    例3（问沸点）「100 degrees celsius . water starts to boil when it」 judge 3/3
```

看这三个例子，跟 §0 里 A 组的三个对照：π 问、沸点问都拿到了 3/3，答 g 的那条即使没答全，也守住"9 ."开头、不再把 π 的公式扯进尾巴——**"脏尾巴"这个 SFT 时代的典型症状被 RLHF 治住了**。一个直观的代价：答案越来越贴金标准开头与事实区，自由发挥的空间小了。

这张表四行，一行一个信息：

1. **奖励真的被挣到了**：-5.2 → +5.6。REINFORCE 的分值函数梯度奏效了——"喜欢"确实变成了可优化的目标，不是纸面概念。
2. **KL 有界**：10.7。策略没有脱缰。对照 §8 里那条"步长 3e-3 无锚"的翻车线（KL 108），这里 10.7 说明 KL 锚在起作用。
3. **训练问三票从 62% → 70%**：把"会回答"往"答得好"推了一格。
4. **全新问三票从 38% → 67%，几乎翻倍**——这是最值得看的数字：模型用的全是**没在训练里整体出现过的问题**，但答案的对/全/干净三条线一起提升，说明对齐改善的是采样分布本身，不只是在背训练问法。

为什么全新问涨得比训练问多？因为训练问在 SFT 阶段已经被压得够好：采样分布里 `chosen` 大多已经接近 3 分，往上顶的余地小；而全新问基线只有 38%，从"错开头的、扯脏尾巴的"翻到 3 分的空间大。**RLHF 把策略拽向"更可能被喜欢的答案"这一团，让没见过的问法也收益。**

> 一句话（C 组）：**150 步之内，"喜欢"真被搬进了损失函数：奖励 -5.2→+5.6、KL 有界、全新问三票 38%→67%。**

## 6. 对照组 β=0：去锚之后，玩具为什么"没疯"（实测 D）

RLHF 教材最爱讲"不用 KL 就 reward hacking"。我们照做了一组对照组：**同样的预算、同样的优化器、唯一的差别是把 β 设成 0**。

```text
实测 D（对照组 β=0，其余与 C 组完全一致）：
  平均 RM 奖励 -5.181 → 0.758   （C 组 -5.181 → 5.610）
  KL(π ‖ SFT_ref) ≈ 9.051       （C 组 10.653）
  perfect 率 78%                （C 组 70%）
  回答去重 23                   （C 组 18）
```

把这张表和"奖励游戏化"几个字摆在一起，是很挫败的：**D 组既没有分数疯涨，也没有多样性坍缩，甚至 perfect 率还比 C 组高。** 这个"没疯狂"本身值得掰开——它恰恰暴露了我在 §8 和 §7 才讲的三个真实机制：

**① 短程内，玩具 RM"没缝可钻"。** RM 判别率 79% ≈ 人类三票裁判，因为裁判就是同一套写死的规则在投影。奖励≈真值，策略刷分≈刷质量，"刷分的富矿"不存在。真实世界不是这样：RM 只有 7-8 成判别率、且会学进去**系统偏差**（长度偏好、措辞偏好、讨好裁判风格），那些偏差是可被策略放大利用的缝隙。

**② β=0 把 REINFORCE "学不动"了。** D 组奖励只爬到 +0.76，而 C 组 +5.61——差距 7 倍。没有 KL 锚的高方差 REINFORCE，在 150 步预算内把大量梯度花在分布漂移上、回报转化率直线下降。**KL 的第一个职能其实是稳定梯度（导航线），而不是只当刹车**——这和我们踩过的翻车坑完全一致：步长放大到 3e-3 的 β=0 直接发散（KL 108、perfect 归零，§8）。玩具里"D 冷场"不是 bug，是无锚高方差优化常见归宿。

**③ 多样性 23 > 18 反直觉但合理。** 收敛/坍缩需要压力聚焦；无锚时策略在 RM 的模糊高原上探索面更宽，没有 KL 收敛到"像 SFT"的窄带。**坍缩是"长期对单一高分模式过度优化"的产物，短程 150 步还没攒够那个压力。**

一颗种子说明不了多少事。同样的预算，把 rollout 的随机种子在 11/13/17/21 之间换（其余全部不变，在**同一条**预训练/SFT/RM 轨迹上只动种子），β=0 的表现跨度非常大：

```text
多种子扫描 D（β=0，rollout 种子换 11/13/17/21；C 组种子恒为 11）：
  C  seed=11：RM 奖励 +5.61 · perfect 70% · KL≈9.8  · 去重 21   （锚在：稳）
  D  seed=11：RM 奖励 +0.76 · perfect 78% · KL≈9.4  · 去重 21   （学不进）
  D  seed=13：RM 奖励 +1.12 · perfect 55% · KL≈12.5 · 去重 29   （微涨，质量略掉）
  D  seed=17：RM 奖励 +2.47 · perfect 24% · KL≈14.3 · 去重 9    （质量崩：比 SFT 基线 62% 还低）
  D  seed=21：RM 奖励 +3.25 · perfect 67% · KL≈16.7 · 去重 23   （涨了点分，质量持平）
  （本表 KL/去重的统计口径与逐位主表略有出入，用于读趋势与形态）
```

三行读法：**没有一个 β=0 种子做到 C 组那种"奖励涨、质量稳"**。最常见的两个走向，恰好是 RLHF 教材警告的两个危险信号——"学不进"（seed 11：分数基本没动）和"质量崩"（seed 17：perfect 从 SFT 基线 62% 掉到 24%，白训了，KL 冲到 14.3——策略在分布上走得很远，答题质量却走丢了）。seed 21 是四个里唯一"涨了分、三票持平"的，KL 也冲到了全场最高 16.7——再给长预算，当收敛与坍缩的压力攒够，这就是刷分怪长出来的第一截形状。**RL 对种子敏感、又没有锚时，漂移方向由随机涨落决定——这正是 KL 锚的用武之地：它把方向钉在'离 SFT 别太远'，而不是交给运气。**

> 诚实的结论：**在这套"奖励≈真值 + 短程"的玩具里，β=0 精确复现的不是"骗过裁判刷高分"，而是"无锚的漂移不受控"——同一预算下 4 颗种子给出 4 种走法，最好也不过 C 组的一半，最差直接质量崩。制造真正"刷分怪"的两个条件这里都欠着：RM 判别率 79%≈真值（没有可钻的缝），训练只有 150 步（没有长程压力）。真实世界里两个条件都满足，β 的安全带作用才是硬结论（§7/§8 对账）。**

## 7. 放大账：玩具 → InstructGPT 真实管线

### 7.1 数据：人类比较，但比例要够

真实 RLHF 的标注不要求人类写出理想答案，只要求人类**比较**两个候选——这就是 §1 说的"比较便宜于书写"。InstructGPT 用 40 位标注员在三套标准（helpful / harmless / honest）下给 7-9 分制打分，再拿这些离散分构造偏好对喂给 RM。规模在"数万条标注 + 每 prompt 多个候选"量级 —— 数据标注占了 InstructGPT 项目预算的大头（论文原话：最大的开销是数据收集）。玩具没有人类，用写死的三票裁判替身，代价同样是"加工偏好对"。

### 7.2 模型：RM 与策略同体出发，但可以更大

我们用 SFT 参数初始化 RM，与真实管线同理由：RM 要继承语言先验才训得动。现代实践里 RM 常与策略同尺寸甚至更大（LLaMA-2 的 RM 比 SFT 模型大一个量级也有出现），因为"评判比生成需要更多容纳细微差别的容量"。判别率是检验凭证——玩具 79%，真实前沿 RM 基准（RewardBench）上的好模型也只在 7-9 成浮动，这正是 §6"没缝可钻"在真实里不成立的原因。

### 7.3 算法：完整 PPO 的三样额外件

我们把三元组（REINFORCE + 基线 + KL）当最小闭环，真实 PPO（Schulman et al. 2017）在这上面还挂三样：

```text
① ratio clipping ：更新幅度按新老策略概率比裁剪 clip(r, 1-ε, 1+ε)，防止单步迈太大
② GAE            ：用 λ-加权多步 TD 估计优势，代替单步 / 整段基线
③ Value head     ：策略带一个 critic 网络，学"这条轨迹值多少分"，给优势做基线（在学中的基线）
```

这三样都是"降方差 + 稳步长"工程，不改变"最大化 reward − β·KL"这个目标本身。KL 惩罚在真实实现里也常常只是 **token 级**：`r − β·Σ_t (logπ_θ(y_t) − logπ_ref(y_t))`，逐 token 逐位置地算。策略在 RL 阶段的"步长比预训练慢 10 倍"（3e-4 vs 3e-3）同样照搬进了玩具。

### 7.4 验证：模型不盯 RM，看三路齐飞

真实验证永远不放一个仪表盘：RM 分数会涨，但**它本身可以骗你**。InstructGPT 实战里跑 PPO 的同时盯三个东西：

1. **文本 PPL / 观察采样**：奖励涨但 PPL 恶化 = 文本退化了（reward hacking 的红灯）。
2. **RM 分数 vs 人类评测**：两条线一起涨才说明 RM 在教对的东西。
3. **KL vs 预算**：KL 涨到预算上限说明策略离 SFT 太远，往往同时就是 PPL 拉警报的地方。

Gao et al. (2023) 把这画成一条经典曲线：**横轴"对 RM 的优化量（KL 距离）"，纵轴"真实人类质量"——曲线先升后落（抛物线）**。优化 RM 到一定程度后，真实质量开始不升反降——这就是"reward overoptimization"，而 β 的安全带作用正是让你停在曲线顶点附近、别再往右滑。

### 7.5 代价账

在线 RL 三份模型（策略/参考/RM）、每次迭代都要重新采样回答、再前向反向着（策略+参考+RM）——对比 SFT 一次性过数据，RLHF 的**计算与内存账都会翻几倍**。玩具三段驻留 62.9 万参数就对应这个结构；真实里模型越大、PPO 迭代越多，"对齐税"（alignment tax，评测分常略降）越明显。这就是 DPO 家族（§10）为什么诱人：想省掉在线 RL 的大头开销。

## 8. 常见坑

下面每一条都是我们把这套玩具"从不会跑到跑出可信数字"的真实过程里试错出来的；前两条几乎决定成败，注意优先级。

| 坑 | 症状 | 解法 / 为何这样能好 |
|---|---|---|
| **RM 随机初始化** | 同等微调预算判别率上不去（冷启动 43%） | RM 从 SFT 参数出发再微调（79%+）；真实管线惯例，先验都在 `π_SFT` 里 |
| **把预训练/SFT 的 lr=3e-3 直接用 REINFORCE** | 发散：perfect 归零、KL 冲到 108 | RL 步长降到 3e-4（慢 10 倍）+ 优势归一化；高方差梯度吃不了大步长 |
| **裁判"只会判开头"** | 同问 40 采全打 1 分、凑不出偏好对、RM 学成 0 分 | 裁判升级成"三票"（对/全/干净）、加"污染"这一票专抓脏尾巴；8 成是对的第一条 |
| **只低温采样** | 所有回答质量挤作一团，无差异可挑 | 高温（2.0/3.0）采样拉开差距，chosen/rejected 才有故事 |
| **词表没有 EOS** | 每个回答固定长度，越写越碎 | 收获：采样上限（max_n=8）成了隐性纪律——故意不引入 EOS，让裁判的"干净票"专抓收不住的尾巴 |
| **"喜欢长答案"代理在玩具里是哑的** | 长度奖励不起作用 | 无 EOS → 每回答恒长 8 token，长度项被均值基线消掉；说明"可 hack 的富矿"（长度/措辞）在这里不存在 |
| **KL 估计拿 numpy 标量当浮点** | 标量是 size-1 数组，代入求和炸型 | `[0]` 取出再 `float()`；玩具小，数值格式不能假设 |
| **多线程 BLAS 让数字不可复现** | 同 seed 两次跑结果不同（偏好对 345/368/383 都出现过） | 固定单线程（OMP/OpenBLAS/… =1）后再训；低维模型对浮点聚序极敏感 |
| **测试问法 OOV** | 脏验证：模型"答对"其实是 unk 拒绝式迷惑 | 训练前 assert 词表覆盖测试句；min_freq=1 全保真 |
| **把 loss 当进度条** | RL loss 不单调、归零也不代表好 | RL 用 RM 奖励/KL/三票三件衡量满意；loss 只用来检查梯度在动 |

## 10. 衔接下一章：DPO 家族，试着把裁判也省掉

RLHF 的痛点是"重"：三份驻留 + 在线采样 + 一堆 RL 超参（β、步长、clip、KL 预算……）。DPO（Direct Preference Optimization, Rafailov et al. 2023）回答一个问题：**既然目标无非是"让 π_θ 比 π_ref 更偏向 chosen"，能不能不显式训 RM、不去做在线采样，直接在偏好对上写一个闭式目标？**

DPO 的做法是在"最优解 = RM 分数 + KL 惩罚"的数学关系里把 RM 消掉，得到一个小巧的监督损失：

```text
L_DPO = −log σ( β·logπ_θ(y_chosen)/π_ref(y_chosen) − β·logπ_θ(y_rejected)/π_ref(y_rejected) )
```

只用到策略 π_θ、冻结参考 π_ref、和偏好对——**不需要训练 RM、不需要在线 rollout**。代价是把"奖励模型单独校准"那一步省掉后，对 `π_ref` 的质量更敏感，且离线偏好对没法像在线 RL 那样滚动更新。后续 KTO（一句话"还好/不行"即可）、ORPO（SFT 里直接加 odds-ratio 惩罚、连 ref 都省）、SimPO 继续在这条"越省越稳"的线上推进。

> 一句话：**RLHF 请外教（RM）再上手，DPO 家族请家教背公式——省了裁判和在线采样，但把校准的敏感度挪到了参考模型与初始分布上。**
