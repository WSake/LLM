## 0. 为什么单列一章："上下文是模型的工作内存"

`05` 章讲过一句话："RoPE 的窗口是模型的记忆半径。"本玩具把这句话变成四层可以各自测量的**墙**。先给一个工作台：

```text
本玩具语境：声明式文本 47 句 · 词表 V=222 · 总 token 597
策略参数（形状直算）= 156,288 · 引擎窗口 T=32（同 ch12-16 引擎）
```

模型在解码位置 `p` 时，"能同时看到的东西"等于它窗口里所有位置的 KV。窗口越大="工作内存"越大：代码仓库的引用、文档前文、Agent 多轮工具日志、视频帧——都是要"同时记得"的东西。而想把它做大，会撞上**四层不同的墙**：

| 层 | 墙是什么 | 谁在撞墙 | 本章实测 |
|---|---|---|---|
| ① 位置编码层 | 已训模型的解码阶段，Δ 越过训练窗 → 打分核冒伪峰 | 只扩窗不重训的人 | A 层基线窗外伪峰 4.56×（与 ch05 同口径）→ 三种重定标 |
| ② 训练层 | 位置没训练过 → 那个位置天然无泛化 | 先短后长的训练者 | B 层 Wpos[16,32) 零梯度 + PPL 墙 |
| ③ 架构层 | 注意力几何写死的"记忆预算" | 滑窗/稀疏/锚点方案 | C 层滑窗掩码实测：局部语料几乎不掉点 |
| ④ 系统层 | 显存与延迟预算（KV 每 token 都占显存） | 服务端 vLLM/SGLang | D 层淘汰策略 + prefix-cache 3.0× 复用 |

四层的顺序不是"从重要到次要"，是**从解码阶段的墙一路推到工程预算的墙**：先看已训模型"能不能解码到窗外"（位置编码），再看"没训过的位置根本不泛化"（训练），再看"把记忆预算写进注意力几何"（架构），最后看"站上一个显存预算"（系统）。一层修好，下一层的墙就露出来——这就是四层叠加的真实形态。

## 1. 位置编码层：RoPE 外推墙与 PI / NTK / YaRN 三种重定标

### 1.1 为什么要单独测量"打分核"

`05` 章已经讲过 RoPE 的旋转频率与窗口关系。这里补一个更锋利的视角：**真正决定"外推墙"的，是注意力打分核长什么样**。

```text
当前 token 与 Δ 步前的 token 的"可分性"权重 ≈ 一个随 Δ 变化的核：
  recent(Δ) = max( q与k的点积分 , 随 Δ 增长而衰减 )   ← 位置编码层测的就是这个
```

`05` 章用 `rope_demo.py` 把"就近核"拟合成 RoPE 频率的正弦/余弦线性组合，并测出基线：**直接外推到训练窗（32）之外，Δ 读到 64 步处冒出窗外伪峰，窗外峰/窗前峰 = 4.6×**。本章 A 层用同一套构造（d=64、L=32、真实 q/k 的有界打分 |s|≤|q||k|），把基线再打一遍锁成 **4.56×**，然后对**同一组已训系数**做三种重定标对比。

### 1.2 两把尺子：扩展窗内伪峰比 与 窗内失真

墙的本质是：**解码时谱位置 Δ 越过了训练窗的上界，核从一个"越来越不可信"的地方突然又翘起来**。要比较三种重定标，用两把尺子：

- **扩展窗内伪峰比**：把窗声称扩大到 `(32, 32×λ]`，测这段里的最强伪峰 / 窗内 [1,32] 的最强峰。**<1 = 墙被按住**；基线=4.6 就是没按住的例子。
- **窗内失真**：在训练过的 [1,32] 上，原始核与改写核的平均绝对差（Δ=1 归一 = 1）。越大说明"已训的原子"被动得越多。

### 1.3 三种重定标一句话

| 方法 | 改什么 | 直觉 |
|---|---|---|
| PI 位置插值 | `Δ → Δ/λ` | 把所有距离压扁 λ 倍，窗外变窗内 |
| NTK 基频重标定 | `θ → θ/λ^(2k/(d−2))`（**除**高频） | 放慢高频旋转，长相位能拉更远 |
| YaRN（简化） | 只把"波长 > 32"的分量除以 λ | 近程频率不动，只动长波 |

注意一个约定的坑：**NTK 的 θ 是"除"**（`θ/λ^(...)`），也就是放慢频率。第一次写反成"乘"（加快高频 → reach 变短 → 墙当场复燃）。这与"NTK 让高频放慢拉长 reach"的说法一致——记住"慢才能远"。

### 1.4 实测：同一组已训系数，三种重定标 18 组对比

```text

    方法            扩展λ   扩展窗内伪峰比   窗内失真    一句话
  ---------------------------------------------------------------------------
```

三个可以直接抄进产品的读法：

1. **三种方法都能把墙按住（伪峰比 <1），差别只在"窗内被改了多少"**：扩 2 倍时 PI 失真 0.283、NTK 0.482、YaRN 0.358——**越往上扩，PI 越"扁"**（全距离压缩），YaRN 只动长波所以近程保真最好。
2. **NTK 不是无限扩窗的免费午餐**：λ=2 时 0.309 看起来很漂亮，λ≥3 直接 14.4→38.6 复燃。原因：每个频率分量的"最大 reach"有限，单一频率缩放拉长不到所有波长。
3. **墙不是消失了，是被重新定义到声称的窗外**：重定标的好处上限 = 你愿意为"窗内被改多少"付多少钱。

> 一句话：**位置编码层解决的是"已训模型解码超出训窗"——不重训、只改坐标系。代价曲线 PI<NTK<YaRN（失真），而每种的扩展上限都有限（NTK λ≥3 复燃）。**

## 2. 训练层：训练窗口 = 泛化窗，PPL 墙实测

位置编码层的墙是**解码阶段**的墙（"能解到窗外但会冒伪峰"）。训练层的墙更狠、也更基本：**位置没训练过 → 那个位置天然不泛化**。

### 2.1 配方：loss_mask 只盖位置 [0,16)

用同一引擎，阶段一跑 900 步预训练，但给 loss 盖一块掩模——**只在位置 [0,16) 上算损失**：

```python
lm = np.zeros((B, T), float)
lm[:, :win] = 1.0          # win=16：位置 16..31 的损失被抹零
```

被抹零的还有另一个东西：**Wpos 行的梯度**。位置 16..31 的预测不参与 loss → 那些位置的 Wpos 行梯度恒为零 → 它们会**严格保持随机初始值**。这给训练层做了个最好用的探针：测试时把窗口从左对齐拉长到 24 / 32，用**固定 32-token 基准**（同一份内容、左对齐、只统计有真实 target 的位置），于是"墙上墙"只归因于位置、不掺内容混淆。

```text
  [阶段一后（窗口=16 的模型）]  按位置区段平均 −logp（固定基准、左对齐、最后一位不计）:
     L=16  [0,8)  0.250  [8,15)  0.006
     L=24  [0,8)  0.250  [8,16)  0.005  [16,23)  5.103
     L=32  [0,8)  0.250  [8,16)  0.005  [16,24)  4.469  [24,31)  2.426
     Wpos 最大更新量：位置[0,16) = 2.23e-01 · 位置[16,32) = 0.00e+00  ← 位置16+从未收到梯度（保持随机初始）
```

读这一张表：

- **窗内 [8,16) 是 0.005**（左对齐后位置 8–15 都在训练窗内，几乎零损失）；
- **窗外 [16,24) 是 4.469**（同一份内容、同一种左对齐，只是因为位置 ≥16 从未见过 → PPL 墙拔地而起）；L=16 更极端：窗口只有 16 长，[8,15) 仍是 0.006，一点都不露馅；
- **Wpos 行的更新量是实打实的物证**：`位置[0,16) = 2.23e-01 · 位置[16,32) = 0.00e+00`——位置 16+ 的绝对位置嵌入从头到尾没动过。

### 2.2 修墙：全窗续训 400 步

```text
  [阶段二后（全窗续训）]  按位置区段平均 −logp（固定基准、左对齐）:
     L=16  [0,8)  0.250  [8,15)  0.000
     L=24  [0,8)  0.250  [8,16)  0.000  [16,23)  0.000
     L=32  [0,8)  0.250  [8,16)  0.000  [16,24)  0.000  [24,31)  0.001
     Wpos 最大更新量：位置[0,16) = 2.16e-01 · 位置[16,32) = 1.41e-01
```

- 全窗续训后窗外全部回落（≤0.001）——**训练窗口确实是泛化窗**；
- Wpos[16,32) 更新量从 0.00e+00 跳到 1.41e-01：说明梯度真的到达了这些行。

> 一句话：**"短窗口训练出来的模型，长位置天然不会"不是玄学——Wpos 行的梯度是零。长上下文的训练侧真相就是'先短后长'的两段式：先低长度训够，再在长序列上续训把墙修回去。**（这正是知识地图 §2.16 训练侧的标准做法，也是 Llama-3.1 128k、Qwen 超长续训的真实形态。）

## 3. 架构层：推理时把滑窗掩码强加给已训模型

位置编码层和训练层都在问"模型能不能记住更远"。架构层问的是**体系结构上的另一个问题**：能不能在推理时——不重训、不更新任何权重——直接改"它看什么"？

### 3.1 机制：可见性矩阵是"注意力几何"的开关

本引擎的前向把注意力写成一张可见性矩阵 `vis`（`vis[j,i]=1` 表示位置 j 能看到 i）。训练时它是全响应：`vis[j,i]=1 ∀ i≤j`。**滑窗 = 推理时把这张矩阵改掉**：`vis[j,i]=1` 只在 `i∈(j−K, j]`。加"attention sink"就是额外保留 `i=0`（首 token）。

```text
      full：j 看所有过去         win-16：j 只看最近 16 位        win-16+sink：最近 16 位 + 永远留首 token
```

`project_head` 只重算注意力下游：**隐藏状态全不动，只把掩码换掉，重新算出 logits**。这模拟的就是"给一个已部署的模型换 attention 掩码"。

### 3.2 实测：24 段"训练对齐"固定块、744 个位置

```text
    平均 −logp · full       = 0.077   （对 full 增幅 +0.000）
    平均 −logp · win-8      = 0.078   （对 full 增幅 +0.001）
    平均 −logp · win-8+sink = 0.078   （对 full 增幅 +0.001）
    平均 −logp · win-16     = 0.077   （对 full 增幅 +0.000）
    过去位置注意力半径（每头每步、只算 Δ≥1；桶和=对过去的关注度，本例 0.72）:
      Δ∈[1,5) : 0.162 · Δ∈[5,9) : 0.131 · Δ∈[9,17) : 0.224 · Δ∈[17,32) : 0.204
```

三个反直觉但极有价值的发现：

1. **滑窗在这个语料上几乎不掉点**（win-8 只 +0.001，win-16 +0.000）。原因：这 47 句声明式事实的答案 token（9.8 / 3.14159 / 2.71828 / 300000 / 100 / 365）总是*刚好在它自己句子的近程*——模型根本不需要远端。**架构层的墙，是由"任务是否强制远回看"决定的**（真实模型在 LongBench 这类长程依赖任务上滑窗才会掉分）。
2. **但模型确实在看远**：注意力半径把"对过去的关注"0.72（其余 0.28 是自注意）按距离摊开，**Δ≥9 的远处 0.43 > 近程 Δ<9 的 0.29**。它看了，只是这语料不必需。
3. **sink 在本玩具是 no-op**（win-8+sink == win-8）。诚实原因见 §7：玩具的首 token 不是信息锚，真实 StreamingLLM 的 sink 是 BOS 的特殊角色，玩具复现不出。

> 一句话：**架构层的滑窗掩码是免费的几何手术——把'保留哪些位置'直接写进注意力。但它的墙不在注意力学，在'语料是否强制远回看'。局部语料给了它一个干净的零代价幻觉。**

## 4. 系统层：KV 淘汰策略与 prefix cache 复用

同一个"保留哪些位置"的问题，换个说法就是 **KV 缓存淘汰策略**：每个 token 的 K/V 都占显存，窗口 32 时无所谓，窗口 128k 时这是几十 GB 的预算决策。还是那 744 个位置，只是用"淘汰"的语言重测：

```text
    平均 −logp · KV 淘汰策略 · full          = 0.077   （对 full 增幅 +0.000）
    平均 −logp · KV 淘汰策略 · recent16      = 0.077   （对 full 增幅 +0.000）
    平均 −logp · KV 淘汰策略 · recent16+sink = 0.077   （对 full 增幅 +0.000）
    平均 −logp · KV 淘汰策略 · uniform16     = 0.449   （对 full 增幅 +0.372）
    argmax 一致性 full vs recent16 = 100.0%（744 位置：淘汰成'最近16'后，top-1 答案不变的比例）
    prefix-cache：前缀 16 token 缓存一次（KV 复用），再解码 16 步
      全量每步重算 =   10.2 ms · KV 缓存复用 =    3.4 ms
      同机相对快 3.0× · 两边 logits 逐位一致: True
```

- **recent16 == full（+0.000）**，argmax 一致性 **100.0%**：本语料下淘汰远端不改变任何答案——系统层非常安全。
- **uniform16 是最痛的淘汰（+0.372）**：它均匀抽 16 个覆盖广的位置，却**拆散了"最近一段连续位置"**。玩具的下一 token 由近 8–16 位几乎唯一决定（声明式事实的近程可预测性），均匀分布把近程连续性丢掉，精度反而崩。
- **prefix cache 是"系统层赢"的标准姿势**：前缀 16 token 只算一次 KV，解码 16 步全部复用，**全量每步重算 10.2ms vs KV 复用 3.4ms = 同机 3.0×**，且两边 logits 逐位一致（True）：KV 复用**不改数学，只改工程**。

> 一句话：**系统层的墙是显存预算，不是数学。淘汰顺序比淘汰数量更讲究——保'最近连续'，别保'均匀覆盖'；prefix cache 让同一段前缀跨请求白拿 3× 速度，还保证数学零变化。**

## 5. 四层协同：每层管什么、为谁修墙、怎么选

四层不是"选一个"，是**按处境叠**。完整决策表：

| 你的处境 | 首选层 | 实测理由 |
|---|---|---|
| 已有模型、不想重训、扩 2–4× | 位置编码层（YaRN/LongRoPE 式重定标） | 伪峰比 0.31–0.39、失真 0.28–0.48；不投训练成本 |
| 扩得比 4× 更狠 | 位置编码 + 训练层（先短后长续训） | λ≥3 位置编码先崩（NTK 14.4），训练层把 Wpos 行补过才撑得住 |
| 服务时窗口大但要省注意力/显存 | 架构层（滑窗/稀疏/锚点） | 滑窗在无需远回看时零代价；需要远端时掉点（真实模型 LongBench） |
| 高并发、延迟敏感 | 系统层（PagedAttention + Prefix Cache + KV 量化） | KV 复用 3.0× 且数学不变；attn 预算=系统预算 |
| 语境内容真需要远端（长文档/多轮工具日志） | 架构层"保留远端关键位" + RAG | 别指望纯滑窗；LongBench 式评测兜底 |

顺手把显存账拉满（ch10 口径的延续）：7B 模型、GQA（8 KV 头）、**128k 上下文**：

```text
7B @ 128k 的 KV 账（fp16，一层 2×(KV头数)×d×L×2B）：
  GQA-8：      2 × 8 × 128 × 131072 × 2B ≈ 8 GB
  KV 量化 INT8：   ≈ 4 GB
  KV + 部分卸载：   进一步降到 ~1 GB 内   ← 系统层把"能跑多长"从显存问题变成架构问题
```

> 四层协作的真实判据很简单：**已训模型先用位置编码白漂几倍；要更多就补训练层；训练层的墙修完后，显存预算把系统层拖下水；而这四层里"远程信息必需时"的那一份，最终通常靠 RAG 而不是纯窗口来给（地图 §2.16 的实践认知）。**

## 6. 旋钮晾衣线：哪些旋钮真的会动

- **位置编码层（A）：扩展倍数 λ 是最凶旋钮。** λ=1.5 → 8 的全扫描追踪三条曲线：PI 伪峰比单调上升至 0.677 且失真 0.737（**扩越多压越扁**）；YaRN 最稳（λ=8 仍 <1：0.599）；NTK 在 λ=3 跳崖式复燃（0.31→14.4）。**旋钮排序：λ 数量级 >> 方法选择。**
- **架构层（C）：窗口宽度 win-K 在本语料几乎不是旋钮。** win-8 → win-16 增幅差只有 +0.001。**真旋钮是"语料是否强制远回看"**——换成 LongBench 类任务，win-K 立刻变成主控。
- **系统层（D）：保留策略是旋钮，uniform16(+0.372) vs recent16(+0.000) 差出 0.37 的分水岭。** 近程连续性 > 均匀覆盖。
- 跨层对照：**A 层伪峰比、C 层掩码宽度、D 层保留策略，同时指向同一件事——"窗内被改多少"才是长上下文选型的核心代价。**

## 7. 诚实声明：四件套 + 一次测量教训

1. **玩具本体不是 RoPE，是绝对位置嵌入（Wpos）。** A 层用与 ch05 完全相同的真实 q/k 构造复刻了 RoPE 的打分核与外推墙（基线 4.56× 同口径），但 B/C/D 层用的模型是绝对位置嵌入——"长上下文"在这里是 **16→32 token** 的相对故事。所有外推结论是机制演示，不是尺寸声明。
2. **T=32 太小。** 真实长上下文是 128k 级，量级差 4000 倍。玩具的价值在"每一层墙都能单独测出来"，不在"能撑多长"。
3. **语料是声明式事实，无 EOS、无对话、无代码。** 真实长上下文的痛点是长文档引用、多轮工具日志、视频帧——它们的"远端依赖结构"完全不同。玩具的局部可预测性是声明式句子的属性，不代表代码更长依赖。
4. **sink 用"窗内首 token"纯几何，真实 sink 是 BOS 特殊角色。** 玩具里测出 sink no-op（win-8+sink == win-8）是*预期结果*（首 token 不承载信息），不是"StreamingLLM 无效"的证据——反向推广必须加引号。

5. **一次测量教训（写进正文是因为它改变了 C/D 层定性）**：最初 C 层用"滚动窗口流式评估"（每个位置取最近 32 token 重新窗口化），测出全注意力平均 −logp ≈ 10（比随机 lnV≈5.4 还差）。排查后确认：玩具把语料按"训练时的规范对齐"整段背下，流式窗口多塞了一个前导 token 就把对齐指纹破坏，损失崩成 junk——**不是注意力的问题，是评测方式被背记毒性污染**。改"训练对齐固定块 + 只换可见性矩阵"后数字才干净（full=0.077）。**测长上下文，先问评测内容自己是否需要长依赖。**

## 8. 放大账：玩具 → Llama / Qwen / DeepSeek 的真实长上下文管线

四层在 2024–2026 的真实生产管线里都能找到对应：

```text
位置编码层（不重训先白漂）：
   PI / NTK-aware / YaRN         — 社区 32k→128k 的默认扩法（长上下文微调前的起点）
   LongRoPE（Ding et al. 2024）  — 非均匀长度伸缩 + 频率缩放，8k→16k 只需数百步长上下文微调，常直接拿下 2×~4×
训练层（先短后长）：
   Llama-3 8B：32k 预训练 + 128k 用 YaRN 式扩展 + 微调
   Qwen2.5：长序列续训（0.5B–72B + 128k–1M）
   统一公式：短窗训好 → 用位置重定标把位置坐标映射到长窗 → 长窗续训把 Wpos/系数补回来（= 本章 B 层"修墙"）
架构层（记忆结构化）：
   Mistral sliding-window (2023)、Gemma-2 交替局部/全局注意力（sliding + global anchor）
   Llama-4 interleaved：大部分层只做局部注意力（30M-token 窗口）+ 稀疏全局层定锚远处
   DeepSeek NSA (2025)：粗粒度 token 压缩 + 稀疏选择，注意力复杂度掉到亚线性
   Infini-attention：窗口注意力 + 压缩记忆（记忆残差恢复远端）
系统层（预算工程）：
   vLLM PagedAttention（碎片 70%→1%，ch10 已测） + Prefix Cache（跨请求复用，本文 D 层 3.0× 同机）
   KV FP8/INT8 量化、KV 卸载、上下文压缩（LLMLingua）
   LongBench / RULER / 大海捞针：先问"评测内容是否真需要长依赖"（§7 教训），大海捞针能找针 ≠ LongBench 能过
```

结合 §7 的测量教训，**"评测先行"**是整条放大帐的第一原则：**多长的窗口、滑窗多宽、淘汰保谁——都由"任务是否强制远回看 + 显存预算"共同决定，而不是由"模型能背多长"决定。**

## 9. 常见坑

1. **大海捞针≠长上下文能用。** 能"找针"只说明"远端有个能精确检索的目标"；LongBench 才测"跨文档推理/汇总/多跳"。评测内容决定墙。
2. **位置重定标后不做任何校准就当成品。** PI 的伪峰比压下了，但窗内失真 0.283（λ=2）会累计到训练分布——真实做法要跟几轮长上下文微调（比如 YaRN 配最大比例重放合数据）。
3. **把 NTK 当无限扩窗。** 单一频率缩放有 reach 上限，λ≥3 就复燃（14.4→38.6）。要做真的"2× 以上"，菜单是 LongRoPE 式非均匀 + 续训。
4. **训练窗不拉长却怪模型"记不住远端"。** Wpos 行梯度为零（B 层实测 0.00e+00）——先短后长是训练的必修课，不是玄学。
5. **把滑窗当免费午餐。** 局部语料下 zero-cost（+0.001）是语料的特权；换 LongBench 类任务就会掉分。先问语料要不要远端。
6. **均匀淘汰 KV（或全保留）。** uniform16 掉了 0.372 分——近程连续性比覆盖广更重要（StreamingLLM 同结论：recent + sink）。

## 10. 实践任务

1. **跑 `long_context_demo.py`**：观察 A 层三条伪峰曲线、B 层 Wpos 梯度物证、C/D 层策略对比；改 λ 扫描看 NTK 从哪一档复燃。
2. **改语料加"长程依赖块"**（比如给语料加"魔表映射：blue→7、yellow→9…"的结构，再编一个"请回忆 blue 的编号"的 eval 段），重测 C 层滑窗——看"任务强制远回看"那一份掉点能不能被滑窗掩码显形。
3. **真实模型上做 prefix cache**：用 vLLM/SGLang 在同一前缀、多个 session 上复现本文 D 层的"复用 vs 全量重算"墙钟（真实模型上通常 2–4× 的 TTFT 差）。
4. **小窗 + RAG 对照**（呼应 08-RAG 体系）：把需长上下文的文档切成块走 RAG 管线，对比"大窗硬吃"与"小窗+RAG"的成本与质量——地图 §2.16 的实践认知落地。

## 11. 衔接下一章：推理模型与 Test-time Scaling、MoE

四层路径讲完了"横向"——**把窗口撑大，模型同时读得更多**。下一条主线是"纵向"——**让模型在答之前想得更久**：

- 长上下文 = "工作内存"扩容（读得更多）；**推理模型 / Test-time Scaling = "工作内存"用得更深**（思考 token 越多，推理质量越高）。两条都是 2025–2026 的"用算力换质量"主线：一条加窗口，一条加思考预算。
- MoE 完全改变这笔账：**推理引擎的长上下文显存账、滑窗/稀疏的架构选择，在 MoE 上对应的是"参数量 vs 激活量"的分岔**——`18-MoE混合专家` 会把这条「参数量 vs 激活量」的决策表补完（Dense-vs-MoE 选型就在它的 §5）。
