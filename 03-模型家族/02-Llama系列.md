## 0. 为什么讲 Llama 要从"开源把论文打成权重"讲起

`03-01-GPT系列` 的主线是"目标函数十年不变、规模翻页解锁能力"。这是**闭源侧**的模型逻辑：OpenAI 造更大的机器，能力按刻度涌现，你看得见结果、给不出内部配方。Llama 家族站在完全相反的位置，它给世界示范了**开源侧**的逻辑：2023 年 2 月 Llama-1 把权重开放（研究许可）开始，Meta 每出一代，全球几千个团队立刻能下载、能微调、能部署、能 A/B 出试错记录——**"论文说什么"第一次变得不那么重要，"跑一下能不能复现、上线省不省"成了真正的投票器**。

这一换，把"模型的哪一层才是价值"整个重排了：

1. **论文是电路图，权重才是能用的书**：Transformer 论文发表于 2017 年，但普通工程师真正"用起来"是在权重文件可以下载之后。Llama 把"明星模型"从 `参数量` 这个数字变成 `一张 7B 的 safetensors`。
2. **谁都能部署，架构细节变成残酷的性价比竞争**：当一万个团队在同一代 GPU 上真的去跑 7B/13B/70B，决定"默不默认用 X"的就不再是论文标题多响，而是三个可测的问题：训练预算下它是更早解锁还是等更久？同样内存它能塞进多长上下文？推理时每 token 多花几字节？
3. **这三年被"投出来"的事实标准，恰好四件**：**RoPE**（相对位置，扩展窗口有根）、**GQA**（KV 头数 < 查询头数，KV 缓存摊薄）、**SwiGLU**（门控 GLU 型 FFN）、**RMSNorm**（免 bias、不做中心化的归一化）。现在的开源基座几乎全部标配这四件——不是它们每个都在单点实验里"赢"，而是**作为一个配方组合，在"谁先够用 + 谁更省"的长期投票里胜出**。

本篇不写"Llama 有多强"（那是力大砖飞的部分，公开事实），攻击点放在**机制**：把一个家族在"工程选型"上的胜负，压成你可以自己重算的四段实验——同一任务上配方对照（[B]）、同一能力上位置方案的翻车对比（[C]）、同一显存预算上的 KV 摊薄（[D]）。

> 一句话（为什么有本篇）：**背"Llama-2/3/4 各多少参数"三个月又过期；理解"开源生态用'谁先够、谁更省'投票，把 RoPE/GQA/SwiGLU/RMSNorm 投成 decoder-only 事实标准"才拿到看懂下一代开源基座架构的通票。八要素给槽位，本篇的四组对照给'为什么是这四件'。**

## 1. 一站全景：从 Llama-1 到 Llama-4 的"工程翻页"

先给全景，再给实验。Llama 家族的翻页和 GPT 的不同：GPT 翻页在"规模/数据/对齐/推理时算力"，Llama 翻页在**工程深度**——每一代都在把"开源场上的能力上限"往前推一档（公开事实，非本机实测）：

| 代数 | 模型（年份） | 规模刻度（公开） | 这一页的工程翻页 | 能力的刻度 |
|---|---|---|---|---|
| LLaMA-1 | LLaMA（2023-02） | 7B/13B/33B/65B · 1T tokens · ctx 2048 | 第一次把"顶级效果"和"权重开源"同时送上桌（本来仅为学术） | 开源权重 + 论文配方，leak 后卫星社区一夜间长满 |
| Llama-2 | Llama-2（2023-07） | 7B/13B/34B/70B · 2T tokens · ctx 4096 | 70B 带头启用 GQA（更早的都还是 MHA）；带上 RLHF 的对齐配方，商用许可 | "能下载的最强 70B" = 开源生态事实上的基座默认 |
| Llama-3 | Llama-3（2024-04） | 8B/70B · 15T tokens · ctx 8192（官方）/ 128k（点拨） | 词表换 128,256 超大 tokenizer；**全家族 GQA**；RoPE base 500k | 8B 都快赶上旧 70B，开源小模型第一次"够用"到能塞端侧 |
| Llama-3.1 | 405B（2024-07） | 405B 最大 · ctx 128k | 开源史上最大稠密开源权重；长上下文 128k | 把"开源闭源能用性差"的最后一层天花板捅破 |
| Llama-3.2 | 1B/3B/11B-Vision（2024-09） | 端侧小模型 + 11B VL | 小模型直连手机内存 + 视觉接入 | 开源多模态 + 端侧推理的"够用"档 |
| Llama-4 | Scout（2025-04） | MoE 109B（约 17B active）· 10M ctx | 原生 MoE + 超长 10M 上下文 | 开源正式进入 MoE 与超长上下文时代 |

读这张表，最该盯的是**"架构细节"这一行在往哪收敛**：Llama-1/2 早期还在 MHA 和 GQA 之间过渡，到 Llama-3 全家 GQA、RoPE、SwiGLU、RMSNorm 四件套全齐，之后每个开源新模型（Qwen、DeepSeek、Mistral、Gemma…）都以这四件为起手默认。**这就是事实标准化的过程：不是某篇论文钦定，是每一代开源模型都在模板上抠最省事的公约数。**

放到八要素卡里，Llama 各代的共同腹腔是什么（本段要素=非本机实测）：

| 八要素 | Llama 家族取值 | 钉 02 复习点 |
|---|---|---|
| 架构 | decoder-only + pre-LN（且用 RMSNorm，不做中心化） | 02-01 Transformer · 02-07 归一化 |
| Attention | MHA（1/2 早期）→ **GQA**（3 起全家；2-70B/405B 也是 GQA） | 02-03 多头注意力 MHA→GQA |
| FFN · MoE | SwiGLU 门控 FFN（隐藏维 8/3·C）；Llama-4 起 MoE | 02-06 FFN与激活 · 02-18 MoE |
| 训练方式 | next-token 预训练 +（对齐期）SFT/RM/RLHF/DPO 家族 | 02-12 预训练 · 02-13 SFT · 02-14/15/16 对齐 |
| 推理方式 | 开源权重 + llama.cpp/vLLM/Ollama 全家桶 | 05-推理与部署 |
| 上下文 | 2048 → 4096 → 8192/128k → 10M（Llama-4） | 02-17 长上下文 · 02-05 位置编码 |
| 多模态 | Llama-3.2 Vision 起原生接受图像 | 10-多模态 |
| Reasoning | 端侧链式推理（reject sampling / RL）；无明显 test-time 翻页 | 02-20 推理模型 |

> 一句话（全景）：**GPT 家族的共同腹腔是"decoder-only + next-token 目标"；Llama 家族的共同腹腔是"同一套开源工程默认"——RoPE + GQA + SwiGLU + RMSNorm，四件全是"谁在大规模上被真跑过、被证明省"的胜利者，不是谁的发明权。**

## 2. 怎么构造：配方可换的引擎，四段可重算的跑

GPT 篇逼出了"目标函数不变→能力按刻度解锁"，它留给我们的引擎遗产特别适合接下来做**配方实验**：同一个 add 任务、同一台迷你解码器，只换"配方开关"，就能回答"为什么开源生态把这四个开关拧在这边"。

本篇纪律沿用 `03-01-GPT系列` 的确定性协议（单线程 numpy、固定种子、三遍逐位一致），引擎升级为**配方可换**的版本（`llama_demo.py`）：

```text
Engine(V, T, C, NL, NH, NV=None, pos="rope", act="swiglu", norm="rms")
  pos ∈ {abs, sin, rope}   —— 位置编码：可学习表 / 正弦 / RoPE 旋转
  act ∈ {gelu, swiglu}     —— 激活：GELU（GPT-2 系） vs SiLU 门控（SwiGLU）
  norm ∈ {ln, rms}         —— 归一化：LayerNorm（含 bias 中心化） vs RMSNorm（无 bias）
  NV < NH ⇒ GQA            —— KV 头数少于查询头数 => K/V 投影窄 (C, NV·DH)，逐头扩展复用
```

任务族仍是 **y = (a+x) mod P（add，P=13）**，每片段 = K=5 对示例 + 1 个 query、每个片段随机新 a——模型必须现场从示例读映射，逼出 ICL（GPT 篇已验证这套任务能干净解锁 ICL）。本篇 4 段各钉一条断言：

- **[A] 引擎对账**：先对 Rx 配方（RoPE+SwiGLU+RMSNorm+GQA）做 bwd vs 中心差分，8 组参数逐元素对（GQA 的 KV 扩展 + RoPE 的反向最容易写错）。
- **[B] 配方对照**：同一 add 任务、同样 1200 步 × bs96（token 预算完全相同），Rx（Llama 配方）vs GptRx（GPT-2 配方：abs+GELU+LN+MHA）。检验"快慢是立即可测的差异"——ICL 解锁的时间表。
- **[C] 位置三臂**：基础配方不动（act=gelu · norm=ln · NV=8=MHA），只换位置方案（abs / sin / rope），[C1] 少对+移位（复刻 GPT 篇 [F]）、[C2] 整块平移到更长窗口——检验"相对位置"是不是唯一能平移到新窗口的。
- **[D] KV 摊薄账**：不训练，纯账（公开配置 × 公式）。检验"GQA 省的是哪本账"——这是开源部署选它最硬的工程理由。

> 一句话（构造选择）：[B] 回答"配方的速度差异可测"，[C] 回答"为什么位置方案是它"，[D] 回答"为什么 KV 要摊薄"——三者全在"谁能先在真实预算上被用起来"的同一把尺上。

## 3. 配方对照 B：同样是 ICL，为什么 Llama 配方先够

先看最"工程"的一问：同样预算下，两个配方谁的 ICL 来得更快。跑 `llama_demo.py` [B] 段（P=13 add，1200 步 × bs96，每 100 步记 loss，结尾 fresh@新 a）：

```text
[B] 等预算配方对照：同一 add 任务（P=13 · K=5 · T=11 · 1200 步 × bs96）
    Rx   = Llama 配方：RoPE + SwiGLU + RMSNorm + GQA(8 头/4 kv)
    GptRx= GPT-2 配方：abs + GELU + LayerNorm + MHA(8 头)
  Rx    loss|| 100:2.3768 200:1.6326 300:0.8491 400:0.5748 500:0.6405 600:0.4295 700:0.4330 800:0.4278 900:0.4176 1000:0.4235 1100:0.4251 1200:0.4233 || fresh@初始化位置=1.000
  GptRx loss|| 100:2.3716 200:2.1715 300:1.3053 400:0.4861 500:0.4265 600:0.4245 700:0.4248 800:0.4233 900:0.4196 1000:0.7632 1100:0.4288 1200:0.4184 || fresh@初始化位置=1.000
```

两条线，三个读数：

1. **两个配方最终都解锁（fresh 都 1.000）**：能力不是某个配方的专利——ICL 是 next-token 目标喂出来的"机制件"，配方能影响的是**什么时候到**，不是**能不能到**。这是先要讲清楚的：四件套不是"没有它们就没有 ICL"。
2. **但落地速度明显差一截**：loss 悬崖（那一下从 ~1.6 跳到 ~0.4 的相变）——Rx 在 **step 200→300** 已经穿过（200:1.63 → 300:0.85），GptRx 要到 **step 300→400** 才穿过（300:1.31 → 400:0.49）。**同一预算、同一计算机，Llama 配方提前约 100 步把能力送到门口。**（GptRx 的 1000:0.7632 是一个偶发回跳——loss 曲线在悬崖后的尾巴上有小毛刺，不改变主结论。）
3. **墙钟也省，参数也少**：两个配方在完全相同步数（1200×bs96）下，Rx 墙钟约 102s、GptRx 约 146s（run1 实测）——**每步快约 1/3**。原因很直接：GQA 把 K/V 投影从每头一套压成每 KV 头一套（投影矩阵窄一截）、RMSNorm 不存 bias 也不做中心化。模型每步的成本与参数总量都是可数的：Rx 总参数 51,936、GptRx 57,072，**同一预算下还少约 9%**——"省"不是某一件的功劳，是四件套各自省了一点（FFN 侧 SwiGLU 也用更窄的 8/3C 隐藏维）。这就是"省"。

> 一句话（B 段）：**两个配方都能解锁 ICL，"谁更早到、谁更便宜"才是工程投票——同一预算下 Llama 配方（RoPE+SwiGLU+RMSNorm+GQA）比 GPT-2 配方提前约 100 步穿过能力悬崖（step 300：0.85 vs 1.31），且每步墙钟快约 1/3、参数还少约 9%（51,936 vs 57,072）。这份"先够、够省"的差异，就是开源生态把四件套投成默认的动力源。**

## 4. 位置三臂 C：事实标准是被"整块平移"这一测法投出来的

四件套里最需要动脑筋的是 RoPE——因为位置方案是纯粹的功能型选择，没有"参数少了"这种账面上的省。它与 abs/sin 的真正分野，要用 **"整块平移进更长窗口"** 这一测法才能照出来。本篇在 GPT 篇 [F] 的位置锁定测法之上，再加一个更苛刻、也更像真实部署场景的 [C2]。

### 4.1 [C1] 少对 + 移位：三臂全塌（诚实负面）

先把 GPT 篇 [F] 的测法原样搬来（训练 = 5 对示例在位置 0-9、query 在 10；现在少几对并把剩下的向左贴齐 query）。三臂在 [C1] 里**全塌**：

```text
[C1] 少对+贴 query 左空 S 位（query 恒在 10）——复刻 01-GPT系列 [F]
    方案     S=0      S=2      S=4      S=6      S=8
  abs      0.917    0.092    0.087    0.122    0.092    （掉到骰子）
  sin      1.000    0.105    0.098    0.087    0.077    （掉到骰子）
  rope     0.975    0.188    0.160    0.125    0.102    （部分保留但大掉）
```

S=0 时三臂都接近满分（0.917/1.000/0.975）；示例一少、位置一挪，全部崩到骰子附近（1/13≈0.077）。这个"位置锁定"在 toy ICL 上是压倒性的主因，无关你用什么位置编码——**它说明 toy 模型学的是"示例必须待在它见过的那个 layout"**。诚实交代：这一个对照同时动了"示例数量"和"绝对位置"，不能彻底分离两者（和 GPT 篇 [F] 同一个 confound）；[C1] 的作用是划定诚实边界，真正的区分在 [C2]。

### 4.2 [C2] 整块平移：只有相对位置能跨窗——但"本身不够"

[C1] 的 confound 在于同时变了对数和位置。更干净的测法是 **整块平移**：5 对示例一个不少、相对距离一个不变，只是把整块从"位置 0-10"右移到"位置 S..10+S"，query 恒在窗口最末位（窗口从 11 拉长到 11+S）。**绝对位置全变了、相对结构全保留**——这正是真实部署里 `ctx 4096 → 128k` 时发生的事：

```text
[C2] 同一 5 对整块右移 S 位（窗口 11→11+S，query 恒在末位）——相对距离全保留
    只有绝对位置变；abs 的 Wpos 表只有 11 行 → 引位置会越界
    方案     S=0      S=2      S=4      S=6      S=8
  abs      0.917    OOB      OOB      OOB      OOB      （表越界，无法引）
  sin      1.000    0.077    0.070    0.075    0.077    （掉到骰子）
  rope     0.975    0.223    0.188    0.175    0.172    （保留部分，仍衰减）
```

三个读数，一个分水岭：

1. **abs 的"方式性死亡"**：可学习的 Wpos 表是一个 `T×C` 的数组，训练只铺了 11 行——现在 query 跑到位置 11 以后，**根本没有那一行的参数可查（OOB，out-of-bounds）**。这是绝对位置最锋利的负例：**窗口不是运行时可以随便拉长的，它在训练时就被表长钉死了**（`02-17 长上下文` 的"Wpos 零梯度 → 训练窗=泛化窗"同一回事）。
2. **sin 的"真实翻车"**：正弦编码不会越界（每个位置都有公式算出的值），但它也没撑住——S=2 就从 1.000 掉回骰子 0.077。**正弦虽然是"公式化的绝对位置"，模型还是只学会了拿它当"位置 0-10 的锚"，平移一格就全乱。** 位置编码的"可外推性"不在公式里，在模型是否学会用它的相对几何。
3. **rope 的"部分保留"**：这是三臂里唯一在整块平移后还保留信号的——S=2 时还有 0.223（超过骰子 0.077 约 3 倍），S=8 时 0.172。**相对位置确实让"整块搬进更长窗"这件事没有当场归零。** 但它也明显衰减（0.975 → 0.223 → 0.172），远不是满格 1.000。

所以本篇标题才说"事实标准是被可测的差异投出来的"：**同样的能力、同样的预算、同样的 eval，只有 RoPE 在"把窗口拉长"这个真实工程动作前没有当场翻车**——这就是为什么所有想扩窗的开源模型把它当默认。但 [C2] 的衰减也给出必须的诚实：**相对位置是必要条件、不是充分解**。真实大模型从 4096 扩到 128k，靠的是位置编码 + 训练窗拉长 + 架构 + 系统（`02-17 长上下文` 的四层墙）一起抬，RoPE 只负责其中最底层的一层——这正是那个"四层墙"实验里位置层单独测出的结果在此处的呼响。

> 一句话（C 段）：**把 5 对示例整块平移进更长窗口（相对结构全保留）——abs 的可学习表直接越界、sin 掉回骰子、只有 RoPE 保留部分信号（S=2 0.223 vs 骰子 0.077）；相对位置是扩窗的第一层地基，但地基之上还要训练/架构/系统三层，RoPE 必要但远不够。这就是"位置方案事实标准"的完整注脚。**

## 5. KV 摊薄 D：GQA 为什么是开源部署的第一个默认

位置方案回答"为什么是它"，KV 摊薄回答"为什么所有人都抄它"。`llama_demo.py` [D] 段不训练，纯账（公开配置，账算非本机实测）：KV 每 token 字节 = L × (2 · H_kv · DH · 2B)——每层每个 token 要存的 K、V 各一份，每份 H_kv 个头、每头 DH 维、浮点 2 字节：

```text
[D] 派生账（Llama 各代公开配置，账算非本机实测）
  模型                  L    H  H_kv   DH  KV B/层/tok       词表   GQA比MHA省
  Llama-1-7B         32   32    32  128       16384 B   32,000         1×
  Llama-2-7B         32   32    32  128       16384 B   32,000         1×
  Llama-2-70B        80   64     8  128        4096 B   32,000         8×
  Llama-3-8B         32   32     8  128        4096 B  128,256         4×
  Llama-3-70B        80   64     8  128        4096 B  128,256         8×
  Llama-3.1-405B    126  128     8  128        4096 B  128,256        16×
  Llama-4-Scout      48  128     8   32        1024 B        ?         16×
  → GQA 把 KV 缓存这本账按 H/H_kv 摊薄：Llama-3-8B ×4、2-70B ×8、3.1-405B ×16、
    与 02-10 KV-Cache 显存账本（MHA 4GiB vs GQA 1GiB）同一条母线。
  派生一行：Llama-3-8B 词表 embedding ≈ 128256×4096×2B ≈ 1.0 GiB，
    而 128k 上下文的 KV = 4096B/层/ tok×32层 = 128 KiB/tok → 16.8 GiB——长上下文里
    KV 缓存比整张词表 embedding 大 16 倍，GQA 摊薄 4 倍是省在最大的那本账上。
```

三个读法：

1. **KV 随上下文线性爆炸，而权重是一次性驻留**——同模型里词表 embedding 只占 1.0 GiB，128k 窗口的 KV 缓存却要到 16.8 GiB，**比整张词表大 16 倍**。这就是为什么"长上下文"第一个挡路的是它，不是计算。
2. **GQA 把这条爆炸的线按 H/H_kv 压下去**：8B ×4、70B ×8、405B ×16——Llama 家族从 70B 起反复把 H_kv 拉低，不是"论文喜好 GQA"，是 **KV 摊薄是开源部署唯一免费拿来就省显存的正交杠杆**；配合 `02-03` 的 GQA 语义（共享 KV 头几乎不损表达力），这笔账算得明明白白。
3. **与 `02-10 KV-Cache` 的显存账本合并**：那篇已经实测算过 MHA 4GiB vs GQA 1GiB（7B @ 32k）——本篇 [D] 是从 Llama 各代配置出发把它做成家族全家福，同一母线、两种证法。

> 一句话（D 段）：**KV 缓存按每层每 token 摊账，128k 上下文里比整张词表 embedding 还大 16 倍；GQA 把这条线按 H/H_kv 摊薄（8B ×4 → 405B ×16）。开源部署要"塞得下长上下文"，GQA 是第一件拿得到、拿得到就不痛的默认——这就是它被投成事实标准的工程账本。**

## 6. 常见坑

**① 把"开源事实标准"当成"论文最优"。**
RoPE/GQA/SwiGLU/RMSNorm 成为默认，是"先在真实预算上够用、够省"的生态投票，不是每个都在单点 SOTA 上赢了论文竞赛。闭源模型（GPT 系列内部架构未公开）完全可以不公开这四件而做得很好。**读 arXiv 问"is it SOTA"，读开源生态问"is it the default"，两把尺刻度不同。**

**② 拿"MHA vs GQA 能力差不多"说 GQA 无意义。**
`02-03` 里 GQA 共享 KV 头几乎不损表达力——那恰恰是答案不是反例：**精度几乎不差 + KV 砍 4-16 倍**，"省"是真实收益。别把"没差"理解成"没意义"。

**③ 用 [C1] 的"三臂全塌"说"RoPE 没用"。**
[C1] 同时动了对数与位置（confound），且所有位置方案都塌——它测的是 toy ICL 的位置锁定，不是某个方案的好坏；看位置方案的分野要读 [C2] 的"整块平移"。

**④ 把 [C2] 的 rope=0.223 读成"RoPE 解决长上下文"。**
它只是"平移后没当场归零"。真实扩窗是 `02-17` 四层墙（位置 + 训练 + 架构 + 系统）一起抬，RoPE 只占底下那层。**"没有归零"≠"已经解决"。**

**⑤ 忘了 KV 账的单位是"每 token"。**
KV 缓存和 weight 不一样：weight 是一次性驻留，KV 是每个 token 都要加的运行期内存。所以"长上下文账本是 KV 主导"（16.8 GiB vs 1.0 GiB embedding）——算 128k 显存别只盯着权重参数。
