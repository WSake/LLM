## 0. 为什么"不背参数"：背的是维度，不是数据点

知识地图 §3 开门见山给了本目录的唯一读法：

> 读法：不要背参数，用统一的「八要素」去解构每个家族：模型架构 → Attention → FFN/MoE → 训练方式 → 推理方式 → 上下文 → 多模态 → Reasoning。每个家族 = 一次技术演进的实验报告。

为什么"不要背参数"？背参数有两个不打自招的问题：

1. **参数是时态数据，而模型是滚动发布**：你背得烂熟的一列数字，三个月后换代理、加楼层全失效。今天的 8B/671B 明天就是一篇更新的"实验报告"。**八要素是维度（不变的问法），参数是取值（会变的答案）**——方法论必须钉在维度上。
2. **参数回答不了"为什么"**：知道 Mixtral 46.7B 帮不了你判断"下一个 8B 是不是该看它的 FFN 是不是 MoE"；知道 DeepSeek 671B 也推算不出"128k 长对话缓存放不放在一张卡上"。后两个问题的答案在 **Attention 用了 MLA 还是 GQA、FFN 是 Dense 还是 MoE**——这些才是能跟 02 的机制对上号、能预测决策的维度。

那为什么偏偏是这八格？因为这八格恰好是 02 核心原理讲过的**八个决策轴**：Attention 是 MHA/GQA/MLA 之争（02-03/04），FFN·MoE 是参数放哪、激活取多少之争（02-06/18），训练方式是预训练/SFT/DPO/GRPO 之争（02-13~16/22），推论方式与 Reasoning 是测试时算力之争（02-20），上下文是长上下文技术之争（02-17）。**八要素不是新学科，是 02 学过的词汇按"模型侧的八个决策点"重新排布**——这就是本篇第 5 节复习链的来由。

> 一句话（为什么有本篇）：**背参数的人遇到新模型就废，会用八要素的人遇到新模型只是多填一张卡。本篇把"八格+两件派生产物"做成一次本机能算的跑，让你下次拿到任何模型卡能当场解构、能当场算账。**

## 1. 一站全景：八要素解构卡 + 两件派生产物

"八要素解构法"拆开是**一张卡 + 两件产物**：

| 八要素 | 它在问什么（决策轴） | 挂 02 复习点 |
|---|---|---|
| **架构** | decoder-only / encoder-decoder / 原生多模态？ | 02-01 Transformer · 02-00 时间线 |
| **Attention** | MHA / GQA / MLA / SWA——谁在压缩 KV，谁在省显存？ | 02-03 MHA-MQA-GQA · 02-04 MLA · 02-10 KV 账 |
| **FFN·MoE** | SwiGLU？细粒度专家？共享专家？参数放哪、激活取多少？ | 02-06 FFN与激活 · 02-18 MoE |
| **训练方式** | 预训练 + SFT / DPO / RLHF / GRPO·RLVR？FP8？蒸馏？ | 02-13 SFT · 02-14 RLHF · 02-16 GRPO · 02-22 蒸馏 |
| **推理方式** | 闭源 API / 开源自部署 / 思考预算（thinking budget）？ | 05-推理与部署 · 02-20 推理模型 |
| **上下文** | 窗口多大？用没用长上下文技术？ | 02-17 长上下文四层技术路径 |
| **多模态** | adapter 拼接 / 原生全模态 / 文档-截图能力？ | 10-多模态 |
| **Reasoning** | o 系列开创 / thinking 模式 / 纯 RL 涌现（R1-Zero）？ | 02-20 推理模型与 Test-time Scaling |

三件套的分工是：**解构卡**（§3）解决"描述"——八个格子的取值；**派生账**（§4）解决"计算"——参数/激活/KV/显存这些能从结构配置直接算出来的东西；**决策引擎**（§6）解决"选型"——给定任务，用规则表推同一推荐。三件都做完，一张模型卡就变成了"能讲技术演进 + 能算钱 + 能选型"的三用剖面。

> 一句话（全景）：**八要素 = 八格剖面（描述）+ 派生账（计算）+ 决策表（选型）的三件套。卡负责让你看懂，账负责让你算清，引擎负责让你在任务里拍板。**

## 2. 怎么构造：四段可重算的跑

真实世界里"解剖一个新模型"是读模型卡、读技术报告、上线前算账——本篇不做现场读卡，把整件事做成一次**本机可重算的四段跑**（`eval_gate_demo.py` 同款纪律，`model_family_demo.py`，纯确定性算术 + 断言自校，墙钟 0.2 ms）：

- **A 八要素解构卡（要素事实非本机实测）**：知识地图 §3.1–3.5 的四张速写（Llama-3.1-8B / Qwen2.5-7B / Mixtral-8x7B / DeepSeek-V3）逐个按八要素入格——格字段不是参数，是"决策轴取值"。
- **B 派生账（本机真算）**：从结构配置往出算三本账——① 参数账（Dense/GQA/MoE 完整结构逐层推导，MLA 结构特殊不做推导、用官方 671/37 为准；推导值与官方校验 ±15% 走廊）；② 激活比（MoE 必须分"总参/active"两本账）；③ KV 账（每 token 每层缓存字节 → 1k/32k/64k/128k GiB，与 02-04 MLA 账同式互证）；④ 40 GiB 单卡桌判定（权重 fp16 + 满上下文 KV）。
- **C 复习链断言**：八要素每一条都断言挂到 ≥1 个 02 复习点，8/8 全非空——把"解构"定性成"收拢 02 词汇"。
- **D 选型决策引擎（规则表 + 断言自校）**：五个任务（中文 / 单卡全能 / 超长上下文 / 开源 MoE 性价比 / 端侧）× 规则表 → 同一推荐；每个推荐本地断言锁死，同一输入永远同一输出。

诚实边界一句话：**这篇的"派生账"是本机真算，但算的是"公开配置的结构"——参数量推导是数量级校验（±15% 走廊），不是逐位复刻官方；要素事实与官方参数量全部标 非本机实测**，两条证据线在正文永不混标。

> 一句话（构造选择）：**四段正好对应解构法的四个动作——把描述做成卡、把能算的做成账、把复习做成断言、把选型做成规则表。A/C/D 是"纪律"，B 是"算术"，全脚本零随机所以三遍逐位一致。**

## 3. A 段 解构卡：四家模型写进同一张剖面板

脚本 [A] 段把四张公开卡按同一张模板入格（`model_family_demo.py` [A] 段，要素事实非本机实测）：

```text
[A] 八要素解构卡（统一模板，四家公开模型卡速写入格，非本机实测）：
    Llama-3.1-8B（开源骨架事实标准 §3.2）：
      架构    decoder-only Dense · Attention GQA(8/32×128)+RoPE · FFN/MoE SwiGLU
      训练    预训练+SFT+DPO/RL · 推理 开源权重可自部署 · 上下文 128k
      多模态  暂无（Llama3.1 纯语言） · Reasoning 弱（无 thinking 模式）
    Qwen2.5-7B（中文全家桶 §3.3）：
      架构    decoder-only Dense · Attention GQA(4/28×128)+RoPE · FFN/MoE SwiGLU
      训练    超长预训练+强化学习 · 推理 开源全栈（API+权重） · 上下文 128k
      多模态  Qwen-VL 系列 · Reasoning QwQ→Qwen3 思考模式
    Mixtral-8x7B（开源 MoE 先驱 §3.5）：
      架构    decoder-only MoE · Attention GQA(8/32×128)+SWA · FFN/MoE MoE 8×SwiGLU·top2
      训练    公开权重（细节少） · 推理 开源权重可自部署 · 上下文 32k
      多模态  弱 · Reasoning 一般
    DeepSeek-V3（MLA+极致MoE §3.4）：
      架构    decoder-only 大MoE · Attention MLA（KV 压缩） · FFN/MoE 细粒度MoE+共享专家
      训练    FP8预训练+MTP+GRPO/RLVR · 推理 开源权重可自部署·长思考 · 上下文 128k
      多模态  R1-V 视觉推理 · Reasoning 开源推理标杆（R1）
```

读这张卡，最能说明"为什么要解构"的是 **DeepSeek-V3 那一格一格几乎全是指向 02 的考点**：Attention=MLA → 02-04（KV 压缩省显存）；FFN=细粒度 MoE+共享专家 → 02-18（总参/active 两本账）；训练=FP8 → 04-09（精度账）+ MTP 多 token 预测 → 02-22（蒸馏上下文）+ GRPO/RLVR → 02-16；推理=长思考输出 → 02-20。**你背"DeepSeek 671B"什么都没得到；你读"MLA+细粒度 MoE+GRPO"就把 02 四五章的决策点全复习了一遍**——这就是"每个家族 = 一次技术演进的实验报告"的读法。

解构卡还能当场做"掌握度检验"的动作：**随机抽一个新发布的模型，十五分钟内写满八格**。比如抽 Qwen3：架构 = Dense 0.6B-32B + MoE 30B-A3B/235B-A22B 双线；Attention = GQA + 多模态侧 M-RoPE；FFN = SwiGLU（MoE 版细粒度专家）；训练 = 超长预训练 + 强化学习；推理 = 开源全套 + thinking mode（hybrid）；上下文 = 128k~1M；多模态 = Qwen-VL 系（动态分辨率/视频/Agentic UI）；Reasoning = QwQ → Qwen3 思考模式。八格填完，你就有了一张"认识一个新模型"的完整坐标，而不是三个碎片化印象。

> 一句话（A 段）：**八要素卡把"读模型"从"记一串数字"换成"填八格子问题"——特别是 DeepSeek-V3 那张卡，几乎每个格子都是在考 02 的某一章。卡写完，模型"这次演进改了什么"就显形了。**

## 4. B 段 派生账：参数·激活·KV·40 GiB 桌，一样能算

解构卡只回答"是什么"，B 段回答"值多少"——从结构配置（层数/维度/头数/词表/FFN 宽度/MoE 拓扑/上下文）往出算三本账（`model_family_demo.py` [B] 段，**本机真算**）：

```text
[B] 派生账（本机真算，科学性=算术确定性）：参数 / 激活 / 权重 GiB / KV 账 / 40GiB 桌判定
    参数账（结构级推导；官方=非本机实测；偏差=走廊校验 ±15%）：
     模型          推导总参     active参     官方       偏差    fp16权重GiB  激活占比
     Llama-3.1-8B  7.505B     7.505B     8.03B     -6.5%        14.0    100.0%
     Qwen2.5-7B    7.070B     7.070B     7.61B     -7.1%        13.2    100.0%
     Mixtral-8x7B  46.572B    12.749B    46.70B     -0.3%        86.7    27.4%
     DeepSeek-V3   671.000B   37.000B    671.00B     ——         1249.8    5.5%
    → 推导值 vs 官方全部落在 ±15% 走廊内（结构级近似，数量级与官方一致）；MoE 的'总参/激活'是两本账。
    激活比（MoE 名义稀疏倍数）：
      Mixtral-8x7B  专家 2/8（每 token 激活 2 个）→ active/总参 27.4%，名义 25%
      DeepSeek-V3   路由专家 9/(257-1)+共享 1 个 → 官宣 active/总参 5.5%（非本机实测）
    KV 账（fp16；每 token 全模型字节 → 各上下文 GiB；后三列只是通用缓存公式，Mixtral 原生 32k）：
     模型          KV/层/token  KV/token   1k     32k    64k    128k
     Llama-3.1-8B    4096B      131072B     0.1    4.0    8.0   16.0 
     Qwen2.5-7B      2048B       57344B     0.1    1.8    3.5    7.0 
     Mixtral-8x7B    4096B      131072B     0.1    4.0    8.0   16.0 
     DeepSeek-V3     1152B       70272B     0.1    2.1    4.3    8.6 
    → MLA 把 128k KV 从 Llama 的 16.0 GiB 压到 8.6 GiB（与 02-04 mla_demo 同式同数互证）。
    40 GiB 单卡桌判定（权重 fp16 + 满上下文 KV ≤ 40 GiB）：
     Llama-3.1-8B  权重   14.0 + KV(128k)  16.0 =   30.0 GiB  →  ✓ 装得下
     Qwen2.5-7B    权重   13.2 + KV(128k)   7.0 =   20.2 GiB  →  ✓ 装得下
     Mixtral-8x7B  权重   86.7 + KV(32k)   4.0 =   90.7 GiB  →  ✗ 差 50.7 GiB
     DeepSeek-V3   权重 1249.8 + KV(128k)   8.6 = 1258.4 GiB  →  ✗ 差 1218.4 GiB
```

三个读数：

1. **参数量推导要落地校验，且只对结构完整的模型承诺**：三张有完整 FFN 结构的卡（Dense/GQA/MoE）从层数·维度·词表·FFN 宽度逐层推导，与官方量级全落在 **±15% 走廊**内——最贴的是 Mixtral **-0.3%**（8 专家顶层算清楚），Llama / Qwen 分别 -6.5% / -7.1%（差幅来自结构细节，比如 Qwen 的分词器词表表就在 15 万量级、多了几档就有零点几 B）。DeepSeek-V3 有 MLA + 细粒度 MoE + 共享专家，结构级逐层推导不再承诺，直接采用官方 **671 / 37**（**非本机实测**）。**会解构 = 会算 + 知道哪里不能硬算。**
2. **MoE 必须报"总参/active"两本账**：Mixtral 46.57B 里每 token 只激活 2/8 专家 → active **12.75B（27.4%）**、名义 25%；DeepSeek-V3 路由 8 + 共享 1 共 9 个 → 官宣 active **37B（5.5%）**。显存看总参（权重全驻留），算力看 active（每 token 实际跑多少）——**这两本账在 MoE 上一眼分开。**
3. **KV 账是 Attention 要素的显性后果**：GQA 每层每 token 2×8×128×2B=4096B（Llama/Mixtral），Qwen 减到 2×4×128×2B=2048B，MLA 只有 (512+64)×2=1152B。128k 下 Llama 的 KV 是 **16.0 GiB**、MLA 只有 **8.6 GiB**——后一个数字与 02-04 `mla_demo` 的 128k×61 层账逐位互证，**这就是"为什么 DeepSeek 在长对话上省显存"的数学**。再把权重加上看"40 GiB 单卡桌"：**只有 Llama（30.0）和 Qwen（20.2）装得下**，Mixtral（90.7）与 DeepSeek（1258.4）直接越界——这张"谁装得下"的判定，就是 D 段决策引擎的硬输入。

> 一句话（B 段）：**会解构的第二个能力=会算账：参数量从结构推导并与官方走廊校验（Mixtral -0.3% / ±15% 全过），MoE 看 active 不看总参（27.4% vs 5.5%），KV 账把 MLA 的省显存算成 16.0→8.6 GiB。背参数的人到这里只能靠查表，会用模板的人当场就出数。**

## 5. C 段 复习链：八要素是 02 词汇的收拢，不是新知识

[C] 段做一件事：断言八要素每一条都能挂到 ≥1 个 02 复习点（8/8 全非空，`model_family_demo.py` [C] 段）：

```text
[C] 复习链断言：八要素每一条都能挂到 02 核心原理（或多模态/推理出口）——断言 8/8 全非空：
     架构 → 02-01-Transformer, 02-00-技术演化时间线
     Attention → 02-03-多头注意力-MHA-MQA-GQA, 02-04-MLA-多头潜注意力, 02-10-KV-Cache与显存账本
     FFN·MoE → 02-06-FFN与激活函数-ReLU-GELU-SwiGLU, 02-18-MoE混合专家
     训练方式 → 02-13-SFT, 02-14-对齐-RLHF与PPO, 02-16-GRPO与RLVR, 02-22-蒸馏与CPT
     推理方式 → 05-推理与部署, 02-20-推理模型与Test-time-Scaling
     上下文 → 02-17-长上下文-四层技术路径
     多模态 → 10-多模态
     Reasoning → 02-20-推理模型与Test-time-Scaling

```

> 一句话（C 段）：**八要素=用张卡把 02 的词汇按模型侧决策轴重新收拢。断言 8/8 全非空，等于把"解构=复习"写成一条可检验的纪律，后面每一个家族篇都拿这张链当填写清单。**

## 6. D 段 决策引擎：选型不选最优，选匹配

[D] 段把账（B 段）和任务装进一张规则表（`model_family_demo.py` [D] 段，**规则表 + 断言自校**）：

```text
[D] 决策引擎（规则表 + 断言自校；task→top-1 + 一句话理由）——'选型不选最优，选匹配'（§3.11）：
     中文优先                  → Qwen2.5-7B          中文全家桶生态最完整（§3.3），词表 151936
     单卡全能（40GiB 桌）         → Qwen2.5-7B          7B 级权重仅 13-14 GiB + 128k KV 7.0 ≈ 21 GiB，单卡余量最大
     超长上下文优先               → DeepSeek-V3         MLA 把 128k KV 压到 8.6 GiB（vs Llama 16.0），长对话缓存账最省
     开源 MoE 推理性价比          → Mixtral-8x7B        权重 87 GiB 用 2×40GiB 可装，active/每 token 仅 12.8B（vs DeepSeek 37B）——安装门槛与单 token 计算量双低
     端侧/最小部署               → （四卡均不达标）            端侧需 ≤1B 级 → Gemma3 1B / SmolLM / Phi 路线（行业小模型，非本机实测）
    → 规则表把'我说不清为什么选它'变成'输入任务×规则→同一推荐'；每个任务结果本地断言锁死。
```

两个读法：

1. **同一批模型在不同任务下推荐不同，这是特征不是矛盾**：中文 → Qwen（词表 151936 中文生态），单卡全能 → Qwen（20.2 GiB 余量最大），超长上下文 → DeepSeek（MLA 最省缓存），开源 MoE 性价比 → Mixtral（权重 2×40 GiB 装得下 + **active 每 token 12.8B**）。**"哪个最好"不成立，"哪个跟我的任务账"才成立**——这就是 §3.11 的"选型不选最优，选匹配"。
2. **决策的可复制性来自"规则=代码"**：每个任务断言锁死同一推荐（断言 `中文→Qwen`、`超长上下文→DeepSeek`），同一输入永远同一输出——别人能复现你的选型，而不是听你一句"感觉这家更火"。

> 一句话（D 段）：**决策引擎把"选哪家"从直觉变成规则表：中文/Qwen、单卡全能/Qwen、长上下文/DeepSeek、MoE 性价比/Mixtral、端侧/四卡都不行。每行断言锁死——选型是"跟任务匹配"，不是"排名最前"。**

## 7. 常见坑

**① 把"背参数"当"懂模型"。**
参数是取值、变量三个月就换；八要素是维度、永远问八句。你背的 "671B" 换一个代就过期，你记的 "MLA+细粒度 MoE+GRPO" 能看清技术演进的每一步。

**② 八要素卡只填"是什么"，不回答"为什么这一格重要"。**
Attention 格不填"GQA"，填不出"Qwen 在长上下文上比 MHA 省显存 4 倍"；FFN 格不填 "MoE"，填不出"Mixtral 46.6B 里只有 12.8B active"——**每格背后要能接一段 02 的机制。**

**③ 把非本机实测事实混进本机实测数字。**
要素卡与官方参数量是公开配置（非本机实测），派生账是本机真算——两线分开标。本篇有硬边界：DeepSeek 的参数量是官方数，不是推导出来的。

**④ 推导了参数量却不校验。**
推导值 vs 官方走 ±15% 走廊（本篇全部通过，最贴 Mixtral -0.3%）——不做校验的推导是自嗨，写进文章要有"对账"证据。

**⑤ MoE 只报总参不报 active。**
显存看总参、算力看 active——Mixtral 46.6B / 12.8B（27.4%）、DeepSeek 671B / 37B（5.5%）两本账一起给，只报任一都会误导预算。

**⑥ 决策引擎只看"哪个新/哪个火"，不看任务。**
超长上下文不选 MLA 最省的 DeepSeek、端侧非选 7B 起、中文不选 Qwen——选型的第一问是"任务要哪本账"，不是"这月谁在榜单前面"。
