## 0. 为什么讲 GLM 要从"填空与续写"讲起

读 `03-01`–`03-08` 八篇，你得到八句话：**① 目标不变+规模翻页；② 开源投成事实标准；③ 数据与对齐壁垒；④"省"机制级；⑤"省"可卖规格；⑥ 端侧另一本账；⑦ 闭源=只给能力不给权重；⑧ 把上下文与多模态做成产品现实。** 但前面八家其实都默认了一件事：**预训练目标是 next-token prediction**（`01`–`06` 明写、`07`–`08` 闭源默认）。而本章读者在 `02-12 预训练` 里被反复强调的一句话是"**autoregressive language model 的下一个 token 目标**"，`02-03` 里则见过三种注意力掩码（self/cross/masked）。

GLM 是第一个值得为此专门停下来的家族——它把"**预训练目标本身**"做成招牌：**GLM = General Language Model**，核心论文 *ChatGLM: General Language Model Pretraining with Autoregressive Blank Infilling*（ICLR 2023），主张"**预测被掩的连续一段内容、且这段内容内部从左到右生成**"。这句话拆开是三张脸：

> **① 填空**：blank（被掩的连续 span）本来就不在该在的位置——你要把它"猜回来"。
> **② 续写**：每个被掩的 span 内部，按从左到右的顺序生成——词与词之间有"谁先谁后"的因果序。
> **③ 双向读上下文**：被掩 span 之外的词，彼此之间双向可看——CPU 两侧的信息都能被利用。

这三张脸为什么值得专门讲？因为 **2019 年 BERT 教大家往"填空"走、2020 年 GPT 教大家往"续写"跑，主流 2021–2022 是"续写压过填空"的一言堂**；GLM 在 2023 年把这些粘回同一枚硬币，并且真的是能跑的开源产品（ChatGLM-6B 是中文开源先声）。本篇的 toy 意义由此而来：

> **"预训练目标"到底买到了什么？天底下所有大模型都在"预测被掩内容"，为什么 causal（换到任意训）、双向（预测孤立符号）、GLM（双向看上下文 + span 内自回归）训出来的模型，能力长得不一样？**

答案的物理量是**信息能流的方向**：掩码形状决定了"被掩的某个位置，究竟能看到哪一侧"。`[A]` 段把它做成一个直接可测的 2×3 表——同语料、同引擎、同预算，只换目标的掩码形状：**需右（掩 x，答案只在右端）LM 只有 0.098（≈随机），双向与 GLM 都 1.000**。这就是"目标 = 能力的形状"的最小实证。

顺带说清本篇在家族谱系上的位置：`03-00` 八要素模板立完，`01–06` 是架构可见的开源家族，`07–08` 进闭源 API 系。GLM 与 Qwen 是中文语境双雄（分别占据 `03` 与本次 `09`），但两者的卖点不同：**Qwen 用词表经济/数据翻页/预算路由讲"数据与对齐壁垒"，GLM 用空白填充讲"同一个目标的两张脸"**——一个讲"喂了什么"，一个讲"目标长什么样"。

> 一句话（为什么有本篇）：**背"GLM 是智谱的对话模型"帮不了你判断它为什么填空续写都能干；理解"双向上下文 + span 内自回归"这个掩码形状是它的招牌，并且亲手跑一个'causal 只让左信息进被掩词（需右 0.098）/ 双向与空白填充都能读两侧（1.000）'的三目标对照，才看得清这家把'预训练目标'做成桌面主菜的公司在卖什么。**

## 2. 怎么构造：把"预训练目标"玩具成 cycle 链世界的三目标方向探针，复用 02-Llama 引擎 + 本期『per-sample 掩码』扩展

"预训练目标决定能力形状"抽象成可测实验，需要先回答：**同一份语料，三套目标的差异到底是什么？** 把 02-12 的 next-token、BERT 的 MLM、GLM 的空白填充，剥到只剩"掩码形状 + 目标位"两个旋钮：

| 目标 | 输入 | 被掩什么 | 谁被监督 | 注意力掩码形状 |
|---|---|---|---|---|
| **causal LM**（GPT 线） | 原句 `[BEG x REL y REL z END]` | 不掩 | 每个位置错位预测下一 token | **下三角**（只看左侧） |
| **双向 MLM**（BERT 线） | 随机 1–2 个内容位 → `[M]` | 随机孤立 token | 只被掩位置 | **全 1**（左右都看） |
| **GLM 空白填充**（本篇招牌） | 随机连续 span → `[M]` | 连续 span | 只 span 内 | **context 双向 + span 内自回归** |

语料用 **cycle 链世界**：10 个节点 E0..E9 组成一个环，`x → y → z` 按"唯一后继"推进；句子写成 `[BEG x REL y REL z END]`（E 系即 Xxx）。这样做的奥妙在于**每个节点的答案信息天然不对称**：

- **需右探针**（掩 `x`）：`[BEG [M] REL y REL z END]` —— 答案 x 只能由右端 y、z 唯一反推（在环上，`prev(y)=x` 唯一，因为后继是双射）。
- **需左探针**（掩 `z`）：`[BEG x REL y REL [M] END]` —— 答案 z 只能由左端 x、y 唯一推出（`z=next(y)`）。

一句话：**x 的键在右，z 的键在左。** 于是"掩 x 猜对了吗"就是对"能不能用右信息"的直接测量，随机基线=节点 10 选 1=0.100。

学习是**确定性记忆**式的（`y=next(x)` 关系固定），意图不是测泛化，而是测"**这个目标允许信息从哪一侧流进被掩词**"——这正是 02-00 想教的判断力：给模型换任务，先问目标形状允不允许。模型用 `engine(7)`：2-block 解码器，RoPE + SwiGLU + RMSNorm + MHA(8 头)，C=48，V=14（4 特殊 + 10 节点），参数 ≈51k，600 步 × bs48，Adam lr=3e-3（warmup 150）。三臂**同一 init seed（seed_init=55）· 同一句子流（seed_tr=1234）· 同步数同预算**，只换目标。

本期给 `02-Llama` 引擎补的钩子是 **『per-sample 掩码』**（glm_demo 内部用；llama_demo.py 未动，None 路径逐字节向后兼容）：引擎的 `self.masks` 原契约是"每层一个 `(T,T)` 掩码"（gemma 批交替注意力沿用此契约），而 GLM 每个样本的 span 起点/长度都不同 → 掩码必须按样本给 → 注入形状 **`(B,1,T,T)`**（B 个样本、H 维展 1 便在 fwd 里与 attlog `(B,H,T,T)` 广播）。掩码只在 fwd 用：`attlog += np.where(mask==1, 0, -inf)`，softmax 阻尼后 att 进 cache；**bwd 不需要掩码**（`d_attlog = att·(d_att − …)` 公式与掩码无关），所以对账必须"设好 masks 后 fwd+bwd 整体对"（本期 [D0] 全参 maxerr≤4.523e-11 ✅）。

> 一句话（构造）：**把三套预训练目标剥成"掩码形状 + 目标位"两个旋钮，用 cycle 链十节点造'键在右 / 键在左'两个探针，再加 per-sample 掩码扩展 —— 于是「目标允不允许用右侧信息」变成一行可复现的数字。**

## 3. A 段 预训练目标三臂 × 信息方向两探针：掩码形状 = 信息能流的方向

（[A] 段由 `glm_demo.py` expA 实测；数字与输出逐字来自 run1 权威副本）

```
[A] 预训练目标三臂 × 信息方向两探针（cycle 链世界：10 节点唯一后继 · 600 步 × bs48）
    探针·需右 = 掩 x（答案只在右端 y,z 上）·需左 = 掩 z（答案只在左端 x,y 上）
    随机基线 = 节点 10 选 1 = 0.100 · 三臂同一句子流（seed_tr=1234）· seed_init=55
  ┌─────┬──────────┬──────────┬────────────────────────────┐
  │目标 │ 需右探针 │ 需左探针 │ 训练 loss(step200/400/600) │
  ├─────┼──────────┼──────────┼────────────────────────────┤
  │LM   │ 0.098    │ 1.000    │ 200:0.382·400:0.391·600:0.391 │
  │MLM  │ 1.000    │ 1.000    │ 200:0.097·400:0.099·600:0.000 │
  │GLM  │ 1.000    │ 1.000    │ 200:0.419·400:0.499·600:0.131 │
  └─────┴──────────┴──────────┴────────────────────────────┘
  → LM   需右 0.098（≈随机基线）· 需左 1.000：只看左，右信息到不了前两个词
  → MLM  需右 1.000 · 需左 1.000：双向上下文都能用，但整句在输入里是『定』的
  → GLM  需右 1.000 · 需左 1.000：双向上下文 + 被掩 span 内自回归，两侧都够
```

**读表（4 条）：**

1. **causal LM 在"键在右"的探针上只有 0.098 ≈ 随机基线。** 这不是它笨，是它的掩码形状物理上不许可：被掩词 x（位置 1）在因果掩码下只看得到 `[BEG]`，右侧 `REL y REL z END` 的信息永远进不了位置 1 —— 训练目标从未教它"用右侧反推"。而需左探针（掩 z，只看左端 x,y 就能推）它拿到 **1.000**。这就是"**续写专用目标的信息方向**"：它只会（也只能）用左侧上下文往右生成。
2. **双向 MLM 双侧都 1.000。** 全 1 掩码让每个掩位都能看两侧；训练时大量出现"掩 x、右侧是 REL y"的样本（y 唯一确定 prev(y)=x），它学会了从右反推——"填空专用目标的信息方向"：左右都能读。
3. **GLM 空白填充双侧也 1.000。** 它的 context 双向 + span 内自回归，同样的探针全部命中——"填空 + 续写一张脸"。
4. **三个训练 loss 曲线各有性格（诚实对照）：** MLM 收敛到 0.000（它的任务最浅：还原孤立符号即可），LM 停在 0.391 不降（句子含 6 个有效 token、12 个目标词的 marginal 难度，记忆后该稳定此处），GLM 0.419→0.499→0.131（span 越长难度越高，见 [B]；曲线进程 200 步先升后降，是混合 span 的难度梯度）。

**最重要的诚实说明：** 在本 toy 上 MLM 与 GLM 两侧探针**都是 1.000**——你没法从这个表区分它们。这不是失败，而是**故事的核心**：填空探针测的是"双向读上下文"，MLM 早就满血；MLM 与 GLM 的真正差别在**"要不要自回归序"**——当被掩内容内部要按顺序、后面跟着前面的输出走时（GLM 的 span 内自回归 vs MLM 的并行还原），任务才会开始挑剔。这个差别需要"任务本身依赖生成顺序"才能看到，`GLM 讲'填空续写一张脸'，MLM 讲'填空很强、续写要靠别人推'` 的边界，恰恰是 [B] 段与真实 GLM 做工具强化/Agent 的用武之地——这给了读者一个判断手势：**先问目标形状允不允许信息流，再问能力。**

> [A] 一句话：**掩码形状 = 信息能流的方向。causal 只让左信息进被掩词（需右 0.098≈随机基线、需左 1.000），双向与 GLM 都让两侧进来（1.000/1.000）——GLM 招牌的'双向读上下文'就是这份双侧自由，加上 span 内自回归的续写序。**

## 4. B 段 span 长度课程：长 span 更难（难度曲线）+『短到长』排序诚实 A/B

GLM 论文在空白填充里有一个容易忽略的机制主张：**把 span 按长度排序，短的在前面（short spans first）**，理由是"curriculum learning——先学容易的，模型再专注难的长 span"。这篇为什么值得单独一段？因为它给了我们一个干净、诚实的 toy 检验机会：**难度到底存不存在（长 span 是不是真的更难），以及"排序"在玩具尺度上值不值**。

（[B] 段由 `glm_demo.py` expB 实测；数字与输出逐字来自 run1 权威副本）

在更长的链世界里（T=13，六节点路径，span 覆盖连续 entity 词长 1/2/3）训练一个 GLM，训练中保存参数快照，每个快照对不同长度 span 各测一遍"被掩词平均 -logp"：

```
[B1] 难度曲线（训练中的快照 · 被掩词平均 -logp）
```

**B1 三点：**

1. **难度随 span 长度单调递增，且早期差距最宽。** step100：L1=0.2467、L3=0.5024（长 span 两倍多难）；全程 L1<L2<L3 从初始到收敛都不翻车。**"长 span 更难"不是纸面话，是全过程可测的单调关系**——这就是"短→长排序有课程依据"的直接 toy 依据。
2. **难度差随训练收窄到 0.00x 级（step600：0.0001 / 0.0013 / 0.0021）。** 这符合直觉：模型把环的记忆背熟后所有 span 都饱和，长 span 的相对劣势只剩"链尾误差累积",差距还在但小到 0.002 级别。
3. **难度曲线在全过程成立** → 课程排序是合理的教学策略（在真实大模型上样本需求大、复杂度差异被放大，排序的用度更大）。

**B2 课程排序诚实 A/B：** 同种子同引擎，前 250 步只喂 L=1 span（短→长）+ 之后混合（CUR），对照全程混合（FLAT）：

```
训练 loss（FLAT）200:0.017·400:0.129·600:0.027 ·（CUR） 200:0.004·400:0.023·600:0.006
三桶平均被掩词 -logp：FLAT 0.0012 vs CUR(短→长) 0.0003 → 差 -0.0009

```

诚实读：**方向为正、幅度小**。CUR 全程训练 loss 更低（200 步 0.004 vs 0.017，CUR 短路先收敛核心），终局三桶平均 0.0012→0.0003（差 -0.0009）。这个 toy 是记忆式任务、模型 600 步就打满——课程序的收益被压缩到千分级。**结论措辞很重要：这不是否定 GLM 论文的排序，而是说"排序的意图（难度先易后难）确实有实测依据（B1），排序本身在玩具尺度上收益有限（B2）"**——把"机制有依据"与"收益可测与否"分开讲，才是诚实的读法。

> [B] 一句话：**长 span 全过程更难（step100 L3/L1≈2×，收敛后 0.002 vs 0.0001），『短到长』排序是真课程；但 toy 记忆式任务 600 步打满，排序本身的收益只有 -0.0009——机制有依据、收益待放大的如实对照。**

**① GLM 家族主线（知识地图 §3.9 原话）**——`ChatGLM-6B(2023 中文开源先声)` → `ChatGLM2/3` → `GLM-4(2024)` → `GLM-4.5(2025)` → `GLM-4V(视觉)/GLM-4.1(长 Agent)/GLM-Z1(思考)` → `GLM-5(方向)`。读作一条三翻页链：**中文开源先声 → 长上下文/工具强化 → 多模态/Agent/思考三枝分叉**。

**② 中文词表账（演算）**：ChatGLM 系列的词表比例约"中文每汉字 ≈ 0.3~0.5 个 token"（与仓库 `tokenizer_demo.py` 对中文 BBPE 的膨胀实测 `03-Qwen系列`[A] 词表经济同量级，中文用好词表后每字 <1 token）。由此 128k 上下文的"中文吞吐"账：`128k ÷ 0.3~0.5 ≈ 32 万~51 万汉字`——它撑住了"整部长篇输入当聊天背景"的产品叙事。

**③ 2D RoPE 机制账（GLM 论文配套，演算）**：被掩 span 需要两套位置信息，一是不够用的——`跨 span 原文位置`（span 在整个文档里在哪）与 `span 内位置`（这是 span 里的第几个词）。GLM 用 2D 位置编码并行送两路：全局位置（跨 span）+ 局部位置（span 内从 0 数）。**这个设计解决"show 到的先后"：** span 内第 2 个词的查询，需要知道自己"在本 span 里是第 2 个"，而不是被绝对槽位暗示。账：两套频率 × 每个 head 的旋转——**参数零新增**（频率表劈两半、旋转运算复用）。本篇 toy 用 rope 承载相对位置（引擎既有路径），2D 的价值在跨度更大、span 更长的真实规模才被伸直。

**④ KV 账（演算，假定 9B 级 GQA-8 档 · L=32 · DH=128 · fp16，仅示范母线）**：每 token/层 `2×8×128×2B = 4 KiB`，×32 层 = 128 KiB/token；128k 上下文 = `16.0 GiB`。与 02-10/03-02 母线同式；真实 GLM-4 头数未公开，这里只为演示"128k 级上下文 + GQA 档位下 KV 账怎么开"。

**⑤ 思考格式账（接 02-20 / 07/08 的旋钮观）**：GLM-Z1 的"hmm 思考段"（先写思考再给答案）与 `02-20 推理模型` 的 think 协议同构——推理时交易 token 预算换正确率，思考段成本 ≈ 输出账单 × 思考长度系数（对照 07 的 thinking 旋钮观、08 的 thinking 模式）。复习链：`02-20` think token → `03-07`/`03-08` 旋钮 → 本家族 Z1 的 hmm 格式是同一家族的三种写法。

> [C] 一句话：**账本不吹牛——GLM 的中文薄（每字 0.3~0.5 token）、KV 在 128k 级要用 GiB 级开（16.0 GiB 演算）、2D 位置零参数新增、hmm 思考段是 02-20 的同款旋钮；除实测数字外，家族细节一律以智谱官方为准。**

## 6. 常见坑

1. **per-sample 掩码的广播陷阱（本批实测踩中）**：`02-Llama` 引擎的 `self.masks` 契约是"每层一个 `(T,T)`"（gemma 批交替注意力沿用），直接喂 `(B,T,T)` 会在 fwd 的 `attlog + np.where(mask==1,0,-inf)` 尾部对齐后多出 batch 维而广播失败。GLM 每样本 span 不同 → 注入 **`(B,1,T,T)`**（展 H 维），fwd 里与 `(B,H,T,T)` 自动广播。

2. **掩码只影响前向、不影响反向公式（决定怎么对账）**：`d_attlog = att·(d_att − Σ…)` 与掩码无关，softmax 阻尼已把 `-inf` 换成 0；所以**必须"设好 masks 后 fwd+bwd 整体对"**（本期 [D0] 8 组全参 maxerr≤4.523e-11 即此路径的端到端验证），不能只看 bwd 公式本身。

3. **被掩词平均 -logp 必须取 tgt 词的 logp（本批实测踩中）**：`c["logp"]·lm` 会把整条词表维也算进平均（曾跑出 277/268/261 的假难数）；正确做法是沿词表取 `logp[..., tgt]` 再乘 lm（与 `mask_loss` 同源），才得到真实被掩词平均难度。

4. **LM 探针裁剪序列时名义 causal 易错（本批实测踩中）**：crop 后（如只喂 `[BEG]`）序列短于引擎 T，直接把引擎默认 `(T,T)` 掩码塞给短序列会广播崩；**crop 后无未来 token，全 1 掩码即等价下三角**，显式给 `(n,1,T,T)` 全 1 即可——别再想当然喂下三角形状。

5. **要素事实≠本机实测**：GLM 家族每代参数/上下文/视觉/思考策略的精确数值，写作环境无外网未在线复核，账算仅演示母线；引用请回智谱官方模型卡。
