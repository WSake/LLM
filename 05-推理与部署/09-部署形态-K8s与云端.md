## §1 部署谱系四级：先问"要不要扩"，再选形态

05-08 选完引擎后，最常见的操作失误是**立刻开始背 K8s YAML**。先停一步：部署不是"选一个工具"，而是一条**四级阶梯**——从"一个人一台机器"到"云端托管"逐级往上，**每上一级，用一句自问决定"该不该往那边走"：要不要扩缩？要不要容灾？要不要运维？**

| 级 | 形态 | 怎么部署 | 什么时候该在这 | 上限 |
|---|---|---|---|---|
| **L1** | 本地 CLI | `ollama run` / `llama-server -m model.gguf` | 开发 / 原型 / 本地研究：一个人、一台机器、无并发 | 无并发、无多用户、非生产 |
| **L2** | 单机多卡 | vLLM TP × N（卡内 NVLink，零跨机通信） | 内部小服务：1~8 卡、少量用户、延迟敏感、**无扩容需求** | 单点故障：机器挂 = 服务挂；容量上限 = 这台机器 |
| **L3** | 多机 K8s 集群 | vLLM Deployment + HPA 自动扩缩 + 网关 | 多用户 / 多租户生产：弹性负载、灰度回滚、容灾 | 复杂度税：必须有 §2 的 6 件套才落地 |
| **L4** | 云端托管 | 云厂商托管 API，按 token 计费 | 无运维 / 快速起步 / 临时需求 / 外部 API 合规可接受 | 数据出境与合规风险（14-08 红线）；每 token 成本取决于量 |

### 1.1 L1 本地 CLI：开发机的起点

`ollama run llama3.2`（05-08 的引擎壳）或 `llama-server -m model.gguf`（llama.cpp 的引擎内核）拉起来即用。**这是开发/原型形态，不是生产形态**——零并发编排、零鉴权、零监控。判定很简单：你的"用户"只有你自己，就停在这一级。

### 1.2 L2 单机多卡：小服务就够，别急着上集群

当服务从"自己"变成"少数内部用户"，就需要**真引擎**（vLLM）替掉壳：一台带 1~8 卡的机器，用 **TP**（05-05 的矩阵层内切）跑起来。这里有个关键物理前提——**TP 要求卡内 NVLink 直连、锁机内**（13-02 实测 NVLink vs PCIe 聚合 28.1×），跨机不能 TP。这一级已经能吃到 05-06 Continuous Batching（GPU 利用率 64.4%→85.0%）与 05-04 PagedAttention（碎片 70%→1%）的完整收益。

**这一级的天花板**：单点故障（机器挂 = 服务挂）、容量上限 = 这台机器的显存 / 算力。**判定：要不要扩容、要不要容灾？都不要？——停在这一级，别支付集群税。**

### 1.3 L3 多机 K8s 集群：多租户生产的常态

当"要不要扩缩 / 要不要容灾"的回答变成"要"，队伍来到 L3：**vLLM + K8s**。本级的三个关键认知（细节全在 13-03，这里只放位置）：

- **扩缩的水位是 GPU**：HPA 看 GPU 利用率/每实例请求水位，期望副本 = ceil(当前 × 水位 / 目标)（13-03 账 C：85% → 8 副本扩 2）。**不数 CPU**。
- **横扩前提是无状态**：无会话粘性 → KV 随请求生灭 → 副本随便加（13-03 账 B）。若协议里带"会话必须续上同一副本"，先拆粘性再谈横扩。
- **模型加载慢是真实的**：7B 模型加载到显存是秒级~十秒级，扩出来的新副本要预热。线上方案分两派——**预热副本**（每次都 ready 后再接流，代价是常驻成本）或 **懒加载 + 冷启动限流**（代价是首批请求变慢，可被 05-10 的 TTFT 峰值捕获）。

L3 的代价是从"软件问题"升级到"运维问题"——所以 §2 的 6 件套从这一级开始变成强制执行。

### 1.4 L4 云端托管：用 token 买运维

最后一个形态：**把引擎外包给云厂商**，`deploy` 即用，按 token 计费。适合"无运维团队 / 快速起步 / 临时需求 / 数据合规允许走外部 API"。它不是免费的——**每 token 成本 × 你的调用量**是持续账单，且**数据出境是红线**（14-08 合规：外部 API 触发数据出境与主体责任重构，很多行业直接一票否决）。

> **一条主线贯穿四级**：L1→L2 是"壳换引擎"，L2→L3 是"单机换集群"，L3→L4 是"自建换外包"。选型的自问顺序就是 `要不要并发 → 要不要扩容 → 要不要合规直通外部`。（§5 账 A 把四级做成确定性判定。）

## §2 上线要素 6 件套：模型"能跑"≠"能上线"

一个残酷的工程事实：**`.decode()` 出文本只是模型跑通了模型；"上线"是一份运维契约。** 契约由 6 件套组成，缺任何一件，要么用户出问题，要么你出问题，要么合规出问题——

| # | 要素 | 管什么 | 引哪站 |
|---|---|---|---|
| 1 | **API 网关** | 鉴权（未认证 401 拦截 · $0.0）、限流（配额硬拒 429）、计费（token 记账） | 13-08 网关六功能 |
| 2 | **监控** | 延迟 P50/P95（**不报均值**，均值君陷阱 05-10 展开）、QPS、GPU 利用率（计算/显存/带宽） | 05-10 / 11-08 指标口径 |
| 3 | **日志与追踪** | OpenTelemetry 一把梭；trace 串起"网关→引擎→模型"全路径；出问题先查链路 | 13-07 可观测四件套 |
| 4 | **灰度与回滚** | 模型版本管理（13-06 注册中心）、金丝雀 5% 灰度、回滚改一行就切回 | 13-06 四发布策略 |
| 5 | **数据流控** | 请求脱敏 / 合规审查 / 重放防护——生产数据进出模型的边界 | 14-08 合规红线 |
| 6 | **SLO 与告警** | 先定 SLO 闸线再谈上线；红灯即告警，告警即查链路（回环到 3） | 13-07 四件套闭环 |

位移很重要：**6 件套不是"上线阶段再加的增强"，是"从 L3 开始就是准入门"。** 尤其前两件——没有网关，你的模型就是一个裸端口 + 无限免费额度；没有监控，19:00 的异常要等用户吐槽才知道。

> §5 账 B 把 6 件套做成确定性归位判定（每件"管什么 → 引哪站"6/6 恒一），保证视图不被迭代打散。

## §3 异构部署：CUDA / ROCm / NPU —— kernel 与引擎支持才是选型关键

异构这条线，最容易犯的错是**先给硬件、再找引擎**。正确顺序倒过来：**先查引擎的硬件支持矩阵，再买机器**——同一个模型、同一分钟，不同引擎在异构栈上的支持完成度可以差很远。

| 计算栈 | 生态成熟度 | 代表引擎支持 | 一句话 |
|---|---|---|---|
| **CUDA**（NVIDIA） | ★★★★★ 最成熟 | vLLM / SGLang / TensorRT-LLM / llama.cpp / LMDeploy 全支持；TensorRT-LLM CUDA **专属** | 事实上的默认栈，95% 生产在这 |
| **ROCm**（AMD） | ★★ | vLLM / llama.cpp 有 AMD 后端；TensorRT-LLM 不支持 | 能用但窄；选前必须有"后端成熟 + 验证成本"两项预算 |
| **NPU**（昇腾等） | ★★（唯一主线） | 昇腾 → MindIE / vLLM-Ascend（05-08 §4.2） | **需算子适配**：CUDA kernel → 昇腾算子集不是自动的 |
| **CPU**（内网/端侧） | ★★★ | ONNX-Runtime / OpenVINO（05-08 CPU 场景） | 企业内网无 GPU 的兜底形态 |

三个落点：

1. **CUDA 是默认**。选型讨论默认以 NVIDIA 为基线；非 NVIDIA 是"有额外适配成本"的特例，不是平行选项。
2. **昇腾最痛的不是算子排布，是适配**。MindIE / vLLM-Ascend（05-08 §4.2）是昇腾唯一主线，但 CUDA 生态的 kernel 到昇腾要换算子集——**部署预算里必须有一项"算子兼容性验证"**（13-03 一句带过的异构提醒，这里展开成意识）。信创/昇腾机群项目对此要有明确的时间与人力刻度。
3. **CPU 是兜底不是目标**。企业内网无 GPU 时，ONNX-OpenVINO 能把存量 CPU 用起来（05-08 的场景判定），但性能与 GPU 差两三个数量级，定位是"测/低并发的兜底"。

> 与选型账本的衔接：13-01 用四参数×三本账（显存/带宽/算力/选型）帮你挑单个配件，本篇补充"先查引擎支持矩阵再配机器"这个前置动作——**同一个算力数字，引擎支持不同，可用量就不同。**

## §5 确定性判定：谱系四级 4/4 + 上线要素 6/6（探针 `dep_form_demo.py`）

把 §1 的四级与 §2 的 6 件套收敛成确定性判定函数（纯 stdlib · 零网络 · 零随机），与 05-03/05-05/05-08 同款小函数风格。

```python
# -*- coding: utf-8 -*-
"""05-09 部署形态 · 谱系四级判定 + 上线要素归位（纯 stdlib · 零网络 · 零随机）"""

import sys
import time

_wall0 = time.time()


# ---------------- 账 A：谱系四级 “场景 → 形态” 判定 ----------------
def form_of(scene, cards=1):
    """scene: dev(本地开发)/single(单机服务)/cluster(生产集群)/cloud(云端托管)"""
    if scene == "dev":
        return "本地 CLI（Ollama / llama.cpp 拉起来即用）"
    if scene == "single":
        return f"单机多卡（vLLM TP × {cards}，卡内 NVLink·无跨机通信）"
    if scene == "cluster":
        return "多机 K8s 集群（vLLM + HPA 自动扩缩 + 网关）"
    if scene == "cloud":
        return "云端托管（云厂商托管 API 按 token 计费）"
    raise ValueError(scene)


SCENES = [
    ("个人笔记本原型/试玩（开发机即用）", "dev", 1,
     "本地 CLI（Ollama / llama.cpp 拉起来即用）"),
    ("单机 1~2 卡内部小服务（延迟敏感·无扩容）", "single", 2,
     "单机多卡（vLLM TP × 2，卡内 NVLink·无跨机通信）"),
    ("多机多租户生产（弹性负载·灰度回滚·容灾）", "cluster", 1,
     "多机 K8s 集群（vLLM + HPA 自动扩缩 + 网关）"),
    ("无运维/快速起步/外部 API 合规可接受", "cloud", 1,
     "云端托管（云厂商托管 API 按 token 计费）"),
]
ok = 0
A = ["== A · 部署谱系四级：场景 → 形态 判定（4 级） ==",
     "  场景 | 形态"]
for i, (name, scene, cards, exp) in enumerate(SCENES, 1):
    got = form_of(scene, cards)
    hit = got == exp
    ok += hit
    A.append(f"  [{i}] {name} -> {got} = " + ("PASS" if hit else f"FAIL(期望 {exp})"))
A.append(f"  形态判定：{ok}/4 PASS")


# ---------------- 账 B：上线要素清单归位（6 件套） ----------------
# (key, 要素名, 管什么, 引哪站)
CHECK = [
    ("api_gateway",       "API 网关",   "鉴权（401 拦截）·限流（429 硬拒）·计费",  "13-08 网关六功能"),
    ("monitoring",        "监控",       "延迟 P50/P95·QPS·GPU 利用率",         "05-10 / 11-08 指标口径"),
    ("logging_tracing",   "日志与追踪", "OpenTelemetry 一把梭·trace 串请求路径", "13-07 可观测四件套"),
    ("rollout_rollback",  "灰度与回滚", "模型版本 5% 金丝雀·回滚改一行",         "13-06 四发布策略"),
    ("data_flow_control", "数据流控",   "请求脱敏·合规·重放防护",               "14-08 合规红线"),
    ("slo_alert",         "SLO 与告警", "闸线红即告警·红了先查链路",             "13-07 四件套闭环"),
]


def checklist(key):
    for k, name, detail, ref in CHECK:
        if k == key:
            return f"{name}：{detail} -> {ref}"
    raise ValueError(key)


okc = 0
B = ["== B · 上线要素清单归位（6 件套） ==",
     "  要素 | 管什么 | 引哪站"]
for i, (key, name, detail, ref) in enumerate(CHECK, 1):
    got = checklist(key)
    exp = f"{name}：{detail} -> {ref}"
    hit = got == exp
    okc += hit
    B.append(f"  [{i}·{key}] {got} = " + ("PASS" if hit else f"FAIL(期望 {exp})"))
B.append(f"  归位判定：{okc}/6 PASS")

# ---------------- 一致性断言（教学自检） ----------------
assert ok == 4, "谱系四级 4/4"
assert okc == 6, "上线要素 6/6"

print("\n".join(A))
print()
print("\n".join(B))
print(f"[wall] {time.time() - _wall0:.3f} s", file=sys.stderr)
```

## §常见坑（部署视角）

1. **把"跑通"当"上线"**：`serve` 起来不代表能上线——没有网关就是裸端口+无限免费额度，没有监控就等用户吐槽才知道 19:00 出问题。6 件套是准入门不是增强。
2. **一上来就 K8s**：单机小服务却上集群，集群税（运维人力、网络、链路排错）贵过你省的并发。先问"要不要扩缩/容灾"，不要就留在单机多卡。
3. **买卡先于查引擎支持**：昇腾买了齐备的卡，却没有"引擎支持矩阵"预算——MindIE/vLLM-Ascend 要算子适配，这比单卡参数更能决定项目周期。
4. **云端一票否决**：数据出境 / 行业合规红线（14-08）面前，云端托管直接出局；外部 API 的 token 账单是持续成本，量大了自建更划算。
5. **有状态拖垮横扩**：上 L3 横扩的前提是无状态（13-03 账 B：无会话粘性 → KV 随请求生灭）。协议里带"会话粘住副本"就扩不动，先拆粘性再谈副本数。
