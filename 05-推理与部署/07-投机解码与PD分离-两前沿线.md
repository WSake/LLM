## §1 Speculative Decoding 机制：让"猜"先跑，让"验"并行

**是什么**：decode 阶段自回归的本质是**一次只能吐一个 token**——每一步都必须等上一步的结果。这是结构性的串行，不是引擎写得差（05-06 已经解决的是"多请求并行",不是"单请求内并行"）。Speculative Decoding（投机解码，Leviathan et al. 2023，同时期 DeepMind 独立提出）换了个思路：**与其让大模型一步步慢慢吐，不如训练一个又小又快的小模型连续"猜"一串候选 token（草稿），再让大模型把这串候选一次并行"验"完**。猜中的部分直接收下（省掉了猜中 token 的逐位计算），猜错的 token 丢弃、从第一个错点重新生成。

**为什么能加速（机制核心）**：加速全部来自**猜中的 token 不用大模型逐位生成**。大模型每验一个 token 的成本 ≈ 它自己 decode 一步的成本；但**一步验证往往可以同时验 N 个**（沿 kv 前缀把 N 个候选并行前向一次）——所以关键量是**接受率 α**：草稿串里被大模型接受的 token 占比。α 越高，省下的"逐位生成"越多。

**账 A（投机解码的单请求吞吐账）**：下面这段是确定性计算（内嵌代码，见 §8 验证）。取 05-01 的 decode 锚点——大模型 7B 单卡 H100 上自己一次 decode ≈ 239 tok/s（带宽限）。投机时每轮的开销变成「1 步草稿 + 1 步验证(并行 N 个)」，但注意**草稿模型也占带宽**（更多权重被读）——账 A 直接把这个带宽争夺算进去，而不是理想化免费草稿：

```
W_L = 大模型权重字节数   = 14e9  (7B fp16 ≈ 14 GiB, 05-01 锚点)
W_S = 草稿权重字节数     = 2e9   (1B fp16 ≈ 2 GiB)
BW  = 显存带宽          = 3.35e12 B/s (H100, 05-01 锚点)
γ   = 草稿长度(每轮猜几个) = 4 (典型)
α   = 接受率(大模型同意的比例) = 0.7 ("猜中率", 与草稿质量挂钩)
每轮耗时 = (γ·W_S + W_L) / BW  ← 一轮草稿 γ 步逐位(每一步读草稿权重 W_S) + 一步验证(读大权重 W_L),带宽共享全算入
期望产出 = (1 - α^(γ+1)) / (1 - α)  …几何期望: 第 k 个接受的概率 α^k, 首拒处也产出 1 个校验 token
实际速度 = 期望产出 / 每轮耗时   ← 脚本就按这个算(§8),不是线性近似 γα+1
```

如果你把草稿当"不抢带宽的免费加速",经典公式长这样：

```
E[加速] = (γ·α + 1) / (γ·W_S/BW + W_L/BW)
```

分子的 `γα+1` 是线性期望,分母同样把草稿的 γ 步权重读取算进来——**但它少算了"接受串里第一个被拒的位置",真实期望是几何期望(上面的 1-α^(γ+1) 式),这也是下面账 A 的基准。**

但更重要的一层是:**草稿模型也读权重**（2 GiB vs 14 GiB），带宽是共享的——同一张卡上同时跑两个模型时,总带宽分成两份吃,而且 γ 步草稿每一步都读一次草稿权重(不是一次)。**这件事下面 §2.2 具体算**,先给直觉结论：

| 场景 | 数值 | 说明 |
|---|---|---|
| 大模型自己 decode | 239 tok/s | 05-01 锚点 |
| α=0.9 强草稿 | ≈ 624 tok/s | 2.61× |
| α=0.7 中草稿 | ≈ 422 tok/s | 1.76× |
| α=0.3 弱草稿 | ≈ 217 tok/s | **0.91×,直接倒亏,不值得上** |

直觉：**接受率 α 是投机唯一的杠杆**。α=0.9 与 α=0.3 拉开约 2.9 倍(624 vs 217),而且**下面第 50-53 行是草稿带宽已扣除后的净账**——α=0.3 时投机不是慢一点,是**比不用还慢**。α 由「小模型和大模型"想得有多像"」决定——这不是调参能补的,是草稿模型的训练质量决定的。

## §2 关键细节：投机不是免费的（草稿模型也占带宽）

**2.1 接受并不总是对的（greedy 之外的对齐代价)**:投机解码**在 greedy/beam 解码下输出与不用投机完全一致**(接受规则保证)。但一旦采样(随机 temperature+top-p),接受规则变成**分多个 token 的逐次多项式采样**,必须严格按论文 r vs p(x) 的拒绝采样对齐——嘴上一个词组改了,后面全不一样。所以**投机解码用于确定性生成是零代价的;用于随机采样的成本是"接受率拖低"**,论文里 α 的"猜中率"在随机采样下要打折扣。这条边界直接决定它适不适合你的场景。

**2.2 带宽争夺(真正的成本)**：上面直觉账把草稿当"免费",现实不是。**同一张卡带宽共享**:草稿模型 1B≈2 GiB 权重 + KV,和 7B 的 14 GiB 抢同一条 3.35 TB/s。小模型每次草稿也要读自己的权重——**草稿不是白送的,是拿带宽换的**。下面 §8 内嵌代码把"权重字节数"写进带宽账,算出带争夺后的真实加速:

```
带宽分配模型: 草稿 γ 步逐位(每步读 W_S) + 验证 1 步(读 W_L):
  一轮墙钟 = (γ·W_S + W_L) / BW         ← KV 读写在带宽里的量级与权重同阶,已含在 W 中近似
期望产出(token) = (1 - α^(γ+1)) / (1 - α)   ← 几何期望,含首拒位置
净速度 = 期望产出 / 一轮墙钟
对照: 不投机 = BW / W_L = 239 tok/s(05-01)
```

(确定性脚本直接算,数字进验证表——这里放结论) **关键结论:草稿模型>2B 时投机几乎不赚**,因为草稿本身的带宽压倒省下的 decode;1B 左右的小草稿在 α≥0.6 以上才明显赚。这也是为什么现实中投机大多用 1B 级(或同模型小版本)当草稿,而不是"再大一点的模型"。

**2.3 什么时候不划算(门槛)**：接受率低(α<0.5)·草稿模型太大(>2B)·或**batch 已经很大**(05-06:吞吐优先时单请求眯一下带宽,投机对 batch=1 时最对症——batch 大时大模型自己也在摊薄带宽,投机收益被稀释)。下面决策表把这些一起判。

## §3 变体：Medusa / EAGLE / self-speculation（都是"找草稿谁出"）

**3.1 三问定位**:投机解码的三要素=**谁当草稿 + 怎么验证 + 接受率怎么保证**。变体全在改这三个问号:

| 变体 | 草稿来源 | 机制一句话 | 特征 |
|---|---|---|---|
| **经典投机**（Leviathan 2023） | 独立小模型 | 小模型自回归草稿 γ 个,大模型并行验证 | 草稿质量=小模型品质,依赖小模型训练 |
| **Medusa**（2023） | 大模型自己加预测头 | 在大模型最后一层上加 γ 个「预测头」(每个头预测下一个 token),一步前向直接输出 γ 个候选 | 不占第二个模型的带宽!但要多几层 heads 的算力;预测头要训练(占用 GPU/数据) |
| **EAGLE-1/2** | 大模型+自回归头 | Medusa 升级版:预测头不只看 last token embedding,还看前几层的特征(更准),EAGLE-2 用动态草稿长度 | 接受率比 Medusa 高(更"懂"大模型) |
| **self-speculation** | 大模型自己 | 大模型自己先草稿(或用自己的 early-exit 中间层预测),再从头验证 | 不需要第二个模型,但自己草稿会占用自身 decode |
| **并行草稿**（med prior） | 多草稿并行 | N 个草稿各产一串,挑最好接受 | 接受率↑,带宽×N |

**3.2 直觉速记:两条路**——**外挂草稿**(独立小模型,依赖小模型质量) vs **内建草稿**(Medusa/EAGLE 加头,占大模型算力但不占第二份带宽)。EAGLE 系列被 vLLM/SGLang 原生支持,**是 2024 后主流的服务端实现**;Medusa 早期被 TensorRT-LLM 用过,如今更多被 EAGLE 取代。self-speculation 没有额外模型,适合端侧/内存受限。

## §4 边界：为什么对"长思考类"收益有限

**长思考(R1/o1 类)生成时,投机解码的收益被四件事稀释:**

| 原因 | 机制 | 为什么难救 |
|---|---|---|
| ① 思考 token 是算出来的,猜不中 | 长推理的 token 高度取决于前文(推演链),小草稿猜中率 α 暴跌(0.4→0.5 都算好) | α 是投机唯一杠杆,一跌全盘亏 |
| ② 输出太长,收益被摊薄 | 投机省的是"每一步的带宽",长输出(几万 token)每一步都省一点,但接受率低的省不足挂齿 | 验证时还是每步都读大模型权重 |
| ③ 推理模型往往要采样 | R1 回链常用 temperature+top-p,p(o) 分布宽,拒绝采样成本更高 | 接受率再打折 |
| ④ KV 巨大,自己存不下了 | 长思考 × 大批 → KV 占满显存,草稿模型没地方放 | 显存是硬约束 |

**结论(诚实边界)**:投机解码对**单请求、中短生成(几百~千 token)、greedy、有强草稿**最对症(提升 2-3×);对长思考类,收益有限甚至为负(草稿白跑+带宽争夺)。这就是为什么 2025 年后 R1/o1 类模型的 serving 主流**不用投机加速 decode,而靠 PD 分离 + long-context 缓存**缓解。**这把边界直接接到 §5 的 PD 分离——上一篇(05-06)与这篇是"调度与延迟"两条线,而长思考是"延迟线"里投机失效的转折点。**

## §5 PD 分离 / Disaggregated Serving：把 prefill 和 decode 拆成两拨机器

**是什么**：05-01 铺了两阶段的本质——**prefill 吃算力(矩阵乘法)、decode 吃带宽**。但生产集群通常把两阶段跑在**同一批机器**(同一张 GPU 又算又吐)。PD 分离(Prefill-Decode Disaggregation,2024-2025 架构前沿;Kimi 的 Mooncake 框架是代表)干脆**把 prefill 和 decode 拆到两拨独立的 GPU 集群**——prefill 集群专门算"长签名、吃矩阵乘法",decode 集群专门"逐 token 吐字、吃带宽",各自按需伸缩。

**为什么值得拆(收益)**:

| 收益 | 机制 | 数字(后端成本账,§6) |
|---|---|---|
| 削峰:prefill 突发不再拖累 decode 吞吐 | 长签名集中算,不占 decode 步 | 见账 B/C |
| 各自独立伸缩 | prefill 吃算力→堆 A100/H100 算力型;decode 吃带宽→堆 H200/B200 带宽型 | 两集群算力/带宽各自最优 |
| 长上下文友好 | KV 很大时 prefill 集群一次算完,decode 集群只做增量 | 长上下文时代架构方向 |
| 推理模型(R1/o1)友好 | 长思考=长 decode,把 decode 集群数排独立伸缩可以扛住 | 直接来自§4 投机的失效 |

**成本(为什么不是白拆)**:
- **KV 跨集群传输**:prefill 集群算完的 KV 要**搬到 decode 集群才能继续吐字**,KV 越大搬运越贵(见 §6 账 C,单条 128k 请求 KV 有 16 GiB 量级);
- **架构复杂度**:两个集群要共享调度、KV 转移协议(如 Mooncake 的 KVCache 池,prefix cache 跨机复用)、可观测;不是把 vLLM 分成两半就能用;
- **首 token 延迟(TTFT)**:对交互服务,TTFT 反而可能更高(KV 传输一次),需要 prefetch/提前传。

**账 B(要不要拆的判断账)** 确定性计算,内嵌代码(§8):给定 prefill/decode 平均耗时、两集群算力单价,比较**拆(两集群各买适配机器)** vs **不拆(一台机器既 prefill 又 decode)** 的总成本在"长度不均衡混合负载"下的差。核心参数=签名长度分布(长/prefill 多)、decode 长度分布、机器规格差价。

## §6 成本账：什么时候 PD 分离真省钱

**6.1 成本结构**:一台 GPU 既 prefill 又 decode 时,瓶颈是两阶段里慢的那一个(stretch 混跑);拆开后,prefill 集群可以买「算力高、带宽低」的便宜卡(比如 A40 或纯算力卡),decode 集群买「带宽高」的卡。长度越两极分化(有的请求 prefill 巨长、有的 decode 巨长),越值得拆。

**6.2 账 C(KV 跨集群传输代价)**:一条 128k 请求,prefill 集群算完 KV ≈ 16 GiB(05-04 锚点 GQA-8 128k fp16);搬 16 GiB 走 200 Gb/s 内网 ≈ `16 GiB × 8 / 200 Gbps ≈ 0.64 s`。如果 decode 端才吐 300 token,传输占了大半生成墙钟——所以 PD 分离疯狂**依赖 KV 压缩(05-04 压缩线,量化省一半)+ 前缀缓存(02-17 同机 3.0×)**来减小传输。这不是可选的,是 PD 分离成立的前提。

**账 B/C 的确定性脚本**:内嵌 `spec_pd_demo`(纯 stdlib,见 §8),直接输出「拆 vs 不拆」在两负载形态下的成本差、以及 KV 传输占 decode 墙钟的百分比。**结论先给:长度越极化的负载,拆越赚;均衡负载拆反而亏(KV 传输费用吃掉削峰收益)。**

## §7 与 05-06 的分工：调用链里的两条前沿线

05-06(Serving 核心技术)与本文是**同一张服务图里的两条正交前沿**:

| 维度 | 05-06(Serving 核心技术) | 05-07(本文) |
|---|---|---|
| 层面 | 调度层(请求怎么进进出出) | 延迟层(单请求内 token 怎么快) |
| 核心问题 | 静态批→CB→Chunked Prefill(多请求共享 GPU) | 投机(单请求内并行)+PD 分离(两阶段拆机) |
| 引擎落地 | CB/PagedAttention/Chunked Prefill 已是 vLLM 默认 | 投机(EAGLE/Draft)=vLLM `--speculative`;PD 分离=生产级 SGLang/vLLM+分布式 |

**为什么不是替代**:CB 解决的是"吞吐"(多请求摊带宽),投机解决的是"单请求延迟"(算力富余兑带宽),PD 分离解决的是"两阶段牵制"(prefill 突发 vs decode 高峰)。三者可同时用:调度层 CB 让 GPU 满载,延迟层投机让单请求快,架构层 PD 分离让两阶段互不拖累。

衔接 05-08(Serving 框架对比选型):vLLM/SGLang/TensorRT-LLM 的原生 `--speculative`/`--draft-model`、PD 分离(distributed serving)支持,是选型时刻别答应的验收项。

## §8 验证：内嵌确定性代码（三进程 stdout 逐字节相同）

> 本段为站内简化账，纯 stdlib（零网络、零随机、零第三方）。三进程 stdout 字节全同（md5 `b00da455b68fe42462b52d00de620472`）。**账 A**=投机解码吞吐账(草稿模型带宽不免费);**账 B**=PD 分离拆 vs 不拆;两者共用同一个参数面,避免编造。

```python
# spec_pd_demo.py —— 05-07 确定性账（纯 stdlib）
import sys, time

_BW   = 3.35e12      # H100 显存带宽 3.35 TB/s(05-01 锚点)
_W_L  = 14e9         # 大模型 7B fp16 权重 ≈ 14 GB(05-01 锚点)
_W_S  = 2e9          # 小模型 1B fp16 权重 ≈ 2 GB

def spec_account(gamma, alpha, w_l=_W_L, w_s=_W_S, bw=_BW):
    """账 A:投机解码净速度。
    每轮:草稿阶段自回归 γ 步,每一步都读小模型权重 w_s;验证阶段读一次大模型权重 w_l。
    带宽共享时,一轮总字节 = γ·w_s + w_l,墙钟 = (γ·w_s + w_l)/bw。
    期望产出 = 几何期望(1-α^(γ+1))/(1-α):接受串尾部首个被拒 token 也算 1 步(它虽被拒但已产出校验)。
    净速度 = 期望产出 / 一轮墙钟。"""
    round_t = (gamma * w_s + w_l) / bw    # 一轮:草稿 γ 步读小 → 验证 1 步读大
    tok = (1 - alpha ** (gamma + 1)) / (1 - alpha)   # 几何期望(标准投机公式)
    return tok / round_t                  # tok/s

def spec_vanilla(w_l=_W_L, bw=_BW):
    """对照:同一带宽下不投机=只读大模型权重,逐步自回归。"""
    return bw / w_l                       # 239 tok/s(理论,05-01 锚点)

def pd_cost_split(np_, nd_, t_p=1.0, t_d=3.0, c_p=1.0, c_d=1.6, kv_gb=1.5, net_gbps=200.0):
    """账 B:PD 分离成本对账。np_ 个 prefill 请求,nd_ 个 decode 请求。
    这一版是【敏感性结构账】——不伪装精确成本,而是把决定拆不拆的真变量
    (失衡度、KV 传输密度)放进同一公式,让读者直接看趋势。
    拆分:prefill 集群算力卡(单价 c_p) + decode 集群带宽卡(c_d 贵但专用更快)
        + 每请求 KV 传输费(kv_gb, net_gbps)。
    不拆:不分集群,一张通用卡既 prefill 又 decode。两阶段时间不相交,
        顺序吃卡(墙钟 = prefill 总卡秒 + decode 总卡秒);折价用两卡均价。
    关键结构:decode 占比越大(长输出)拆越划算;KV 传输费占比升高时拆被侵蚀。
    无自造摩擦系数——全部由参数直接算。
    """
    p_work = np_ * t_p          # prefill 总卡秒
    d_work = nd_ * t_d          # decode 总卡秒
    # 拆分:两集群各自卡秒 × 单价 + KV 传输(KV 传输也在 decode 集群吃带宽卡秒)
    d_fast   = t_d / 1.5        # 专用带宽卡单步更快
    kv_sec   = (np_+nd_) * kv_gb * 8 / net_gbps      # GiB*8→Gbit, /Gbps→s
    split    = p_work * c_p + nd_ * d_fast * c_d + kv_sec * c_d
    # 不拆:两阶段顺序吃同一张通用卡
    unsplit  = (p_work + d_work) * (c_p + c_d) / 2
    return split, unsplit, kv_sec

def main():
    base = spec_vanilla()
    print("[spec account] 投机解码净速度（H100 共享带宽,大模型 7B / 草稿 1B,几何期望公式）")
    print(f"  不投机基准: {base:.0f} tok/s（05-01 锚点）")
    for gamma in (2, 4, 8):
        for alpha in (0.3, 0.7, 0.9):
            s = spec_account(gamma, alpha)
            print(f"  gamma={gamma} alpha={alpha}: 净 {s:.0f} tok/s（倍率 {s/base:.2f}x）")
    print("[spec account] 上面每一行=草稿模型带宽已从总带宽扣除,不是免费草稿")
    print()
    print("[pd account] PD 分离拆 vs 不拆（失衡形态 + KV 传输密度共同决定）")
    print("[pd account] 场景 A-D:默认 KV=1.5GiB/请求,200Gbps 内网")
    for (np_, nd_) in ((10, 200), (50, 200), (100, 50), (200, 10)):
        split, unsplit, kv_sec = pd_cost_split(np_, nd_)
        r = split - unsplit
        w = '拆省' if r < 0 else '不拆省'
        print(f"  prefill={np_} decode={nd_}: 拆 {split:6.1f} vs 不拆 {unsplit:6.1f} → {w} (差额 {abs(r):.1f})")
        print(f"       其中 KV 传输 {kv_sec:.2f} s(占总 {100*kv_sec/split:.0f}%)")
    print("[pd account] 场景 E:长上下文(每条 KV=16GiB)+ 均衡负载,传输费暴涨")
    for (np_, nd_) in ((100, 100),):
        split, unsplit, kv_sec = pd_cost_split(np_, nd_, kv_gb=16.0)
        r = split - unsplit
        w = '拆省' if r < 0 else '不拆省'
        print(f"  prefill={np_} decode={nd_}(KV=16GiB): 拆 {split:6.1f} vs 不拆 {unsplit:6.1f} → {w} (差额 {abs(r):.1f})")
        print(f"       其中 KV 传输 {kv_sec:.2f} s(占总 {100*kv_sec/split:.0f}%)")
    print()
    print("[pd account] 结论:decode 占比大(长输出)拆最值;KV 越大/越均衡,拆被传输费侵蚀。")

if __name__ == "__main__":
    _t0 = time.time()
    main()
    print(f"[wall] finish in {time.time()-_t0:.3f} s (stderr)", file=sys.stderr)
```

## §常见坑（两前沿线视角）

1. **把投机解码当"免费的加速"**：草稿模型占同一张卡的带宽（§2.2），接受率低时净速度反而下降；草稿不是白送的。
2. **随机采样下直接套 greedy 的 α**：采样时接受规则是逐次多项式拒绝,α 要打折（§2.1）,否则账是虚的。
3. **对长思考类上投机**：R1/o1 类的思考 token 猜不中、输出太长、KV 装不下（§4),投机几乎白跑;错误地把投机当长推理的解药。
4. **把 PD 分离当"直接加速"**：拆开要付 KV 跨集群传输费(§6.2),长度均衡时拆反而亏;不是无脑拆。
5. **用同一个集群规格跑 prefill/decode**：PD 分离的价值恰恰在两集群规格不同(算力型/带宽型),规格拉不开就白拆。
6. **不配 cache+压缩就上 PD 分离**：KV 量化(05-04 省一半)+prefix cache(02-17 3.0×)是传输费降低的前提,不先做会亏死。
