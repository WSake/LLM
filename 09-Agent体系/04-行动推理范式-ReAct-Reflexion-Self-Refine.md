## 0. 为什么第 4 课是「行动推理范式」？

03 把 Planning 讲成了「想几次才做」。但前两课里反复出现却一直没正名的那个东西——**「边做边想」**——就是本课的主角。02 账 A 的四个模板轨迹里，查天气回答 1 遍、客服 2 遍、代码解释器 2 遍、Operator 3 遍，每"遍"都在做一个循环：**想一下 → 做一下 → 看一眼**。这循环有个正式名字，叫 **ReAct**。

知识地图 §9.4 把「行动推理范式」一页放进了五个字头：ReAct / Reflexion / Self-Refine / ToT / LATS，外加一句 2025 现实（推理模型把"思考"搬进了模型内部）。本课把这五兄弟 + 那个现实**一次钉完**——因为它们拼在一起才是 Agent 的"行动推理"全貌：

- **ReAct**：想→做→看，标准骨架。所有范式的地基。
- **Reflexion**：做错了，把"为什么错"写进记忆，再试。自我提升的关键机制。
- **Self-Refine**：不做，先自己把稿子骂一顿改一遍，再骂再改。没执行器也能改。
- **ToT / LATS**：不确定路怎么走时，铺开多条路同时找——ToT 靠分叉+回溯，LATS 再给每条路配上价值函数和反思引导。
- **2025 现实**：推理模型在内部"思考"，框架能省的只剩 行动/观察/反思 与工具编排。

一句话定位：**02 画了循环，03 专业化了『计划』节点，本篇专业化的就是『行动』节点——把"边做边想"从口头禅变成五张可算的账，并告诉你 2026 年哪几张账已经交给模型了。**

## 1. 先把问题拆开：行动推理是什么

和「符号推理」（脱机推演，想完才动）相对，**行动推理是"想一步、做一步、看一步"的程序性推理**——每一步的正确性不是靠事前想全，而是靠事后观察往回修正。要把它变成可测的问题，拆成三个：

| 三个小问题 | 对应范式 | 一测就知 |
|---|---|---|
| **想完了再做，还是边做边想？** | ReAct（逐步）vs 计划范式（一次性/分层） | 循环遍数 = Thought 数；每个 Action 是否都被 Observation 接住 |
| **做错了靠谁纠？** | Reflexion（执行器）vs Self-Refine（自我批判） | 有没有执行器真值；失败后有没有"反思→记忆→重试" |
| **一条路够不够？** | 线性 vs ToT/LATS（树搜索） | 同一棵树，各策略烧多少评估（eval）才命中最优路径 |
| **2025 年起：Thought 还在不在框架手里？** | 推理模型 thinking 吸收 Thought 层 | 框架层 Thought 调用的 token 账（挂靠 02-20 think≈6×） |

四个问题前三个是「范式选型」，最后一个是「时代性迁移」。本课的读法是：**范式不是越新越高级，是你手里有什么验证资源、任务值不值得多花探索钱**——选型依据在账 A/B/C，时代判断在账 D。

## 3. 实验 A · 范式骨架账：Thought→Action→Observation 三元组

把 02 账 A 的四个模板任务（查天气回答 / 客服 / 代码解释器 / Operator）用 ReAct 标准骨架逐"遍"跑一遍，每个循环遍 = 1 Thought（决定下一步做什么）+ 1 Action（调用工具）+ 1 Observation（读回工具结果）：

| 模板任务 | 循环遍数 | Thought | Action | Observation |
|---|---:|---:|---:|---:|
| ReAct 查天气回答 | 1 | 1 | 1 | 1 |
| LangGraph 客服 | 2 | 2 | 2 | 2 |
| 代码解释器 | 2 | 2 | 2 | 2 |
| Operator 订航班 | 3 | 3 | 3 | 3 |

一句话先把骨架钉死：**每个 Action 后面必须跟一个 Observation——观察是动作的视线，是外部世界进入循环的唯一口；Thought 数恒等于遍数——每遍行动前必先想。** 探针断言这组不变式在 4 个模板上 4/4 成立。

三个直接结论：

1. **ReAct = §9.3『逐步计划』的字面骨架**：03 账 A 动态场景里那个「0 白做、0 显式重规划」的逐步计划，逐遍展开就是上面的三元组循环——「想」在每遍做，变化自然被下一步思考吸收。**03 说的『形态是任务确定性的函数』，落到范式上就是这个骨架：任务确定用一次性（省思考）、任务会变用逐步（省重规划）。**
2. **Observation 是循环的命门**：T→A 之后如果断了 O（工具结果不读回），下一步 Thought 就是闭眼瞎猜——行动推理和"自说自话写计划"的分界就在这一步。02 账 C 的评估节点只是内部判断，Observation 是**外部事实入口**，两者缺一不可。
3. **Thought 不调外部 = 零成本修正位**：改主意（Thought）不花钱，改动作（Action）才花钱。所以 ReAct 骨架里「多想一步」比「多做一步」便宜得多——这为账 C 的树搜索"多想"铺了个底价，也为账 D 的 2025 融合埋了个伏笔（如果想被搬进模型内部，成本会计就要重算）。

> 探针断言：4 任务 (T,A,O) 全等于各自遍数 1/2/2/3 · A==O 不变式 4/4 锁死——骨架不是模板，是**结构约束**。
> 挂靠：02 账 A 的「循环遍数 1/2/2/3」原样复用（四模板轨迹 = 本篇三元组的来源）；本篇不重测 02 已有的循环语义，只把遍数拆成三元组。

## 4. 实验 B · 自纠错两大范式账：Reflexion 外验 vs Self-Refine 内验

骨架跑起来后，Agent 第一个要面对的现实：**会做错。** §9.4 给了两大纠错范式——用执行器真值兜底（Reflexion），或用模型自我批判兜底（Self-Refine）。探针各跑一场。

**Reflexion（执行器反馈 · 反思写记忆再试）**——任务：写排序函数，用测试集验证：

| 阶段 | 测试 | 反思/记忆 | 结果 |
|---|---|---:|---|---|
| v0 初版（比较方向反 bug） | 1/3 失败 | 生成反思「compare 方向反（用例2 期望升序实得降序）」并写入记忆（1 条） | 失败 1 次 |
| v1 重写 | 3/3 通过 | — | 完成（尝试 2 次 · 失败 1 次 · 反思 1 条 · 记忆 1 条） |
| 任务二（同型任务） | 3/3 直接通过 | 记忆命中「compare 方向反」→ 第二版直接写对 | **尝试 1 次 · 失败 0 次 = 0 重复错** |

三个读点：**(1) 反思的价值在复用**——如果反思只写在思维里不落记忆，第二次碰到同类错误还是要犯错一次；写进记忆后，同型任务从「尝试 2 / 失败 1」变「尝试 1 / 失败 0」，这是「0 重复错」的机制。（2）**Reflexion 靠的是执行器真值**——1/3 → 3/3 有没有过，测试说了算，不靠模型自我感觉。（3）**它和 02 账 A 的『两遍完成』是同一机制的正式命名**——客服 2 遍、代码解释器 2 遍，本质都是"失败 → 反思 → 再试"。

**Self-Refine（无执行器 · 生成→自我批判→修订）**——任务：写自我介绍文案（没有测试集可跑，只有文本）：

| 迭代 | 词面代理评分 | 动作 |
|---|---:|---|
| 初稿 | 0.44 | — |
| 批判 1 → 修订 2 | 0.62 | 没有执行器，靠模型中立地批自己 3 条 → 改 |
| 批判 2 → 修订 3 | 0.78 | 再批 2 条 → 改，收敛 |

全程**批判 2 次 · 修订 2 次 · 外部反馈 0 次**——这就是 §9.4 说的"不用执行器"。

**两大范式的分界线就是『验证资源』：**

| | Reflextion | Self-Refine |
|---|---|---|
| 反馈来源 | 执行器真值（测试/运行/API 报错） | 模型自我批判（无真值） |
| 需要的环境 | 可执行、可验证 | 只要会说话 |
| 可信度 | 客观（真值兜底） | 主观（批判力即上限，自评会自嗨） |
| 迭代闭环 | 失败 → 反思 → 写记忆 → 重试 | 生成 → 批判 → 修订 → 再批判 |

> 探针断言：Reflexion 尝试 2/1（任务一/二）· 失败 1/0 · 反思 1/0 · 记忆命中拦截复查 0 重复错 · Self-Refine 2 轮批判收敛且 0 外部反馈，全部锁定。
> 挂靠：06-05 行动层「工具错误回喂自愈 3/3」= Reflexion 在真实工具调用上的同族机制（错误返回→修正→重试）；06-记忆系统 = 反思落地的内容层存储（与 06 的 profile/记忆库同源）；02-20 规则验证器 best-of-k≈78/80 —「真值>看起来像」在自纠错里的分水岭：**有真值就走 Reflexion（外验），没真值才走 Self-Refine（内验），别反着来。**

## 5. 实验 C · 树搜索成本账：ToT/LATS 的"充分"值多少钱

前两账都是"一条路走到黑"。日子久了会发现：有的任务是绕着弯的（第 1 条路就走死），这时候 §9.4 的 ToT / LATS 才有登场理由。探针把四策略放进**同一棵 4 深×3 叉树（正确分支=每条的最后一条）**，看各自的探索成本：

| 策略 | 评估次数 | 相对贪心 |
|---|---:|---:|
| ReAct式贪心（线性逐步） | 12 | 1.00× |
| ToT（分叉实现 B=3 · 剪枝保留 2） | 21 | 1.75× |
| **LATS（价值引导 + 反思）** | **6** | **0.50×** |
| 穷举展开（全部路径） | 120 | 10.00× |

四策略**都命中最优路径**（4/4，深度 4 全对），差异全在成本：穷举 vs LATS 差 **20×**。三个读点：

1. **ToT = 分叉 + 回溯，探索充分 = 显式付钱**：贪心在"正确分支=最后一条"的树上，每层把 0、1、2 三条都试满才找到对的=12 次；ToT 每层保留 2 条最好的继续=21 次。**充分买的是"不陷入局部最优"**——要是第 1 条路是死路，贪心会白打一次死墙，ToT 因为保了两条路不会。
2. **LATS = ToT + 反思 + 价值函数，把"充分"省下来**：价值函数先指路（每层直接走向分更高的分支）+ 反思在失败分支给反馈（探错少）。于是连贪心的钱都省了——6 次 vs 12 次。**价值引导是把『探索充分』的成本从 10×/1.75× 压到 0.5× 的杠杆**，这正是 §9.4 原话「LATS 把树搜索与反思、价值函数结合」的账本面。
3. **成本账的边界**：四策略命中一样，是因为这棵树"正确路径是唯一的、并落在可复测的分支上"。真实任务里评估器（价值函数）好坏决定 LATS 指路的准头，任务死路分布决定探索的必要性——**值钱的是"可评估多分支 + 会指路的价值函数"，不是"分叉"这两个字本身。**

> 探针断言：greedy 12 < ToT 21 < 穷举 120 · LATS 6 全场最省 · 4/4 命中，全部锁定。
> 挂靠：07-02 recursion_limit 真抛 GraphRecursionError —— 树搜索的深度在真实框架里吃"步骤上限"护栏（ToT 扔深了真被引擎拦）；02-20 best-of-k≈78/80 —— 多路采样试错 = ToT 多分支、LATS best-of-a-tree 都是同一族"多条腿走路"思想。

## 6. 实验 D · 2025 融合与范式选择树账：Thought 层去哪儿了

前三账都是 2022-2023 的地盘。§9.4 最后一句「2025 现实」改写了账本的记法——**Thought 层被推理模型吸走了**。探针用三世代台账把它画出来：

| 世代 | Thought 在哪 | 会计成本 |
|---|---|---|
| 2022 · ReAct | 框架外显式：模型文本里显式写「Thought: …」再给 Action | 思考 = 一个显式 prompt 步骤 |
| 2024+ · 推理模型 | 模型内部：o1/R1 的 think 模式在生成 Action 前先在内部思考 | 内部思考是 token 会计（02-20 think≈6× 输出预算） |
| 2026 · 现实 | 框架 Thought 层与模型 thinking 模式融合：框架不再自己造 Thought | **框架手里只剩 行动/观察/反思 + 工具编排** |

融合理由一句话：**框架手写 Thought 等于付两次钱**——外部显式一次 + 模型内部 think 又一次（02-20 已测：think 输出预算≈6×）。所以 2026 的 Agent 框架把"想"整个还给模型 thinking，自己只保留三件事：**行动（工具调用）、观察（结果回读）、反思（失败反馈）**，外加工具编排。成本会计的重心也从「显式 Thought 的 prompt 工程」移到「内部 thinking 的预算/token 调度」。

范式选择树（探针 6 断言锁死），选型核心 = **看手里有没有验证资源、任务值不值得多花探索钱**：

| 场景 | 选谁 | 为什么 |
|---|---|---|
| 即时应答 / 无验证器 | **ReAct** | 骨架最省，想一步做一步 |
| 有执行器反馈且可重试 | **Reflexion** | 真值兜底，反思记忆复用（账 B） |
| 只有文本 / 无执行器 | **Self-Refine** | 没真值就靠自我批判，别硬造执行器 |
| 需充分探索 / 可剪枝打分 | **ToT** | 多路分叉防局部最优（账 C 21 次是明码标价） |
| 高价值任务 / 舍得算力 | **LATS** | 价值函数+反思把探索钱花在刀刃上（账 C 6 次） |
| 2026 默认 | **推理模型 thinking + 框架控制流** | Thought 交模型，框架管行动/观察/反思（账 D） |

> 探针断言：6 场景 6/6 锁死 · 融合三世代 2022→2024+→2026 台账完整。
> 挂靠：02-20 think≈6×（内部思考成本锚点，账 D 的会计底账）；02 账 C 验证回路（选 Reflexion/Self-Refine 的分界线就是有没有真值）。

## 7. 这篇行动推理怎么用（一页带走 + 掌握度检验）

一页带走（四条硬记忆）：


## 8. 常见坑（行动推理的 8 个）

1. **把 ReAct 当"高级提示词模板"**：ReAct 是循环骨架，不是让模型把「Thought:」「Action:」念出来就完了。只写 Thought 不动 Action = T→A 都没形成，是单口相声不是行动推理（账 A 骨架）。
2. **T→A 之后断了 O**：工具结果不回读，下一步 Thought 就是闭眼猜。观察（外部事实入口）和评估（内部判断）缺一不可，别把 Observation 省了（账 A 结论 2）。
3. **Reflexion 反思不落记忆 = 白反思**：反思的价值在复用（账 B 任务二 尝试2→1、失败1→0）。反思写出来但丢在会话里=每次同型错误重犯一遍。
4. **Self-Refine 当万能**：没有真值兜底，自我批判会自嗨，上限受批判力限制（账 B 分界）。能用执行器就别懒——02-20 已证明规则的 verify 比"看起来像"便宜可靠。
5. **该探索却贪心**：任务死路深、第一条分支就引向错误时，一条路走到黑 = 局部最优（账 C 四策略只有分叉类能把"正确分支在最后"的树走穿还不吃亏）。
6. **无脑全上 ToT**：分叉=显式成本（账 C 21 vs 12 eval）。值钱的是"可评估多分支 + 价值函数"，不是"分叉"两个字本身；性能预算里没这笔钱就别硬铺。
7. **2026 还手写显式 Thought**：框架自己造 Thought + 模型又 think 一次 = 付两次钱（账 D 融合台账，挂靠 02-20 think≈6×）。把想交给推理模型，框架管行动/观察/反思。
8. **Reflexion/Self-Refine 分不清**：一个有执行器（外验）、一个没有（内验）。没测试环境硬上 Reflexion=没真值硬外验；有真值却靠 Self-Refine=可信度白打折（账 B 分界 + 选择树第 2/3 行）。
