## 0. 为什么第 2 课是「主循环」？

09-01 把「什么是 Agent」钉死了：**Agent = 大脑 + 手脚 + 循环 + 记忆 + 目标**，判别器里最硬的那条线是「**有 LOOP 才进 Agent**」。但判别器只回答「是不是」，没回答「LOOP 长什么样」。知识地图 §9.2 说得很重：这是 🔴 **必须会画**的一课——**Agent 这个词可以有很多定义，但所有 Agent 都要跑同一个骨架**。

> 章末视角：09-03 讲 Planning 时你会说「这是 §9.2 的计划节点」，09-04 讲 ReAct 时你会说「这是最简版的 §9.2 循环」，09-12 讲评测时你会说「停机条件的引擎化」。**本篇是整章所有后续篇目的公共底座图。**

本课把地图的一句话「主循环」降维成一张**能跑的状态机**，用 4 个已经判过类(01 账 B)的 Agent 模板系统填进去，再回答三件事：每个节点在**哪一步可能坏**（四个可失败点）、怎么**兜住**（护栏三件套）、**停在哪**（停止判据三态）。

## 1. 先把问题拆开：LOOP 不是「反复调用」

给一个循环程序加个 `while True`，那不是 Agent 循环。§9.2 的主循环是一个**带状态的行动过程**，六步各司其职：

| 环点 | 它回答的问题 | 一坏就坏在哪 |
|---|---|---|
| 🎯 目标 | 用户到底要什么？验收标准是什么 | 「完成=没定义」=不知道何时停 |
| 👀 感知 | 现在知道什么？要额外拿什么（检索/上下文/工具结果） | 信息不够就动手=盲做 |
| 🗺 计划 | 下一步做什么？拆几步、用什么策略 | **计划太抽象**=列的是目标不是步骤 |
| 🛠 行动 | 执行具体动作（调工具/写代码/发消息） | **工具用错**=参数/工具名不匹配 |
| 🔍 观察 | 读执行结果（工具返回/测试输出/网页内容） | **观察被噪声淹没**=陪跑行盖住目标行 |
| 🔁 评估 | 够了吗？出错了吗？该停了吗？ | **评估放过幻觉**=「看起来像」就当对 |

**循环 = 行动 → 观察 → 评估 → 再计划**，直到评估判出三种终局之一：**完成 / 放弃 / 转人工**。所以一张主循环图的灵魂是两个问题：**谁来决定「停」**（停止判据）、**停不下来怎么办**（护栏）。§9.2 的原文就是这句：「工程重点 = 给循环加护栏（步骤上限、错误重试、人工确认、评测）」——本课把它做成三件套。

## 2. 把图降维成本机测量（探针设计：四本账）

## 3. 实验 A · 六状态机：把 4 个 Agent 模板任务跑起来

01 账 B 判出的 4 个 **Agent** 档系统（有 LOOP、运行中决策），本篇原样当模板样本跑一遍状态机。首遍走全六环（目标→感知→计划→行动→观察→评估），回环只走「计划→行动→观察→评估」（目标/感知只在最开头收敛一次）：

| 模板样本 | 循环遍数 | 终局 | 一句话终局依据 |
|---|---|---|---|
| ReAct 带工具·查天气回答 | 1 | **完成** | 检索结果信息够 → EVAL 判「够了」 |
| LangGraph 客服·故障重试（里程碑012） | 2 | **完成** | 第一遍观察=失败 → EVAL 判「重试」→ 第二遍观察=恢复 |
| 代码解释器·写函数并测试 | 2 | **完成** | 第一遍测试失败 → EVAL 判「修正」→ 第二遍测试通过 |
| OpenAI Operator·订航班 | 3 | **转人工** | 查→比→选三遍，付款属高风险动作 → EVAL 判「升级人工」 |

探针把每条任务的循环轨迹逐遍打出来（`GOAL→PERCEIVE→PLAN→ACT→OBSERVE→EVAL`），统计：**4/4 终止 · 终局三态 {完成3 放弃0 转人工1} · 六节点全动**（每个环点至少被访问一次）。三个直接可用的结论：

1. **完成≠一遍过**：客服与代码解释器都是两遍才完成——第二遍回环就是 §9.4 说的「Reflexion/自纠错」在循环上的字面形态（执行后回喂再试）。
2. **转人工不是因为失败了**：Operator 三遍都是「成功」的查询，转人工是**风险评估踩到的停点**——停止判据不全看「有没有完成」，还看「该不该让机器做」。
3. **节点访问计数 = 成本刻度**：6/10/10/14 次节点访问给了「查天气最便宜、订航班最贵」一个可打印的数字——把 agent 成本挂在循环步数上，正是 §9.12「成本指标」的可计算起点。

## 4. 实验 B · 护栏三件套：步骤上限 ｜ 错误重试 ｜ 人工确认

§9.2 点名了护栏，本课把它钉成三件套，每件都跑出两个对照：

**① 步骤上限（防死循环白烧 token）。** 一个「看似正常却在空转」的循环需要 7 步才收敛——可能永远不收敛。cap=4 时探针在**第 4 步触顶 → 放弃·转人工**，不再烧后续 token；对照的健康循环 3 步收敛、cap=6 → 正常完成。**cap 越界才触发 = 不误伤好循环。** 这是「stop、giveup 都算成功出口」的工程版。真实引擎版已经有仓库实测：07-02 的 **recursion_limit 真抛 `GraphRecursionError`**——框架级轮上限就是 cap 的原生护栏。

**② 错误重试（自愈 vs 交人）。** 同一任务带 2 次瞬时错误（网络抖动/参数被拒），budget=3 → 第 3 次尝试成功，**重试 2 次自愈**；budget=1 → 第 2 次失败就越界 → **转人工**。护栏把「重试几次」从感觉变成预算参数。挂靠 06-05 的**报错自愈 3/3（重试 1·1·2）**——工具调用层已经把这件事实测过一遍，本篇把它放回循环的评估节点。

**③ 人工确认（高风险动作分诊）。** 同一批动作里，**低风险（读项目文件）自动放行，高风险（向对公账户付款 ¥5000）升级人工审批**，人工确认后才执行。别小看这一条：01 账 B 里「Agentic System」比「Agent」多出来的特征位就有 APPROVE（人工审批）——**护栏三件套的第三件，正是 Agent 升格 Agentic System 的门槛之一**。

> 三件套的实战关系一句话：**步骤上限管「别停不下来」、错误重试管「出错别当场认输」、人工确认管「高风险别自作主张」。** 一个把三件套都装上才配谈「能进生产」——这与 01 账 A 的 Agentic System（ENV/EVAL/APPROVE/GOV）完全对账。

## 5. 实验 C · 四可失败点 × 四条护栏：验证回路大于提示词

§9.2 给了循环的四个伤口，本课给每个伤口配一条护栏，并把「护栏有没有用」做成能跑的演示：

| 环点 | 可失败点 | 护栏 | 仓库已有实测 |
|---|---|---|---|
| 计划 | 计划太抽象 | 步骤上限 + 计划可执行性检查 | 本账 B cap=4 · 账 D P&E |
| 行动 | 工具用错 | 错误回喂 · 自愈重试 | 06-05 报错自愈 3/3 |
| 观察 | 被噪声淹没 | 证据纯度过滤（只留命中行） | 08-06 纯度 0.226→1.000 |
| 评估 | 放过幻觉 | 规则验证器（真实验收条件） | 02-20 best-of-k≈覆盖率 78/80% |

**演示一：评估放过幻觉 → 规则验证器抓住。** 任务 `3+5`，agent 初答 `7`（幻觉）。规则验证器按真值判决 `7 ≠ 8` → 抓住 → 重规划 → 修正为 `8`，用了 **2 遍循环，比不校验多付 1 遍，但把幻觉拒在门外**。要点在「真值来源 = 可执行计算，不是『看起来像』」——这正是 §9.7 那句 **「Agent 可靠性来自验证回路，而不是更好的提示词」** 的最小可运行版本，也直接挂靠 02-20 的规则验证器账本（best-of-k≈覆盖率 78/80%，验证器只负责把覆盖率兑现）。

**演示二：观察被噪声淹没 → 证据纯度过滤。** 一段观察含 5 行、命中行只有 1 行：**raw 纯度 0.200 → top-1 过滤后纯度 1.000**。这是 08-06 上下文压缩那笔大账（证据纯度 0.226→1.000）在 Agent 观察节点上的一次最小再现——**陪跑行盖住目标行时，先过滤再读，别指望模型自己扛噪声。**

结论：四个伤口没有一个靠「写更好的提示词」愈合，全靠在循环结构里加**验证/过滤/重试/上限**——这就是 2025 年「验证回路式 Agent」与「提示词召唤流 Agent」的分水岭。

## 6. 实验 D · 计划形态与停止判据：想几次才做？什么时候停？

**计划形态账（§9.3）：** 同一 3 子任务，三种规划方式在「想几次才开始做」上的差别被量化：

| 形态 | 计划调用 | 循环遍数 | 适用 | 机制一句话 |
|---|---|---|---|---|
| Plan-and-Execute（一次性） | **1** | 3 | 确定性任务 | 1 次计划列全 3 步清单 → 顺序执行不重算 |
| ReAct（逐步） | **3** | 3 | 开放任务 | 每子任务前现想一步，task1/2/3 各 1 次 |
| 分层计划（Task 树） | **4** | 3 | 复杂大任务 | 1 次根计划 + 3 次子任务细化 = 1+3 |

**计划调用 1 < 3 < 4：计划越细 = 想得越多。** 适用任务也因此分档——确定性任务用一次性省思考、开放任务用逐步边做边改、大任务用分层避免「一步计划就崩」。注意三档的「循环遍数」都是 3：**计划形态改的是思考成本，不改执行遍数**——这正是预算路由的话题（02-20 的难度路由：@k4 拿 32% 预算换 92% 准确率）。

**停止判据三态（§9.2/§9.12）：** 这个循环什么时候算「跑完」？三态互斥，各有可验证的触发条件：

| 终局 | 触发条件 | 成本 | 本课台账来源 |
|---|---|---|---|
| 完成 | 验证通过（测试/规则校验/真实验收） | 最低·算到确认对为止 | 账 A 完成×3 · 账 B 自愈循环 |
| 放弃 | 步骤上限 / 预算耗尽（护栏①） | 已烧步数白付（但比继续烧省） | 账 B cap 触顶 · 重试预算耗尽 |
| 转人工 | 高风险动作 / 不确定反复失败 | 半途交人 · 保全风险 | 账 A Operator · 账 B 交人 |

合起来看：**全探针产生 6 个终局样本（完成3 · 放弃1 · 转人工2），全部落在三态内**。§9.12 说「好的 Agent 评测 = 固定环境 + 可验证的终结条件 + 成本指标」——这里的三态就是终结条件的枚举：**没有枚举停止判据，你就没法评测一个 Agent**（因为它连「做完了吗」都没定义）。这也是本课给 09-12 评测篇埋的接口。

## 7. 把这条 Loop 怎么用（一页带走 + 掌握度检验）

一页带走（四条硬记忆）：

```
① 六环图：目标→感知→计划→行动→观察→评估→(循环)，回环只走计划→行动→观察→评估；目标/感知收敛一次
② 四伤口：计划太抽象→上限+可执行检查 ｜ 工具用错→错误回喂 ｜ 观察噪声→证据纯度过滤 ｜ 评估幻觉→规则验证器
③ 三护栏：步骤上限(cap 触顶→放弃·转人工) + 错误重试(budget 内自愈→耗尽转人工) + 人工确认(高风险升级人)
④ 停止三态：完成=验证通过 ｜ 放弃=触顶/预算耗尽 ｜ 转人工=高风险/反复失败——三态互斥，各有可验证触发
```

## 8. 常见坑（Loop「画图病」的 6 个）

1. **把 while 循环当 Agent 循环**：`while True: call_model()` 没有「观察→评估→改口径」的闭环，是空转不是主循环——主循环的核心是**评估节点决定往哪走**（完成/放弃/转人工/再计划）。
2. **只画六节点，不画停止判据**：一张没有「停在哪」的循环图等于没有——三态互斥、各有可验证触发，才是这图能进生产的原因（§9.12 接口）。
3. **把「完成」当唯一出口**：账 A 的 Operator 三遍全成功却转人工——**高风险动作是评估节点的合法停点**，不是失败。
4. **护栏只装一半**：只加 cap 不加重试，遇到瞬时错当场认输；只加重试不加 cap，遇上有偏的循环无限自愈下去。三件套是配套的，跟账 B 的对照看。
5. **指望提示词修四个伤口**：账 C 的四个可失败点没有一个靠「写更好的提示词」愈合——**钱要花在验证回路（规则验证器/测试/过滤），不是花在讲道理**（§9.7 原话）。
6. **计划形态一刀切**：P&E 最强不代表处处用——确定性任务用一次性省思考、开放任务用 ReAct 逐步、大任务才分层；账 D 的 1<3<4 是「想得越多」的刻度，不是「越好」的刻度。
