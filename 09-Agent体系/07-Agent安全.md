## 0. 为什么第 7 课是「Agent 安全」？

06 讲完评测，把"安全事件>0 不上生产"当红线踩了一脚——但那条红线的**下面藏着整块地基**：为什么 Agent 会闯祸？什么威胁在什么样的位置打进来？护栏该怎么排才能拦得住、兜得住？§9.13 把这块地基明确成了"必须看过威胁模型"的必修课，并指明**详细展开在 §12 章**。

这一课在 09 章的位置很特殊：**前面六课都在教 Agent 怎么更会干活，这一课在教怎么让它干活干得不闯祸。** 模型评测是在测"答案对不对"，Agent 评测在测"动作对不对"，Agent 安全在测"如果动作全错了，你拦得住吗"。三者的关系正是 §9.14 趋势①说的：**Agent 系统化 = 评测 + 护栏 + 人工审批进生产**——06 是评测这块拼图，本篇（07）是护栏这块拼图，人工审批横跨两者。

为什么必须专门讲 Agent 安全，而不是引用一遍 §12 章就完事？因为 **Agent 的安全面和纯 LLM 应用的安全面是有额外新增的**：纯 LLM 只有输入输出两层（网页用户问→模型回），Agent 在这之间插进了**工具执行层**——它真的会删文件、转账、调接口、连外部 Server。这就凭空多出一整类攻击面（§12.5）和一堆可用的缓解手段。§9.13 的五威胁×六护栏，就是把这层"多出来的面"钉成一张能背下来的清单。

## 1. 先把问题拆开：Agent 的威胁不在模型，在进脑与动手

§9.13 给出五类威胁、§12.0 给出五侧（输入/模型/系统/输出/治理）一张地图。先把这五威胁在五侧上的落点想清楚，就能看出一个模式——**Agent 的威胁几乎不在模型本身，而在它『读进什么』和『能调用什么』**：

| 威胁 | 打在哪一侧 | 一句话 |
|---|---|---|
| **Prompt Injection（工具内容注入）** | 输入侧 | 查到的资料/网页/邮件里藏指令，Agent 分不清数据与指令（§12.1） |
| **工具滥用（越权）** | 系统侧 | 让 Agent 用最高权限 token 删库/转账/调管理接口（§12.5） |
| **数据外泄** | 输出侧 + 治理侧 | 工具输出带敏感数据、日志记敏感输入（§12.3） |
| **供应链（恶意 MCP Server）** | 系统侧 | 伪装成计算器的 Server 接进 Agent 工具列表（§12.5 + 07-11 MCP） |
| **权限逃逸** | 系统侧 | 逃出沙箱容器读宿主机盘、无权提权到管理员（§12.5） |

三条关键观察：

1. **模型侧几乎零新增**。五威胁里没有一档是"模型太笨"导致的——越狱/幻觉/训练记忆泄露那些模型侧威胁归 §12.2-12.4，得由 12 章（越狱、模型提取、Content Safety）去管。**Agent 安全是工具链安全，不是模型安全**。§9.13 要你"必须看过威胁模型"，看的是工具执行这层多出来的面。
2. **威胁分两大类**：一类是"**读得进毒**"（输入侧的注入——内容污染了 Agent 的判断），一类是"**拿得到钥匙**"（系统侧的越权/逃逸——就算没有内容污染，坏了权限边界也能闯祸）。这两类对应的护栏完全不一样：前者靠**输入输出过滤 + 数据标注**（账 B），后者靠**最小权限 + 沙箱**（账 C）。把威胁和护栏的配对关系记清楚，比死记六条护栏列表有用得多。
3. **基线护栏六件套是纵深防御，不是单点**：最小权限 + 沙箱 + 人工确认 + 输入输出过滤这四道是"拦得住"，审计日志 + 可回滚这两道是"兜得住"。§9.13 的六件套不是一个按钮，是一条流水线——先让毒进不来，再让钥匙变少，最后出事了能查、能回滚。

## 3. 实验 A · 威胁模型账：五威胁 × 五侧，扎堆在『输入+系统』

把 §9.13 的五威胁展开成 10 个工具链威胁样本（每个都对应到 §12 章节与五侧之一），跑出密度：

| 五侧 | 条数 | 代表威胁 |
|---|---|---|
| **输入** | 2 | Prompt Injection（工具内容注入 / 网页·邮件间接注入） |
| **模型** | 0 | （越狱/幻觉归 §12.2-12.4，本篇聚焦 09 特化威胁） |
| **系统** | 6 | 越权调用 / 参数越界 / 恶意 MCP Server / 依赖投毒 / 容器→宿主逃逸 / 提权 |
| **输出** | 1 | 工具输出带敏感数据 |
| **治理** | 1 | 日志记敏感输入 |

**10 个威胁里 8 个落在『输入（进脑）+ 系统（动手）』。** 这个数字是账 A 唯一一条、也是全章最重要的一条读数：

> **Agent 的威胁不在模型本身，而在『它读进什么（缺一次鉴别）』与『它能调用什么（缺一把锁）』。** 所以基线护栏一头装输入输出过滤（管"读进毒"）、一头装最小权限（管"拿到钥匙"）。

这也直接解释了六护栏为什么是"三管进 + 三管出 / 拦 + 兜"的结构：**输入输出内容过滤管注入与外泄（进与出都在过内容），最小权限 + 沙箱 + 人工确认管系统侧的动作（钥匙、隔离、兜底），审计 + 回滚不管"能不能做"而管"做了怎么办"**。§12.0 的"输入/模型/系统/输出/治理"五侧不是分类学装饰——**每一侧都对应一组该装护栏的位置**，地图给了坐标系，本篇后面的账就按坐标系装护栏。

## 4. 实验 B · 提示注入账：只能缓解不能根治

第一类"读得进毒"的威胁就是 Prompt Injection。§12.1 把注入分成两种：**直接注入**（用户亲自对 Agent 说"把我老板密码改掉"）和**间接注入**（网页/文档/邮件/工具返回的内容里藏指令，Agent 读到它就触发）。探针给 Agent 喂 12 条内容（6 条含注入指令：2 直接 + 4 间接；6 条正常），跑三档缓解：

| 档位 | 触发行动量 | 说明 |
|---|---|---|
| 无标注回喂 | **6 条** | 工具/网页/邮件返回与指令混在同一上下文 → 注入内容全被当指令执行 |
| **工具结果标注为数据** | **2 条** | §12.1 缓解：把工具/网页返回包裹标注为 data，打破数据-指令混合 → 间接注入 4 条全降级，只剩直接注入 |
| **叠输出侧规则校验** | **1 条** | §12.1 缓解：对仍要触发的指令做执行前词面检查（llama-guard 式）→ 拦 1 条，剩 1 条混淆措辞照旧触发 |

关键读数是那条**永远压不掉的 1 条**：

1. **词面判别器的天花板是 0.67**。探针里的哨兵（挂 02-20 验证器）对 6 条注入召回 4/6=0.67，漏 2 条——一条直接注入用"顺便处理一下系统配置"这种混淆措辞绕过去，一条间接注入用"分享到公链"这类无害措辞装正常内容。**规则召回永远不到 1.00，因为注入者可以无限改写措辞。** 这不是探针的假设，是 §12.1 的结论：**模型分不清数据与指令，只能缓解，不能根治。**
2. **最便宜的一档是"工具结果标注为数据"，不是放个词面过滤器**。数据标注把"这是数据"这条元信息物理地加在工具返回上——间接注入从"伪装成指令的命令"变成"明晃晃写着 data 的内容"，触发率直接清空间接那一整类。这是结构性防护，不依赖内容识别，所以不会被改措辞骗过（只有直接注入——用户真在跟 Agent 说话——仍绕不过）。
3. **输出侧规则校验管的是"真要去执行的那几条"**。它不检查读进来的所有内容，只检查开始执行动作前的那一下——把内容当成指令执行是"执行层的决定"，那就从执行层拦截（§12.9 的"输出护栏→执行护栏"位置）。这也是 06 账 C 教训的镜像：**拦动作比拦内容更靠近事态发生点**。

账 B 的诚实分寸：1 条混淆措辞照旧触发，**说明护栏永远不是 100%，所以要账 D 的审计+回滚来兜底**——"拦得住"不足以保证"不出事"，"兜得住"才是最后的安全网。

## 5. 实验 C · 最小权限账：砍钥匙不砍功能

第二类威胁是"拿得到钥匙"——工具滥用（越权）和权限逃逸。§12.5 的攻击面里"工具滥用（删除/转账）"排在第一位，基线第一条就是**最小权限**。探针让 Agent 的工具循环（挂 06-05：声明工具→选工具→校验入参→执行）收到 10 次工具请求，其中 5 次合法、5 次越权（删库/转账/读他域文件/提权/关服务），两套配置对照：

| 配置 | 越权成功 | 合法任务 |
|---|---|---|
| **全权限 token**（一把最高权限钥匙通吃全部工具） | **5/5**（全放行） | 5/5 |
| **最小权限签名**（每工具只给所需最小 scope） | **0/5** | **5/5** |

三条读数：

1. **全权限 token 下"一次注入 = 一次灾难"**：只要输入被污染（账 B 的漏网混淆注入），最高权限钥匙让 Agent 的任何动作都执行得了——删库、转账、关服务全过。**权限越大，注入的放大倍数越大。** 这正是 §12.1 缓解清单里"最小权限"反复出现的原因：它不挡注入，它让注入即使成功了也没有可执行的动作面。
2. **最小权限签名把越权 5/5 打到 0/5**：删库工具根本没装、转账走了人工确认+限额、身份是只读的、提权无对应 scope。**注意代价账：合法任务 5/5 照跑**——最小权限不是"砍功能"，是"砍钥匙"。该干的活全在（读文件、查天气、回消息），只是不该有的权限一分不给。
3. **参数白名单再补一刀**：合法工具也可能被传危险参数（read_file 传上级目录路径），参数校验（06-05 那把尺）把它拦下 2 次。**权限管"能不能调这个工具"，参数白名单管"同一个工具能不能干超出预期的事"**——两层都是 §12.5 的基线项。

把账 C 和 06 账 B 对上：06 里 B 激进型的 2 起安全事件，就是"少了这把锁"——它快、省 token，但工具正确率 0.83 的那次错误调用撞上了没有最小权限的环境。**安全事件 = 注入（账 B）撞上高权限（账 C），两个条件少一个都闯不了祸；护栏的职责就是让至少一个条件永假。**

## 6. 实验 D · 护栏装配账：六护栏层层扣

前三账是零件的理解，账 D 把它们装成一条流水线，回答"到底上不上生产"。§9.13 六护栏——**最小权限 · 沙箱执行 · 人工确认高风险 · 输入输出过滤 · 审计日志 · 可回滚**——前四道管"拦得住"，后两道管"兜得住"。探针把 §9.13 的 20 个攻击事件（提示注入 5 · 工具滥用 4 · 数据外泄 4 · 供应链 3 · 权限逃逸 4）过三档配置：

| 配置 | 漏网 | 按类型拆解 |
|---|---|---|
| **无护栏** | **20/20** | 全部放进来——不是能力问题，是根本没装门 |
| 最小权限+沙箱 | 12/20 | 供应链 2 · 提示注入 5 · 数据外泄 4 · 权限逃逸 1 |
| **全配·六护栏** | **2/20** | 提示注入 1（混淆注入 #4）· 权限逃逸 1（prompt 覆盖 #20） |

三条读数——**护栏流水线的图层逻辑**：

1. **无护栏 20/20 = 没有纵深，只有"信任"**。这在生产里不是配置选项，是裸奔——任何一次注入成功就是一次灾难（03 账 C 已算过放大倍数）。
2. **最小权限+沙箱把系统侧基本管住（4/20），但注入/外泄还在（9/20）**。这验证了账 A 的坐标系：系统侧威胁被"钥匙+隔离"锁死，但"读进毒、带出毒"这两条输入输出通道还没有过滤，间接注入照样进来、敏感数据照样出去——**一把锁管不住另一类威胁，护栏必须按威胁落点配对安装**。
3. **全配漏 2（但不致命）**：混淆注入 #4 混进了词面过滤器（账 B 的 1 条永远压不掉），prompt 覆盖 #20 是连人工都难发现的元指令攻击。**关键是这 2 条被『审计 20/20 全留痕 + 回滚 2/2 恢复』兜住了 → 残留影响 0。** §12.10 那句"安全不是加一个过滤器"在这里有了数字——过滤器会漏，但**审计让漏掉的可见、回滚让漏掉的可逆**，这才是防护的完整形状。

**上生产判定**（红线沿用 06 账 D 的"安全事件>0 不上生产"）：

| 配置 | 残留影响 | 是否上生产 |
|---|---|---|
| 无护栏 | 20 起 | ❌ |
| 最小权限+沙箱 | 12 起 | ❌ |
| **全配·六护栏** | **0 起** | **✅** |

这也是 §9.14 趋势①"评测+护栏+人工审批进生产"的落地：**06 的评测台保证"它干得对"，本篇的护栏保证"它闯祸也拦得住、兜得住"，人工审批（05 的 3/7 高危拦截 + 账 D 的人工确认）是两条流水线上的共同兜底。** 三块拼图齐了。

## 7. 这篇 Agent 安全怎么用（一页带走 + 掌握度检验）

**一页带走：**

- **威胁五件套**（§9.13）：Prompt Injection（工具内容注入）· 工具滥用（越权）· 数据外泄 · 供应链（恶意 MCP Server）· 权限逃逸。**扎堆"输入+系统"8/10**——Agent 安全在工具链，不在模型（越狱/幻觉归 12 章）。
- **组合拳关系**：威胁 = 注入（读得进毒）撞上高权限（拿得到钥匙）。**两个条件少一个就闯不了祸**，护栏的职责是让至少一个永假。
- **缓解层次**（账 B）：**注入只能缓解不能根治**（§12.1：模型分不清数据与指令）——工具结果标注为数据清空间接注入（结构性、最便宜），输出侧规则校验压制直接注入（拦执行点），但词面召回 0.67、永远剩混淆的 1 条。
- **最小权限 = 砍钥匙不砍功能**（账 C）：越权 5/5→0/5、合法任务 5/5 照跑；参数白名单补拦"工具对但参数危险"。
- **护栏六件套 = 拦得住 + 兜得住**（账 D）：最小权限/沙箱/人工确认/输入输出过滤拦，审计/回滚兜。漏网 20→12→2，**审计 20/20 全留痕、回滚 2/2、残留 0 才上生产**（06 红线）。
- **§9.14 趋势①**：评测（06）+ 护栏（本篇）+ 人工审批 = Agent 系统化三块拼图进生产。

**掌握度检验（自问自答）：**
1. §9.13 五威胁各打在哪一侧？为什么模型侧几乎为零新增？（答案：输入=注入、系统=越权/供应链/逃逸、输出=外泄、治理=日志；模型侧越狱/幻觉归 §12.2-12.4，Agent 安全是工具链安全。）

## 8. 常见坑（Agent 安全的 7 个）

1. **给 Agent 一把最高权限 token**（账 C 的靶子）：全权限下"一次注入=一次灾难"。**修法**：最小权限签名，删库工具不装、转账限额、只读身份——越权 5/5→0/5 合法任务不受损。
2. **以为内容过滤器能根治注入**（账 B 的靶子）：词面召回 0.67、混淆措辞漏网。**修法**：工具结果标注为数据（结构性清空间接注入）+ 输出侧规则校验（拦执行点）+ 接受"永远剩漏网的"，交给审计回滚兜底（§12.1"只能缓解不能根治"）。
3. **只装输入护栏不管输出护栏**（§12.9 位置的坑）：数据外泄走的是输出侧与日志。**修法**：输入护栏→模型→输出护栏→执行护栏四层都装；日志脱敏（账 A 治理侧正是为这个）。
4. **忽略供应链**（§9.13 第五威胁）：随便接了一个 MCP Server，它伪装成计算器实际偷密钥。**修法**：工具准入审核 + 人工确认高风险接入（账 D 的供应链 3 条半配漏 2、全配靠人工确认拦下）——07-11 MCP 的语境。
5. **没有审计日志 = 事后无法复盘**（账 D"兜得住"的坑）：漏网事件不可见，等于没漏网判定。**修法**：全链路审计日志（20/20 全留痕），出事才能追根因（06 账 C 的 FP 放行也要靠日志抓现行）。
6. **忽略可回滚**（兜底闪失）：删库了才发现没有备份/快照。**修法**：危险操作先建快照/走事务再做（账 D 全配残留 0 的关键一步）。
7. **先上生产再补安全**（最贵的坑）：生产环境的 Agent 每次事故都是真实损失。**修法**：§12.10"安全是常态输入不是事后过滤器"——评测台 + 护栏 + 人工审批在生产前齐活（06 账 D 红线）。

## 9. 诚实边界（AAA 自我审查）

- **要素事实 vs 本机实测**：威胁五件套、五侧划分、间接注入机制、"模型分不清数据与指令·只能缓解不能根治"、"最小权限/沙箱（gVisor/Firecracker）/人工确认/参数白名单/审计日志/回滚"等护栏定义、Llama Guard/NeMo Guardrails 等工具名单、§9.14 趋势① = **按知识地图 §9.13/§12 与公开资料整理的要素事实（写作环境无外网，未在线复核）**；不是本机跑真实 Agent 注入攻击的结果。**请在引用时保留"要素事实"前缀**。
- **仿真 vs 真实运行**：账 B 的 12 条内容与词面哨兵、账 C 的 10 次请求与两套权限配置、账 D 的 20 个攻击事件 = **作者按 §9.13/§12 预置的确定性数据表**（`agent_security_demo.py` 内固定常量），不是真实 Agent/真实 Llama Guard 的输出。词面哨兵召回 4/6=0.67 是"这类规则防护会漏"的教学演示数字；真实判别器召回率因模型/语料而异，但"不是 1.00 且会漏混淆措辞"的方向性结论与 §12.1"只能缓解不能根治"一致。
- **统计 = 本机确定性计算**：四账全部计数/密度/档位/覆盖矩阵/残留判定为纯 stdlib 逻辑运算，stdout 三个独立进程 md5 恒一 `8d701839…`，墙钟 ≈0.001 s 仅进 stderr——不依赖任何随机种子、网络或第三方库。
- **边界不自留坑**：本篇没有把"真实 Agent 在生产环境的注入成功率"冒充成本机测量；没有把词面过滤器贬成"完全没用"（数据标注+输出侧校验是公认缓解）；没有把六护栏说成"装了就绝对安全"（账 D 特意演示全配仍漏 2，靠审计回滚兜底——护栏是纵深不是保险柜）。
