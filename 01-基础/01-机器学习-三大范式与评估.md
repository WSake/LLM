## 0. 为什么把"三大范式"和"评估"放在一起讲

先想一个问题：如果有人抛给你一句"我这个模型准确率 95%"，你该怎么回应？

答案是要**连续反问三句**：
1. 你的问题是什么类型——监督、无监督还是强化？（决定你用哪套评估工具）
2. 你的数据是怎么切分训练的？（决定这个数字有没有作弊嫌疑）
3. 你的"95%"是哪个指标、在什么类分布下算的？（决定这个数字有没有意义）

所以"范式"和"评估"必须一起学：**范式决定你在解决什么类型的问题，评估决定你怎么证明自己解决了。** 你接下来在 `02-核心原理` 看到"这个 LLM 在 MMLU 上 92%"、在 `08-RAG体系` 看到"Hit@5 1.0000"、在 `09-Agent体系` 看到"成功率 0.84"时，问的正是这三个问题。

本课的骨架：

```text
三大范式是什么（§1） → 怎么把数据切明白（§2）
                         ↓
             分类怎么评估（§3）· 回归怎么评估（§4）· 无监督怎么评估（§5）
                         ↓
          这套语言怎么迁移到 LLM 评测（§6 → 预告 11-评测目录）
```

## 1. 三大范式：监督 / 无监督 / 强化，差的是"信号"

机器学习只有三种"问法"，差异在**模型拿到的信号**不一样：

| 范式 | 信号是什么 | 经典问题 | 代表算法 | 在 LLM 世界的对应 |
|---|---|---|---|---|
| **监督学习** | 每个样本给一个"标准答案（标签 y）" | 分类（猫/狗）、回归（房价） | 逻辑回归、决策树、神经网络 | **SFT**：训练数据就是"问题的标准回答" |
| **无监督学习** | 只有样本本身，没有标签 | 聚类（用户分群）、降维 | K-Means、PCA、Autoencoder | **预训练**：给语料不给答案，模型自己学结构 |
| **强化学习** | 奖赏信号，随行动 + 环境给出（带延迟） | 下棋、机器人控制 | Q-Learning、PPO、GRPO | **RLHF/RLVR**：按奖励/可验证答案调偏好 |

> 不要被"我怎么知道该用哪一种"吓到。判断口诀只有一句：**数据里"有没有给答案"**——给了，就是监督；没给、你想找结构，就是无监督；等不到固定答案、只能靠"试错+奖赏"，就是强化。

一个容易踩的误区：**"无监督就比监督弱"是错的。** 三者是"信号不同"，不是"地位高低"——今天的语言模型最强部分恰恰是预训练（无监督）学到的。

**范式 → 评估工具的映射**（先记住这张表，后面三节逐个展开）：

| 范式 | 我看什么数字 | 一句话记忆 |
|---|---|---|
| 监督·分类 | 准确率 / 精确率 / 召回率 / F1 / AUC | 类别是否均衡，决定用哪个 |
| 监督·回归 | MSE / MAE / R² | 先看 R²，再看误差量级 |
| 无监督 | 轮廓系数等内部指标 + 业务人验 | 没有标准答案，只能"看起来像" |

## 2. 评估的地基：训练集 / 验证集 / 测试集 与交叉验证

在谈任何指标前，先立下**数据纪律**——它比指标本身更能防止自欺。

### 2.1 三个集，各干各的活

```text
全体数据
 ├─ 训练集 train   ← 模型在这上面学（更新参数）
 ├─ 验证集 val     ← 你不在这上面训练，只拿它"调超参数/选模型"（试了又试）
 └─ 测试集 test    ← 全程不许碰，模型定稿后才测一次，报告的是"真实泛化"
```

三条铁律：

1. **测试集一测到底**：测试集用来给"最终报告"一个干净数字。任何"看了测试结果再回去改模型"的行为，都会把测试集悄悄变成验证集——你报告的 95% 是"背下来的"，不是"学回来的"。
2. **调参只能在验证集**：learning rate、网络宽度、正则强度这些超参数，在验证集上比较取舍。这就是为什么学术实验"test 只能碰一次"。
3. **测试集必须来自同一分布**：用 2023 年数据训练、拿 2026 年数据测试，数字会失真得离谱——领域漂移会让"绝对数字"失去意义。

### 2.2 交叉验证：数据太少时的"反复横跳"

验证集的价值 = 剩余数据够不够。数据不够时，用 **K 折交叉验证** 把训练+验证合并，切 K 份轮流当验证：

```text
第1折 [val][train][train][train][train]
第2折 [train][val][train][train][train]
...
第5折 [train][train][train][train][val]
最终分数 = 5 次的均值（± 标准差）
```

本课实测里你会看到 `5 折交叉验证 ROC-AUC = 0.9257 ± 0.0314`——**均值告诉你"平均好到什么程度"，标准差告诉你"在哪儿不稳定"**。标准差大 = 这个分数对数据切分敏感，别太当真。

> 你会在 `04-训练体系` 的"评测门禁"看到同样的纪律升级版：评测不是事后补拍，而是每一轮训练的闸门。

## 3. 分类指标：准确率会骗你（含实测）

### 3.1 先看一场"漂亮数字"的骗局

构造一个**95% 负类、5% 正类**的分类任务（1000 样本，随机种子固定）——这种极度不平衡，在医院筛查、欺诈检测、离群检测里天天见。跑真实代码（`code/scripts/ml_eval_demo.py` 实验 A）：

```python
# 训练集上：负类 757 个、正类仅 43 个
clf = LogisticRegression(max_iter=2000, random_state=0).fit(Xtr, ytr)
acc = accuracy_score(yte, clf.predict(Xte))
acc_base = accuracy_score(yte, np.zeros_like(yte))   # "无脑全猜负类"
# → clf 的 accuracy = 0.9750，而"全猜负类"也有 0.9450
# → 分类器真正抓到的正类只有 6/11
```

**实测输出（可复现）：**

```text
[分类器] accuracy = 0.9750   [全猜负类] accuracy = 0.9450
正类(少数)实际抓到的样本数: 6 / 11
宏平均 F1 = 0.8464
ROC-AUC  = 0.9288
```

两个教训，一个比一个重：

1. **"97.5%"几乎是免费的**——因为 94.5% 的样本本来就是负类，"全猜负类"就能拿到 94.5%。**在不平衡数据上，accuracy 反映的是"类别分布"，不是"模型本事"。**
2. **真正想抓住的正类（11 个）只抓到 6 个。** 如果你做的是骗贷检测，漏掉的 5 个坏人远比多拦下的好客户贵——单看 accuracy 会把这种灾难包装成优秀。

### 3.2 混淆矩阵与 P / R / F1

把预测 vs 事实画成 2×2 表（实测实验 B 的混淆矩阵）：

```text
             预测负       预测正
实际负      TN 189      FP 0      ← 把负类误报成正（假阳性）
实际正      FN 5        TP 6      ← 把正类漏成负（假阴性）这条最贵
```

由它定义四兄弟（都以"我们关心正类"为视角）：

| 指标 | 含义 | 直觉 | 本实测 |
|---|---|---|---|
| 准确率 accuracy | (TP+TN)/全部 | "整体蒙对比例"，类别均衡才有效 | 0.9750 |
| 精确率 precision | TP/(TP+FP) | "我说正类里，对的比例" | 1.0000 |
| 召回率 recall | TP/(TP+FN) | "真正的正类里，我抓住的比例" | 0.5455 |
| F1 | 2·P·R/(P+R) | P 和 R 的调和平均，谁低拖谁后腿 | 0.7060 |

> 看实测数字，你立刻抓到问题：**precision=1.0（只要我说是正类，就全对——因为我几乎只说负类）、recall=0.5455（漏了一半真货）**。F1 用调和平均把这对矛盾压成一个数：**F1 被更小的 recall 压到 0.706**。这就是"F1 比 accuracy 诚实"的机制。

Q：到底照顾 precision 还是 recall？
A：取决于"漏掉 vs 误伤"哪个更贵。医疗筛查宁误报不漏诊 → 保 recall；垃圾邮件宁漏垃圾不漏删邮件 → 保 precision。没有唯一答案，只有 trade-off。

### 3.3 ROC-AUC：不受"阈值"摆布的排序能力

P/R/F1 都依赖"输出概率 ≥ 某个阈值才判正"。而 **ROC-AUC** 把"模型能不能把正类排到前面"这件事，与阈值彻底解耦。实测实验 B：

```text
5 折交叉验证 ROC-AUC: 0.9257 ± 0.0314
```

直觉：把所有人按"模型给的正类概率"从高到低排队，ROC-AUC ≈ 0.93 表示"随机抽一个正类、一个负类，正类排前头的概率约 93%"——**0.5 是瞎猜，0.93 是排序很能打**。查一下上面的演绎就能看出：单看 accuracy（0.975）和看 AUC（0.9288）结论一致地"模型能打"，但 accuracy 会因类别分布虚高，AUC 不会。

**用指标的口诀**：类别均衡看 accuracy 就行；类别不平衡或"抓少数类"是目标的，看 P/R/F1 + AUC 的组合，别让 accuracy 独自上岗。

## 4. 回归指标：MSE / MAE / R²（含实测）

回归预测连续值（房价、气温、token 数），三类指标（实测实验 C，`load_diabetes` 442 样本内置数据）：

```text
[线性回归]   MSE = 3424.26   MAE = 46.17   R² = 0.3322
[预测均值]   R²  = 0.0000   <- 永远输出训练均值，当"地板"
```

| 指标 | 定义直觉 | 特性 | 本实测 |
|---|---|---|---|
| **MAE** | 平均"差多远"（绝对值） | 量纲可读，对离群不敏感 | 46.17（关注糖尿病情指数，可读） |
| **MSE** | 平均"差多远²" | 放大离群错误惩罚；量纲是平方，别直接读 | 3424.26 |
| **R²** | 相对"预测均值"好了多少 | **-∞到1，1 完美、0 等于均值、负数比均值还差** | 0.3322 |

> 关键规则：**任何回归模型先跟"预测均值"（R²=0）这条地平线比。** R²=0.33 意思是"模型解释了 33% 的方差，比地板强，但离'好'还很远"。曾见报告只写"MSE=3424 很低"，却不说目标的量级——**MSE 的数字大小必须对标目标本身才能读**（预测糖尿病情指数差 46、还是差 3424？），R² 帮你免掉这个翻车。

## 5. 无监督评估：没有"标准答案"的困境（含实测）

监督有标签、回归有目标，无监督呢？聚类结果没有"ground truth"，评估天然两难：

- **内部指标**：只靠数据自身。轮廓系数（silhouette）= 平均"离同类比离最近异类近多少"，取值范围 [-1,1]（1=类内紧类间远）。实测实验 D（乳癌数据 6 维）：

```text
KMeans 轮廓系数: {2: 0.6991, 3: 0.5621, 5: 0.5433}
```

  只看这个数字，"分 2 类最'像一团团'"。但——**轮廓系数回答不了"分 2 类业务上对不对"**。
  
- **业务人验**：把每簇挑出代表样本，让领域专家/你自己看"这一簇是不是一伙人"。这是无监督交付里不可省略的一步。

> LLM 世界里你会反复撞见这个困境："这组 embedding 聚在一起说明什么"——物理学家用相似度、产品经理用分群目标，**"像一坨"不等于"是一类"**。轮廓系数是起点，不是终点。

## 6. 从传统评估到 LLM 评测：这门语言会被你用到最后

你现在掌握的这套"先问范式、再问切分、再问口径"的肌肉，会在 `11-评测与可观测` 目录原样放大三倍。先给你三张地图：

| 传统 ML 概念 | LLM 世界的对应（详见 11 目录） |
|---|---|
| 训练/验证/测试 | benchmark 全生命周期：**用过的 benchmark 会"测穿"（刷爆）**，和"测试集被偷看"同构 |
| accuracy 骗局 | 单一静态 benchmark 的虚高——必须配"判别性对照"（拿故意错的输入验证评测有耳朵） |
| P/R/F1 | 生成任务没有标准答案，指标换成了**忠实度 + 相关性**（`08-RAG体系/07-RAG评测-RAGAS` 的 0.74→0.40 跳水就是"评估能抓住错误"的实证） |
| human eval | LLM-as-a-Judge 同样有偏置——像"类别不平衡"一样，长度偏置会静默污染打分 |
| 数据切开 | 评测集的可观测性（Langfuse 等工具）保证每个分数"能看到来源" |

> 提前看一眼就够：你现在已经不会再把"95%"当免检产品。这已经比 90% 的键盘侠强了。

## 7. 常见坑

| 坑 | 症状 | 修法 |
|---|---|---|
| 拿测试集调参 | 验证集分数一直上不来，测试集"越试越好" | 测试集锁死只跑一次；调参只认验证集/交叉验证 |
| 忽略类别分布 | 不平衡数据报 accuracy 95% | 永远附上混淆矩阵 + P/R/F1/AUC |
| 单一指标判输赢 | 只看 accuracy / 只看 MSE | 同一场对比至少报"1 主指标 + 1 受保护指标" |
| MSE 不看量纲 | "MSE 很小所以很好" | 同报 MAE 或 R²，对标目标量级 |
| 无监督只看内部指标 | 轮廓系数高就说"分对了" | 追加业务人验，用代表样本审簇 |
| 拿测试集反复打分的变体 | "我调的就是这几个超参，没碰测试集" | 每一次看测试集结果都是偷看，无论多小 |
