## 0. 为什么在基础章就谈 GPU

大多数课程把 GPU 放到"部署"才讲，但你会比想象中更早撞到它：

- 读 `02-核心原理/10-KV Cache 与显存账本` 时，要算"一个 7B 模型长上下文的 KV Cache 占多少显存"——**这是显存账本**。
- 跑 `04-训练体系` 的 LoRA/QLoRA 微调时，第一个问题是"我这张 16G 卡能跑 7B 吗？"——**这还是显存账本**。
- 看 `05-推理与部署` 的量化和 Serving 时，核心逻辑是"为什么量化能把速度翻倍"——**这是算力/带宽账本**。

所以 GPU 不是"部署环节的一个东西"，而是**整条学习线上反复出现的成本单位**。早一点学会"算账"，后面每一章你都比别人更清楚自己在干什么。

## 1. CPU vs GPU：一个"胖核" vs 一万个"瘦核"

### 1.1 一台"杂技演员" vs 一支"蚂蚁军团"

```text
CPU（几~十几核）            GPU（几千个核）
┌────────────┐             ┌──────────────────┐
│ 每核：算得快、能玩花活 │             │ 每核：算得慢、只能做简单事 │
│ 适合：分支、排队、协作 │             │ 但一开就是几千个一起上     │
└────────────┘             └──────────────────┘
场景类比：让米其林厨师处理 4000 道菜   让 4000 个学徒每人 1 道
```

- CPU 是单点能力强：指令复杂、分支预测、大缓存，适合"做的事情千变万化"——比如处理你的操作系统。
- GPU 是**数量**打击：每个核都精简（没有复杂调度），但一次能同时跑几千个线程。矩形运算（矩阵乘、卷积）天然是一堆"同样的算术各做各的"——**蚂蚁军团主场**。

### 1.2 一图看懂"为什么矩阵运算吃 GPU"

一次 2048×2048 的矩阵乘法 ≈ **86 亿次乘法 + 86 亿次加法 = 172 亿次浮点运算**（2·N³）。把它拆给：
- CPU：乘 172 亿次，每次都要读内存、判分支，已被算法优化到"每次尽量快"。
- GPU：同一时刻令 2048 个线程各算一行的部分积，一轮并行就吃掉一块。

**本机 CPU 实测**（`gpu_math_demo.py` 第 1 步，纯 CPU 环境）：

```text
2048×2048 fp32 矩阵乘(CPU 实测): 57.21 ms ≈ 300 GFLOP/s
```

一块消费级 GPU 的 fp16 算力约 100 TFLOP/s，约是本机的 **300 倍量级**（脚本按本次实测值动态算出）。这就是"一个朴素矩阵乘，CPU 变成蚂蚁 vs GPU 变成军团"的数差。

> 注意：**300 倍是"算力"的差距；推理的真正瓶颈往往不在"算"，在"读"。** 这是本章最反直觉也最重要的一句话，§4 会证明它。

## 2. CUDA：语言、驱动还是加速器？无卡怎么学

### 2.1 三个词必须分清楚

| 词 | 是什么 | 一句话 |
|---|---|---|
| **GPU** | 硬件（显卡） | 跑矩阵运算的那个芯片 |
| **CUDA** | NVIDIA 家的 **并行计算平台**：驱动 + 编程接口 + 工具链 | "让程序能指挥 NVIDIA GPU"的那套东西 |
| **CUDA 核** | GPU 里最小的计算单元 | 蚂蚁军团里的每一只蚂蚁 |

不是所有 GPU 都支持 CUDA——**只有 NVIDIA**。AMD（ROCm/ROCm）、Apple（Metal）、国产（昇腾/NPU）各有各的栈。对我们学概念的人来说，知道"`torch.cuda.is_available()`"那三行就够了。

### 2.2 无卡怎么学：填空判断题 + 一张"有没有卡"体检单

你完全可以在无 GPU 的机器上学会本课全部概念（作者复现这些数字用的就是 CPU 机器）。可跑的第一条命令：

```python
import torch
print(torch.cuda.is_available(), torch.cuda.device_count())
# True 2   → 有 2 块 NVIDIA 卡
# False 0  → 无卡（本仓库复现环境就是这个情况）
```

> 无卡策略三件套：① 概念与账本直接用本文（CPU 能算）；② 真要训/部署时用 Colab（免费 T4/A100）等云端卡，`nvidia-smi` 看设备；③ 上卡后第一时间重跑 `gpu_math_demo.py`，对比"真卡的矩阵乘时间"，你会对"并行"有体感。
> 有卡验证步骤（品牌通用）：`nvidia-smi` 看显存总量/占用 → `python code/scripts/gpu_math_demo.py` 看第 1 步时间断崖式下降 → 第 0 步打印出卡名。全文数字在真卡上会不同——**这正说明"实测要标环境"**。

## 3. 显存账本：一个模型到底要多少显存

### 3.1 每参数几个字节（先把"权重有多重"变成整数）

| 精度 | 每参数字节 | 7B 模型权重 | 直觉 |
|---|---|---|---|
| FP16（"半精度"，训练常用） | 2 | **≈ 13 GB** | 7B × 2 字节 = 14×10⁹ 字节 ÷ 2³⁰ ≈ 13.0 GB |
| FP8（推理/量化后） | 1 | ≈ 6.5 GB | 字节减半！ |
| INT8（更激进的量化） | 1 | ≈ 6.5 GB | 同上 |
| FP32（"全精度"，老训练） | 4 | ≥ 26 GB | 只做教学对照，现在没人这么推 |

**账本公式（背下来，能用一辈子）：**

```text
模型权重显存 ≈ 参数量 × 每参数字节
7B × FP16 ≈ 7×10⁹ × 2 = 14 GB（十进制）≈ 13.0 GB（二进制，见脚本实测）
```

于是"16G 卡能不能跑 7B"的第一判据立刻清楚：**13GB 权重 + 激活/KV/框架开销，16G 卡很悬；量化到 FP8（6.5GB）就从容了。** 这就是为什么你在 `04-训练体系` 会看到 QLoRA、在 `05-推理与部署` 会看到量化——**先学会算账，工具的选择逻辑就自己冒出来了。**

> 以上全部是"纸面算术"（脚本第 2 步按参数 × 字节计算），不是真卡实测——**账本本来就是算术**，这正是它能复现的价值。额外的激活显存、KV Cache 显存，见 `02-核心原理/10-KV-Cache与显存账本` 与 `05-推理与部署`。

## 4. 算力 vs 带宽：为什么推理卡在"读"而不是"算"（含实测）

### 4.1 一个反直觉的事实

生成每个 token，Transformer 都要**把全部权重读一遍**（权重不随 token 变，是反复读）。以下全是算术账（纸面参数，非本机实测）：

```text
7B 模型，FP16（13.0 GB）：
  显存带宽 800 GB/s（消费级） → 把权重读一遍 ≈ 17.50 ms
  显存带宽 3.35 TB/s（H100） →             ≈  4.18 ms
```

一个 token 就要等这么久的"读"，而"算"这部分在 GPU 上只占零头——**于是推理的墙是带宽墙，不是算力墙**。这也解释了你会在 `05-推理与部署` 看到的两个看似奇怪的现象：

1. **量化把速度几乎线性翻倍**：FP16 → FP8，每 token 读的字节减半 → 读时间减半 → 整句推理提速。为了省显存？顺带的。本位是减带宽。
2. **为什么老有人纠结"稀疏还是稠密"**：稀疏化省的是"算话不多"的算力；对带宽减负远不如量化立竿见影。

### 4.2 用本机实测关闭"好像懂了"

跟随脚本做两个动作（都是 CPU，但机制人生）：

```text
动作 1（真实计时）：2048³ 矩阵乘 → 约 52–58 ms（本机 CPU，300±30 GFLOP/s）
动作 2（算术账）：   7B x FP16 读一遍 → 800GB/s 需 17.5 ms ｜ H100 需 4.18 ms
对照：GPU 上"算"一次 token 的理论时间远小于"读"权重的时间 → 读的时间就是瓶颈。
```

见过一次"读比算慢"的数字，后面看 Serving 优化（KV cache 缓存、Preill/Decode 分治）就不会问"这是不是玄学"了。

## 5. 并行计算的三句话预备

本章不展开（深度在 `04-训练体系/07-训练并行` 与 `05-推理与部署`），但先给你三个词的三句话，让它们第一次出现时不像黑话：

| 词 | 三句话预备 | 好比 |
|---|---|---|
| **数据并行（DP）** | 每张卡各持一份模型，喂不同批量数据，一起算梯度，再汇总一次更新 | 一个厨师团队四人都做同样配方，各接单自己炒 |
| **张量并行（TP）** | 把一个大矩阵切成几块，分给几张卡同时算，合起来 = 一个矩阵 | 一道大菜的食材分给四个厨师同时切 |
| **流水线并行（PP）** | 把模型按层竖切：卡1算第一段 → 结果传给卡2 → 卡2算第二段… | 流水线上每个人只干自己那道工序 |

记忆锚点：**数据并行=横切数据、张量并行=纵切矩阵、流水线=竖切层。** 单卡放不下模型就上 TP/PP，单卡算不动就上 DP——`05-推理与部署` 的"并行"章从此不再劝退。

## 6. 常见坑

| 坑 | 症状 | 修法 |
|---|---|---|
| 只看算力 TFLOPS | "这块卡 TFLOPS 高，就快" | 推理先看**带宽**；训练才主要看算力（还要看显存） |
| 显存"够装权重"就误判够用 | 权重 13GB，16G 卡跑起来 OOM | 再加激活/KV/框架开销，留 20–30% 余量；具体账本见 `02-10` |
| 忽略 CPU↔GPU 拷贝 | 训练很慢但 TFLOPS 很高 | 数据/中间量来回拷贝是隐藏杀手；用"留一张卡算，不让 CPU 拖后腿"的方案 |
| 无卡就以为自己学不了 | 见"GPU"就回避 | 本章（账本+概念）纯 CPU 可学；云端卡补齐训练/部署 |
| 把"纸面参数算账"当"实测" | 报 17.50ms 说"在我们卡上是这数" | 账本数字永远写"按 XX 带宽的算术演示"，实测才写实测 |
