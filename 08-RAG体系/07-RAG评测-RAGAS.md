## 0. 为什么「RAG 不评测等于没做」

RAG 的每个环节都有多个旋钮：分块多大、检索哪一路、融合权重、Reranker 用哪个、上下文塞多少、Prompt 怎么写。**每次调一个旋钮，都可能「感觉更好了」或「感觉没差」——但感觉不作数，只有数字作数。**

评测的三层价值：

1. **回归刹车**：每次改 embedding / rerank / chunk，都跑同一套评测集对比——改坏了，立刻知道改坏了；
2. **定位归因**：答案错了，是检索没找到（检索层指标低）还是找到了但生成没用对（生成层指标低）？指标分层才能指认凶手；
3. **上线闸门**：没有达标数字，不给人用。企业知识库尤其如此——合规要出处，出处要验证。

> 地图 §8.13 的原话值得记死：**RAG 是「检索工程」，唯一的刹车就是评测。**

---

## 1. 三层指标总览：检索 / 生成 / 系统

```
┌─ 系统层   延迟 / 成本 / 端到端质量（LLM-as-judge 总评分）
├─ 生成层   Faithfulness（忠实度）· Answer Relevance（答案相关性）
└─ 检索层   Recall@k · Hit@k · MRR · nDCG（"袋子"问与"排位"问）
```

**哪层出问题，答案就死在哪层**：

| 症状 | 哪层指标掉 | 凶手 |
|---|---|---|
| 答非所问（答案在袋子里但不贴问题） | 生成层 · Answer Relevance | 问题理解 / 生成跑偏 |
| 答案与文档矛盾（睁眼说瞎话） | 生成层 · Faithfulness | 生成没忠于证据 / 噪声块混入 |
| 该有的信息根本没进袋子 | 检索层 · Recall@k / Hit@k | 分块、embedding、查询改写 |

---

## 2. 检索层：Recall@k 与 Hit@k（快速复习）

在 01 章已经讲透（Hit@k / Recall@k / MRR / nDCG），这里只补一句评测语境的话：

- `Hit@k`：gold 上下文在不在 top-k 里 → 测「袋子里有没有」；
- `MRR@k`：gold 排第几 → 测「翻袋子够不够快」；
- **评测集没张力时两者都满分**（009 那类易语料就是 Hit@5=1.0），别误读成"系统无敌"。

## 3. 生成层两个主角：Faithfulness 与 Answer Relevance

这是 RAG 评测区别于"一般 LLM 评测"的核心，也是 RAGAS 的两个看家指标。

### 3.1 Faithfulness（忠实度）：答案是否忠于证据

**定义**：答案里的每个论断，有没有在「喂进去的上下文」里找到支持。不忠于证据 = 幻觉。

```
答案: "张三是 2023 年入职。"          ——论断 1: 张三入职
              论断 2: 入职年份 2023
上下文: 「张三于 2023 年加入公司。」——全部支持          → Faithfulness 高
上下文: 「张三于 2021 年加入公司。」——论断 2 冲突        → Faithfulness 低
上下文: 「李四是运营负责人。」        ——完全没这回事      → Faithfulness 极低
```

**判据三种**：人工抽样看、规则/重叠度量（本章 probe 用 4-gram 证据覆盖率）、LLM-as-judge（RAGAS 默认：让 LLM 先从答案里抽"细粒度论断"，再去上下文里逐条找支持，找不到就是幻觉）。

### 3.2 Answer Relevance（答案相关性）：答案是否贴问题

**定义**：答案和问题在语义上对不贴。不贴 = 答非所问（哪怕句子本身是对的）。

```
问题: "提前还贷要交违约金吗？"
答案A: "提前还贷通常需支付一笔违约金，比例视合同而定。"   → 高
答案B: "贷款分为等额本息与等额本金两种还款方式。"          → 低（事实没错，但答非所问）
```

**实现思路**：计算 `query 向量` 与 `answer 向量` 的相似度（RAGAS 以映射回问题的口径实现，本章 probe 用 bge 余弦直接近似）。

### 3.3 两者的关系（一句话记忆）

> **Faithfulness 管「说对没有」= 忠于证据；Relevance 管「说的对不对题」= 贴着问题。** 好答案两者都要高；只高一个都不行。

## 4. RAGAS：怎么把这两件事儿做成自动化指标

RAGAS（RAG Assessment）是当前最常用的 RAG 评测库，核心价值是**把上面的"判据"用两步 LLM 调用拆成可复现的分数**：

```
Faithfulness = (支持论断数) / (答案总论断数)
  步骤: LLM 把答案切成细粒度"论断"(claims) → LLM 逐条判"上下文支不支持"
Answer Relevance = 答案与问题语义贴近度（LLM 生成"答案对应的虚拟问题"，再与真实问题算相似）
  步骤: LLM 由答案反向生成若干"假问题" → 假问题与真实问题算向量相似 → 取均值
Context Precision / Recall 等：评估"找回来的上下文到底是不是都相关"
```

**为什么值得学它而不是只看聊天框**：RAGAS 把"口径"和"判据"固定下来，一次评测 = 一套可对照的分数，换模型换分块都能横着比。同类工具：DeepEval、TruLens、LangSmith/Langfuse 评测面板。

> 本章探针因为想「零依赖能跑」，用 **4-gram 证据覆盖率**做 Faithfulness proxy、**bge 余弦**做 Relevance proxy——原理与 RAGAS 一致、口径更朴。生产请直接用 RAGAS claims-based 版，一个 `pip install ragas` 的事。

## 5. 实测：一套评测台，两个真数字

本章在 009 语料上（100 问取 20 样本，随机种子固定）实跑了一版 RAGAS 风格三层指标，**抽取式基线（USE_LLM=0，答案 = top-1 上下文）**：

```
=== RAGAS 风格三层指标（009 语料 · 样本 20） ===
检索层  Hit@5  Recall                  : 1.0000
生成层  Faithfulness（4-gram 证据覆盖率）  : 1.0000
生成层  Answer Relevance（bge 余弦）      : 0.7362 ± 0.069

=== 对照：故意给「错来源」答案（应显著下降） ===
Wrong-source Faithfulness                : 0.1667
Wrong-source Answer Relevance            : 0.4018
```

**读这些数字（再次强调别误读）**：

1. **正确性**：正确基线 → Faithfulness=1.0（抽取式答案的 4-gram 全部能在喂入的上下文里找到，天然如此）；
2. **判别性（关键）**：换成错来源答案，两项从 1.00/0.74 掉到 **0.17/0.40**——**这套评测台能抓住坏答案**。评测指标最怕的就是"怎么改都 0.9"，这个对照实验正是校验「指标是不是真的在量东西」的标准动作；
3. **Relevance ≈0.74 而检索全命中**：说明"找得到"和"答得贴"确实是两种能力——这也解释了为什么 009 让你把 `USE_LLM` 打开再跑一遍：换成真生成模型，Faithfulness/Relevance 会真实分化，那才是评测真正上岗的时刻。

复现：009 notebook 第 7-8 节就是这套评测台的原始实现（judge 单元格 + 对比表 + 固定随机种子）。

## 6. 怎么把评测变成工程（不只是脚本）

**评测集**：50–200 条**生产真实问题**（不是论文题凑数），每条标注 `(gold 上下文, gold 答案要点)`。造不齐先 20 条起步，好过没有。

**随机种子固定**：AB 对比时采样一定要 `seed=` 固定，否则两次采样不同，分数差异会被采样噪声污染。

**回归机制**：表里加一行"最近一次满分/基线分数"，每次 PR 动 RAG 组件必须附这行对比。CI 里甚至可以挂"关键指标不得低于基线 X%"的门禁。

**看长尾，不要只看平均**：all green 的平均分可能藏着一类问题全挂。按 query 类型（专名 / 口语 / 多跳）分组看，才是排查的前线。

**多评委校准**：LLM-as-judge 先拿 20 条人工标注做一致性检验（比例 > 0.85 才信 judge），别裸奔上 judge。

## 7. 常见坑（5 条）

1. **只看端到端"答案对不对"，不看分层指标**：坏了不知道坏在检索还是生成——白改了。
2. **评测集没有张力**：全是有唯一答案的事实题，Hit@5 永远 1.0，指标失去判别力（用第 5 节"错来源对照"自检）。
3. **没固定 seed**：两次采样不同 → 分数差异全是噪声，AB 完全失真。
4. **拿 judge 裸奔**：LLM-as-judge 不做人工校准，偏置（长度偏置、位置偏置）直接污染分数。
5. **只跑一次不当回归**：改了 chunk 大小不重跑旧评测——那一次改好可能是把其他环节改坏了。
