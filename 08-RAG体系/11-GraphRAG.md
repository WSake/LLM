## 0. 为什么向量检索看不见"全局"

回看 [02-核心流水线](02-核心流水线.md) 那张两端流水线图：**索引端把文本切成块、编码成稠密向量，查询端把问题编码后做 ANN 近邻检索**。这一整条管的都是「找相似」——给一个问题向量，在向量空间里捡最贴近的 k 个片段。它对"库里有没有这句话"近乎完美，但对另一类问题无能为力：

- **全局问题**："这 100 篇文章整体讲了哪些主题？"——没有一个 query 向量能同时像"机器学习全家桶"、"分布式系统"、"天文"和"工程基建"；
- **实体关系**："知识蒸馏和联邦学习都跟哪些方法沾边？它们之间能不能跨两步挂钩？"——关系是"图中可达"，不是"向量余弦"；
- **跨文档总结**："综合所有文档，大模型相关的技术栈是怎么长的？"——每个片段只讲一小块，没有片段本身是"全局答案"。

[09-Advanced-RAG模式清单](09-Advanced-RAG模式清单.md) 的对照诊断表早就写死了这一条：

| 症状 | 常见归因 | 该去哪 |
|---|---|---|
| 要跨全局总结 / 实体关系（多文档综合） | 语义检索不擅长 | 转 §8.10 Agentic / **§8.11 GraphRAG**（本篇） |

而 [10-Agentic-RAG](10-Agentic-RAG.md) 给我们留了一笔现成的账：**全局问题用向量硬答，只能"多查几次 + 判重聚合"**，且每次查询都只进自己的 top-k「念力窗口」——窗口外的家族根本看不见。本篇要回答的正是：这一笔账，换成图谱的社区表是不是更划算。

> 一句定位：**Agentic RAG 是在"检索这一层外面"加判断；GraphRAG 是在"检索这一层底下"换一种数据站——从向量空间换成图。** 两者不互斥，见 §9 衔接。

## 1. GraphRAG 三步：建图 → 切社区 → 社区摘要与查询

知识地图 §8.11 给的机制很白（此处为要素事实，非本机实测，精确实现以官方为准）：

```text
文档集 ──LLM 抽取──> 实体 + 类型化关系三元组（EntityA --关系--> EntityB）
          │
          ▼
   知识图谱 ──社区发现（Leiden/Louvain）──> 若干"社区"（主题族）
          │
          ├─ 为每个社区生成一段 LLM 摘要（社区摘要 / community summary）
          │
          └─ 查询：全局性问题 → 先定位社区 → 读该社区摘要 + 涉及的关键实体/片段
                   事实性查询 → 仍可回退到向量检索（混合使用，§8.11 明确主张）
```

三个动作各答一个问题：

1. **建图**：LLM 把自由文本变成"实体-关系"三元组，得到有结构的知识库。贵，贵在 LLM 逐篇抽取。
2. **切社区**：在图论意义上把强连通的实体聚成"主题族"（Leiden/Louvain 社区发现）。这一步是 GraphRAG 的招牌——**它让"全局"变成一个可枚举的清单**：哪些主题族、每个族里有什么。
3. **社区摘要 + 查询**：建图时预生成每族摘要，查询端就能在"不搜全文"的前提下先回答"全局讲了啥"；具体事实再下钻。

这一节不展开，因为本仓库的原则是**每一章都带本机实测**——下面把这三步逐一本机落地。

## 2. 把那三步做成本机实测：规则词典 × 文档共现的图

> **诚实声明先行**：生产 GraphRAG 的"建图"是 LLM 抽取类型化关系三元组（`(实体A, 关系, 实体B)`），这在本机不可能零成本复现（模型调用 + 非确定输出 + 无外网）。本篇改用 **LightRAG 式轻量图**：用一份规则词典子串匹配 + "两个概念同现于同一文档"建共现边。它是确定性的、零下载，且**每条边都能回溯到支撑文档** = 断言可溯源。代价是：没有类型化关系、没有实体消歧，召回上限受词典约束——这些留到 §7 诚实边界。

探针复用与 009/010/05/10 完全相同的语料与检索栈（`code/notebooks/_demo_corpus.json` 100 篇中文百科 + `BAAI/bge-small-zh-v1.5` + faiss），数字全部本机实测。跑一遍就得到这张图：

| 读数 | 值 | 含义 |
|---|---|---|
| 文档 / 词典 | 100 / 105 概念 | 规则词典子串匹配 |
| **命中** | **98/100** | **规则抽取召回上限：2 篇主题词没进词典** |
| 概念节点 | 103 | 出现在语料里的词典概念去重 |
| 共现边 | 28 | 两概念同现于一篇文档 → 一条未类型化边 |
| 跨文档概念 | 13 | 在 ≥2 篇出现（图的主干；其余 90 个只出现一次） |
| 建图墙钟 | **≈ 2 ms** | 概念抽取 + 社区检测，见 stderr `[wall] extract` |

两个马上能读出的点：

1. **图很稀疏**：103 个节点只有 28 条边，90 个概念是"一次性的"。这是 100 篇**单主题百科**的典型形态——每篇文章是一个独立小世界，跨文档共享的概念很少。这个形态直接决定了 §6 的代价分界。
2. **规则抽取召回上限 98/100** 是诚实的第一课：词典没收录的主题词，规则图里根本不存在。生产 LLM 抽取的召回会高得多，但也贵得多，且仍会有漏——没有免费的召回。

## 3. 社区划分实测：11 族 + 69 单点，Q=0.806，和一个"桥接错对"

探针用**确定性多级 Louvain**（单轮贪心 + 聚合重划，节点按索引序、严格 ΔQ > 1e-12 才动，模块度用权威公式独立核算）把图切成社区，得到：

```
社区检测：确定性多级 Louvain（单轮贪心 + 聚合重划）· 轮次=2 · 每轮步数=3-2
  轮1 单层贪心达局部峰顶：真实模块度 Q=0.471 · 初划 14 族（单层贪心不保证全局最优）
    「桥接错对」：剪枝 | 图像识别 并无直接共现边（各自只与神经网络共现），单层贪心仍凑为一族 —— 聚合轮把它并回训练簇
  聚合重划后最终分区：11 族，原始图独立核算的权威模块度 Q=0.806
-> 80 个社区（11 多概念主题族 + 69 单点主题·孤点概念）
```

最终 11 个多概念主题族 + 69 个单点主题：

| 族 | 成员概念 | 支撑文档 |
|---|---|---|
| 族[0] | 剪枝 / 卷积 / 图像识别 / 损失函数 / 梯度下降 / 正则化 / 神经网络 / 过拟合 | 3 5 14 17 23 |
| 族[1] | 大模型 / 提示工程 / 知识蒸馏 / 联邦学习 / 联邦蒸馏 | 22 25 34 94 96 97 |
| 族[2] | N-gram / Transformer / 注意力 / 语言模型 | 2 8 9 31 50 |
| 族[3] | 反向传播 / 批归一化 / 深度学习 | 6 19 |
| 族[4] | 5G / 自动驾驶 | 59 60 |
| 族[5] | CRISPR / 基因编辑 | 62 |
| 族[6] | 一致性哈希 / 缓存 | 40 47 |
| 族[7] | 奖励信号 / 强化学习 | 10 |
| 族[8] | 引力波 / 时空 | 0 |
| 族[9] | 梯度消失 / 残差 | 20 |
| 族[10] | 空间站 / 长征火箭 | 86 90 |

三个读数：

1. **社区发现真把"语义世界"切出来了**：训练与剪枝（族0）、LLM 与蒸馏（族1）、语言模型（族2）、基建（族6）各归各位，Q=0.806 的模块度（权重图、权威公式核算）说明社区内部远比族间的连接密。这就是 GraphRAG 的"全局目录"素材。
2. **69/80 社区是单点**：大多数概念只出现一次、没有同伴可选，只能孤独成族。这对 GraphRAG 是刺眼信号——**社区摘要大多只有一句话**（"引力波，出现在 doc[0] 关于引力波的一篇文章里"），建图成本（§6）摊不回来。§8.11 说"中小知识库用不上 GraphRAG"，我们的数字给了它一个具体注脚。
3. **"桥接错对"是社区检测的诚实现场**：单层贪心把**没有直接共现边**的"剪枝 | 图像识别"凑成了一族（二者各自只和神经网络共现，图论上隔了两条边但语义上可连）。聚合重划把它并回训练簇——**社区发现是 NP 级的局部最优问题**，单轮贪心不保证全局最优，生产上要么多轮聚合要么换 Leiden，还要人工抽查族内容（我们的族[0]经人工看是成立的，但它的大小远超"剪枝+卷积+损失函数"直觉，值得抽查）。

> 一句口诀：**看社区表时的态度应该是"半信半疑"——它是建图成本的成果、是全局目录的骨架，但它的正确性要拿测试集去验**（我们 §5 的 B 实验就是这么验的）。

## 4. 实验 A·全局问题：向量念力窗口 2/11 vs 社区表一次全给

实验 A 把"全局问题"做成三镜头，对照向量和图谱。先看 stdout（完整副本见文末 📎 附）：

```
A0 事实查询底数：100 条专属问答 向量 Hit@1=98/100 · Hit@5=100/100
   -> 事实查询场景向量近乎完美；GraphRAG 的用武之地不在这里
A1 全局问题（这个语料库都讲了哪些机器学习、人工智能、科学、工程的主题）
    向量单次 top-10 -> 覆盖主题网络族 2/11 （其余是单点主题/同族重复）
      doc[ 2]  覆盖 = N-gram+Transformer+注意力+语言模型
      doc[ 9]  覆盖 = N-gram+Transformer+注意力+语言模型   ← 同族重复第 2 次
      doc[39]  覆盖 = 单点:数据库索引
      doc[ 7]  覆盖 = 单点:元学习
      doc[45]  覆盖 = 单点:数据库事务
      doc[37]  覆盖 = 单点:向量数据库
      doc[ 4]  覆盖 = 单点:图灵测试
      doc[36]  覆盖 = 单点:检索增强生成
      doc[94]  覆盖 = 大模型+提示工程+知识蒸馏+联邦学习+联邦蒸馏
      doc[55]  覆盖 = 单点:人类基因组
A2 图谱社区表（索引端建图时刻已算好，查询端一次给出）：
    11 个多概念主题族 + 69 个单点主题 = 全库 98/100 篇的主题目录
```

### A0：先立底数——事实查询向量近乎完美

100 条"第 i 条问答答案在第 i 篇上下文"的专属问答：**Hit@1=98/100、Hit@5=100/100**。这一行的作用是当赛道地板：**"某实体是什么"这类事实查询，向量已经近乎完美，图帮不了忙**。GraphRAG 的用武之地从来不在"找答案"，在"找全局"——所以千万不要把 GraphRAG 当成"更强的向量检索"装上又拆。

### A1：全局问题，向量单次检索只看到 2/11 个主题族

用一个真正"全局"的问题（"这个语料库都讲了哪些机器学习、人工智能、科学、工程的主题"）做单次 top-10 检索，结果很有戏剧性：

- **覆盖主题网络族 2/11**；top-10 里 8 个文档是单点主题（数据库索引、元学习、图灵测试、向量数据库……），2 个是族[2]的**同族重复**（doc[2]、doc[9] 都是语言模型族）；
- 11 个族的别的主题——训练与剪枝族、5G/自动驾驶族、CRISPR/基因编辑族……**一个都没进窗口**。

为什么？向量检索是对"问题 vs 片段"算相似度，"都讲了哪些主题"这个问题离任何一个具体片段都不近，top-k 被"泛主题的数据库/概念条目"和"高频单点词"占满。**单次查询的"念力窗口"天生看不见全局**。

把 10-Agentic 的账续过来：要答全这个全局问题，向量路线的唯一办法是**改写成多个子查询（"讲机器学习的主题""讲分布式的主题"…）+ 判重 + 聚合**——每次子查询仍只进各自的 top-k，而"拆几个子问、聚合规则怎么写"正是决策点。GraphRAG 想省掉的正是这一摊。

### A2：社区表一次给全——索引端建图时刻已经算好

图谱侧的回答是 **0 次查询**：`11 个多概念主题族 + 69 个单点主题 = 全库 98/100 篇的主题目录`。社区表在**建图时刻**就沉淀好了，查询端要全局目录时直接读表，不再做检索。

对照表（全局问题）：

| 路线 | 查询次数 | 一次能看到多少全局 | 成本来源 |
|---|---|---|---|
| 向量单次 | 1 | **2/11 主题族**（+一堆单点） | 一次 ANN |
| 向量 + Agentic | N 次改写/判重 | 取决于子问覆盖，仍可能漏族 | N 次检索 + N 次判断（10 章的账） |
| **图谱社区表** | **0** | **11/11 族都在表里** | 建图时刻已付 |

> 这一格的结论不是"向量废了"——见 A0。是 **全局问题适合图谱预聚合，事实问题适合向量直查，混合是 §8.11 的标准用法**。

## 5. 实验 B·实体关联：关系精确 vs 语义近似

实验 B 是"实体关联/多跳"镜头：给 5 个种子概念，让**图**回答它的 1-hop 邻居（每条断言带支撑文档），让**向量**给出 top-5 相关片段里的主题袋，比谁的"相关列举"更靠谱。完整 5 组 stdout 在 §10；这里看聚合行和三组代表：

```
seed=知识蒸馏
   图 1-hop（断言，共现文档={'大模型': [22], '联邦学习': [97], '联邦蒸馏': [97]}）: ['大模型','联邦学习','联邦蒸馏']
   向量 top-5 袋=['大模型','批归一化','提示工程','检索增强生成','深度学习','联邦学习','联邦蒸馏']
         命中期望 ['大模型','联邦学习'] · 图上未断言噪声=['批归一化','提示工程','检索增强生成','深度学习']
seed=一致性哈希
   图 1-hop（断言，共现文档={'缓存': [47]}）: ['缓存']
   向量 top-5 袋=['区块链','大模型','对比学习','数据库索引','缓存'] 命中期望 ['缓存'] · 噪声=['区块链','大模型','对比学习','数据库索引']
...
合计：期望相关 10 个概念，向量 top-5 命中 10/10（recall=100%）· 图外未断言噪声 23 条
B3 2-hop 可达性：种子 知识蒸馏 ->1hop(共现断言)-> 联邦学习 ->再向外-> ['大模型','联邦蒸馏']
```

### B1：相关列举——两边都能答，向量甚至 100%

**B1 先承认向量的强项**：5 组、10 个期望相关概念，向量 top-5 主题袋**全部命中（recall=100%）**。"知识蒸馏和什么相关？"这种单跳列举，向量语义近邻绰绰有余。**不吹不黑**——关系检索的第一档，向量没有输。

### B2：差异在"袋子里装着没证据的候选"

向量袋里塞了很多"图上未断言"的语义近邻：`seed=知识蒸馏`的袋子里有 `批归一化/深度学习`，`seed=一致性哈希`的袋子里有 `区块链/大模型`。合计 **23 条图外未断言噪声**。

差别在哪？

- 向量把 `区块链` 当成"一致性哈希"的近邻，是因为**语义嵌入觉得它近**——但它俩在语料里从没同现过，**没有一条文档能证明这层关系**；
- 图的 1-hop 每条都带 `共现文档={…}`：`缓存:[47]` 明明白白告诉你"断言出自 doc[47]"。**可回溯**就是知识型应用的硬要求——用户追问"你怎么知道它相关"时，向量答不出来，图能翻出篇目。

> 这正是 §8.11"实体关联推理"那行的本机注脚：**向量的近邻是"像"（语义相近），图的关系是"是"（有共现证据）。**

### B3：2-hop 是图上唯一长腿的地方

`知识蒸馏 --共现--> 联邦学习 --再向外--> 大模型、联邦蒸馏`。这层"隔兩跳"的关联，向量没有个运输机制：**余弦相似度是两两之间的数，不传递**——"知识蒸馏≈联邦学习"与"联邦学习≈大模型"推不出"知识蒸馏≈大模型"的关系断言（只能推出"也很像"，但像不等于相关、更不是从 doc97 里消出来的可回溯断言）。图不一样，**2-hop 是图上可计算的可达性**，一次 BFS 就有答案。

对照总结（关系/多跳镜头）：

| 镜头 | 向量 | 图 |
|---|---|---|
| 单跳相关列举（B1） | 10/10 recall=100% ✓ | 自证 100%（带证据） |
| 候选可回溯性（B2） | 袋里 23 条无证据候选 | 每条 1-hop 断言都有支撑文档 |
| 多跳传递（B3） | 余弦不传递"共现断言" | 可达性一次算出 |

## 6. 实验 C·代价账：2 ms vs 1.15 s，贵在 LLM 不在规则

最后是工程决策最关心的：**建这套图值不值**。探针量了两笔本机墙钟（stdout 只说"见 stderr"，精确值在 stderr，因为墙钟跨 run 浮动）：

| | 墙钟（run1） | 内容 |
|---|---|---|
| C1 规则建图 | **≈ 2 ms** | 概念抽取 + 多级 Louvain 社区检测 |
| C2 向量建索引 | **≈ 1.15 s** | 100 篇 encode + build IndexFlatIP |
| total | ~9.7 s | 其中模型加载 ~9 s 占大头，encode 才是语料线性开销 |

### C1 vs C2 的反直觉：规则建图比建向量索引便宜 500×+

规则建图 2 ms vs 向量建索引 1.15 s——**规则图比向量索引便宜了三个量级**。为什么？向量索引要拿一个 300MB 的模型给 100 篇文档编码，规则图只做子串匹配。但注意：**这个"便宜"是偷换来的**——规则图用确定性词典替代了 LLM，召回上限 98/100 且没有类型化关系（§2）。真正的 GraphRAG 账单在别处：

### C3：生产建图的真实账单在 LLM（非本机实测，外推账）

生产 GraphRAG 的建图是每篇文档**多次 LLM 调用**（抽取实体 → 抽取关系 → 清洗消歧），成本 ≈ `单篇 LLM 调用次数 × 文档数 × 单次 token 价`。规范化例子（要素事实，精确价格以官方为准）：假设单篇叫 3 次模型、每次 2k token 输入 + 1k 输出，**100 篇 ≈ 100 × 3 × 3k token**——对你而言是"量级远大于一次编码"的账单，且 LLM 抽取非确定，结果还要校验。

### 值不值分界：先回答两个问题，再装 GraphRAG

探针给的判决线：

1. **有多少"全局/关系"问题？** 全是事实问答（A0 那种），GraphRAG 用不上——A0 的 98/100 已经替你答了"向量够用"。
2. **图密不密？** 本书结构是 `69/80 社区是单点`：跨文档共享的概念太少，**社区摘要大部分是单句**，建图成本摊不平。§8.11 说的"中小知识库用不上 GraphRAG"——单主题小库就是这么个形态。

所以工程决策不是"上不上 GraphRAG"，是**先算账**（对应 [07-RAG评测](07-RAG评测-RAGAS.md) 的"先测张力再上技术"）：

```text
值不值 ≈ 全局/关系问题占比 × 单次救回价值
        − 建图成本（LLM 调用次数 × 文档数 × token 价）
        − 图维护成本（实体漂移后要重抽）
一句话：语料越大、共享实体越密、全局问题越多，图越被需要；反之（本书 69/80 单点就是反面例）先别上。
```

## 7. 诚实边界（AAA 自我审查）

以下为本实验的边界，必须诚实交接（对应仓库"每篇带实测量、不吹不黑"的原则）：

- **"图"是规则共现图，不是生产实体图谱**：无类型化关系、无属性、无实体消歧。生产 GraphRAG 的"实体-关系三元组"抽取 = 非本机实测，本篇只验证了**图检索这一机制层的方向**（社区表 → 全局目录、共现断言 → 可回溯），不替代对 LLM 抽取质量的评测。
- **测试集 = 图上共现关系本身**：B 实验的"期望相关概念"是从同一个词典/同一语料里挑的，所以 B1 的 100% 是"断言自证"，不是"模型对世界建模正确"的独立证据。真实场景的评测要用独立人工标签集。
- **规则抽取召回上限 98/100**：2 篇语料的主题完全不在词典里；生产 LLM 抽取召回更高也不是 100%，别用这篇的 98% 当真实 GraphRAG 的召回。
- **社区检测是局部最优**：桥接错对（剪枝 | 图像识别）就在输出里，多级聚合把它拉回 Q=0.806，但 Q 本身是局部最优值，家庭划分要人工抽查（§5 的 B 实验就是一种抽查姿势）。
- **单语料、小样本**：100 篇单主题百科、11 族；更大的多主题库（跨文档实体更密）图中点数会暴涨，本文全部数字都是这个规模上的。

## 8. 常见坑（5 条）

1. **把 GraphRAG 当"更强的向量检索"**。它是另一层检索原语：全局/关系问题才用它。事实查询上 A0（98/100）向量已经近乎完美，图只会更慢更贵。§8.11 的"混合使用"是默认姿势，不是进阶玩法。
2. **一上来全库建图，不算跨文档密度**。本书 69/80 社区是单点——先数"跨文档共享实体"，密度低（比如 <10% 实体有多篇支撑）就不要上 GraphRAG，那本在烧 LLM 账单造一堆单句摘要。
3. **相信社区的"正确性"**。社区发现是局部最优（我们的桥接错对就是现场），别把社区表当金科玉律——抽查族内容、随访 Q，必要时换 Leiden 或加人工验证集（§5 B 实验那种"断言可回溯"）兜底。
4. **拿 Hit@k 验收全局问题**。全局问题没有一个"正确答案文档"；A1 里向量 top-10 的 Hit@k 打进的全是单点/同族，但**一个主题族都没讲全**。全局问题的指标是"是否覆盖全部主题族"，不是"第几位命中正确片段"——这是 GraphRAG 和向量 RAG 评测口径最该分开的地方。
5. **建完不维护**。实体在文档演进后会漂移：新概念闯入老社区、旧关系失效。图要按版本重建（书上没有的实践，但这是生产图的常态成本，和 04 的元数据治理同量级）。
