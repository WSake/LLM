读完只记住三句：
1. **先单 Agent，再谈别的**：默认起点是单 Agent 服务——能一支主循环跑完的任务，不上多也不挂人工。
2. **高风险的唯一解 = 审批闸**：改生产/处方/放款/签署这类不可逆动作，只能靠人机协同审批兜底，护栏不能替代授权。
3. **多 Agent 是一种选择，不是一种境界**：只有分工有回报才上它（09-08 原文），星型绕路不增质——行业产品最常见的错就是「热闹地上多」。

## 1 为什么"行业方案装进产品"要收口成三形态（§14.7）

14 章 01-05 篇把五行业各自的「方案」讲完了：医疗判形态、金融困在数据、代码最难是流程、法律引用要可溯源、企业知识库成败在数据和权限。但**方案 ≠ 产品**——四栏模板回答的是「这行业能做什么、该收哪段」，而"装进产品"回答的是「一个用户坐进来，什么形态撑着它跑」。

§14.7 的收口方式不是给五行业各画一套新架构，而是抽共性：**行业的差异化在四栏模板（§14.2-14.6 已交付），产品的差异化在三形态的取舍（本文）**。五行业 15 个高频场景探针全数归位（账 A 15/15）：

| 行业 | 单 Agent 服务 | 多 Agent 协作 | 人机协同审批 |
|---|---|---|---|
| 医疗 | 问诊分诊 | 多科室会诊 | 处方开具复核 |
| 金融 | 投顾问答 | 反洗钱多源取证 | 信贷审批放款 |
| 代码 | 仓库问答解释 | 规模重构并行 | 改生产发布 |
| 法律 | 法条检索问答 | 多合同并行审查 | 对外签署/文书中转 |
| 企业 KB | 员工政策自助问答 | 跨部门专长问答 | 涉密越权转人工 |

三点关键观察（账 A2 5/5）：
1. **每行业都是低/中/高三种都占**——形态不是行业属性，是动作属性。
2. **每种形态都覆盖全部五行业 3/3**——没有哪种形态能缺席任何行业。
3. **风险档位天然分流**：几乎每个行业的「低风险高频」都归单 Agent 服务，「强时效多方交叉」归多 Agent 协作，「不可逆高后果」归人机协同审批。

## 2 三形态判据正文（账 B1：三形态×两判据 6/6）

- **单 Agent 服务**：①任务单角色·可原子串行——一台主循环 09-02 从头跑到尾；②低风险·只读或轻动作——能单就不上多，第一个版本永远是它。
- **多 Agent 协作**：①多角色分工有回报——并行/交叉真能提质量或省墙钟，只有分工才有回报（09-08 星型绕路不增质只引）；②有检查点/隔离防错误传导——星型检查点把错误传导从链/网 3/3 降到 1/3（09-08 只引）。
- **人机协同审批**：①高风险不可逆——改生产/处方/放款/签署=人工拍板；②有权者确认门禁——09-05 人工拦高险、09-07 最小权限+人工确认只引。

三条分水岭：**单 Agent 的代价是能力上限，多 Agent 的代价是协调税，审批的代价是人工时延**——选形态就是选代价。

## 3 装配判据：先单、再挂闸、才上多（账 B2 5/5）

装配优先序是一节课不是一道算法：
1. **默认 → 单 Agent 服务**：任务单角色可原子·低风险=一只主循环搞定；
2. **加审批 → 人机协同审批**：出现高风险不可逆动作=只在这一个动作挂人工闸（不是全程人工）；
3. **上多 Agent → 多 Agent 协作**：多角色分工有回报·并行能省墙钟=才值得付协调税（09-08 上下文 10→78 只引）；
4. **不加审批 → 保持单 Agent**：只读低风险动作=不加审批点，免人工等（拦截成本 > 风险时别拦）；
5. **审批+回滚 → 人机协同审批强化**：不可逆影响大=人工确认之外必带回滚预案。

一句话：**形态不是加法是预算**——「自动/复核/强制人工」三档分级（见 §5）就是预算表。

## 4 三形态挂靠：每件产品都从 09 全家拿零件（账 B3 3/3）

- **单 Agent 服务** ← 09-02 主循环（任务驱动）/ 09-03 规划（拆步骤）/ 09-04 行动推理（ReAct 骨架）/ 09-10 浏览器阅读（读屏信息来源）；

## 5 人机协同审批模型（账 C：三档不是两档）

行业 Agent 产品里「审批」不是非黑即白，是**三档分级**（探针 C1 12 动作 3 档 12/12）：

| 档位 | 处置 | 动作 |
|---|---|---|
| 低风险-自动放行 | 直接执行 | 政策问答 / 代码解释 / 法条引用检索（3 个） |
| 中风险-提示复核 | 做之前给人看一眼 | 低风险建议生成 / 跨部门转发文档 / 多文件代码重构（3 个） |
| 高风险-强制人工 | 不出授权绝不执行 | 处方建议开具 / 信贷放款 / 改生产配置 / 合同对外签署 / 涉密文书中转 / 发布推送（6 个） |

高风险的判据不需要模型——帖五个钩子即可：**可逆吗？影响面大吗？授权够吗？出错成本高吗？能留痕吗？** 全否=自动，有「不可逆」或「无权」=强制人工。

审批节奏实测（探针 C2/C3 mock 6/6）：Agent 提案 → 人工批准 4 / 打回 2 → 打回后修订再提 2/2 批准 → 终批准 6/6，**打回率 33.3%**。打回不是失败——高危动作宁可打回不可放行，人工每次打回只是多付 1 轮修订成本；而漏放一个处方/放款的代价是不可逆的。**审批闸的哲学：宁可慢，不可错。**

## 6 行业 Agent 产品红线三件（账 D1 3/3）

| 红线 | 攻击实样 | 护栏 |
|---|---|---|
| 越权自动执行 | 高危动作被设为自动放行（如自动改生产） | 最小权限+审批点强制挂人工 → 拦截 |
| 绕过审批点 | Agent 跳过人工闸直连执行接口 | 审批闸不可绕·未批准动作拒绝执行 → 拦截 |
| 多 Agent 越权通信 | 协作 Agent 间传递无权信息/提权请求 | 隔离+消息标注+监督者审查 → 拦截（09-08 只引） |

三条红线合成一句话：**会做 ≠ 敢做**——把「会做」变「敢做 + 能停」，靠的不是模型守规矩，是架构不给它跳闸的口子。

## 7 评测集四件套（账 D2 4/4）

1. **通用 Agent 评测台**（09-06 固定环境+可验证终结+成本指标）：通用基准——任务成功率/成本三件套，先看「这产品到底能不能干活」；
2. **行业真题场景库**（处方/放款/发布/签署=商业资产）：领域真题——比通用集更有判别力，且随业务更新；
3. **业务专家盲评**（医生/风控/法务/工程师判可用性）：专家盲评——真实岗位用户判「敢不敢用它」，人工评测（11-04 只引）；
4. **越权/绕过审批/越权通信用例**：安全用例——红线拦截回归，门禁核心。

## 8 合规五动作（账 D3 5/5）

1. **最小权限执行**：按角色只给要用的工具；
2. **高风险动作人工审批**：审批点不可绕·高危必挂人工；
3. **审计留痕**：提案/批准/打回/执行全记录（喂 13-07 可观测与 11-09 回合）；
4. **回滚预案**：不可逆动作=监控+回滚按钮；
5. **责任边界**：AI 辅助标注+免责声明·决策权在人。
