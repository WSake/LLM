## 0. 为什么第 2 课是金融？

00 课结束时那张总表里，医疗 10 和金融 9 是"四栏全重"里最接近的两个行业。医疗做完，金融就是最自然的对照实验：**同样是高分行业，却跟医疗走了完全不同的路**。

为什么是金融？三个字概括它的特点（§14.3）：**强时效、强合规、数值敏感**。

- **强时效**：研报/公告/财报是"今天的数据问得准"才算准——你训进权重的知识，下个季度就作废。这直接决定金融**比医疗更不该重训**。
- **强合规**：留痕（调用日志可审计）、不得荐股——咨询类输出是"给信息，不替客户拍板"。
- **数值敏感**：不许编数字——营收 500 亿就是 500 亿，模型"自信地编"在金融是事故。所以数值要走 **RAG+校验+落库**：检索到才回答、检索不到就拒答、回答过的要落库留痕。

所以这一课的题眼和医疗相反：医疗问"最难是不是数据"（是），金融问"我该不该为金融重训"（**几乎不该，五需求里够格 CPT 的 0 个**）。**金融是全球最工程优先的行业——因为它的核心竞争力（实时+准确+留痕）恰恰是训练给不了的。**

**本章的"第二次实战"体现在三件事：**
1. **六价值点 → 七段链（金融版）**：研报问答落在 RAG+合规（增量更新快+引原文出处），财报结构化落在 SFT+校验（数值格式要对齐+数字不许编）。
2. **四栏模板 → 金融账**：总表的"金融 9"展开成 4 行明细（数据 3 · 知识 2 · 流程 2 · 合规 2），并辨明为什么"最难=数据"且金融的合规反而只有 2（可留痕、可事后追）。
3. **红线 → 拦截动作**：金融的红线从"别这么做"变成探针里三个确定性拦截（荐股→转资讯+风险提示 · 编造数值→RAG 未命中即拒答+抛错 · 泄露持仓→脱敏）。

## 3. 账 A · 场景账：六价值点 → 产品形态（§14.3 价值点 = 产品入口）

**一句话：§14.3 给的六个价值点是"需求入口"，真正要答的是"这个入口落在七段演化链哪一段、主资产是哪栏"。**

运行结果：
```
A1 六大价值点→产品形态 6/6： 研报摘要问答→研报/公告摘要+引原文出处 · 财报结构化→财报数值落表格 · 信贷审核辅助→信贷材料审核建议+人工审批 · 投顾助手→资讯整理+风险提示(不荐股) · 反洗钱→交易流水异常监测+规则引擎 · 客服→产品FAQ+账户操作指引

```

**A1 六价值点 → 产品形态 6/6** —— 每个价值点必须先长出"产品形态"，因为形态决定了合规难度：

| 价值点 | 产品形态 | 为什么是这个形态 |
|---|---|---|
| 研报摘要问答 | 研报/公告摘要 + 引原文出处 | 信息有时效、要可追溯——摘要必须挂原文出处（强合规留痕） |
| 财报结构化 | 财报数值落表格 | 数值敏感：格式要对齐（SFT），数字不许编（校验+落库） |
| 信贷审核辅助 | 信贷材料审核建议 + 人工审批 | 输出行为对齐+留痕，人审兜底不替代信贷员决策 |
| 投顾助手 | 资讯整理 + 风险提示（不荐股） | 不得荐股红线：给信息不给买卖建议，守咨询边界 |
| 反洗钱 | 交易流水异常监测 + 规则引擎 | 遍历流水+规则引擎标记可疑，复核升人工 |
| 客服 | 产品FAQ + 账户操作指引 | 解答常规问题，知识库动态更新，边界锁死在业务咨询类 |

**A2 六价值点 → 演化链判段 6/6（先判型再动手）** —— 这是"会画架构"的实操动作：看价值点症状，落到七段链某一格。

- **研报摘要问答 → RAG+合规**：研报/公告增量更新快——知识天天变，训进权重=交割期；RAG 引原文才有出处（强合规）。
- **财报结构化 → SFT+校验**：格式对齐要行为（SFT），数字不许编要校验（RAG 未命中即拒答+落库）——**数值敏感专享组合**。
- **信贷审核辅助 → SFT+合规**：输出行为对齐+强合规留痕，人审兜底不替代信贷员决策。
- **投顾助手 → RAG+合规**：给信息不给建议——情报与建议分层，守"不得荐股"红线。
- **反洗钱 → Agent**：工作流自动化是主战场——遍历流水+规则引擎标记可疑，是 09-02 主循环的业务版。
- **客服 → RAG**：产品 FAQ 动态更新，检索是主场，训进权重=过期。

> 教学点：**"他会六件事"不等于"六个模型"** —— 六价值点共用同一通用底座，靠 RAG+校验+SFT+Agent 按需组合，缺哪块补哪块（详见账 C）。

## 5. 账 C · 选段账：该不该为金融重训（00 课账 C 的金融版）

**一句话：金融≠必须重训——五个典型需求里够格 CPT 的 0 个（比医疗的"只有 1 个"更极端），2 个 SFT 级、3 个工程级。金融是全球最工程优先的行业。**

运行结果：
```
C1 五金融需求→方案组合 5/5： 研报问答→RAG+合规(增量更新快+要引原文出处) · 财报结构化→SFT+校验(格式对齐+数字不许编) · 信贷审核辅助→SFT+合规(行为对齐+留痕) · 投顾助手→RAG+合规(只给信息不给建议) · 客服→RAG(FAQ动态更新)
C2 三档成本级： 纯工程×1 · 领域SFT×10 · 领域CPT×100 —— 能工程先工程，能SFT不CPT
C3 五需求成本档 5/5： 研报问答→工程级×1 · 财报结构化→SFT级×10 · 信贷审核辅助→SFT级×10 · 投顾助手→工程级×1 · 客服→工程级×1
C4 金融跳段纪律： 够格 CPT 的 0 个（强时效=知识天天变训进权重就过期 · 数值敏感=靠校验不靠记忆 → 金融比医疗更工程优先）· 2 个 SFT 级(行为/格式对齐) · 3 个工程级(RAG/合规)
```

**C1 五需求 → 方案组合（附判型依据）：**

| 需求 | 方案 | 判型依据 |
|---|---|---|
| 研报问答 | **RAG + 合规** | 增量更新快+要引原文出处，训进权重=过期 |
| 财报结构化 | **SFT + 校验** | 数值格式对齐要行为（SFT），数字不许编要校验（RAG 未命中即拒答+落库） |
| 信贷审核辅助 | **SFT + 合规** | 行为对齐 + 强合规留痕，人审兜底 |
| 投顾助手 | **RAG + 合规** | 只给信息不给建议——情报与建议分层，守咨询边界 |
| 客服 | **RAG** | 产品 FAQ 动态更新，检索是主场 |

**C2/C3 三档成本 + 成本档**：还是 00 课那张梯子——**纯工程 ×1 · 领域 SFT ×10 · 领域 CPT ×100**。五需求里 **0 个够格 CPT**、2 个 SFT 级（财报结构化/信贷审核辅助——都是"行为/格式对齐"）、3 个工程级（研报问答/投顾/客服——都是 RAG/合规）。

**C4 跳段纪律（金融版·比医疗更极端）**：医疗已经有"五需求只有 1 个够格 CPT"，金融更极端——**一个都没有**。为什么？两个杀手锏：
1. **强时效**：知识天天变——研报、公告、财报、股价，训进权重=交割期作废（RAG 才能"今天的数据问得准"）。
2. **数值敏感**：靠校验不靠记忆——营收/净利/增速这种硬数字，模型"记错了"是事故，必须检索到才答、检索不到就拒答。
所以金融 = 比医疗更工程优先的行业。**先判型、再动手，RAG 给实时先于重训——金融把这条纪律练到了极致。**

## 6. 账 D · 合规账：红线怎么拦、评测怎么做（§14.8 点到 · 金融专属）

**一句话：金融红线的性质 = 三条硬拦截（不得荐股 · 数值不许编 · 隐私不留痕）；评测四件套 = 通用基准/领域真题/专家盲评/安全用例；合规五动作里"留痕"是金融的压舱石。**

运行结果：
```
D1 危险动作→红线拦截 3/3： 荐股给个股价(‘XX 会涨到 20 元，快买’)→不得荐股·拦截转资讯+风险提示 · 编造财务数值(说营收 500 亿而实际 320 亿)→数值敏感不许编·RAG 未命中数值即拒答+统一抛错 · 泄露持仓账户(回复带客户持仓/账户信息)→隐私与留痕·脱敏校验拦截
D2 金融领域评测集四件套 4/4： FinBen 等通用金融评测(通用基准·金融任务集·作者预置例) · 内部研报/财报真题集(领域真题·自家数据=商业资产) · 分析师/合规专家盲评(专家盲评·摘要/建议质量) · 荐股/编数/隐私用例(安全用例·红线拦截回归)
D3 金融合规五动作 5/5： 数据来源合法(授权行情/财报/研报) · 脱敏(账户/持仓/流水隐私) · 留痕(强合规：调用日志+审计追溯) · 模型备案+审计 · 人审+风险评估(投顾/信贷类上线评估)
```

**D1 危险动作 → 红线拦截 3/3** —— 三个拦截动作本身就是"信息+人拍板"这条产品形态的代码化：

| 危险动作 | 红线 | 拦截 |
|---|---|---|
| 荐股给个股价（模型输出"XX 会涨到 20 元，快买"） | 不得荐股 | 拦截转资讯 + 风险提示（给信息，不给买卖建议） |
| 编造财务数值（模型说"营收 500 亿"而实际 320 亿） | 数值敏感不许编 | RAG 未命中数值即拒答 + 统一抛错（数字必须检索到才说） |
| 泄露持仓账户（回复带客户持仓/账户信息） | 隐私与留痕 | 脱敏校验拦截（回吐前先过滤 PII） |

**拦截≠拒绝人**：金融红线是要把"模型自己拍板"变成"模型给信息、人拍板"——而且金融比医疗多一层：**可留痕可事后追**，所以拦截动作不只是"挡"，还要"记"（调用日志可审计 = 强合规）。

**D2 评测四件套 4/4（挂 00 课账 D1 口径）：**
- **FinBen 等通用金融评测** —— 通用基准（金融任务集，测"懂金融不"；作者预置示例）
- **内部研报/财报真题集** —— 领域真题（自家数据=商业资产，测"本机构的报告对不对"）
- **分析师/合规专家盲评** —— 专家盲评（摘要/建议质量尺子）
- **荐股/编数/隐私用例** —— 安全用例（红线拦截的回归测试）

**D3 合规五动作 5/5（挂 00 课账 D2 口径）：** 数据来源合法（授权行情/财报/研报）→ 脱敏（账户/持仓/流水隐私）→ **留痕（强合规：调用日志+审计追溯——金融的压舱石，B2'"可事后追"的抓手）** → 模型备案+审计 → 人审+风险评估（投顾/信贷类上线前评估）。

## 8. 常见坑（金融大模型的 8 个）

1. **把"投顾助手"做成"荐股"**——投顾助手的产品形态是资讯整理+风险提示，不是买卖建议；输出个股价踩红线（D1），且违反"不得荐股"合规。
2. **模型"自信地编数字"**——金融的数值敏感=只有检索到才答；RAG 未命中数值必须拒答+抛错，不能靠模型记忆（D1 第二条拦截）。
3. **把知识调包进权重**——研报/公告/财报天天更新，训进权重=交割期作废；RAG+时间衰减才"今天的数据问得准"（B1 知识栏）。
4. **以为"金融难"= "必须训练"**——五个需求 0 个够格 CPT；财报结构化/信贷审核走 SFT，其余走 RAG/Agent/合规（账 C）。
5. **把金融数据问题看成"数据量"**——真正的难是强时效（追不上）+数值敏感（不许错）+强隐私（共享不了），不是多少 T（B1 数据栏）。
6. **用通用基准当行业验收**——FinBen 等通用金融基准全线高分≠你的投顾条目合规；内部研报/财报真题集才是商业资产（D2）。
7. **留痕做成了"可选项"**——金融留痕是强合规的压舱石（调用日志+审计追溯），不是上线前的装饰（D3·B2'）。
8. **合规五动作只留一条"备案"**——数据来源合法/脱敏/留痕/审计/人审是链条，断一环"事后追"就断了（D3）。
