## 0 直给：代码垂直化一张表

代码领域与医疗/金融完全相反的题眼在第一栏就暴露：**通用模型大多已强于代码**（§14.4 原话）。所以序列长这样：

| 路线段 | 产品形态 | 主资产栏 | 演化链判段 | 这一段的真相 |
|---|---|---|---|---|
| 代码补全 | IDE 内联补全（Cursor/Copilot 形态） | 工具链集成 | 工程（不训练） | 拼 IDE/延迟/上下文，不是再预训练 |
| 代码问答 | RAG over repo 仓库问答 | 领域知识库 | RAG（仓库索引） | 语法感知分块+符号图，09-05 仓库索引只引 |
| 改仓库 Agent | Edit 精确修改 + 测试执行回路 | 业务流程建模 | Agent（工程） | 测试/编译是真值，09-05 测试回路只引 |
| 企业 Coding Copilot | 权限/策略/合规 + CI/CLI 集成 | 合规与责任边界 | Agent+合规 | 收尾=权限/审计/人审（09-07 护栏只引） |

读完只记住三句：
1. **别急着给代码模型再训练**。代码补全到企业 Copilot 四段路线**足足一个 CPT 都没有**——五需求全落在"工程级×1"成本档。
2. **代码是最"验证友好"的领域**。测/编译=真值，Agent 能不能修 bug 一跑便知，这是 §9.11 说的 Agent 最佳落地原因。
3. **危险动作要拦**。越权改生产 / 泄露密钥 / 依赖投毒三类红线，靠最小权限+人工审批+沙箱拦成"审批后落地"。

## 1 为什么"代码=Agent 最佳试验田"（§9.11 只引）

09-05 已实测的结论这里只引不重测：代码任务的**可验证性**（测试/编译器）让自动评测与强化学习燃料都齐了——一个 patch 过了测试就是过，代码 Agent 的"完成"是客观的，这是其它领域没有的奢侈品。

也正因为可验证，代码 Agent 演化出了一个干净取向：**先做"能过测试的函数"，再做"能改仓库的 Agent"**（§9.11 趋势原话）。这解释了四段路线为什么把"代码问答"放第二段——在 Agent 改仓库之前，先让模型+索引完成"仓库不出错地看懂"。

判定：探针 A1/A2/A3 里，四段路线形态与判段 4/4 归位；五技术（仓库索引/Edit/测试回路/LSP 编译反馈/并行多分支）与 §9.11 完全一致（只引，本文不重测）。

## 2 通用模型已强于代码的四栏结论（账 B）

00 篇账 B 锚点：代码总分 **6**（医疗 10/金融 9/法律 8/代码 6），最难资产=流程（4 行业里唯一"难在系统不在资产"的）。

| 四栏 | 评分 | 为什么 |
|---|---|---|
| 领域数据 | 1 | 代码语料公开海量（GitHub 开源），通用模型已强 → 数据不是难点 |
| 领域知识库 | 1 | 仓库"自身知识"靠 RAG over repo 检索，不重训 |
| 业务流程建模 | **3** | 仓库集成=Edit/测试/CI/LSP/IDE/CLI/并行分支——**垂直化真主战场** |

1+1+3+1=6，唯一双 1 行业、唯一"最难=流程"行业。这个不对称正是 §14.4 那句"垂直化重点在工具链与系统"的量化。

## 4 选段账：五需求全工程级（账 C）

代码可能是最罕见的一类：**领域垂直化几乎不走训练**。五个典型需求的全方案组合：

| 需求 | 方案组合 | 为什么走这段 |
|---|---|---|
| 代码补全 | 工程 | 模型已会补全——拼 IDE/延迟/上下文，训进权重不划算 |
| 仓库问答 / Bug 归属 | RAG | 仓库索引+符号图定位（09-05 索引 top-6 只引） |
| 改仓库修 Bug | RAG+Agent | 测试回路看真值，09-05 实测只引 |
| 代码审查 | RAG+Agent+合规 | 安全审查+依赖检查+人工审批（09-07 只引） |
| 企业 Copilot | 工程+Agent+合规 | 权限/策略/审计+CI 集成，落地只管不管训 |

三档成本级只引：纯工程 ×1 · 领域 SFT ×10 · 领域 CPT ×100。判型：C4 显示**够格 CP 的 0 个·够格 SFT 的 0 个**——五需求全落"工程级×1"（探针 C3 5/5 断言恒通过）。这就是代码行业的预算纪律：**省下来的"训练预算"全砸进系统——索引/测试回路/权限模型**。

## 5 企业 Coding Copilot 的三开关（§14.4 收尾段）

四段路线的终点是"企业 Coding Copilot（权限/策略/合规）"。落地时三个开关决定成败：

1. **权限**：Agent 只有当次任务需要的读/写权（最小权限），5/5 场景在 09-07 已属必有护栏；
2. **策略**：哪些代码/分支/生产配置 Agent 可以碰，碰了谁来审批——策略表写在系统里不是模型里；
3. **合规**：每一步改动留审计日志，push/发布这类高风险动作必须人审后才过。

这三点让代码 Agent 从"模型直接落地"变"审批后落地"。红线把结果拦在系统层，这正是 §14.4 与 09-07 的接缝。

## 6 危险动作清单：三条红线（账 D1）

§9.13 威胁模型（工具滥用/数据外泄/供应链）在代码场景最典型的三条：

| 红线 | 攻击实样 | 护栏 |
|---|---|---|
| 越权改生产 | Agent 无权限直接改生产配置/发布 | 最小权限+人工确认 → 拦截升人审 |
| 泄露密钥 | 代码里嵌入 API key/内部地址 | 秘密扫描 → 拦截+轮换（签名扫描规则） |
| 依赖投毒 | 自动装上伪造的恶意依赖包 | 供应链审查 → 锁定版本+来源校验+人工确认 |

这三条每一次命中都该是拦截（拦截率=1 的教科书项）——代码 Agent 的护栏不是锦上添花，是没有护栏上不了生产（09-07 六护栏 20→12→2 全配才上生产，只引）。

## 7 评测集四件套（账 D2）

代码领域评测有天然的"真值优势"（测试过没过），所以组合很干净：

1. **SWE-bench Verified / LiveCodeBench**：通用基准，真实 GitHub issue 2025 事实标准（§9.12 只引）；
2. **企业内部真实仓库题**：领域真题——自家 bug 库是商业资产，比通用集更有判别力；
3. **资深工程师盲评**：专家盲评——代码质量/可读性测试说不出来；
4. **越权/密钥/依赖用例**：安全用例——三条红线拦截回归，02 里警务门禁的核心。

判定：探针 D2 4/4 断言（通用/真题/盲评/安全四类各锚一个）恒通过。

## 8 合规五动作（账 D3）

代码场景落地的五步底线（05/07 篇已铺垫，只引）：

1. **沙箱执行**：无网络+隔离文件系统；
2. **最小权限**：只给当次任务需要的读/改权；
3. **审计日志**：每次改动留痕可追因；
4. **人工审批高风险动作**：push/生产配置/删除；
5. **安全扫描**：密钥/依赖版本/漏洞。
