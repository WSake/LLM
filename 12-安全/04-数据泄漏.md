## 一、四种形态：数据是从哪漏走的（攻击面）

数据泄漏不一定要「攻破」什么。模型不是数据库，它没有「权限」概念——它只回答最可能的下一段文字。任何进了它上下文、或者进了它日志的东西，都可能以某种方式再出来。四种形态对应四条不同的出口：

| # | 形态 | 一句话 | 出口在哪 | 谁的手 | 判别要点 |
|---|---|---|---|---|---|
| 1 | **训练数据记忆背诵** | 模型把训练语料里的敏感段落「原样短句」吐出来 | 生成面 | 模型自身（cm） | 逐字复现训练期文本，不是推理出来 |
| 2 | **RAG 越权** | 多租户共享向量库，检索漏加租户隔离，查到别家数据 | 检索面 | 检索管线 | 命中结果里的文档权属 ≠ 提问者权属 |
| 3 | **Agent 工具输出** | 工具函数把不该给的内容直接返回进对话 | 工具面 | 工具调用 | 返回值未经裁剪直接进入上下文 |
| 4 | **日志记录** | 查询日志把用户原文/密钥原样落盘 | 观测面 | 日志管线 | 明文 PII 进日志文件 |

判别要点都用「**权属/口径**」而不是「能不能答」——最后一条尤其反直觉：日志泄漏不是模型「答」出来的，是系统自己记下来的，但危害完全同级别。12-01 威胁模型的五侧（输入/输出/RAG/工具/供应链）里，形态 2/3/4 分属 RAG 与工具侧、外加观测侧这个「第六侧」。

### 1.1 形态一：训练数据记忆背诵

最硬的一条数据泄漏。训练语料是事实上的「没设权限的默认共享」——语料里的一段原文，预训练后可能以较高概率被条件生成复现。特征：

- **原样性**：复现的是训练期文本的近似直背，而不是一种可推导的结论；
- **短句更容易**：能背出来的多是重复度高、在语料里多次出现的片段（新闻导语、版权文本、地址人名列表）；
- **触发条件**：提示词恰好把「回忆概率」抬过生成阈值，例如直接逼问原文。

这是**待测面最难**的一种：你无法枚举「全部训练语料」，所以也无法穷举它能背出什么。工程上的做法是**抽测而非全测**——把已知敏感语料切片成探针集，定期跑「外才提问」验证泄漏率（对照 11-07 安全评测四尺）。缓解靠最小化 + 事后删除（语料清洗），详见 §2.2。

### 1.2 形态二：RAG 越权（租户隔离失效）

在今天型应用里最高频的一类。多租户共享一套向量库时，「检索命中」这一步如果不带权属过滤，A 租户的查询向量可能命中 B 租户的文档并回灌上下文——**数据自己走进了生成流程里**，模型只是照常回答。特征：

- **根因在检索不在生成**：模型没做错任何事，错的是一次没有 ACL 的向量搜索；
- **越权是「软」的**：不像 SQL 注入那样碰库，而是「检索得到的片段」直接进 prompt，模型对来源没有感知；
- **租户隔离的有效位置**：要么在写入侧（每个租户独立索引/独立命名空间），要么在读取侧（检索过滤条件必须带租户字段）。14-05 企业知识库的实测结论是：**文档级 ACL 必须进检索过滤**，放在回答后校验已经晚了。

### 1.3 形态三：Agent 工具输出敏感数据

Agent 把工具当数据库用（12-09 工具调用）。工具返回值默认「进上下文 = 可被模型引用 = 可被复述」。如果工具封装不检查输出裁剪——比如查询接口返回了整行数据库记录、内部 API 返回了完整账号字段——这些敏感字段就变成了「生成材料」。特征：

- **高危场景**：把查询接口直接当函数暴露给 Agent，返回值未经裁剪；
- **判别**：看「返回值 → 上下文 → 用户可见」这条链上有没有裁剪/白名单层；
- **和越狱的呼应**：12-02 里讲「数据与指令分不开」，到这里再加一层——**数据与权限也分不开**，凡是进了上下文的东西，模型都会当可信背景引用。

### 1.4 形态四：日志记录敏感输入

最容易被忽略，但几乎是 leak 对外的标配出口。排查问题时最容易打的一条日志 `f"user_input={msg}"` 把用户原话原样落盘；更糟的是有人顺手把整个请求体打下来，密钥、身份证、手机号全进日志文件。特征：

- **泄漏的「出口」变了**：不是生成面，而是观测面——日志文件、追踪平台、监控系统；
- **风险等级不降反升**：日志会被复制、被同步进 SIEM、被开发者本地查看——一次落盘等于多个潜在副本；
- **治理原则（13-07 锚点）**：日志里的 PII 必须脱敏后落盘，规则顺序是关键（身份证长规则先跑，否则手机号规则吃掉身份证中间位）。

### 1.5 判分要点：形态识别是「这道防线的第一道闸」

四种形态来源不同、出口不同，处置手段也不同——所以第一步是**判得准**。用一个简单判别器对 5 条预置样例做形态分类，是账 A 的用意：训练记忆 / RAG 越权 / Agent 工具 / 日志四类各归位，外加一条良性样例（群发 PDF 不算泄漏）不应被误判。

## 二、缓解六件：防线怎么排（防御面）

给定形态在攻击面，缓解六件在防御面。它们不是并列的六个 checkbox——每条形态有它「最管用」的那一件，而某些件要配套才成立：

| # | 缓解件 | 主要拦截的形态 | 一句话做法 | 判据（怎么做算到位） |
|---|---|---|---|---|
| 1 | **脱敏** | 日志 / 工具输出 | 敏感串在落库与呈现前替换为掩码 | 账号、ID 逐字 0 残留；规则顺序正确（长规则先跑） |
| 2 | **最小化** | 训练记忆 / 工具输出 | 只保留完成任务必要的最少字段 | 能不带就不带：返回值裁剪到业务所需字段 |
| 3 | **租户隔离** | RAG 越权 | 写入侧分索引 + 读取侧过滤字段，双保险 | 检索命中集的权属 ⊆ 提问者权属 |
| 4 | **输出过滤** | 工具输出 | 模型回答前的最后一道输出侧规则校验 | 敏感字段规则命中即重生成或打码（对齐 12-02 六件） |
| 5 | **日志脱敏** | 日志 | PII 明文不进日志；必要保留走脱敏掩码 | 日志文件整体扫描含 0 条明文 PII |
| 6 | **访问审计** | 全形态兜底 | 谁、何时、查过什么、命中哪些文档，全程留痕 | 告警链与审计可追溯；异常访问能定位到会话 |

**配套关系**几条：
- **脱敏与最小化**是两种策略：最小化是「根本不拿」，脱敏是「拿了也看不清」——能最小化就别只靠脱敏；
- **租户隔离**必须＋**访问审计**：隔离把「该不该」做成硬约束，但隔离失效率永远 >0（配置错、字段漏），审计负责把漏掉的那部分变成「事后可发现」；
- **输出过滤**不能单独成立：它拦得住「明文规则已知的」，拦不住格式无法穷举的部分——所以它和脱敏/最小化是叠加而不是选择（呼应 12-02「任何一件单独都不够」）。

三件做成实在账：**脱敏**（账 B）、**租户隔离**（账 C）、**日志遮盖凝视**（账 D）；剩下三件给判据表（上表第 2/4/6 行）而不做实验——最小化与访问审计是工程配置游戏，不是计算判断题。

## 三、验收用例：租户 A 查不到 B（判别性双臂对照）

12 章教学法的验收标准是「判别性对照」——不是看某个绝对分数，而是看**干预前后信号是否翻转**。这里用越权场景：租户 A 搜索「数据」，**不加 ACL 时命中 4 条、其中 2 条属于 B/C 租户；加 ACL 后只剩 A 自己的 2 条**。这就是「租户 A 查不到 B」的电报信号。再补一个好臂：租户 B 加 ACL 后仍拿到自己的调度数据——隔离不该误伤合法访问。

### 3.1 拦截前（不加 ACL）：泄漏基线

```
[租户 A] 不加 ACL：查『数据』命中 4 条 ['d1', 'd2', 'd3', 'd4']
   其中属于 B/C 租户 2 条 ['d2', 'd4'] → 越权泄漏
```

预置 4 篇文档分属三个租户（A×2 / B×1 / C×1），搜索条件只有 `_QUERY in doc`，没有任何权属约束。命中集 = 全库 4 条 → 其中 2 条明显越权。**这就是「共享索引无隔离」的基线**。

### 3.2 拦截后（加 ACL）：泄漏清零

```
加 ACL 后：A 只见 ['d1', 'd3']，2 条异租户被拦 → 泄漏 0
```

读取侧过滤加一行 `and owner == current_tenant`，命中集被收窄到 `['d1','d3']`，B/C 租户文档全部拦下。**判别信号：越权命中 2→0。**

### 3.3 好臂（租户 B 不误拦）

```
[租户 B 好臂] 加 ACL 后命中 ['d2']（自己的调度数据仍在，不误拦）
```

如果隔离实现是「一刀切只留自己的」，要注意别把合法访问也拦了——B 查询自己的调度数据（`d2`，key=… 那条）依然命中。**好臂信号：0 误拦。**

### 3.4 判定

> **判别性对照：越权泄漏 2→0（干预有效）＋ 好租户 0 误拦（不误伤）。两端信号同时成立，才叫通过。**
> 单看「越权归零」不够——把检索接口锁到谁都查不到也算归零，但那是把合规做成了不可用。验收必须两端一起看。

```

### 4.4 账 D——日志遮盖凝视（对应 §2.5 日志脱敏）

```
[账 D] 日志遮盖凝视：4 条模拟落库日志全部长 token 遮盖为 '***'
   query='zhangsan@qq.com'                    → ***
   user_phone=13812345678                     → ***
   auth=sk-proj-abcdef1234567890              → ***
   doc=110101199003074515                     → ***
   [PASS] 账D 遮盖后 4 条日志原始敏感串 0 残留

日志脱敏的另半条路：**遮盖**——对日志里超过 8 字符的 token 全部以 `***` 遮蔽。账文档说「日志可留」：脱敏保留可读结构（方便排查），遮盖把这层也抹掉（极端最小化），两者适合不同日志级别。断言检查遮盖后原文敏感串 0 残留。

## 衔接：→ 12-05 幻觉缓解（§12.4）

数据泄漏是「**它把我不知道的、不该给的拿出来了**」；幻觉是「**它编了一个根本不存在的东西给我**」。一个对抗「拿错」，一个对抗「编错」——两者在其实共享同一根救命稻草：**引用可溯源**。12-05 会把「幻觉的工程解法」展开成检索增强、引用标注、事实校验加回滚的完整链路。
