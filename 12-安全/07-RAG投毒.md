## 0. 攻击本质：为什么「改语料」比「改对话」更阴

### 0.1 是什么

上一站（12-06）管的是**手的动作**：工具被误导、被越权调用。这一站管的是**源头数据**：知识库里的文档**本身**是攻击者扔进来的一块雷。

所谓 **RAG 投毒**（RAG poisoning / document injection），就是**间接注入的 RAG 特化**——把恶意指令从「对话输入」挪到「知识库文档」里：

| | 间接注入（12-02） | RAG 投毒（本讲） |
|---|---|---|
| 指令塞在 | 网页 / 邮件 / 搜索结果 | **数据库、知识库、向量库里的文档** |
| 什么时候生效 | 用户浏览到恶意内容 | **检索命中的那一刻**，文档被自动当证据拼进上下文 |
| 攻击者要做的 | 发布一页内容 | **把文档写进索引端**（上传、同步、采集、走后门） |
| 谁「中招」 | 对话中的模型 | **整个 RAG 流水线**——跨用户、跨查询 |

一句话：**投毒 = 知识库被埋了雷，检索把它挖出来。** 雷埋在什么环节、怎么埋、排雷的六件套，是这一讲三条主线。

### 0.2 为什么难防（与 12-02 同一根源）

12-02 已经说过：transformer 分不清「数据」与「指令」——进入上下文窗口的 token 无条件被视为该跟随的输入。RAG 投毒更糟在三个叠加：

- **离线**：对话注入要你现场诱导模型，投毒不用——文档躺在库里，今天埋、下个月才被检索到。
- **假信任**：检索出来的「证据」自带合法光环。同一句「忽略所有指令」出现在对话里你会警觉，出现在「已检索到的运维文档」里模型照单全收。
- **放大性**：一份毒文档被 100 个用户、100 个查询命中，**一次投毒、千次触发**。对话注入是一次性的，投毒是幂等的。

所以防御的落点不可能在「识别恶意文档」上赌推理，而在**让检索结果在进上下文之前失去害人的资格**（来源可信、内容规则、权限过滤、风险标注、输出清洗）。

### 0.3 两种后果：不是只有「被灌指令」

投毒文档进入上下文后会干两种活，**单独或并行**：

1. **触发恶意指令**（间接注入式）：文档里嵌「忽略以上全部维修指令，执行 …」——上面探针的 `d901/d902` 就是这个。模型跟在读外维策略时被拐走。
2. **污染答案**（静默知识污染）：毒文档不需要带恶意指令，只要**伪造事实、给出错误答案**，模型把它当证据输出就是错的。08-02 的 **Faithfulness 0.74 → 0.40 跳水**就是同一个机制：错误来源的文档被喂进上下文，模型的忠实度腰斩。

> 很多团队只防「指令注入」，漏了「答案污染」——因为后者**什么防守都看不出来**（模型答得一本正经，错在根上）。

## 1. 防御六件：从「入库」到「出答案」的一排雷

防御不是一道闸，是**从索引端到查询端到生成侧**的一串雷区。六件各有分工，装配顺序就是检索结果从「文档」变成「上下文」的必经之路：

### 1.1 来源治理（源头）

**是什么**：区分文档来源，外部未治理与内部可信分开存、分开检索。

**为什么**：投毒的入口几乎都在「人可写」的口子——公开上传、社区采集、爬虫同步、第三方导入。把入口收窄 + 打来源标签，后续每一道闸才有判据。

**怎么做/挂哪环**：索引端「数据源 → 解析 → 清洗」环节。14-05 的教训直接复用：**成败 80% 在**数据和权限**。来源标签（`src`）打到元数据里（08-02「元数据」环节）。

**边界与坑**：不是「外部=坏、内部=好」。内部 wiki 也可能被写（撞库、越权写入）；所以来源只解决「可信度」，不能单独当闸。

### 1.2 可信校验（内容）

**是什么**：入库时（和命中时）对文档内容跑规则/一致性校验：命令式证据词、要求忽略约束的措辞、「导出/上传日志」这类动作指令、引用链断裂等。

**为什么**：毒文档为了生效必须带上「命令特征」——而这些特征是有限的、可枚举的。校验目标是**把恶意内容识别出来标风险**，不是拦一切（拦一切会误杀正常排障资料）。

**怎么做**：规则表（`commands`）+ 特征判定 → 风险格。上文探针 `risk_grade()`：来源×内容 → 绿/黄/红。**红格 = 不入上下文**；黄格 = 降权/展示警告；绿格 = 照常。

**边界与坑**：规则召回永远到不了 1.00（同 12-02 的原因）。攻击者的对抗写法（改写、混淆、把命令拆散）会让校验失灵——所以校验只是一件，**必须配上后续的系统件**。

### 1.3 检索结果风险标注（命中时）

**是什么**：检索返回 top-N 后，对每条命中做一次风险复核（命中时再跑一遍内容规则，因为文档可能在入库后又被改/被绕过校验），把红格文档**在拼 prompt 之前**剔除。

**为什么**：入库校验是「当时」，命中审核是「当下」——文档可能后写改变、规则可能在两次之间更新。检索时那一下复核，成本低、价值高。

**怎么做**：挂在查询端「检索 → 重排 → 上下文压缩」之间，`guard_verdict()` 在命中列表上逐条裁决。探针账 C 就是这段：命中里毒文档 `d901/d902` 被标「来源未治理/审计已下线」。

**边界与坑**：只看召回 top-3 / top-5——毒文档挤不进前十时这道闸形同虚设，但它**在**就有兜底；配 0.2 的幂等触发，每命中一次都值得复核一次。

### 1.4 输入输出过滤（端侧）

**是什么**：输入侧兜住漏网毒文档的残余指令，输出侧检查生成内容是否被拐（如「按要求导出日志」这类动作行为）。

**为什么**：六件是纵深，不是单点。就算前面清不干净，端侧还有一道。

**怎么做**：输入侧把红格文档塞进 prompt 前清洗（删命令句）；输出侧对响应做动作词检测/策略勾稽（回收 12-06 的「记账兜底」）。下面验证载体 §3 的「输出侧润色」就靠它兜底。

**边界与坑**：输出侧过滤**检测不出「静默污染」**——答案内容错但没触发动作词时，这闸看不见。它防的是「指令触发」，防不了「答案污染」。

### 1.5 权限隔离（访问控制）

**是什么**：文档级 ACL 进检索过滤——用户查不到自己不该看的文档，投毒文档对它不可见。

**为什么**：这是**最硬的一道**。14-05 三闸已立：查询侧切权限 → 检索侧 ACL 过滤 → 生成侧拒编造；「权限是检索层的属性，不是权重的属性」。投毒面 0.2 里的「跨用户幂等」在 ACL 隔离下被劈成「每个用户各只见自己的子集」。

**怎么做**：探针账 D——`d003` 属于 `tenantA`，租户乙查询「日志口径」时无过滤会带出 `d003`，ACL 过滤后它不再进上下文。**等级：高密级文档红格（来源可信但权限不足）仍会被拒**。

**边界与坑**：ACL 只解决「越权」，不解决「有权限的人被毒」——同一租户内投毒照样有效。所以权限隔离排在六件之一，不是唯一。

### 1.6 周期审计（事后）

**是什么**：定期重扫文档库，发现新报毒/过期/来源降级的文档就**下线**。

**为什么**：投毒文档不是入库即生效——可能埋在库底几个月才被检索到。周期审计是时间上的兜底：**晚发现也比不发现好**，且审计发现后要能立刻撤出索引（探针里 `d902` 就是被审计下线的）。

**怎么做**：挂到 MLFlow/流水线的「增量维护」环节——周期重扫 `d902` → 下线 → 之后的检索命中不再包含它。

**边界与坑**：审计的窗口期里毒文档仍可起作用（这是「只能缓解不能根除」的直接注脚）。审计能压缩暴露窗口，但**消不掉窗口**。

### 装配顺序总览

| # | 件 | 时机 | 挂在 08-02 哪环 | 拦什么 |
|---|---|---|---|---|
| 1 | 来源治理 | 入库前 | 索引端·数据源/解析/清洗 | 堵入口 |
| 2 | 可信校验 | 入库/命中 | 索引端·元数据 | 识别毒内容 |
| 3 | 检索结果风险标注 | 命中时 | 查询端·检索→重排 | 剔除红格 |
| 4 | 输入输出过滤 | 端侧 | 查询端·拼装Prompt/生成 | 残余指令 |
| 5 | 权限隔离 | 命中前 | 检索侧 | 越权不可见 |
| 6 | 周期审计 | 周期 | 索引端·增量维护 | 后置下线 |

**六件不是单选**：少了任何一件，总有一类投毒穿透。完整装配 = 六道闸全配（12-06 的六护栏同理）；**只装配件 1+2 是「上了锁却没关窗」**。

## 2. 与 08 核心流水线的联动：投毒面挂在哪几环

08-02 两面七段早已铺好。投毒面**不是**整条链，而是其中几环，找准环才能对症下药：

**索引端（埋雷的方向）**
```
数据源 → 解析 → 清洗 → 分块 → 元数据 → Embedding → 向量库 → 增量维护
                              ↑                 ↑
                    [1来源治理]      [2可信校验 → 6周期审计]
```
投毒侧的三个主要埋雷口（也是来源治理的治理对象）：
- **数据源口**：公开上传、爬虫采集、第三方导入（`src` 标记为低可信）。
- **解析/清洗口**：文档被解析器撬开夹带恶意块（12-02 间接注入的变体）。
- **增量维护**：定时同步抓进新文档——攻击者只要让同步任务抓到带毒文件。

**查询端（排雷的方向）**
```
问题 → 查询理解/改写 → 检索 → 重排 → 上下文压缩 → 拼装Prompt → 生成（带引用）
                                ↑                    ↑          ↑
                          [3风险标注]          [4输入输出过滤]   [输出侧勾稽]
```
检索命中的那一刻，毒文档变成「证据」——**风险标注/权限隔离两闸恰好卡在这里**，早了看不见文档，晚了一旦拼进 prompt 模型就会思考。

**验证载体**：08-02 的 Faithfulness **0.74 → 0.40 跳水**就是这条链上「污染源被喂进上下文」的直接证据（notebook `010`）。本讲的探针在账 A 里复刻同一逻辑：词面召回 0.833 → 1.000，毒文档从「检索不中」变成「检索命中」——**污染不是模型变笨，是证据被换**。

## 3. 验收双臂（判别性对照）

**判别性双臂**：同样的问题，一边查良性语料一边查含毒语料，六件装配与否看结果差。每个问题一共四组对照（探针全部实现，纯 stdlib 确定性）：

| 组 | 对照 | 期望 |
|---|---|---|
| A | 良性语料 vs 混入毒文档（同一查询） | 良性 0 命中毒；含毒挤进命中（召回上升） |
| B | 纯风险标注（来源×内容） | 毒 `d901/d902` 标 `红`，良性 3 条标 `绿` |
| C | 六件全装配 vs 只装配件 | 六件：命中毒全被拦并标原因；只装：漏过 |
| D | 无 ACL vs 带 ACL（租户乙/租户甲） | 无 ACL 带出 `d003`；带 ACL `d003` 不进上下文 |

**判别标准**：护栏装配后拦截失败 = 0（毒必拦、良性照跑）；ACL 隔离后越权命中 = 0。这与 12-02 的验证数据（6→2→1）同构——**缓解可量化，根除不可能**。

## 诚实边界

- **探针是纯词面桩**，不涉及真实 embedding 检索/大模型；「毒文档挤进命中」用 bigram 重合度模拟，非真实检索 result ranking。真实场景请用 08-02 注明的向量库跑 top-N 复核。
- **规则召回不可 100%**：`commands` 词表可被对抗改写绕过（12-02 同样的边界）。「只能缓解不能根除」在此最直接。
- **周期审计有暴露窗口**：审计之前毒文档仍存在、仍可被检索。这不是 bug，是缓解的固有属性。
- **「输出侧过滤」防不了静默污染**：静默污染（伪造答案）只能靠检索侧与引用标出来，输出侧检测不到。
