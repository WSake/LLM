## 0. 为什么 06 章第六课是记忆系统？

06 章的能力谱系走到 05，已经把一台助手推到「一次会话内能干成事」：模型替你把参数对齐（04→05），工具替你把动作做掉（05 回喂循环）。但隔一天再来，这台助手**什么都不记得**——你在 05 里加的日程、偏好的咖啡、说过住址，随上一次会话的上下文一起烟消云散。§17.7.4 一句话点破：**短期上下文 + 长期存储 = 让 Agent 有连续性**。没有记忆的 Agent 不是新用户，是**失忆的用户**。

为什么单独一课？因为「记忆」不是把历史聊天记录攒着，而是三笔独立的纪律：

1. **写入分工**：对话原文是流水账，该沉淀成「实体-插槽-值」（谁/什么属性/什么值），且要分两层——**画像**（该记住的不变属性）与**账本**（用完即弃但可回查的事务史）。
2. **整合自洽**：同一实体跨多次会话出现，同一槽位新值要覆盖旧值（最新值语义），别名（张先生 vs 张三）要归一——不然档案自相矛盾。
3. **读取要剂量、遗忘要预算**：记忆是攒不完的，上下文窗口是硬约束（§9.5 原话）；每次回灌该带多少（检索），预算不够时该留谁（衰减/遗忘）。

§6.10/§9.5/§17.7.4 三个外部坐标：**与 RAG 同源**（都是"检索-注入"，但 RAG=外部知识、Memory=自身历史）；**MemGPT（2023）**把"何时换页进上下文"做成操作系统式内存分层；**LangGraph checkpoint** 把记忆固化进 Agent 状态。这三条都是「要素事实，非本机实测」。

> 🧩 一句话立于全章之先：**05 解决「一次会话内动作能不能做完」，本篇解决「动作与对话能不能跨会话留存」——同一个助手，从『会话内的状态』升级到『跨会话的连续性』，是 06 章应用主线把能力谱系补齐的收束站。**

## 1. 先把问题拆开：从「回喂循环」到「跨会话留存」

05 的闭环长这样（§17.5.4）：声明工具 → 模型给参 → 执行 → 结果回喂 → 再循环，收在「任务完成」。它的时间边界是**一次会话**：上下文窗口把 05 的工具入参（`add_event(title=团队例会, start=2026-09-28 10:00)`）和结果（`→ OK`）装进去，会话一关，全没了。

记忆系统把它拉长到**跨会话**：

```
05 的循环（一次会话内）：思考 → 调工具 → 看结果 → 再思考 → 完成 —— 状态只在窗口里
本篇的延续（跨会话）：  同一会话 → 把「入参 + 结果 + 用户陈述」抽取成实体-插槽-值 → 落库（画像/账本）
                       新会话    → 按需检索相关记忆 → 回灌进上下文 → 用"记得你"的姿势继续干活
线：会话内的状态（05） → 会话外的状态（本篇）= Memory Manager 的存取时机（§6.10 原话）
```

四个可度量的工程问题（与 05 四账同构，本篇逐一定实验）：

| 问题 | 你在决定什么 | 对应实验 | 可度量指标 |
|---|---|---|---|
| Q1 写入记什么 | 哪些会话内容落库、落成什么结构 | A | 结构化条数、画像/账本分账、token 账 |
| Q2 整合怎么不打架 | 同实体跨会话更新、别名归一 | B | 覆盖/去重/别名计数、naive vs upsert |
| Q3 读取带多少 | 全表回灌 vs 按需 top-k | C | 命中率、回灌里程（token）、纯度 |
| Q4 遗忘忘什么 | 预算不足时留谁、丢弃谁 | D | 保留后可答率、策略对比、遗忘曲线 |

探针的业务题取 §17.7.4 的「实践」原话：**给客服 Agent 加长期画像记忆**——同一个用户"张三"跨 11 次会话（3 次画像会话 + 8 次事务会话），把「他说过什么 + 工具做过什么」沉淀成可跨会话回灌的记忆表。于是每个数字都是确定性的、随时可复现。

## 2. 把「记忆系统」降维成本机测量（探针设计）

探针 `memory_demo.py` 照 05 模式：零网络、零下载、不训练模型、纯 stdlib 确定性计算。三项工程声明立规矩：

1. **双库分层**（直接映射 §9.5 的分层）：
   - **画像层 profile**：每一槽=该实体的属性最新值，`upsert` 即写即覆盖（同槽第二个值会顶掉第一个）——`{张三: {姓名, 职业, 偏好, 生日, 居住地}}`。
   - **账本层 ledger**：工具入参/结果逐条追加（append），带会话戳 `s<n>`——`{张三: {城市: 北京·s1, 天气: 晴…·s1, 事件: 团队例会·s2, …}}`。
2. **抽取规则**=词面/结构正则（作者预置）：`我是X→姓名`、`住在X→居住地`、`我是一名X→职业`、`更喜欢X→偏好`、`生日是…→生日`、工具条 `city=X→城市`、`→结果→天气`、`title=X→事件`；`张先生/老张→张三` 别名表解决「同人不同称呼」。
3. **检索两档打分**：`纯词面`=查询与记忆条目的汉字双字组（bigram）共现；`对齐语义`=再叠加一张「词面→槽位」语义对照表（`住哪/哪里→居住地`、`喜欢/咖啡→偏好`、`几点/开始→事件`、`出差/城市→城市`…，模拟 embedding 检索在词面共现之外补上的「字段语义」那一截）——作者预置，只量确定性上限，不是真语义模型。

四账与三个问题一一对应：**A 写入账 · B 整合账 · C 检索账 · D 衰减与预算账（+ 选择树 8 场景）**。

## 3. 实验 A · 记忆写入账（会话 → 实体-插槽-值）

11 次会话、41 条 user+tool 条（原文共 **419 tok**），全走一遍抽取规则再整合入表：

```
[实验 A] 记忆写入账 —— 会话/工具结果 → 结构化记忆（实体-插槽-值 · 画像+账本两层）
  语料：11 次会话 41 条 user+tool 条（原文共 419 tok）→ 抽取事实 43 条 → 整合入表 34 条
  画像层（用户画像·每一槽=该实体属性最新值）：张三 5 槽 —— 偏好=喝美式咖啡 · 姓名=张三 · 居住地=上海 · 生日=1990年5月20日 · 职业=软件工程师
  账本层（事务/工具结果·逐条追加带 s 会话戳）：29 条 —— 城市 10 · 天气 10 · 事件 9
  → 结构化后 354 tok vs 原文 419 tok（=84%）：去虚词、只留实体-槽-值骨架，顺带压了 65 tok——但记忆的价值不在省字，在『下次不用重读原文』
```

**教学落点：**
- **写入的第一纪律是「分账」**：同一份会话流出两个库——画像层存「你是谁」（每槽一个最新值，upsert 语义），账本层存「你干过什么」（工具入参/结果逐条 append）。§9.5 的原话是工作记忆（对话上下文+工具结果）与长期记忆（结构化/用户画像/程序性）——我们的 profile/ledger 就是「长期结构化」与「工作记忆落库」的最小实现。
- **抽取在丢信息上是故意的**：对话里的「帮我记得：我更喜欢喝美式咖啡」被抽成 `偏好=喝美式咖啡`——语气、请求、虚词全丢，只留可复核的实体-槽-值。结构化的代价是语义损失（冷冰冰的事实骨架），收益是 34 条 vs 41 条原文、每一条都可被新会话精确检索到（C 接上）。
- **有压缩，但别把它当卖点**：354 vs 419（=84%，顺带省 65 tok）只是「去虚词留骨架」的记账稿；记忆的账不该算「省了几个字」，而该算「下次会话不用重读 419 tok 原文、只带相关窗口」（C 的 45% 才是真实杠杆）。**记忆=把一次性会话折旧成跨会话可复用的资产，不是免 token 压缩包。**

## 4. 实验 B · 记忆整合账（同槽覆盖 · 别名归一）

同一实体跨会话，第二笔纪律是整合——先看探针台账：

```
[实验 B] 记忆整合账 —— 同实体跨会话：同槽覆盖(最新值) · 别名归一 · 不去重自行矛盾
  整合台账：新增 34 条 · 覆盖更新 1 次 · 去重 8 条 · 别名解析 1 处（张先生→张三）
  覆盖：居住地 北京(s1)→上海(s3) 同槽覆盖 1 次=1 条最新值；生日/职业 等 4 槽新增
  naive 不去重（append）：画像 6 条 60 tok（含两条『居住地 北京/上海』=档案自相矛盾）
  upsert 整合后：画像 5 条 51 tok · 同槽唯一=语义最新值 → 省 9 tok（15%）且不再自相矛盾
```

**教学落点：**
- **upsert 的价值不在省 token（9 tok 只是零头），在「查询永远取最新」**：张三搬家了（北京→上海），过一周你问"张三住哪"，naive 的两条 `居住地` 会同时命中——到底答北京还是上海？没有整合端的记忆不只多占 9 tok，还给下游留了个**语义地雷**（挂靠 08-13 D「版本戳陈旧」：内容本身看不出新旧的坑在记忆库里等价）。
- **别名在写入侧归一，一次解决所有查询**：`张先生→张三` 在抽取时落到规范实体，此后任何查询按"张三"命中（C 的 q3「张先生的生日」、q5「团队例会」都因此直中）——这跟 08-13 C 的"搜索侧别名扩展"是同一想法的两种落地：**写侧归一省事，读侧归一费事**（各有一个更优场景）。本探针走写侧归一。
- **去重 8 条**：同一会话用户说"把产品评审加到日程"+ 工具回执 `add_event(title=产品评审)` 会各出一条事件——`(slot,val,ts)` 三重相等视为同一条，防止同一次动作在账本里记两遍。

## 5. 实验 C · 记忆检索账（按需回灌的剂量）

记忆写好了，新会话来了。第三笔纪律是读——**回灌多少**。六个问题的金标准（作者预置）对着 34 条记忆跑两档打分：

```
[实验 C] 记忆检索账 —— 记忆回灌：全量 vs 相关检索（写得好是画像，读得好是剂量）
  6 问：q1 张三现在住哪里？· q2 职业 · q3 张先生生日 · q4 喜欢喝什么 · q5 团队例会几点 · q6 出差过的城市
  纯词面 top3 命中 4/6（2 条被『张三』实体名冗余摊平=画像里同名反复出现→词面拉不开）
  对齐语义（ALIGN 表=模拟 embedding 越过词面的一截）top3 命中 6/6 · 6 问合计回灌 tok 195 vs 全量 354（省 45%）
```

**教学落点：**
- **实体名冗余是词面检索的天然坑**：6 条画像里 5 条都带"张三"，q1「住哪里」按词面共现拉不开（金条目 rank32）、q4「喜欢喝什么」同样被摊平——**只有越过词面去认「字段语义」（居住地/偏好）才能命中**。这正是真实系统要用 embedding 向量记忆的原因（§9.5：向量记忆=语义检索）。本探针用 ALIGN 表量出"语义那一截补上后 4/6→6/6"的确定性上限，真正的 embedding 线上表现=非本机实测。
- **全量回灌是隐性浪费**：每问都把 34 条 354 tok 全塞进上下文=纯度低、带宽贵；**top-3 相关回灌命中不掉（6/6）、6 问只花 195 tok（省 45%）**。读的纪律=剂量——挂靠 03-C 的 top-k 覆盖曲线（拐点处零损失省 34.9%）与 08-13 B 的 k=5/10/20 成本线：**记忆检索和 RAG 检索共享同一本「按需注入」账**，因为它与 RAG 本来就同源（§6.10/§9.5：都是检索-注入）。
- **这 195 tok 是「只够答好这 6 问」的窗口**：跳到 D 你会发现，真正的无预算问题不是"每次带多少"，而是"记忆越攒越多、窗口永远只有那么大"。

## 6. 实验 D · 衰减与预算账（遗忘是预算不是 bug）

会话无限、记忆无限；上下文窗口有限（§9.5：上下文窗口是硬约束）。第四笔纪律是忘——预算内留谁：

```
[实验 D] 衰减与预算账 —— 会话无限 · 回灌窗口有限：谁留下、谁遗忘
  全量回灌：34 条 354 tok（超预算 135）→ 6 问可答 6/6（但窗口装不下）
  预算 219 tok：
  策略1 最近优先：保留 21 条 218 tok · 可答 1/6 · 丢的是最早的画像（职业·偏好→『不记得你的职业』）
  策略2 画像优先：保留 21 条 217 tok · 可答 5/6 · 保住画像全 5 槽，丢的是老账本（团队例会s2）
  策略3 画像+摘要：保留 8 条 95 tok · 可答 5/6 · 账本折叠成『共N条·最近一条』=最省
  遗忘曲线（最近优先保留 K 条 → 可答数）：K=4·8·12·16·20·24·28·34 → 1·1·1·1·1·1·3·6
```

**教学落点：**
- **最近优先≈灾难性遗忘**：按时间戳倒序保留，最先丢掉的恰恰是最早建立、但最该记住的**画像**（职业 s1、偏好 s2）——1/6 可答，只剩近年的事务（q6 城市）。**"哪个信息新"!=“哪个信息重要"**：画像级事实没有保质期，事务级才有。
- **画像优先/摘要策略在预算内保住 5/6**：画像 5 槽全程在窗内（职业/偏好/生日都答得上），只把老账本（团队例会 s2）交给遗忘——**6 问 5/6 只需 95-217 tok**，对比全量 354 tok 才能拿 6/6。遗忘不是 bug，是**预算管理的取舍**：全量什么都答但窗口超限；聪明的取舍把覆盖保住、把账本折旧掉。
- **遗忘曲线**：最近优先保留 K 条，前段是 1 的平坦平台——**直到保留接近全量，画像槽（ts1-3）才回得来**；曲线说明按时间优先的剪枝对画像型任务几乎无效，必须按"类型/重要性"优先（这正是 Memory Manager 该做的决策，§6.10：存取时机由它定）。摘要折叠（08-06 剪刀的账本版）是最省的形态：8 条 95 tok，账本一行一条"共 N 条·最近"。
- 挂靠：遗忘策略决定论与 02-17 系统层的 KV 淘汰（uniform 最痛 vs argmax 一致性）同构——**"留谁忘谁"是记忆系统与缓存系统共同的预算题**。

**选择树（8 场景，规则：会话内即时→不落库；跨会话复用→长期记忆；外部知识→RAG；工具结果即时→05 回喂；工具结果跨会话→账本落库；用户长期偏好/属性→画像；超长历史→摘要折叠；敏感信息→不入库/脱敏）**：断言 8/8。

## 7. 常见坑（5 条）

1. **会话一关全忘**：05 的回喂循环只在会话内有效，重开会话问"我上次几点开会"答不上——把工具入参/结果落账本（A 账本层），把用户偏好落画像（A 画像层），C/D 按需取用。没落库=每次会话都从"你是谁"重新学起。
2. **只写不整合**：想起来了就 append 一条，导致同槽多条互相打架（B：naive 6 条含两条 `居住地` 北京/上海，查询不知道该答哪个）。用 upsert 同槽最新值 + 别名归一，把"档案自相矛盾"消灭在写入端。
3. **全量回灌当记忆**：以为"把全部历史倒进上下文=记忆充分"，结果是每问带全表（C：354 tok vs top-3 回灌 195 tok，命中还更好）——**记忆的读取是检索-注入，不是全文搬运**（§6.10 与 RAG 同源的同一句）。
4. **把遗忘当 bug 修**：记忆无限攒、窗口有限，不裁=超预算运行（D：全量 354 tok 超预算 135）。遗忘是预算管理：画像优先/摘要把 6 问保在 5/6 只需 95-217 tok；按"最近优先"剪枝=把画像扔了（1/6）。忘什么由策略定，不由时间戳定。
5. **记忆与 RAG 混着用 / 无视隐私**：RAG 管外部知识、Memory 管自身历史（§17.7.4 分界），检索、注入是同源剑法是没错，但数据性质不同；敏感信息（医疗/金融/身份）照 §6.10 受 GDPR/个保法约束——**该不入库就不入库，该脱敏先脱敏**。

**探针造假/夸大风险：** 无——`memory_demo.py` 纯 stdlib 确定性计算（预置 11 次会话语料 + 词面抽取规则 + 两档检索打分 + 三种保留策略），stdout md5 `b0cbfdc3…` 三遍逐位一致；无随机源，任何一版实现重跑必得同一串。墙钟 ≈0.01s（只进 stderr）。

**口径声明（哪些是近似/非本机）：**
- **抽取规则 = 词面/结构正则（作者预置）**：`我是/住在/是一名/更喜欢/生日是/city=/title=` 之类的固定模式；真实记忆系统用 LLM 抽取 + 实体链接，行为因模型而异——但机制结论（分账、整合、检索、预算）与输入无关，换个语料方向不变。
- **检索打分 = 词面 bigram 共现 + 槽位语义对齐表（作者预置）**：ALIGN 表（`住哪→居住地` 等）模拟的是 embedding 越过词面共现的那"一截语义"，量的是**确定性上限**；真实向量语义检索在更大语料上的相对表现=非本机实测。
- **查询金标准 = 作者预置**：6 问各指一条记忆（哪个槽/哪条事件），真实系统需评估集。
- **三种保留策略 = 本机实现示例**（最近优先/画像优先/画像+摘要折叠）；MemGPT(2023) 的内存分层、LangGraph checkpoint、ChatGPT 式记忆、与 RAG 同源与隐私监管（GDPR/个保法）=要素事实，非本机实测，精确行为以官方文档为准。
- **遗忘曲线/覆盖口径 = 金标准条目出现在保留集即"可答"**，未计生成质量；**token 估算** = 中文 1 字 1 + 英文/数字连续段 1（非真实 tokenizer，相对账同口径不变）。
