## 0. 为什么 06 章第三课是 Context？

02 讲了「怎么说（Prompt）」：把任务、约束、边界组织成稳定执行的输入。但同一个模型，**给它看的东西不同，答的质量天差地别**——同样的「帮我订 4 人桌」，看到「用户常来、预算三千、周六方便、评分 4.7」，和只看到一句任务，是两个等级的回复。决定「看到什么」的那半边，就是 Context Engineering（§6.3）。

为什么是 2025 年关键词？两个趋势压过来的（§6.2 / §2.16）：

1. **prompt 在瘦身、context/工具在变胖**：越强的模型越不需要技巧（02 第一节引过），真正拉开产品差距的是「喂进去的是不是刚需信息」。系统提示词从 500 行模板变成「一句任务 + 一段高质量上下文」。
2. **上下文是模型的工作内存**：长上下文窗口（§2.16）不等于检索——生产里「读得下整本书」几乎都是靠 RAG + 压缩 + 路由把**最该看的那几段**装进窗口（§2.16 实践认知），而不是无限加窗口。于是在 06 章，除 Model API / Prompt 之外，你必须单独会一门「上下文工程」的课。

一个必须先立在 02 之上的分线（§6.3）：**Prompt 是「怎么说」，Context 是「给什么」**。02 管主语（一句好指令怎么写、怎么评测），本篇管宾语（装什么、装多少、怎么排、要不要带）——后者是 RAG（§8）／Memory（§6.10）／Agent（§9）的统一上层概念：它们最终都以「把东西装进上下文，再配一句好 prompt」为落点。

> 🧩 一句话立于全章之先：**Context 工程 = 四个可度量的工程决策，而不是一种可以「多塞一点」的玄学。**

## 1. 先把「给什么」拆成四个可度量问题

§6.3 把上下文来源列成五类：**检索内容 + 记忆 + 工具结果 + 系统约束 + 压缩**。四类「装什么」的内容 + 一类「装完之后怎么办」的手段。要度量化，把它们重新组织成四个问题：

| 问题 | 你在决定什么 | 对应来源 | 可度量指标 |
|---|---|---|---|
| **Q1 装什么** | 哪些来源必须带、哪些是陪跑 | 检索/记忆/工具/约束/指令 | token、可作答性、必需 token 纯度 |
| **Q2 装多少** | 预算在哪里停（k / 长度 / 压缩率） | 检索块数、记忆窗口、压缩 | token 成本曲线、答案覆盖拐点 |
| **Q3 怎么排** | 哪块先看到、结论是否在首屏 | 块顺序、约束位置 | 噪声前置 token、首屏命中 |
| **Q4 要不要带** | 这条查询到底需不需要上下文 | 路由闸 | 路由命中率、FNR/FPR、token 节省 |

四个问题都可以做成**确定性实验**：token 用估算器、可作答性用词面覆盖判定、位置用按序累计、路由用词面规则。这就是本篇探针的骨架。

关于「模型侧真实收益」的纪律（与 02 同）：上面四个问题的答案是**工程结论**（能省多少 token、覆盖率几个拐点、首屏命中率）；至于「带对的上下文能让模型答得多好」，是模型侧的真实增益——本文不实测，只挂靠：ICL 相变与 shot-scaling 挂靠 02-01 `gpt_demo.py`，长上下文 KV 预算递减挂靠 02-20 `reasoning_demo.py`，检索命中率与噪声挂靠 08 系各章。

## 2. 把「上下文」降维成本机测量（探针设计）

探针 `context_engineer_demo.py` 照 02 的模式：零网络、零下载、不训练模型、纯 stdlib 确定性计算（无任何随机源，64~128 组枚举、按序累计、词面规则全部固定）。三处工程声明，先立规矩：

1. **token 账本**：沿用 01 章的价格表（PIN=2.50 $/百万输入，要素事实）与 02 章的 token 预算思路；token 估算=中文 1 字记 1、英文/数字连续段记 1（确定性近似，非真实 tokenizer、也非 jieba）。
2. **确定性指标**：
   - 可作答性=所需「必需词」组合能否被所选来源覆盖（词面代理）；
   - 纯度=必需 token / 上下文总 token（信息被多少噪音稀释）；
   - 首屏=前 3 块窗口；噪声前置=答案块前累计 token；
   - 路由=词面信号规则（历史词 / 系统单号）判定该不该带上下文。
3. **挂靠纪律**：模型侧现象（primacy/recency、真实检索增益、真实 ICL 增益）一律写在「挂靠」行，不在本机光标点。

四账与四个问题一一对应：**A 装什么（来源组合账）· B 装多少（长度预算账）· C 怎么排（位置效应账）· D 要不要带（路由闸）**。

## 3. 实验 A · 装什么：来源组合账（最简集 vs 全全集）

一个复合任务同时压四个来源：**查评分（检索）+ 记预算（记忆）+ 加日程（工具）+ 回复简洁（约束）**，外加 3 项可选（指令前缀 + 两段纯陪跑：广告块、升级公告）。把 7 项来源的 token 明细列出来，再枚举**全部 2⁷=128 个子集**，标记「可作答」= 包含 4 个必需来源，找出最省的可作答子集：

```
来源(7 项) token 明细：{'RETRIEVAL': 32, 'MEMORY': 19, 'TOOL': 21, 'SYS_CONSTRAINT': 21, 'SYS_PROMPT': 18, 'ADS': 24, 'UNREL': 28}
全子集枚举 2^7 = 128 个子集；可作答（含 4 必需来源）= 8 个
最简可作答集（只带 4 必需）：token=93  $0.00023  纯度=93/93=1.000
全全集（7 项全带）：token=163  $0.00041  纯度=93/163=0.571
全带比最简贵：+70 tok（+75.3%）· 纯度 1.000→0.571（陪跑把信息稀释）
陪跑代价行：ADS=24 tok · UNREL=28 tok 均不增加可答性
```

**教学落点：**
- **上下文每一段都有价格**。全带比只带必需贵 **75.3%**，而 24+28=52 个 token 的陪跑块对「可作答」贡献为 0。写实现时「把能找到的都塞进去」是最常见的隐性浪费——比调 prompt 贵得多，因为它每轮查询都在付。
- **纯度是可量化的稀释计**：1.000 → 0.571，意思是模型看到的 token 里只有 57% 是完成任务必需的，43% 在分散注意力（模型侧噪音的实际代价挂靠 08 系评估：陪跑块越多，忠实度与检索精度越被稀释，见 08-07 RAGAS / 08-13 诊断）。
- **最简集 = 只带可答必需**：4 类来源全用上了吗？不是——128 个子集里**只有 8 个可作答**，其余 120 个都是缺一块就不能答的组合（忘带检索→评分是编的；忘带记忆→预算按默认来；忘带工具→日程没写进日历；忘带约束→回复成了清单）。「带什么」的第一原则先把**必需集**枚举出来，再谈省。
- **缓存友好性**（挂靠 01 章缓存输入半价、02 章 batch=10 省 40.3%）：越靠前的段跨查询越可复用，所以最简集（更短、更稳定的前缀）天然是更长的缓存命中前缀——省 token 和回头钱是同一件事。

## 4. 实验 B · 装多少：长度预算账（top-k 截断曲线）

检索经常带回 10 块、20 块。真实答案分布可疑地只落在前几块上——模拟 10 块按相关度降序、10 个答案词全部在前 5 块，后 5 块零命中（纯陪跑）。逐 k 看「token 涨了没、命中有没有跟上」：

```
k       token     命中(10)   成本($)     累积@k
 1         32          3     0.00008     0.300
 2         68          5     0.00017     0.500
 3        103          7     0.00026     0.700
 4        138          9     0.00034     0.900
 5        168         10     0.00042     1.000
 6        188         10     0.00047     1.000
 7        204         10     0.00051     1.000
 8        219         10     0.00055     1.000
 9        239         10     0.00060     1.000
10        258         10     0.00064     1.000
拐点：k=5 token=168 命中 10/10；再往后 token 涨、命中不涨（后 5 块零贡献）
策略账：I 全量(k=10) token=258  $0.00064
        II top-5     token=168 命中 10/10 → 省 34.9% 零损失
        III 压缩(只留含答案词句子) token=106 → 省 36.9%（相对 top-5）
```

**教学落点：**
- **更多块 ≠ 更多答案**。覆盖在第 5 块到 100%，后 5 块 token 从 168 涨到 258（+53.6%）但命中纹丝不动——继续加大检索深度（08-13 那条 k=5/10/20 成本线 154.4/307.9/614.1 字符就是这么涨上来的）只是把钱投给了陪跑。
- **先画覆盖拐点再定 k**：k=5 是本数据的拐点，全量省 **34.9%** 且零答案损失。生产里的做法是对自己语料跑一遍「答案词覆盖率 ~ k」曲线，把 k 定在拐点附近而不是拍脑袋取 20。
- **压缩是在拐点上的第二刀**：只留含答案词的句子（句子级提取，实现思路同 08-06 的提取式压缩 88.2%）比 top-5 再省 **36.9%**——两刀合计把 258 token 压到 106（-58.9%），答案词一个不丢。检索多路 + 生成用精，是同一套思想（挂靠 08-06 的结论：检索放宽、生成收紧）。

## 5. 实验 C · 怎么排：位置效应账（答案块在第几才露面）

同一批块，排列方式不同，「结论是否被先看到」完全不同。把答案块依次放在 6 个位置的任意一个，量两件事：**噪声前置**（读到答案前必须消耗的 token）与**首屏命中**（前 3 块窗口内是否露出）：

```
pos  噪声前置(token)  首屏(前3块)
 1          0          YES
 2         17          YES
 3         33          YES
 4         42          no
 5         57          no
 6         79          no
原文顺序（答案 pos5）：噪声前置 57 tok · 首屏命中 0
相关块置顶（答案 pos1）：噪声前置 0 tok · 首屏命中 1 → 首屏 0→1 · 噪声前置 57→0 tok
```

**教学落点：**
- **先看到什么决定先答什么**。答案埋在第 5 块时，模型要先消化 57 个 token 才能撞上核心结论——你还得指望它注意到。答案置顶，噪声前置归零，首屏命中从 0 变 1。
- **相关块置顶是零成本改造**：不用换检索、不用加 token，只是把排序从「数据库返回顺序」改成「相关度降序」（+ 系统约束置顶），首屏命中就救回来了。这是四个决策里性价比最高的一条。
- **挂靠**：注意力 primacy/recency（前段比中段更易被利用）是模型侧现象，本文不实测；本机量的是「结构排序的确定性可见性」。长上下文里这效应会被放大——背景块越多，越靠后的位置越难真正被读到（02-20 KV 预算递减：k 越大、后续每 token 归属越弱）。
- **约束也是上下文**：回复长度、格式、防注入（§12）这些系统约束应放在 prompt 头部（指令区），检索/记忆内容放中部，工具结果放尾部——按「哪些块必须先被处理」排，不是按「哪个块先查到」排。

## 6. 实验 D · 要不要带：路由闸（全带 vs 路由的省）

不是每条查询都需要上下文：寒暄「写首诗」不需要近 5 条会话摘要。「全带」是最平滑但也最贵的实现。仿 08-10 Agentic RAG 的决策层，做一道**词面路由闸**：含历史词（上次/之前/最近/常去）或系统单号（ZX-数字）→ 带上下文，否则不带。8 条查询对着真值打分：

```
q     GND  路由  判定
q1    T    带    OK
q2    T    带    OK
q3    T    不带    FNR
q4    T    带    OK
q5    F    不带    OK
q6    F    不带    OK
q7    F    不带    OK
q8    F    不带    OK
命中 7/8 · FNR=1（该带没带，人名类上下文引用漏网）· FPR=0
token 账：全带 8 条=301 tok  $0.00075；路由后=171 tok  $0.00043 → 省 43.2%
```

**教学落点：**
- **路由是 Context 工程的第一个省钱闸**：8 条查询省 **43.2%** token。省下来的不是哪条查询变短了，而是**该带才带**——5 条不需要上下文的查询（一首诗/天气/圆周率/翻译），一句都不用多付。
- **规则词面永远有漏网，且漏网长在信号弱的地方**：q3「把张三加进明天的会议日程」真需要上下文（要去记忆/系统里查张三这个人），但既没有历史词也没有单号——**人名类引用**是词面信号的盲区，FNR=1。教训不是「规则没用」，而是：词面路由适合「省钱的闸」，不适合「错的闸」；生产里要么挂语义模型召回率更高，要么像 08-10 那样对关键路径（涉及写操作/隐私）强制带。
- **与 08 系同源**：08-10 的 judge 把三个决策点（要不要检索、检索几轮、要不要信首屏）把关省了 25.4%——「要不要去拿」是同一类闸；本篇是词面版（零成本、可离线、确定性），08 是模型判别版（更准、更贵、非本机实测源）。

## 7. 常见坑（5 条）

1. **把「带全」当默认**：所有来源无差别塞进每一轮——最贵的隐性配置债。正确姿势是先枚举必需集（实验 A），再谈省。
2. **不看覆盖拐点就定 k**：搜索语义复杂、答非所问先怀疑「k 太大」，检索结果塞满了绿皮文档。先跑覆盖曲线再定预算（实验 B）。
3. **答案埋在最后**：检索返回顺序直接当上下文顺序。相关块置顶、约束前置、工具结果兜底（实验 C）。
4. **全带上下文、不做路由**：把「要不要带」交给 prompt「请只关注相关信息」。词面路由一眼能省下的钱，用嘴皮子求模型不省（实验 D）。
5. **把「约束」踢出上下文**：有人以为上下文工程只是「塞资料」——忘了回复格式、长度、防注入约束也是上下文的一部分；它们该固定在指令区头部，而不是散在检索块后面，否则每轮都可能被陪跑块带偏（§12 注入同理）。

## 8. 诚实边界（AAA 自我审查）

**探针造假/夸大风险：** 无——`context_engineer_demo.py` 纯 stdlib 确定性计算（枚举/累计/词面规则），stdout md5 `8c3edefc…` 三遍逐位一致；无随机源，任何一版实现重跑必得同一串。

**口径声明（哪些是近似）：**
- **token 估算** = 中文 1 字 1 + 英文/数字连续段 1，非真实 tokenizer、亦非 jieba；真实子词器会使绝对数有差异，但**相对账（省 XX%）在同口径下不变**。
- **价格** = PIN 2.50 $/百万（要素事实，写作环境无外网未在线复核，以官方价目表为准）。
- **可作答性/命中** = 词面覆盖代理，衡量「信息是否出现在上下文里」，不衡量「模型是否用上了它」——后者（真实 ICL 增益）挂靠 02-01、真实检索收益挂靠 08 系。
- **实验 B 的压缩** = 句子级词面提取的规则仿真（提取式压缩的一类实现），不是 LLMLingua 式的小模型困惑度打分层；真实压缩率挂靠 08-06（字符口径 88.2%）。
- **路由** = 手工词面规则（2 个信号），真实产品应上语义模型并做召回率评测；「人名引用漏网」正是在提醒这一边界。
- **primacy/recency / KV 递减** = 模型侧现象，本文只挂靠既有的 02-20 / 02-01 实测，绝不在光标点当作本机数据。
